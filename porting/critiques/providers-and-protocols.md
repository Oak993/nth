# Critique: providers-and-protocols

**Verdict:** NEEDS_REREAD: coverage is real and mostly accurate (all 30 files in DroppyCode/Services/Providers are assigned, line counts match `wc -l` exactly), but R041 misstates the Claude handshake argv, R044 omits two whole algorithms (the Copilot model filter and the entire account.getQuota percent/skip logic), and several load-bearing details (persisted-seed identity, dead per-turn state, fallback auth branches) are missing across R039/R043/R046.

## Contradictions (a report disagrees with the source) (4)

1. R042 (CodexSession) and R044 (CopilotSession) both file `sendsVersion:` as an unresolved question ("whether sendsVersion: false omits the jsonrpc version field or some client-version field"). It is settled one grep away in an adjacent bundle: JSONRPC.swift:109 `if sendsVersion { message["jsonrpc"] = "2.0" }`. Codex's app-server is the only connection built with `sendsVersion: false` (CodexSession.swift:508) and therefore must receive frames with NO `jsonrpc` member, while ACP (ACPSession.swift:117) and Copilot (CopilotSession.swift:494) must receive `"jsonrpc": "2.0"`. Two reports leaving this open risks the port sending a uniform envelope.

2. R041 asks who populates PlanLimits.Window.detail ("declared with default nil but never set anywhere in this file"); R040 answers it for Z.ai (ZaiAPI window details "<current> of <usage> credits" / "<current> of <usage> calls"). Not a factual conflict, but the two reports were not reconciled, so the family leaves a field looking unused when it is not.

3. R041 asks which readers call PlanLimitsReader.windowTitle(minutes:); R040 (ZaiAPI) and R045 (PiPlanLimits, "Codex · " + windowTitle(minutes: limit_window_seconds / 60)) and R042 (Codex plan windows) all name callers. Same unreconciled-question pattern.

4. R044's header note claims "session delete was verified live" and then admits no session.delete call exists in the file; nothing else in the family accounts for a Copilot session ever being deleted. Either the header comment is stale or the delete lives outside Services/Providers and no reader in this family chased it.

## Gaps (referenced but never pinned down) (12)

1. R041 / ClaudeSession.swift:185-193 - the handshake argv is described as "the argv omits --include-partial-messages and adds --no-session-persistence". It is not a delta of the session argv: it is a fixed, much shorter list `-p --input-format stream-json --output-format stream-json --verbose --no-session-persistence --setting-sources user,project,local`, with no --permission-prompt-tool, no --allow-dangerously-skip-permissions, no --permission-mode, no --mcp-config, no --append-system-prompt. A port following the report's wording would launch the catalog probe with the full session argv.

2. R041 / ClaudeSession.swift:201-204 - handshake() requires `response.commands` to be a non-nil array before it will return anything; if the CLI answers the initialize without a `commands` array it throws "Claude could not load its commands." even though the caller (ProviderRegistry.loadClaudeCatalog, ProviderRegistry.swift:498-502) only wants `.models`. The report records the two error strings but never states that a missing `commands` key kills the Claude model catalog too.

3. R044 / CopilotSession.swift:407 - listModels skips every entry where `model["policy"]["state"] == "disabled"`. The report lists `.policy.state` among the fields read and documents the "unconfigured" detail string, but never mentions the disabled filter, so a port would surface models the CLI will refuse.

4. R044 / CopilotSession.swift:444-467 - readPlanLimits has no entry at all in feature_notes. Missing: a snapshot is skipped when `isUnlimitedEntitlement == true` or when `entitlementRequests` is absent or <= 0; percent is `max(0, min(100, 100 - remainingPercentage))` when remainingPercentage exists, otherwise `min(100, usedRequests / entitlementRequests * 100)`; `resetDate` is parsed with a plain ISO8601DateFormatter and then retried with `formatOptions = [.withFullDate]` (CopilotSession.swift:470-475); the whole read returns nil when no window survives; and the plan name is a SECOND request (account.getCurrentAuth) whose `authInfo.copilotUser.copilot_plan` is wrapped as "Copilot <plan>".

5. R044 / CopilotSession.swift:428-439 - authStatus's non-happy paths are undocumented: a failed connect() returns .unknown, a failed account.getCurrentAuth request returns .unknown, and a null or missing `authInfo` returns .signedOut. Only the " · no Copilot access" suffix made it into the report.

6. R046 / ProviderRegistry.swift:780 - the opencode auth branch's fallback is stated only as far as the credential parse. When no U+25CF line is found the result is `result.succeeded ? .signedOut : .unknown`, not an unconditional .signedOut. A port that hardcodes .signedOut will show "Not signed in" for a CLI that merely failed to run.

7. R043 / CommandCodeAPI.swift:349-359 - the report gives the nine seed detail strings but never the seed ids or names. Those exact ids are load-bearing twice over: they are what goes into the persisted "providerModelCatalogs" blob, and ProviderRegistry.loadCatalog compares `models(for: .commandcode) == Self.commandcodeSeed` (ProviderRegistry.swift:464) to decide whether to re-probe. The ids are claude-sonnet-5 (isDefault), claude-fable-5-1, claude-opus-5, gpt-6-astra, gpt-5.6-sol, google/gemini-3.8-flash, deepseek/deepseek-v4-flash, moonshotai/kimi-k3, zai-org/glm-5.3, with names "Claude Sonnet 5", "Claude Fable 5.1", "Claude Opus 5", "GPT-6 Astra", "GPT-5.6 Sol", "Gemini 3.8 Flash", "DeepSeek V4 Flash", "Kimi K3", "GLM 5.3".

8. R039 / AntigravitySession.swift:23-24, 88, 150-151 - the report says runtimeMode and interactionMode are "refreshed on each send". They are written on every send and then never read: modeArguments is called once at line 88 with `configuration.runtimeMode` / `configuration.interactionMode`, so the two stored properties are dead after init. The practical consequence for the port (a mid-thread runtime-mode or plan/build switch cannot reach `agy` without relaunching the process) is not stated anywhere. Contrast PiSession.swift:279-288, where the same switch does take effect because it is rewritten into the gate file every turn.

9. R039 / ACPSession.swift:381-385 - applyConfigOptions sets `effortConfigID = nil` and `fastConfigID = nil` at the top of every call. A config_option_update or a set_config_option reply that omits the thought_level or model_config entries therefore drops the effort slider and the Fast toggle for the rest of the session. The report describes what the branches build but not this reset.

10. R039 / ACPSession.swift:534-535 - the `config_option_update` session/update notification is handled (it re-runs applyConfigOptions, which re-emits .models with a new current model / effort scale / fast tier). It appears only as the bare word "configOptions" inside persisted_fields; there is no feature note saying the agent can push a live model or effort change mid-session. `agent_thought_chunk`, `plan` and `available_commands_update` are likewise handled but never named in feature_notes.

11. R040 / OpenAICompatibleSession.swift:437-446, 471-482, 808-812 - no feature note covers cancellation. interrupt() sets `interrupted`, cancels sendTask, roundTask and sseDrain, and resumes every pending approval continuation with `false` (i.e. an in-flight approval is silently treated as a decline); stop() does all that plus sets isStopping and nils sessionID, which makes isRunning false (line 240). finishInterrupted resolves approvals the same way and emits .turnCompleted(.interrupted). Also unstated: `approveAllRemaining` (set by the "always" option at line 450) is reset per turn at line 292, which is what makes the label "Approve for turn" honest.

12. R046 / ProviderRegistry.swift:626-641 - refreshCredits has no 25-second watchdog and no `defer` around `loadingCredits.remove(provider)` (unlike refreshPlanLimits at lines 550-566), and when the key is empty it clears `credits[provider]` but leaves `creditsFetchedAt[provider]` intact. The report flattens both reads into "the read runs on its own task" and states only the credits-clearing half.

## Thin reports (1)

1. R044 (CopilotSession.swift, 1075 lines) - dense and accurate on the event stream and permission model, but the static half of the file is compressed almost to nothing: listModels, authStatus and readPlanLimits (CopilotSession.swift:400-475) get field lists in persisted_fields and title strings in ui_elements, with no feature note describing their actual logic. The disabled-model filter and the entire quota percent/skip computation are absent. Needs a targeted re-read of lines 400-475.

## Cross-cutting findings (9)

1. Three different JSON-RPC dialects ride on the same JSONRPCConnection with different envelopes and framings, and the port must keep them apart: ACP (ACPSession.swift:117, sendsVersion true, default framing), Codex app-server (CodexSession.swift:508, sendsVersion FALSE, default framing), Copilot SDK (CopilotSession.swift:494, sendsVersion true, StdioProcess framing: .contentLength). Pi and Command Code and Antigravity use line/JSONL framing instead (PiSession.swift framing: .lines).

2. Every unsupported inbound JSON-RPC request is answered with error code -32601, but the message differs by provider: ACPSession.swift:559 sends "Method not found"; CodexSession and CopilotSession send "Droppy Code does not support <method>." A port should not unify these.

3. The client identity string "droppy-code" / title "Droppy Code" / version AppInfo.version is sent on four separate handshakes with different key paths: ACP `clientInfo` in initialize, Codex `clientInfo` in initialize (CodexSession.swift:517), Copilot `clientName` in session.create/resume plus the ping payload `{"message":"droppy-code"}` (CopilotSession.swift:496), Claude control request ids prefixed "droppy-code-<n>".

4. RuntimeMode.rawValue and InteractionMode.rawValue are an on-disk contract, not just an in-memory enum: PiSession.swift:281-286 writes them verbatim into the per-session gate JSON, and the shipped TypeScript in PiCLI.extensionSource compares them against the literals "fullAccess", "autoAcceptEdits", "auto" and "plan". No report in this family states that those raw values must match exactly, and the enum is declared outside the bundle.

5. Four independent "install a helper file next to the app, only when the bytes differ" patterns exist and must all be ported: CommandCodeAPI.installMod() writing droppy-code-approvals.ts, PiCLI.installExtension() writing droppy-gate.ts, MCPBridge.installBridge(), plus the per-session scratch directories (Command Code approvals dir, Pi gates dir). All are under Application Support on macOS.

6. Runtime-mode changes reach the provider by three different mechanisms, and only one survives without restarting the process: a live protocol call (Claude set_permission_mode, Copilot session.permissions.setMode, Codex per-turn approvalPolicy/sandboxPolicy, ACP set_config_option), a rewritten gate file (Pi, Command Code), or launch flags only (Antigravity, ACP launchArguments, Copilot isExperimentalMode). Antigravity and the ACP launch flags need a session restart; the family never says so in one place.

7. Only two providers expose a cancellable, interruptible turn over the wire (Claude control `interrupt`, Codex `turn/interrupt`, Copilot `session.abort`, ACP `session/cancel`, Pi `abort`). Antigravity and Command Code have no interrupt message at all and rely on SIGTERM plus an isStopping/interruptRequested flag to keep the UI from reporting a crash (AntigravitySession.swift:165-175, CommandCodeSession.swift:229-236). A Windows port has no SIGTERM equivalent with those semantics and must decide what replaces it.

8. Three providers pass MCP configuration by three different channels that all originate in the same settings: --mcp-config + --strict-mcp-config (Claude), config.mcp_servers inside thread params (Codex), --allowed-mcp-server-names <ids...> (Antigravity), MCPSessionOverrides.copilotArguments() (Copilot), MCPSessionOverrides.opencodeEnvironment() merged into the child env (opencode), GEMINI_CLI_SYSTEM_SETTINGS_PATH (antigravity), and DROPPY_CODE_MCP_BRIDGE / DROPPY_CODE_MCP_CONFIG env vars read by the Pi and Command Code helper scripts.

9. Two UserDefaults keys and one alternate defaults suite carry the whole provider cache: "providerModelCatalogs" and "providerModelCatalogDates" on UserDefaults.standard, "recentSlashCommands" on (CaptureRun.defaults ?? .standard) (ProviderRegistry.swift:47-49, 158, 697). The catalogs blob is rewritten whole on every change, and at load time every cached row is re-sorted through ACPSession.orderedEfforts (ProviderRegistry.swift:167-172) - a migration step that only exists as that one map call.
