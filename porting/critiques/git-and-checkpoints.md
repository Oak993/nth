# Critique: git-and-checkpoints

**Verdict:** NEEDS_REREAD - R036 is dense and mostly accurate on the small files, but Git.swift carries two outright wrong claims (an `add -A` timeout, and an unreachable error string presented as shipped UI text), omits the exact argument vectors of six shipped commands, and leaves the checkpoint commit's parentless shape, its two `phase` literals and the git/forge-CLI identity split undocumented.

## Contradictions (a report disagrees with the source) (3)

1. TIMEOUT, report vs source. R036 (Git.swift feature_notes) states 'default timeout 120 s, 300 s for push, fetch, pull, worktree add, the forge CLIs, `add -A` and diff.' Git.swift:164 `commitAll(message:)` runs `["add", "-A"]` with NO timeout argument, i.e. the 120 s default. Only the scratch/throwaway-index adds take 300 (lines 253, 448, 459, 484, 707). A port copying the report would give the user-facing commit path a 300 s budget it does not have.

2. UNREACHABLE STRING, report vs source. R036 ui_elements for Git.swift lists 'Error text surfaced to the user: "The request could not be merged."'. In Git.swift:212-226 `lastFailure` is initialised to that literal but overwritten with `result.failureMessage` on every failed attempt, and the loop `for attempt in 0..<6` always executes at least once; Shell.swift:15-19 guarantees `failureMessage` is never empty (it falls back to "The command failed with exit code \(status)."). The literal is dead code, not user-visible text. R036 did not classify it.

3. SCRATCH-INDEX FALLBACK, report vs source. R036 says currentTree's capture closure, 'when scratch is nil or the incremental add fails it deletes the scratch, re-seeds by copying the real index (or read-tree HEAD) and runs `add -A -- .`'. Git.swift:434-438: when `scratch` is nil the closure returns `try await captureTree()`, which builds a *fresh* `droppy-code-index-<UUID>` under temporaryDirectory and removes it in a defer (lines 471-487); it never touches the shared scratch. The delete-and-reseed path is only inside `captureTree(scratch:paths:)` (Git.swift:452-461), where `scratch` is non-optional.

## Gaps (referenced but never pinned down) (12)

1. Git.swift:409 `checkpointRef(thread:turn:phase:)` - R036 documents the ref template but never names the only two `phase` values shipped: "start" (ThreadRuntime.swift:1226) and "end" (ThreadRuntime.swift:2281). Nor does it name the persisted fields that hold the resulting ref strings, `Turn.baseCheckpoint` (set ThreadRuntime.swift:1250, read ThreadRuntime.swift:1773) and `Turn.endCheckpoint` (ThreadRuntime.swift:2282, read :1775). Migration behaviour of those two persisted strings across a rename of the ref namespace is stated nowhere.

2. Exact argument vectors missing for six shipped commands that R036 only lists as symbols: Git.swift:290 `fetch()` = `["fetch", "--quiet", "origin"]` (timeout 300); Git.swift:300 `changedPaths(from:to:)` = `["diff", "--name-only", "-z", from, to]`; Git.swift:260 `treeHash(of:)` = `["rev-parse", "<ref>^{tree}"]`; Git.swift:264 `commitHash(of:)` = `["rev-parse", "--verify", ref]` with an undocumented default parameter `ref: String = "HEAD"`; Git.swift:269 `commitWork` = `["commit-tree", tree, "-p", parent, "-F", "-"]`; Git.swift:294 `isAncestor` = `["merge-base", "--is-ancestor", commit, other]`. The bundle's own rule is that exact flags are the specification.

3. Git.swift:544-570 `diff(from:to:binary:paths:)` boundary unstated. R036 says it 'chunks pathspecs at diffPathChunk = 400 per invocation'; the guard is `paths.count > Self.diffPathChunk`, so exactly 400 paths is a single call. More importantly `paths: []` (non-nil, empty) still prepends `--literal-pathspecs` and appends a bare `--`, producing a full-tree diff, with no early return of the kind `resetIndex` (Git.swift:392), `checkoutPaths` (:398), `removePaths` (:403), `restore` (:602) and `previewRestore` (:577) all have. Shipped callers guard (AppModel+Hydra.swift:726, ThreadRuntime.swift:3289), so this is unreachable today, but the port needs the rule written down.

4. R036's unresolved_question 'isBuildOutput has no call site inside this bundle' is answerable: seven shipped call sites, all silent filters that drop the path with no user-visible report. AppModel+Hydra.swift:251 (`!isBuildOutput(path) && projects.contains { relative(...) != nil }`), AppModel+Hydra.swift:754, AppModel+HydraMerge.swift:144, :503, :530, ThreadRuntime.swift:3288, :3347. Nothing surfaces 'this file was excluded', which is a port-visible behaviour decision.

5. `TouchedPaths.matches` - R036 documents the suffix-matching rule but not where it is consumed: DiffInspector.swift:144 (`focus.isEmpty ? [] : files.filter { matches($0, touched: focus) }.map(\.id)`, which drives which diff rows are auto-expanded) and DiffInspector.swift:167-168 (a turn is skipped when neither `files` nor `missing` matches). The loose suffix rule therefore decides UI focus, not just accounting.

6. R036's unresolved_question on `previewRestore` path spaces is answerable: ThreadRuntime.swift:1776 binds `Git(thread.worktreePath ?? project.path)` and `paths` are `Set(removed.flatMap { $0.touchedPaths ?? [] }).sorted()` (repository-relative, produced through `TouchedPaths.relative`, e.g. ThreadRuntime.swift:2290, :3265). `previewRestore` itself calls `repositoryRoot()` (Git.swift:582) before the blob lookups, so the two spaces coincide only while the project path IS the repository root; a project opened at a subdirectory of a repo is the untested case, and nothing in the code guards it.

7. R036's unresolved_question on forge cases is answerable: MergeRequestLink.swift:6-11 declares exactly three, `.gitlab`, `.github`, `.gitea` (the comment names Forgejo and Codeberg as tea's family). It also carries a user-visible literal R036 never reaches: `var label: String { forge == .gitlab ? "!\(number)" : "#\(number)" }` (MergeRequestLink.swift:18), and URL parsing keyed on the path segments "merge_requests", "pull" and "pulls" (:25-31).

8. WorkingTreeWatch.swift teardown asymmetry unflagged. `shared(for:gitDirectory:)` carries an explicit comment (lines 96-98) that tearing down the *registered* watch 'stopped its stream and deleted the scratch index a capture may be writing through'. But the cookie-timeout path, `guard arrived else { tearDown(); return nil }` (line 271), calls the same `tearDown()` (lines 157-170, which does `try? FileManager.default.removeItem(at: self.scratch)`) on a watch that may have `state.capture` in flight. R036 describes both paths separately and never notes that the hazard the registry path documents is unguarded here.

9. WorkingTreeWatch: a watch torn down by the cookie timeout stays in the `watches` registry (nothing removes it; only the `limit = 32` eviction in `shared` does, line 102). `state.stream` is nil forever after, so `settledGeneration()` returns nil at line 244 and every later `currentTree` for that directory takes `capture(nil, nil)`. R036 says 'every later snapshot is a fresh capture' but not that the dead watch is permanently sticky per directory and never rebuilt.

10. Git.swift:31-48 `run(_:environment:input:timeout:)` merges the caller's `extra` LAST (`environment.merge(extra) { _, new in new }`), so a caller could override GIT_TERMINAL_PROMPT / GIT_OPTIONAL_LOCKS. No shipped caller does (only GIT_INDEX_FILE is ever passed), but R036 states the two variables as 'always set on git' without the precedence rule.

11. DiffParser.swift:92-93 - the `--- ` branch is consumed for every `--- ` line, and only the exact string `"--- /dev/null"` has an effect; the old path on a normal `--- a/foo` line is discarded (oldPath is set only by `rename from `). R036's prefix-dispatch list reads as if only `--- /dev/null` reaches that branch, so a port could be tempted to parse oldPath from `---`.

12. RevertPreview.swift:50 - the outer `numstat.split(separator: "\0")` uses the default `omittingEmptySubsequences: true`, so empty numstat text yields zero files and no throw, while each *entry* is split with `omittingEmptySubsequences: false` (line 51). R036 states the inner flag but not the outer one, and that asymmetry is what makes a trailing NUL harmless.

## Cross-cutting findings (6)

1. Two git identities, never distinguished by R036. `Git.commitWork(_:parent:message:)` (Git.swift:268-272) runs `commit-tree <tree> -p <parent> -F -` with the message on stdin and WITHOUT `Self.identity`, so a head's branch commit carries the user's own git config identity. `commitTree(_:message:)` (Git.swift:668-673) and `captureCheckpoint` (Git.swift:423) both pass `environment: Self.identity`, forcing GIT_AUTHOR_NAME/GIT_COMMITTER_NAME="Droppy Code" and GIT_AUTHOR_EMAIL/GIT_COMMITTER_EMAIL="droppy-code@localhost". R036 lists commitWork only as a key_symbol and never states its flags or that it is the one commit path left in the user's name.

2. Checkpoint commits are PARENTLESS. Git.swift:423 is `run(["commit-tree", tree, "-m", "Droppy Code checkpoint"], environment: Self.identity)` with no `-p`. Contrast Git.swift:669-670 (`commitTree`) which appends `["-p", "HEAD"]` when `hasCommits()`. R036 describes commitTree's parent rule but says only that captureCheckpoint 'runs commit-tree with the message'. For the port this matters: checkpoints are root commits reachable solely through `refs/droppy-code/checkpoints/...`, so ref deletion (Git.swift:651-658) makes them immediately gc-able.

3. Forge CLIs run in a different environment from git. `Shell.run(tool:)` calls in Git.swift:181, 186, 191 and 215-217 pass no `environment:`, so Shell.swift:49 substitutes `LoginEnvironment.current` WITHOUT the GIT_TERMINAL_PROMPT=0 / GIT_OPTIONAL_LOCKS=0 that `Git.run` (Git.swift:37-38) always sets. glab/gh/tea can therefore prompt on a terminal where git never would. R036 listed this as unresolved rather than reading Shell.swift.

4. Missing forge CLI throws an exact string R036 left unresolved: Shell.swift:129-131, `guard let executable = LoginEnvironment.which(name) else { throw ShellError("\(name) was not found on your PATH.") }`. That is the message a user without gh/glab/tea sees from createPullRequest and mergePullRequest.

5. macOS-only git resolution nobody flagged concretely. `LoginEnvironment.git` (Shell.swift:394-409) is `resolvedGit` else `which("git")` else `/usr/bin/git`; `developerGit` runs `/usr/bin/xcode-select -p` with an 8 s timeout and prefers `<developer>/usr/bin/git` over the `/usr/bin/git` shim (the comment cites 11.5 ms vs 4.5 ms per call). `which` splits PATH on ":" (Shell.swift:417). Every one of these is a Windows port decision and R036's platform_assumptions only says 'git is invoked as an executable URL from LoginEnvironment.git'.

6. `Git.run` never passes `outputLimit`, so every git invocation buffers stdout/stderr unbounded (Shell.swift:36-44, `outputLimit: Int? = nil`). R036's only size note is the 40,000-character truncation inside `workingChanges()`, which is a caller-side trim, not a capture bound. A binary `diff --binary` over a large tree (Git.swift:544-570) is read whole into memory.
