# Critique: chat-and-composer

**Verdict:** NEEDS_REREAD — the reports are mostly accurate and specific, but R051/R052 mis-classify two never-written environment flags (so one described rendering path is unreachable in this checkout and the shipped path is hedged as "undetermined"), R052 paraphrases the bare-domain regex and TLD table the contract demands verbatim, and R010/R015/R016 leave several user-visible strings, a revert-visibility rule and the changes-popover lifecycle unrecorded.

## Contradictions (a report disagrees with the source) (3)

1. Unreachable path presented as shipped behavior, and the two reports disagree about it. R051 (LinkParagraphView) states as fact: "passesProseThrough = !markdownBlockSelection: inside a finished reply hitTest returns nil over prose so SwiftUI's whole-reply drag selection takes over". R052 states `markdownBlockSelection` defaults true (MarkdownView.swift:877-880, MarkdownBlockSelectionKey defaultValue true). A repo-wide search shows the key is never written anywhere in the checkout (only reads: LinkParagraphView.swift:30 and :37, MarkdownView.swift:889), so `passesProseThrough` is always false and R051's prose-pass-through behavior is unreachable as shipped. One of the two must be re-read and re-classified.

2. R052 (MarkdownView) leaves markdownProseRuns "could not be determined from the assigned files" while R052 (ProseRunView) asserts ProseRunView is "the non-streaming alternative ... chosen when markdownProseRuns is true". The flag defaults true (MarkdownView.swift:881-884) and is never written anywhere in the checkout, so the ProseRunView AppKit path is the only path finished replies ever take and MarkdownBlockView's per-block stack runs only while streaming. Presented as undetermined in one place and asserted conditionally in the other, neither report states the settled consequence.

3. R012 describes the row-expansion reveal as one mechanism ("calls the revealTimelineEnd action so the view scrolls to keep the end in sight"), while R010 documents TimelineRevealBox as two distinct closures where `action` deliberately holds back when the jump button is up and `follow` does not (ThreadTimeline.swift:321-322). The code confirms R010: TimelineRows only ever calls `action()`, ThreadTimeline.swift:2089 is the sole `follow()` caller.

## Gaps (referenced but never pinned down) (19)

1. R016 / EffortSlider.swift:500-503: the pair caption strings are never recorded. Source is `if let headsEffort { return "The lead's effort · heads run at \(headsEffort) effort" }` and `return "The lead's effort · heads keep their own"`. headsEffort = `ModelOption.effortTitle(pair.workerEffort ?? resolvedHeadsEffort).lowercased()` (EffortSlider.swift:494), where resolvedHeadsEffort = `model.hydraLaunch(for: thread)?.workerEffort` (EffortSlider.swift:193). The caption also renders only when `pair != nil && !efforts.isEmpty` (EffortSlider.swift:637), a condition R016 omits. R016 only says "Pair caption line: font 11 secondary, lineLimit 1, minimumScaleFactor 0.9, padding .top -6".

2. R016 / EffortSlider.swift:531-534: `private var title` returns the literal "Standard" when `efforts.isEmpty`, and that title button still renders (EffortSlider.swift:570) above the "This model has one reasoning level." line. R016 documents the body text but never the "Standard" title, so a port would show an empty or wrong title for single-level models.

3. R016 / EffortSlider.swift:729-738: the mapping from state to TrackLook.Kind is unstated. Source: `switch (isMax, fastMode) { case (true,true): .fusion; case (true,false): .supercharged; case (false,true): .fast; case (false,false): .plain }` with `isMax = count > 1 && index == count - 1`. R016 gives every kind's fill/glow/spark colours but never says which slider state selects which kind.

4. R016 / EffortSlider.swift:331 and 363-367: the model list's detail lines are undocumented. A model row's detail is `locked ? "New chats only" : (showsProviders ? entry.provider.displayName : nil)`; a pair row's is `[modelsTitle (only when pair.customName != nil), HydraPairSummary.providers(pair), HydraPairSummary.efforts(pair)].compactMap{$0}.joined(separator: " · ")`. R016 lists `detail(for: HydraPair)` as a symbol but never its composition or separator.

5. R016 / FollowUpQueueTab.swift:401: the reorder gesture's own parameters are missing: `DragGesture(minimumDistance: 1, coordinateSpace: .global)` with `.updating($isGrabbing)`. R016 gives the settle maths (fallbackHeight 32, pairBand 0.25) but not the gesture that feeds it, and not the cursor-stack balance contract (openHand pushed on grip hover :389, closedHand pushed on first dragChanged :233, pop in dragEnded :294, compensating pop in `.onChange(of: isDragged)` when the row was released away from the grip :398, pop in onDisappear :392).

6. R009 / ChatView.swift:1395, 1407, 1502, 1513: the four in-flight git activity labels shown as the BranchMenu's own title are never recorded: "Switching", "Creating", "Pushing", "Opening pull request", set and cleared by `GitStatusModel.perform(_:_:)` (ChatView.swift:1319-1328, `defer { self.activity = nil }`). R009 states the title is `git.activity ?? git.status?.branch ?? "Detached"` but leaves the literals out.

7. R009 / ChatView.swift:1142: the Hydra button is gated on `model.settings.hydraEnabled, !thread.isHelper`. R009's persisted_fields records only hydraEnabled, so the rule that a helper thread never shows the button is lost.

8. R009 / ChatView.swift:106-109: the minimap condition is `!scene.dockedSides.contains(.leading) && (paneSize == .zero || paneSize.width - scene.reserve.leading - scene.reserve.trailing >= 900)`. R009 reports only the >= 900 branch and drops the `paneSize == .zero` case, so a port would hide the rail on the first frame before the pane is measured.

9. R015 / ComposerView.swift:19-49: the changes-popover lifecycle is entirely undescribed. `@State diffPopover = DiffPopoverCoordinator()`; `diffPopover.sync(isVisible: runtime.isDiffVisible, runtime:)` fires `.onAppear`, on `runtime.threadID` change and on `runtime.isDiffVisible` change; `diffPopover.reopen(runtime:)` on `runtime.diffOpenRequest`; `.close()` on `.onDisappear` and whenever the `chatColumnIsShown` environment value turns false; the tab supplies `setAnchor($0)` while the area background supplies `setFallbackAnchor($0)`. R015 mentions the coordinator only in calls_into.

10. R015 / ComposerView.swift:826 vs :343: the report never says which control does what. The send button while running calls `runtime.interrupt()`; Escape calls `runtime.takeBackRunningTurn()` (which returns the words to the box); Return while running calls `runtime.interruptAndSend()`. R015 lists all three calls in side_effects without binding them to their controls, so the port cannot tell the stop button from the take-back.

11. R015 / ComposerView.swift:310-329: the key precedence while the suggestion list is open is only half described. Source: `.up`/`.down` move `suggestions.selected` (clamped), `.tab`, `.submit` and `.steer` all call `pick(suggestions.items[suggestions.selected])`, `.escape` sets `dismissedSuggestions = true` and clears the state, `.deleteAtStart` returns false and falls through. R015 records only the escape case, so Tab/Return-picks-the-selection is unstated.

12. R010 / ThreadTimeline.swift:162-166: the rule that decides whether revert/edit controls exist at all is unreported: `if supportsRewind && !runtime.isRunning { rewindable = Set(runtime.turns.lazy.map(\.id)) } else { rewindable = [] }`, fed into `RowContext.canRewind`. R012 only sees the resulting `canRevert` flag, so nothing in this family states that the edit pencil and the turn-card Revert button vanish while a turn runs or on a provider without rewind support.

13. R010 / ThreadTimeline.swift:2236-2256: WorkingBlockView's second mode is unreported. With `earlierEntries` non-nil (a segment split off by a Hydra note, or a turn with no end marker) the same WorkingIndicator renders with `startedAt = earlierEntries.first.item.date`, `finishedAt = earlierEntries.last.item.date`, `thinkingSteps = []` (thinking is suppressed outright) and the "Earlier steps" label. R010 lists WorkingBlockView's symbols but describes only the live mode.

14. R010 / ThreadTimeline.swift:131-137: the empty state's side effects are missing: `NewThreadPrompt(...).onAppear { scrollChrome.update(travel: 0); scrollState.showsJumpButton = false }` resets the chrome scroll travel and hides the jump button.

15. R012 / TimelineRows.swift:1708 and 2624: the reveal-the-end hook has four call sites, not two. ToolRow's inline-output expansion (`if expanded.wrappedValue { revealBox?.action() }`) and TurnFinishedBlock's expansion (`if isExpanded { revealBox?.action() }`) also request it, alongside WorkGroup (:1481) and WorkSteps (:1537). R012 says only "expanding either a group or the fold".

16. R012 / TimelineRows.swift:1481,1537,1708,2624 vs ThreadTimeline.swift:321-322, 2089: R012 collapses `TimelineRevealBox.action()` and `.follow()` into one "revealTimelineEnd action". They are two different closures with different scroll behavior (`action = revealEnd`, held back while the jump button is up; `follow = followEnd`, reveals anyway). Every row in TimelineRows uses `action()`; only the WorkingIndicator chevron uses `follow()`.

17. R052 / MarkdownView.swift:750-767: the bare-domain autolinker is paraphrased where the contract demands verbatim. The regex is never given: pattern `(?<![A-Za-z0-9@._/-])((?:[A-Za-z0-9](?:[A-Za-z0-9-]*[A-Za-z0-9])?\.)+[A-Za-z]{2,24})(/[^\s<>()]*)?` with options `[.caseInsensitive]`. The `bareDomainTLDs` set is described as "comprehensive list of gTLDs and ccTLDs, 'com'..'pe'" instead of its ~115 literal entries (com, org, net, edu, gov, mil, info, biz, io, ai, app, dev, co, me, xyz, site, online, store, shop, tech, cloud, tools, blog, fm, gg, so, tv, live, news, studio, design, social, works, codes, run, page, link, chat, bot, art, fun, space, world, email, group, team, digital, agency, solutions, software, systems, network, media, photo, video, games, zone, city, life, one, plus, pro, then the ccTLDs nl...pe). A port cannot reproduce linkification from the paraphrase.

18. R012 / TimelineRows.swift:293 and 1116: the help string is conditional, not fixed. Source is `.help(details.isEmpty ? "" : "Show the message")` on HydraReportRow and `.help(outcome.details.isEmpty ? "" : "Show the message")` on HydraMergeRow; R012 records an unconditional "Show the message".

19. R015 / AttachmentFlight.swift:55: `fly(...)` returns before calling `onLanded()` under reduce motion and also when `image.cgImage(...)` or `NSScreen.main` is nil (:60-61); the armed drop has already been consumed by `AttachmentDrops.shared.take()` at the call site (AttachmentFlight.swift:195). R015 says only "fly() returns immediately with no animation when reduce motion is on" and does not state that the completion is dropped, which matters for any port that hangs chip visibility off it.

## Thin reports (2)

1. R010 — 2298 lines of the family's densest control flow (scroll pinning, the AppKit nudge, blank-viewport repair escalation, phase watchdogs) summarised in the smallest report per source line of the nine (~11 bytes of report per source line, against ~21 for R009 and ~46 for R017). Its numbers check out, but it drops whole behaviors: the `rewindable` rule that governs whether revert controls exist (ThreadTimeline.swift:162-166), WorkingBlockView's `earlierEntries` mode (:2236-2256), the empty-state scroll resets (:131-137), and the distinction between TimelineRevealBox.action and .follow is stated but never tied to its callers. It also leaves six unresolved questions that other bundles of the same family already answer.

2. R016 — coverage is uneven rather than uniformly shallow: TrackEffect's particle, streak, bolt, sheen and fusion maths are captured to the last coefficient, while the EffortSliderCard section that a user actually reads is paraphrased. Both pair-caption strings, the "Standard" title fallback, the (isMax, fastMode) to TrackLook.Kind mapping and both list-row detail compositions are absent. The same report also hedges on a value it prints two lines apart ("28x28 -> actually 28 wide by 22 tall", EffortSlider's sibling FollowUpQueueTab.swift:383), which reads as a transcription that was not reconciled against the source.

## Cross-cutting findings (10)

1. Five unresolved_questions across R009, R010 and R011 ask for TimelineMetrics' literal values; R012 has them from the source of truth, TimelineRows.swift:8-27: rowSpacing 20, hoverLineHeight 22, iconWidth 16, iconSpacing 8, pillLeading 12, pillTrailing 14, pillVertical 8, pillRadius 18. The whole family's pill geometry (ChatBadge, LimitResumeBadge, WorkingIndicator, NoticeRow, TodoListRow, merge and head pills) derives from these six numbers plus the fixed 96-point trailing gutter and the 820-point content column.

2. R015 and R016 both leave Storage.attachmentLimit unresolved. It is 8 (DroppyCode/Services/Store/Storage.swift:153). It caps ComposerView.maxAttachments (ComposerView.swift:137), disables PromptEditor's Add files button (PromptEditor.swift:87), and is interpolated into the three overflow notices ("... a message holds 8 attachments").

3. R015 and R016 leave ThreadChangesTab.overlap unresolved; R017 has it: 14 (ThreadChangesTab.swift). It is the negative VStack spacing in ComposerArea (ComposerView.swift:27), the extra bottom padding on both tabs, and FollowUpQueueTab.overlap is a straight alias of it.

4. R015's unresolved about AttachmentPreviewSlot vs AttachmentPreviewCoordinator is settled: they are two distinct types in DroppyCode/UI/Common/AttachmentPreviewPanel.swift (Coordinator at line 20, an NSPopoverDelegate; Slot at line 259). Neither is a typealias of the other, so the port needs both.

5. R052's unresolved "LinkTextVeil has no call site within the assigned four files" is answered by R051's bundle: LinkTextView owns `let streamVeil = LinkTextVeil()` and LinkParagraphView calls `streamVeil.update(view, active: markdownVeiled)` after every render and `streamVeil.detach(view)` in dismantleNSView. Symmetrically, R051's unresolved "who calls HydraHeadHoverPopover.show()/hide()" is answered by R052's bundle: MarkdownView's InlineText and ProseRunView, both on `.onContinuousHover`.

6. Because markdownProseRuns is always true, ProseRunView's rendering is what a reader sees for every finished reply: ballot-box task markers (U+2611 / U+2610), bullet U+2022 at depth 0 and U+25E6 deeper, no quote capsule rule, plain label colours. MarkdownBlockView's accent-coloured circles, capsule quote rule and SF-Symbol task markers appear only while a reply streams. R052 flagged the visual difference as possibly unintentional; for the port both renderings must exist and must switch on isStreaming.

7. Popover dismissal is implemented the same way five times and must be ported as one mechanism: an NSPopover with `behavior = .applicationDefined`, content pre-measured through a throwaway NSHostingView (fittingSize or intrinsicContentSize) and frozen with `setFixedContent(_:size:)`, plus NSEvent local monitors for keyCode 53 (Escape) and [.leftMouseDown, .rightMouseDown]. Sites: ChatBadge.BadgePopoverCoordinator, PromptEditor.PromptEditorPopover, LinkPopover (this one uses `.transient` and only an Escape monitor), HydraHeadHoverPopover (250 ms hover debounce, 300pt fixed width, 78pt height fallback), ComposerController's suggestions popover (NSSize(width: 340, height: min(340, 44 + max(itemCount,1) * 26))).

8. macOS primitives with no Windows equivalent, appearing across the family and needing one substitution strategy each: NSCursor push/pop stacks (TimelineMinimap, ProseRunView, MarkdownView.InlineText, FollowUpQueueTab), CADisplayLink at CAFrameRateRange(24,60,preferred 30) (StreamVeil, two clocks), CAReplicatorLayer dot fields (ComposerWorkingDots, also used by ChatBadge's attention overlay and HydraDelegationBlock's sweep), CASpringAnimation with mass 1 / stiffness 170 / damping 26 (AttachmentFlight), NSHapticFeedbackManager .alignment and .levelChange (EffortSlider drag stops, FollowUpQueueTab reorder and bundle), TextKit 1 vs TextKit 2 duality (ComposerTextView measures via textLayoutManager with a layoutManager fallback because its draw override forces TextKit 1; LinkTextView is TextKit 1 throughout).

9. Three separate caches key on whole message text and must be sized together in the port: MarkdownView.blockCache RecentCache limit 800, RichLink.prettyCache limit 1200, TableBlock.cellCache limit 1200, plus the fixed rings MarkdownView.streamingParses 48 slots and RichLink.streamingPretty 4 slots, TimelineBlockCache 24 threads LRU, TimelineMinimap.entryCache 400, DiffDetailCache 60, HydraDelegationBlock.readingCache 200, FileIndex.built RecentCache limit 2 with 60s freshness, FaviconCache.memory flushed wholesale at 300, LinkTitles titles flushed wholesale at 400 (with its `claimed` set never cleared, so post-flush ids can never be re-fetched).

10. Every editable surface keeps its edit state on ThreadRuntime rather than in the view, so the port must persist it the same way or editors will close on scroll: `runtime.messageEdit` (UserMessageRow / MessageEditor), `runtime.followUpEdit` (FollowUpQueueTab / FollowUpEditor), `runtime.followUpsCollapsed` (queue fold). All three survive the row being recycled by the lazy stack and the thread being left and re-entered.
