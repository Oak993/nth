
## ED-186

[UI] Which `.headline` is semibold (question raised by the App.Views.Tour.TourView unit, 2026-09-23). SOURCE FACTS: the semibold default belongs only to the app's chat font builder: B2 UI/Common/ChatFont.swift:6-10 `static func chat(_ style:, weight:, design:)` with `let resolvedWeight = weight ?? (style == .headline ? .semibold : nil)`, and before it B1 UI/Common/ChatZoom.swift:62-65 (the same rule in `chat(_:weight:design:zoom:)`); the port mirrors it in ChatFont.Chat (src/Marrow.UI/Common/ChatFont.cs:16). A plain `.font(.headline)` is SwiftUI's system text style and never passes through that builder; the pinned sites are TourView.swift:106 and RequestCards.swift:13 (plain), and TimelineRows.swift:1938, :2282 and MarkdownView.swift:380 (`.chat(.headline)`), identical in B1 for TourView. DECISION: (1) SwiftFont.Headline and SwiftFont.System(TextStyle.Headline) keep ED-091's weight for the plain style, bold (SwiftFont.cs:244); only ChatFont.Chat resolves .headline to semibold. (2) UI-UPDATE-045 misapplied the chat builder's rule to TourView's plain `.headline`; its expected result is corrected to the plain style's weight, and TourView's empty-state title is `SwiftFont.Headline.Apply(text)` with no weight override. (3) Plain `.font(.headline)` sites use SwiftFont.Headline; `.chat(.headline)` sites use ChatFont.Chat. (4) UNRESOLVED, oracle O-64: the weight macOS 26 gives SwiftUI's plain `.headline`. ED-091 parks bold (the macOS type ramp); the upstream comment at ChatZoom.swift:59-61 ("headline keeps its semibold weight") suggests the authors saw semibold. Tests that pin the plain headline's weight carry Oracle O-64. ENGINEERING DECISION; not a deviation.
