## What was missing at the start

- No production caller registered Voice hardware or switched on the feature; startup did not bind
  the engine, VAD, resampler, or settings-page self-test adapter.
- The Welcome question was optional and never supplied by production startup. Orb clicks went
  directly to capture, without preparation, download progress or the deferred slow-PC PopoverCard.
- Voice sessions ignored stored `LiveWords`; the final-only path lost audio older than 30 seconds.
- Reusing a current record dropped an unanswered slow question. No startup key was supplied, and
  the post-probe path repeated download verification and timing rather than reusing current results.
- A manual hardware-check record with no model could falsely license listening. Session model loads
  also needed the model-store path and verification guard.

## Built

Startup now binds one preparation/question per settings object before GR-1 plans its work, registers
Voice hardware and switches on the feature. Construction opens no microphone or speech model and
starts no download. The raw startup identity checks stored results without reloading native inference.
The production VAD opens lazily; local engine loads verify the shared model store first. The existing
settings-page Use recommended action uses the preparation self-test adapter.

Welcome uses that question and the existing V2 strings. Welcome Yes and the first orb click grant
consent. A setup click opens the orb PopoverCard and prepares, without starting capture; a click during
Welcome's transfer joins its single-flight operation and shows its latest actual progress. A later
click starts listening. The same card asks the slow question after Welcome closes, persists the
answer, and blocks capture until it is answered. Current records retain pending questions across
restart; probe-only records cannot bypass preparation. The store progress subscription is released.

Stored LiveWords now controls live inference. Accurate after-stop transcription keeps the complete
recording, including speech before the last 30 seconds; existing streaming behavior remains the
default. Existing tests, fixtures, time bounds, tolerances, assertions and V2 words are unchanged
relative to the branch base. All eight added test files use fakes. The new mounted-orb test initially
deadlocked in its own fake constructor; the dump identified its synchronous probe wait on the UI
dispatcher. `5a65c450` moved only that newly added setup off the dispatcher, without changing an
assertion or a staging test.

The mounted test then caught a real duplicate logical parent in the orb card. `f11ca528` creates only
the orb host when drawing inside PopoverCard; the original Welcome card remains. The unchanged
assertions then reach the Windows popup host and fail on Linux's missing `user32.dll`. The existing
Welcome/DetailView tests pass (11/11) in that same run. `0344a55d` adds the required R-TEST-10 tags
to the eight new test classes after the traceability meta-tests identified missing tags; it changes
no test assertion or execution.

An independent static review found pending-question restoration, repeated timing and probe-only
record bypass. Added regressions and the production changes address all three. Its final review
reported no further concrete defect; it did not supply Windows runtime evidence.
