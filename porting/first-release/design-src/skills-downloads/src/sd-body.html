Adding your own: the Add button on each page (Custom C)

Plugins, Skills and Tools each have an Add button with a chevron at the right end of the title row. It is the page’s own glass button, and its menu is the page’s menu style: From a folder…, From a .zip…, From GitHub…. Each item opens the add sheet with that source. A folder and a .zip are chosen, never typed: From a folder… opens the system folder picker, From a .zip… the system file picker filtered to .zip files, and the sheet then shows a read-only field (“No folder chosen” or “No .zip chosen” until you pick, the chosen path after) with a Browse… button beside it, and Check stays off until something is chosen. A web page cannot open the real Windows dialog, so it is drawn here as a labelled stand-in with a couple of entries to pick; the app opens the real one. From GitHub… stays a link field, because there is nothing local to browse. The sheet then checks what it finds (a skill needs SKILL.md with a name and a description, a plugin its manifest, a tool an .exe, a name and the command it provides), lists every item with a box to tick and a Select all, and greys out the invalid ones with the reason. The ticked ones install side by side: each row’s ring turns into a green circle with a white check as it finishes, a failed one gets a warning and Retry, and the footer counts “3 of 5 added”. They land under Your own in the list, removable, with the same Enable switches. The buttons work: click Add, pick a source, browse and choose, Check, tick, Add. Play browses to a folder with no SKILL.md (nothing valid), chooses another, finds six skills (one invalid, one failing and retried), then does a .zip of plugins, a folder with a tool and a GitHub link.

What each page holds

Plugins holds the vendors’ bundles: Anthropic’s knowledge-work and financial-services plugins, OpenAI’s open plugins and its proprietary-labelled ones. Skills holds the skill sets: Anthropic’s document, example and life-sciences skills, OpenAI’s document and curated skills, and Codex’s built-in skills. Tools (the existing page, next to the provider CLIs and OD-0100’s update rows) holds the programs they run: Python and its package sets, Node.js, LibreOffice, Poppler, qpdf, pandoc, Git, GitHub CLI, uv and Playwright’s Chromium. Every set and plugin Anthropic and OpenAI publish is offered. Each one downloads only when you ask, from the vendor’s official source, with its licence file kept, and none is bundled with Marrow (owner, 2026-10-04). Your own additions join each page under Your own.

Each page’s Download all takes the items on that page that aren’t on this PC yet. The confirmation shows the exact download size, the disk space it takes, the free space, where it comes from and every item included. Above 100 MB it opens with the amber “This can be a large download” warning; at 100 MB or under it states the size plainly. Then Cancel or Continue, and nothing downloads before Continue. After that: downloading (overall and per item, with Hide, Pause and Cancel), paused, done, and partly failed with Retry and the manual fallback. Getting everything means confirming on Plugins, Skills and Tools in turn.

How each provider lists the enabled skills and loads one on use

From the skills research notes, the add-ons plan (PLAN.md 2.1 to 2.7) and the on-demand plan (ONDEMAND-PLAN.md section 4). Each chat gets a folder Marrow builds when the chat starts. It holds the installed skills that are enabled, and nothing else, so a skill that is not installed or is switched off is never listed. Every provider then does what Claude does with it. The names and descriptions go into the model’s context: Claude Code within 1% of the context window, each description cut at 1,536 characters; Codex within 2% by default. A skill’s full text loads when it is used (SF). SF read or run at the source, ED a proposal, UN to be checked live before it is built.

Two honest limits. (1) The listing is paid in every session: the detail pane shows each skill’s share, and Marrow keeps its skills to at most half of each provider’s listing budget, leaving its own lowest-priority skills out first (PLAN.md 2.7). (2) A switch applies to new chats. A running chat keeps the folder it started with (ONDEMAND-PLAN 4.4).

Download it yourself (ED)

When an item fails, including after Retry, its row offers the vendor’s official page, the exact pinned file, and an Open folder button for %LOCALAPPDATA%\Marrow Code\addons\downloads\manual\. The folder name is a proposal (ED, UN until built); addons\downloads\ is the plan’s own (3.1). Check again verifies the file against the pinned SHA-256 (every file, for a skill set) and installs it the normal way. A file that doesn’t match is refused, as in 3.3.

Pause, Cancel, Retry (ED)

Download all runs one item at a time, as in OD-0100’s update run. Pause stops the current file where it is, and Resume carries on from there (downloads are resumable, plan 3.2). Cancel stops the rest, and what is already downloaded stays. A failed item doesn’t stop the others. Your own additions are copied side by side, because they are local or small.
