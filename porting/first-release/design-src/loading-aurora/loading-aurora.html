Loading Animation

The Marrow boot animation and the loading choices for empty areas, built from the locked app icon, D Aurora (OD-0112). The icon on this page is the locked D-aurora.js with iconkit.js, inlined unchanged and run as it is: its own launch (the night tile fades up, the aurora unfurls) and its own idle loop. Nothing in src changes; this is a review page.

Page theme

1 · Boot: the tile grows into the window

Picked by the owner: B. The Aurora tile appears large over a dimmed desktop and its aurora unfurls (D's launch, 1200 ms). When the app is ready, the tile’s rectangle opens from the icon square to the exact frame of the main window, in one move: same position, width and height, the Windows 11 corner radius (8 DIP), the 38 DIP title-bar band. The window’s glass and content fade in inside that same rectangle, on the same clock and easing, so the last frame of the tile is the window frame. The GPU warm-up runs behind it with the window hidden (OD-0108); the window appears only when the app is ready, and never before H = max(app ready, 1800 ms). Each size is shown dark and light, with one scrubber.

2 · Loading an empty area

The icon is not used as a loader. Nothing in the chat moves while the model works: that stays the composer’s working dots. This section is only for three places where a large area is still empty after 400 ms (ED-097): opening an older chat while its history loads, the diff pane while it reads the diff, and the large attachment preview while its image or video frame loads. Shorter waits show nothing, as upstream does. After 400 ms the loader fades in over 200 ms, and it fades out when the content arrives. Five loaders that only borrow the Aurora’s light (emerald, teal, violet) and its slow curtain sway, each shown in all three real places. Pick one for all places, or press press “Only here”ldquo;Herepress “Only here”rdquo; on a pane to choose per place. Each pane replays the same 5 s wait.

    3 · Reduce Motion

    With Reduce Motion on (R-VIEW-6) nothing travels, grows, sways or shimmers; things fade only. The boot is one version, since the tile only fades; the five loaders become still.

    What is source and what is proposed. SOURCE FACT: D’s draw code, launch (1200 ms) and idle loop (7200 ms) are the locked files; OD-0016/0018 sites; ED-097 (400 ms rule, 200 ms fade, sizes 64, 64 and 48); the 1800 ms hand-over floor of ED-103; the main window’s layout bands (38 DIP title bar, 260 DIP sidebar, 96 DIP composer, from BootStageWindow.Layout) and its 1320 × 860 default size (WindowManager); the composer’s working dots stay as they are for a running turn. ENGINEERING DECISION (proposals): the dim scrim, the grow, its 1000 ms duration and glow, the five loaders (24 to 48 px; sizes 48, 44 and 40 here), Windows 11’s 8 DIP corner (platform value; the source’s 26 point radius is the rectangle the OS then rounds, ED-338). UNRESOLVED: whether the stage window can sit beneath the main window with its Acrylic backdrop (the glow needs it; probe after P12), and what the real warm-up costs.

    • The desktop and the Marrow window are CSS approximations drawn for this page, not screenshots; no vendor artwork.
    • Motion is transform and opacity, plus canvas for the tile, the glow and the loaders; the window’s clip rectangle follows the tile (a clip-path, one per frame).
    • No network, no external links, no external fonts: the system font stack only.
