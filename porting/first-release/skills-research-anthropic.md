# Anthropic pre-installed and pre-built skills: research for Marrow (OD-0080)

Researched 2026-10-02. Primary sources only: the official repositories (cloned and read), Anthropic's own docs, and the files that Claude Desktop and Claude Code have already placed on this machine. Short commit SHAs are from the clones made on 2026-10-02.

## 1. Bottom line

1. Anthropic ships skills through five different channels. Only one of them (the public repo `github.com/anthropics/skills`) is mostly open source. The rest are proprietary or unlicensed.
2. **14 of the 19 skill folders in `anthropics/skills` carry an Apache-2.0 LICENSE.txt and may be bundled in Marrow**, provided Marrow ships the licence text, keeps the notices, and marks any file it changes.
3. **Four skills must NOT be bundled: `docx`, `pdf`, `pptx`, `xlsx`.** They are "source-available, not open source". Their LICENSE.txt forbids copying, extracting, making derivative works and distributing them to third parties. These are exactly the "Word, PowerPoint, Excel, PDF" skills the owner is probably thinking of when he says "pre-installed Claude skills".
4. **One skill (`doc-coauthoring`) has no licence at all**, neither a file nor a frontmatter field. Under default copyright law that means "all rights reserved". Do not bundle until Anthropic confirms.
5. **The skills that Claude Desktop pre-installs** (the `anthropic-skills` plugin found on this machine) are: the 4 document skills, `skill-creator`, 3 browser/computer-control skills, and 10 more with no licence file. Only `skill-creator` is bundleable. [verified fix] The Desktop copy is NOT identical to the public repo: its LICENSE.txt still has the unfilled Apache template line "Copyright [yyyy] [name of copyright owner]", and its SKILL.md and scripts/quick_validate.py differ. Bundle the `anthropics/skills` copy (filled-in "Copyright 2026 Anthropic, PBC."), never the Desktop copy. Most of the others are glued to Claude Desktop's own tools (`mcp__Claude_Browser__*`, `mcp__computer-use__*`, the docs connector, scheduled tasks), so they would not work in Marrow even if the licence allowed it.
6. **Claude Code's bundled skills** (`/simplify`, `/debug`, `/loop`, `/batch`, `/code-review`, `/verify`, `/run`, `/claude-api` and so on) are compiled into the Claude Code CLI. They are not files we can ship, they cost nothing to "install", and they appear on their own whenever Marrow runs the `claude` CLI. Marrow only needs to surface them (the Mac app already shows Skill tool calls).
7. The Agent Skills format is an open standard (agentskills.io, originally from Anthropic). The same `SKILL.md` folders are read by Codex, Gemini CLI, GitHub Copilot, OpenCode, Cursor, Pi, Command Code, Hermes and many more, so a single Marrow bundle can serve all providers (see section 6). [verified fix] "Antigravity" is not on the agentskills.io adopter list (Gemini CLI is); check Antigravity's own docs before assuming it reads the format.
8. A second, much bigger Apache-2.0 library exists in `anthropics/knowledge-work-plugins` (252 skills) and `anthropics/financial-services` (112 skills). These are not "pre-installed" anywhere, but they are Anthropic's pre-built skills for non-coding work, and the licence allows bundling. Many need external connectors (Slack, HubSpot, and so on). Listed in section 5 as an optional second wave.
9. [verified fix] The `anthropics/skills` README says: "These example skills are all already available to paid plans in Claude.ai." So the repo's example skills (the 14 Apache-2.0 folders plus the unlicensed `doc-coauthoring`) are, in effect, Claude's pre-installed example skills, alongside the four document skills.

And: "ADDITIONAL RESTRICTIONS: ... users may not: Extract these materials from the Services or retain copies of these materials outside the Services; Reproduce or copy these materials ...; Create derivative works based on these materials; Distribute, sublicense, or transfer these materials to any third party; Make, offer to sell, sell, or import any inventions embodied in these materials; Reverse engineer, decompile, or disassemble these materials."

The docs say "Some of Anthropic's skills, such as `pdf` and `xlsx`, always sync."); (3) ask Anthropic for a licence.

## 6. The Agent Skills format and where skills live

### 6.1 The open standard
- Home: https://agentskills.io (spec at /specification). Statement: "The Agent Skills format was originally developed by Anthropic, released as an open standard, and has been adopted by a growing number of agent products." Repo: https://github.com/agentskills/agentskills (145 commits when read; code Apache-2.0, documentation CC-BY-4.0; validator `skills-ref`).
- Anthropic's repo `spec/agent-skills-spec.md` now only says "The spec is now located at https://agentskills.io/specification".
- Layout: `skill-name/SKILL.md` (required), optional `scripts/`, `references/`, `assets/`.
- Frontmatter (YAML between `---` lines):
  - `name` (required): 1-64 chars, lowercase letters, digits and hyphens, no leading or trailing hyphen, no `--`, must match the folder name.
  - `description` (required): 1-1024 chars; says what the skill does and when to use it.
  - `license` (optional): a licence name or the name of a bundled file.
  - `compatibility` (optional): up to 500 chars on environment needs.
  - `metadata` (optional): string-to-string map.
  - `allowed-tools` (optional, experimental): space-separated pre-approved tools, for example `Bash(git:*) Bash(jq:*) Read`.
- Body: free Markdown, ideally under 500 lines and about 5,000 tokens. Three loading levels (progressive disclosure): name and description at start (about 100 tokens), body when activated, other files on demand. Keep references one level deep.
- Claude API and claude.ai extra rule: `name` may not contain "anthropic" or "claude", and neither field may contain XML tags.
- Client guidance (agentskills.io/client-implementation/adding-skills-support): scan project and user scopes, in both the client's own folder and the shared `.agents/skills/` convention; some clients also read `.claude/skills/`. Project overrides user. Gate project skills on a trust check. Be lenient with bad YAML (retry with quoted values). Hide disabled skills entirely. Catalogue entries are name, description, location. [verified fix] Note: this guide's "project-level skills override user-level skills" is the opposite of Claude Code, where personal beats project. Protect skill text from context compaction. Let the user invoke a skill with `/name` or `$name`.
- Adopters named on agentskills.io/home include (names as listed there): Claude, Claude Code, ChatGPT and Codex, Gemini CLI, GitHub Copilot, VS Code, OpenCode, Cursor, Pi, Command Code, Hermes Agent, Goose, Amp, Roo Code, Junie, Kiro, Factory, OpenHands, Mistral Vibe, Tabnine, Trae and more. This covers every provider named in the Marrow context.

### 6.2 Where Claude Code looks for skills (code.claude.com/docs/en/skills, read 2026-10-02)

| Location | Path (Windows form) | Applies to |
|---|---|---|
| Enterprise / managed | `.claude/skills/<skill-name>/SKILL.md` inside the managed settings directory. On Windows that directory is `C:\Program Files\ClaudeCode\` (macOS `/Library/Application Support/ClaudeCode/`, Linux and WSL `/etc/claude-code/`) | All users on the machine |
| Personal | `%USERPROFILE%\.claude\skills\<skill-name>\SKILL.md` (`~/.claude/skills/...`); `CLAUDE_CONFIG_DIR` moves the config folder | All projects, not Cowork or cloud sessions |
| Project | `.claude\skills\<skill-name>\SKILL.md` in the repo; also read from every parent folder up to the repo root | That repo |
| Nested | `<subdir>\.claude\skills\...`, loaded when Claude first works on files there (or with `/add-dir`) | Monorepos |
| Additional directory | `.claude\skills\...` inside a folder passed with `--add-dir` | That session |
| Plugin | `<plugin>\skills\<skill-name>\SKILL.md`, used as `/plugin-name:skill-name`; plugin manifest `.claude-plugin/plugin.json` may add paths with a `skills` array | Where the plugin is enabled |
| claude.ai account | Downloaded to `~/.claude/skills/synced/` (on this machine one subfolder per `<org>_<account>`), refreshed about every 10 minutes (v2.1.273+), [verified fix] invoked by short name `/<name>`, or by full name `/anthropic-skills:<name>` when another command already uses the short name; turn off with `syncClaudeAiSkills: false` | When signed in to that account through `/login` (not with an API key or env token, not on Bedrock, not in bare or safe mode); also Cowork and cloud sessions |

Rules: precedence is enterprise over personal over project; [verified fix] a local skill with a bundled skill's name replaces the bundled command, and a local or plugin command that takes a synced skill's short name pushes the synced skill to its full name only; a plugin skill is namespaced so it never clashes; a skill folder that contains `.claude-plugin/plugin.json` loads as a plugin named `<name>@skills-dir`; folders named `synced` or `anthropic-skills` are reserved and skipped outside the sync feature; symlinked skill folders work; changes are picked up live in a session (`/reload-skills` for a brand-new top-level folder). Claude Code also accepts these extra frontmatter fields: `when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `disallowed-tools`, `model`, `effort`, `context: fork`, `agent`, `background`, `hooks`, `paths`, `shell`. It substitutes `$ARGUMENTS`, `$0..$n`, `${CLAUDE_SKILL_DIR}`, `${CLAUDE_PROJECT_DIR}`, `${CLAUDE_PLUGIN_ROOT}` [verified fix: also `$ARGUMENTS[N]`, named `$name` arguments, `${CLAUDE_SESSION_ID}`, `${CLAUDE_EFFORT}` and, in plugin skills, `${CLAUDE_PLUGIN_DATA}`]. [verified fix] Claude Code ignores unknown fields silently, but claude.ai uploads, the Skills API and `package_skill.py` accept only `name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools` and fail hard on anything else. For synced skills on the user's own machine, Claude Code does not run `!` commands or substitute `${CLAUDE_PROJECT_DIR}`. The skill listing is capped by a character budget (`skillListingBudgetFraction`, `SLASH_COMMAND_TOOL_CHAR_BUDGET`) and description plus `when_to_use` is cut at 1,536 characters. Settings: `disableBundledSkills`, `skillOverrides` (`on`, `name-only`, `user-invocable-only`, `off`), `disableSkillShellExecution`, `allowManagedPermissionRulesOnly`. Permission rules: `Skill(name)`, `Skill(name *)`.

### 6.3 What this means for Marrow's design (input for the later plan, not a decision)
- Safest way to "pre-install" without overwriting user skills: ship the bundle inside the Marrow install folder, then expose it to each provider in the way that provider already reads. For Claude, either add Marrow's folder as a plugin (`--plugin-dir` or a marketplace entry) so skills appear as `/marrow:<name>`, or copy into `~/.claude/skills/<name>/` only when no folder of that name exists. Never write to `~/.claude/skills/synced/`, and never to the managed directory. The SDK equivalent is the `plugins` option. [verified fix] Prefer the plugin route (`claude --plugin-dir <Marrow bundle>`, per session, no files touched in the user's folders). Copying into `~/.claude/skills/` has two side effects even when no folder of that name exists: a copied `claude-api` would replace Claude Code's newer bundled `/claude-api`, and a copied `skill-creator` would take the short name from the user's synced `skill-creator`, which then works only as `/anthropic-skills:skill-creator`. Personal skills also do not reach Cowork or cloud sessions. Do not name the plugin `anthropic-skills` (reserved).
- Do not name any Marrow skill with "claude" or "anthropic" if the same folder might be uploaded to the API.
- Each file shipped needs the Apache text plus a Marrow `THIRD_PARTY_NOTICES` entry for the skill, the OFL font texts, and a "changed by Marrow" mark on any edited file.

## 7. Risks and open points for the owner

1. **The four document skills cannot be bundled** (section 3.2). Decision needed: write original replacements, rely on the user's own Claude sync, or ask Anthropic.
2. **`doc-coauthoring` has no licence.** Ask Anthropic (open an issue on `anthropics/skills`) or skip it.
3. **Desktop-only skills have no licence and depend on Claude Desktop tools.** Not bundleable and not useful.
4. **`brand-guidelines` and Anthropic names.** Apache-2.0 gives no trademark rights. Shipping a skill that makes documents look like Anthropic's brand, inside a third-party app, is legally allowed as text but could confuse users. 5. **`web-artifacts-builder` bundles a tarball of shadcn/ui components (MIT)** that THIRD_PARTY_NOTICES does not list. Add an MIT notice if shipped.

Do not bundle those; only the `anthropics/skills` copies are clean. [verified fix] This applies to the 11 plugins found in both repos. The plugins only in `claude-plugins-official` (except `claude-security`) and the 6 `life-sciences` skills have a plain Apache-2.0 grant and may be bundled if wanted.
