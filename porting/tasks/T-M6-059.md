### PR-GIT-120 - Sending an edited message reverts first and only sends when the files were restored as asked
- **Source:** DroppyCode/App/Runtime/ThreadRuntime.swift:1820-1831 resend(_:text:attachments:restoreFiles:) - revert returns whether the files were restored; when it returns false the edited draft is left in the composer and nothing is sent; otherwise the current draft is set aside, the edit is sent, and the previous draft is put back
- **Preconditions:** The message editor's Send was pressed.
- **Action:** The edit is sent.
- **Expected:** The revert runs first and may throw, in which case the conversation is untouched and the editor shows the error. When the revert succeeded but the files could not be restored, the edited text and attachments are placed in the composer and nothing is sent, so the edit waits beside the notice rather than going out against the wrong tree. Otherwise whatever was in the composer is set aside, the edit becomes the draft and is sent, and the earlier draft is put back afterwards.
- **Side effects:** A new turn is started on success
- **Persistence:** The composer draft is part of the thread's runtime state.
- **Failure cases:** A thrown revert leaves the editor open with the error shown beneath the text
- **Cancellation:** The editor is disabled while sending.
- **Windows path:** Direct port of the three-way outcome.
- **Verify by:** interaction test with a restore failure asserting the edit stays in the composer
