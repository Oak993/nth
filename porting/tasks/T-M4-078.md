### PR-PROVCLI-146 - Copilot changes the permission mode only when it differs, and trusts the reply over its own request
- **Source:** DroppyCode/Services/Providers/CopilotSession.swift:328-341 - applyModes permission branch with its comment | DroppyCode/Services/Providers/CopilotSession.swift:46 - permissionMode starts as "manual"
- **Preconditions:** A live session.
- **Action:** applyModes runs.
- **Expected:** The stored runtimeMode is updated. The wanted permission mode is computed by permissionModeName. When it differs from the stored one, one request "session.permissions.setMode" is made with {"sessionId":...,"mode":<wanted>,"source":"rpc"} - "source" is the literal "rpc". The stored permissionMode then becomes the mode the REPLY reports, or, when the request threw or the reply carried none, the PREVIOUS stored value - not the requested one. This matters because "assisted" is refused outside experimental mode and the reply says which mode actually holds; in "manual" every request reaches the app's own rules instead.
- **Side effects:** At most one RPC round trip
- **Persistence:** none
- **Failure cases:** A refused mode leaves the stored value unchanged, so the app keeps asking on every turn.
- **Cancellation:** not cancellable
- **Windows path:** None.
- **Verify by:** interaction test where the server answers with a different mode than requested
