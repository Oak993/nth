### PR-COMPOSER-208 - The changes popover adopts a new thread's open-request counter rather than treating the difference as a request to open
- **Source:** DroppyCode/App/Views/Diff/DiffInspector.swift:593-594 `/// The thread's `diffOpenRequest` as last seen, so a counter that merely differs between two threads never opens the popover.` with `private var seenOpenRequest = 0` | DroppyCode/App/Views/Diff/DiffInspector.swift:556 the thread-switch branch's `seenOpenRequest = runtime.diffOpenRequest` | DroppyCode/App/Views/Diff/DiffInspector.swift:562 the first-appearance branch's `seenOpenRequest = runtime.diffOpenRequest` | DroppyCode/App/Views/Diff/DiffInspector.swift:596-603 `/// A tool row or a Review button bumped the request on the thread the coordinator already serves; a bump seen only because the composer moved to another thread is not an opener.` with `func reopen(runtime: ThreadRuntime) { guard runtime === self.runtime else { sync(isVisible: runtime.isDiffVisible, runtime: runtime); return }; guard runtime.diffOpenRequest != seenOpenRequest else { return }; seenOpenRequest = runtime.diffOpenRequest; desiredVisible = true; ... }`
- **Preconditions:** Each thread runtime carries its own monotonically bumped diffOpenRequest counter, and two threads hold different values.
- **Action:** The composer moves between threads, or a tool row or Review button bumps the counter.

- **Cancellation:** not cancellable
- **Windows path:** A counter compared against a remembered baseline, adopted on every runtime change. Comparing against zero, or against the previous thread's value, makes every thread switch pop the changes panel.
- **Verify by:** interaction test: two threads with different counters, moving between them with no bump (nothing opens), then bumping on the served thread (opens once), then moving away and back (nothing opens)

- **Failure cases:** An edit whose patch yields no hunks contributes nothing
- **Cancellation:** Cancellation is checked before and after the detached parse.
