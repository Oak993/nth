## Before you start

1. Read `WORKER_BRIEF.md` at the project root. Its rules override anything you assume.
2. Read the source file above completely. Every behaviour you write must trace to a line in it.
3. Write the tests FIRST, from the "Expected" text below, and stop. The orchestrator reviews the

### PR-LAUNCH-048 - Reopening the app from the Dock shows the main window only when no window is visible, and always accepts the reopen

- **Preconditions:** The app is running with no windows visible, or with at least one visible window.
- **Action:** The user clicks the Dock icon or otherwise reopens the app.
- **Expected:** With no visible windows, the main window is created if needed and shown, and the app activates. With at least one visible window, nothing is created or reordered by this handler. The handler returns true in both cases, so the system performs its standard un-hide and activation.
- **Side effects:** May create and show the main window; activates the app
- **Persistence:** None.
- **Cancellation:** not cancellable
- **Windows path:** PLATFORM BOUNDARY: Windows has no Dock reopen. Because closing the main window quits the app (OD-0008 C1, PR-LAUNCH-074), the no-visible-window state is not reached by closing it. The path this handler defines runs on a second launch of the single-instance app (engineering_decisions.md, [LAUNCH] single-instance lock): the main window is shown when none is visible, and the app is activated in both cases.
- **Verify by:** interaction test: with the app running, launch it again; assert one process and one main window, brought to the front and active
