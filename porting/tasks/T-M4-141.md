### PR-PROVCLI-443 - StreamedTextTracker tracks one streamed turn's message and thinking ids and text, minting a fresh id only when a delta arrives with none current, and keeping accumulated text across ids until a reset clears it too
- **Source:** DroppyCode/Services/Providers/SessionSupport.swift:45-59 struct StreamedTextTracker - stored state (:48-54) and init(messageID:thinkingID:) (:56-59) | DroppyCode/Services/Providers/SessionSupport.swift:62-67 startMessage() - `messageCounter += 1` / `currentMessageID = messageID(messageCounter)` / `messageText = ""` / `streamedText = false` | DroppyCode/Services/Providers/SessionSupport.swift:70-78 appendMessage(_:) - mints an id only `if currentMessageID == nil`, then always sets `streamedText = true` and appends to `messageText` | DroppyCode/Services/Providers/SessionSupport.swift:80-99 startThinking() and appendThinking(_:resetsText:) - `resetsText` true calls startThinking() (clears thinkingText); false mints an id directly without clearing it
- **Preconditions:** A provider session (Pi, Command Code or Antigravity) is streaming one assistant turn and holds one StreamedTextTracker (Swift: `var stream`) for it.
- **Action:** The session calls the tracker's mutating methods as the turn's stream events arrive: startMessage/appendMessage for message text, startThinking/appendThinking for reasoning text, and endThinking/endMessage/resetThinking/resetForTurn/resetIDs to close or clear state.
- **Expected:** startMessage always mints a fresh message id (messageCounter incremented, id built from it), empties messageText and clears streamedText. appendMessage mints an id only when none is current (the first delta of a turn); otherwise it keeps the current id. Every appendMessage call sets streamedText true and appends the delta to messageText, so a later call accumulates onto the existing buffer. startThinking always mints a fresh thinking id and empties thinkingText. appendThinking mints an id only when none is current: resetsText true (the default, Pi's fallback) does so by calling startThinking, which also empties thinkingText; resetsText false (Command Code's fallback) mints the id directly without clearing thinkingText, so text already accumulated survives. Every appendThinking call, on either path, appends the delta to thinkingText. endThinking and endMessage each clear only their own current id, leaving the accumulated text untouched. resetThinking clears both currentThinkingID and thinkingText together (a message_start that interrupts an in-progress reasoning block drops it). resetForTurn clears only streamedText, leaving ids and text alone. resetIDs clears both currentMessageID and currentThinkingID but leaves messageText, thinkingText and streamedText untouched.
- **Side effects:** messageCounter and thinkingCounter are monotonically incremented counters that never reset, so minted ids stay unique across a session's turns
- **Persistence:** none
- **Cancellation:** not cancellable (every method is a synchronous, in-memory state mutation with no suspension point).
- **Windows path:** Ported verbatim as the sealed class StreamedTextTracker in src/Marrow.Services/Providers/SessionSupport.cs (:45-124, unit N7): Func<long,string> delegates for messageID/thinkingID (Swift `(Int) -> String`), long counters for messageCounter/thinkingCounter (Swift Int), and get-only properties for CurrentMessageID/CurrentThinkingID/MessageText/ThinkingText/StreamedText mirroring the Swift private(set) vars. Shared by every session that adopts SessionSupport; Pi, Command Code and Antigravity keep their own inlined copies until their own lanes switch them over (this unit, lane L2b, only adds the shared type).
- **Verify by:** unit test per method: StartMessage mints a fresh id, clears the buffer and streamedText; AppendMessage mints an id only when none is current and always sets streamedText, keeping the current id and accumulating text on a later call; StartThinking mints a fresh id and clears thinkingText; AppendThinking exercises both resetsText branches (true starts fresh and clears the buffer, false mints an id without clearing it); EndThinking and EndMessage clear only the current id; ResetThinking clears both the current id and the reasoning text; ResetForTurn clears only the streamedText flag; ResetIDs clears both current ids but not the accumulated text

### PR-PROVCLI-444 - EditSnapshots captures a file's before-text when a tool call starts and reports the finished edit as before/after text, or as a no-diff edit when the file did not change, when the call finishes

- **Preconditions:** A tool call that edits a file (a provider session's edit/write tool) is about to run, and the session holds one EditSnapshots (Swift: `var edits`) across the call.
- **Action:** capture(_:path:) is called as the tool call starts; finish(_:path:relativeTo:) is called when it completes. discard/removeAll/text are used elsewhere to drop a pending snapshot, clear all of them, or read a snapshot's captured text without finishing it.
- **Expected:** capture reads the file's current text and stores it keyed by the call's id; a file that read(_:) returns nil for (missing, over 1 MB, or undecodable as UTF-8) is stored as empty string, so a call that then writes a brand-new file reports a whole-file addition rather than failing to find a before-text. finish removes and returns that stored before-text; if the id has no stored snapshot (never captured, or already finished/discarded) it returns nil and the row's edits list is left as already queued. Otherwise it re-reads the file's current text as after (again empty if unreadable), turns path into a root-relative path (ToolTitles.relativePath), and if before and after are equal by Swift's canonical `!=` comparison it returns a single FileEdit with no diff; otherwise it returns a single FileEdit carrying both before and after text. discard drops a snapshot without producing a FileEdit. removeAll drops every pending snapshot. text returns the id's captured text, or empty string if nothing was captured for it, without removing it.
- **Side effects:** capture and finish/discard mutate the shared `contents` dictionary keyed by call id, so a session must not reuse a call id across two in-flight snapshots
- **Persistence:** none
- **Failure cases:** finish for an id with no stored snapshot returns nil rather than throwing or fabricating text; a file that cannot be read (missing, larger than 1 MB, or not valid UTF-8) is treated as empty string on both capture and finish, not as an error
- **Cancellation:** not cancellable (capture/finish each do a single synchronous file read; no suspension point).
- **Windows path:** Ported as the sealed class EditSnapshots in src/Marrow.Services/Providers/SessionSupport.cs (:16-44, unit N7), backed by a Dictionary<string,string> keyed with SwiftStringComparer.Instance (:18) rather than plain ordinal string keys, matching Swift's canonical Dictionary<String,String> key equality. Read(path) (:36-40) checks FileInfo.Exists/Length instead of Swift's resourceValues(forKeys: [.fileSizeKey]), and decodes with SwiftText.DecodeUtf8OrNil over File.ReadAllBytes instead of Foundation's String(contentsOf:encoding:), matching this port's established UTF-8-decode convention (keeps a literal U+FEFF for a BOM, unlike Encoding.UTF8's reader/writer defaults) rather than a plain File.ReadAllText call. Finish's before/after comparison uses SwiftString.Equal, not C#'s ordinal ==, to match Swift's canonical `!=` (:31).
- **Verify by:** unit test per behavior: capture+finish with no change returns a single no-diff FileEdit; capture+finish with a change returns the before/after FileEdit; finish for an uncaptured id returns null; finish reports a path relative to the given root; capture of a missing file and of a file over 1 MB both read as empty so a subsequent write shows as a whole-file addition; discard removes a snapshot without finishing it; removeAll clears every snapshot; text returns the captured text or empty string; and a dedicated test pins Swift canonical string equality (precomposed vs. decomposed accented character), not ordinal ==, for the before/after comparison in finish
