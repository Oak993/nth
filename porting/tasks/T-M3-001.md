### PR-GIT-083 - DiffParser recognises exactly eight header forms while no hunk is open or the line starts a hunk
- **Source:** DroppyCode/Services/Git/DiffParser.swift:73-108 - "diff --git " closes the previous file and starts a new one; then, only while hunk == nil or the line starts "@@": "new file mode", "deleted file mode", "rename from ", "rename to ", "Binary files" or "GIT binary patch", "--- ", "+++ ", "@@" | porting/port_impacts.md entry 230 (G11) - the "--- " arm is a consuming branch whose only effect is the exact test against "--- /dev/null"; oldPath is never derived from it
- **Preconditions:** A patch string.
- **Action:** The patch is parsed.
- **Expected:** The patch is split on "\n" keeping empty subsequences. A line starting with the literal "diff --git " closes the current file and opens a new one whose path comes from the header and whose change starts as modified, binary false, hunks empty. Before any file has been opened every line is ignored. While no hunk is open, or the line starts with "@@": "new file mode" sets added; "deleted file mode" sets deleted; "rename from " sets renamed and takes the remainder as oldPath; "rename to " replaces the path with the remainder; "Binary files" or "GIT binary patch" sets isBinary; a line starting "--- " is consumed with its only effect being that the exact string "--- /dev/null" sets added, and it never sets oldPath; a line starting "+++ " sets deleted when it is exactly "+++ /dev/null", else sets the path to the prefix-stripped remainder after the first four characters; "@@" closes any open hunk and opens a new one.
- **Side effects:** None
- **Persistence:** None.
- **Failure cases:** Malformed input simply produces fewer files; the parser never throws
- **Cancellation:** Parsing runs off the main actor and is not separately cancellable.
- **Windows path:** Split on \n only and treat a trailing \r as ordinary content, as the source does. Deriving oldPath from the "--- " line would widen every focus and de-duplication match downstream, so it must not be added.
- **Verify by:** unit over recorded patches covering add, delete, rename, binary and mode-change headers

### PR-GIT-084 - DiffParser numbers body lines by kind and skips only a trailing empty line at the very end of the patch
- **Source:** DroppyCode/Services/Git/DiffParser.swift:111-125 - "+" is an addition carrying the new number then advancing it; "-" is a deletion carrying the old number then advancing it; "\\" is a note whose text drops the first two characters; " " or an empty line is context carrying both numbers and advancing both; an empty line whose range ends at the patch's end is skipped | DroppyCode/Services/Git/DiffParser.swift:56-58 and :111 - a single monotonically increasing line id counter shared by hunks and lines
- **Preconditions:** A hunk is open.
- **Action:** Body lines are consumed.
- **Expected:** A shared counter increments before each line and supplies its id, and is also what numbers hunks. A line starting "+" becomes an addition whose text is the line minus its first character, carrying the current new-side number, which then advances. A line starting "-" becomes a deletion with the old-side number, which then advances. A line starting with a backslash becomes a note whose text drops both the backslash and the following character. A line starting with a space, or an empty line, becomes context carrying both numbers, both of which advance; but an empty line that is the final line of the whole patch string is skipped entirely. Any other line is ignored.
- **Side effects:** None
- **Persistence:** None.
- **Failure cases:** Not applicable
- **Cancellation:** not cancellable
- **Windows path:** Direct port. The note text drops exactly two characters, so "\\ No newline at end of file" becomes "No newline at end of file".
- **Verify by:** unit asserting line numbers and the note text for a patch ending without a trailing newline

### PR-GIT-085 - The header path prefers the text after the LAST occurrence of " b/", and prefix stripping removes surrounding quotes then a leading a/ or b/

- **Action:** The file path is extracted.
- **Expected:** The text after the literal "diff --git " is searched backwards for the literal " b/"; when found, everything after that occurrence is the path, unstripped. Otherwise the whole remainder goes through prefix stripping: surrounding double quotes are removed when both are present and the string is at least two characters long, then a leading "a/" or "b/" is removed. The same stripping is applied to the "+++ " line's remainder.
- **Side effects:** None
- **Persistence:** None.
- **Failure cases:** A path containing " b/" itself is split at its last occurrence; reproduce
- **Cancellation:** not cancellable
- **Windows path:** Direct port with a backwards ordinal search.
- **Verify by:** unit with a path containing a space and one containing " b/"

### PR-GIT-087 - parseHunks wraps a bare per-file patch in a synthetic diff --git header and forces the known path back onto the result
- **Source:** DroppyCode/Services/Git/DiffParser.swift:131-137 parseHunks(_:path:) - the body is the text itself when it already starts "diff --git", else "diff --git a/<path> b/<path>\n" prepended; the first parsed file is used, or a fresh modified file with no hunks; the path is then overwritten with the supplied one
- **Preconditions:** A provider reported a per-file diff for a known path.
- **Action:** The app parses it.
- **Expected:** When the text already begins with the literal "diff --git" it is parsed as given; otherwise a synthetic header line "diff --git a/<path> b/<path>" followed by a newline is prepended. The first file of the parse is taken, or, when nothing parsed, a file with the given path, change modified, not binary and no hunks. The path is then set to the supplied path unconditionally, overriding anything the patch claimed.
- **Side effects:** None
- **Persistence:** None.
- **Failure cases:** A patch that parses to nothing yields a hunkless file, which the caller then treats as having no detail
- **Cancellation:** not cancellable
- **Windows path:** Direct port; the synthetic header uses forward slashes regardless of the platform.
- **Verify by:** unit with a bare hunk body and with a full patch
