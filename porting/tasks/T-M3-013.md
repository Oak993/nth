### PR-GIT-089 - TurnDiff.merge filters a whole-checkout snapshot down to the paths the chat's turns actually reported
- **Source:** DroppyCode/Services/Git/TurnDiff.swift:4-37 merge(...) - repositoryRoot defaults to root; reportedPath resolves against root then normalizes against repositoryRoot; touched is mapped through reportedPath; the known set is grown with every reported file's path and oldPath and every non-empty edit path; snapshot files not in the known set are skipped; snapshot paths use normalize directly while non-snapshot paths use reportedPath; with a snapshot present, reported files are added only when the path starts "/" and no entry exists yet | DroppyCode/App/Runtime/ThreadRuntime.swift:2031-2035 - 'Only the files this chat's turns reported count.'
- **Preconditions:** A snapshot diff between two checkpoints, the provider's patch, the turns' reported edits and their touched paths.
- **Action:** A turn's or a thread's diff is assembled.
- **Expected:** When a touched set is given, it is expanded with every reported file's path and old path and every non-empty edit path, all run through the path resolver, and any snapshot file outside that set is dropped. This is what keeps another chat's work, a merge, or an agent's writes to its own notes out of the chat's diff. A turn with no record contributes nothing rather than lifting the filter. Snapshot entries are normalised against the repository root directly, while reported and edit paths are first resolved against the working root. With a snapshot present, reported files are added only when their resolved path is absolute and no entry already exists for it.
- **Side effects:** None
- **Persistence:** None.
- **Failure cases:** No touched set at all means no filtering, and the snapshot is taken whole
- **Cancellation:** Runs off the main actor; not separately cancellable.
- **Windows path:** Normalise agent-reported paths to forward slashes before they enter this function, since every comparison here is forward-slash based.
- **Verify by:** unit with a snapshot containing another thread's file, asserting it is dropped

### PR-GIT-090 - TurnDiff adds per-edit files last, only for paths no authoritative entry already covers, and falls back to the edit's reported counts when it has no hunks
- **Source:** DroppyCode/Services/Git/TurnDiff.swift:38-49 - the authoritative set is the keys already present; an edit is added only when its resolved path is not authoritative and either there is no snapshot or the path is absolute; the file comes from parseHunks of the edit's diff, and when that has no hunks the edit's own additions and deletions become the reported counts; the result is sorted by path ascending
- **Preconditions:** A turn reported tool edits.
- **Action:** The diff is assembled.
- **Expected:** After snapshot and reported files, each non-empty edit path is resolved and skipped when an entry already exists for it. The edit's own patch is parsed for that path; if it yields no hunks, the edit's reported addition and deletion counts are attached instead so the row still shows numbers. The final list is sorted by path ascending.
- **Side effects:** None
- **Persistence:** None.
- **Failure cases:** An edit with neither a patch nor counts contributes a zero row
- **Cancellation:** not cancellable
- **Windows path:** Sort with an ordinal comparison so the order matches.
- **Verify by:** unit with an edit whose patch is empty but whose counts are set

### PR-GIT-091 - Merging two diff entries for the same path renumbers every appended hunk to the same id

- **Preconditions:** Two entries name the same path.
- **Action:** They are merged.
- **Expected:** The totals are summed into the reported addition and deletion counts, the binary flag becomes the logical or of the two, and every hunk of the incoming file is appended after having its id set to one more than the id of the existing file's last hunk as read before the loop began. - **Persistence:** None.

- **Cancellation:** not cancellable
- **Windows path:** Reproduce the collision; do not renumber correctly.
- **Verify by:** unit merging two multi-hunk files for one path and asserting the duplicate ids
