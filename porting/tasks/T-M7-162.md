### PR-SETTINGS-018 - Both scroll areas stop answering the pointer while a finger is dragging them, and answer again the moment the flick coasts
- **Source:** DroppyCode/App/Views/Settings/SettingsView.swift:177 - sidebar content .allowsHitTesting(!scrollTracker.isFrozen) | DroppyCode/App/Views/Settings/SettingsView.swift:222 - page content .allowsHitTesting(!scrollTracker.isFrozen) | DroppyCode/App/Views/Settings/SettingsView.swift:179-184 - sidebar .onScrollGeometryChange(for: CGFloat.self, of: { $0.contentOffset.y }) { _, _ in scrollTracker.note() } and .onScrollPhaseChange { _, phase in if phase == .interacting { scrollTracker.note() } else { scrollTracker.coast() } } | DroppyCode/App/Views/Settings/SettingsView.swift:226-236 - the same pair on the page scroll, with the comment "Fingers on the content freeze the rows (no click can land then anyway); the moment the scroll coasts or settles they come back, so a click that stops a flick always reaches its target. Wheel scrolling reports no phases and is caught by the movement above instead."
- **Preconditions:** The settings window is open.
- **Action:** The user scrolls either the sidebar or the page, by trackpad drag or by wheel.
- **Expected:** While a drag is in progress the rows are frozen and take no clicks. Once the drag ends and the flick coasts, or the scroll settles, the rows take the pointer again, so a click that stops a flick reaches its target. Wheel scrolling reports no phases, so it is caught by the geometry change alone: each movement frame calls note(), which freezes only if the tracker is not already coasting.
- **Side effects:** Reports scrolling to the shared ScrollActivity, which pauses frame-driven animations app-wide
- **Persistence:** Nothing.
- **Cancellation:** not cancellable
- **Windows path:** A pointer-events: none toggle on both scroll contents driven by a scroll tracker that distinguishes an active pointer drag from momentum and wheel movement.
- **Verify by:** interaction test: begin a drag over a toggle, release over it, assert the toggle did not flip; wheel-scroll and click immediately, assert the click lands
