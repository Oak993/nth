- **Preconditions:** A control request (initialize, set_permission_mode, set_model, interrupt, stop_task) is made from a task that is, or becomes, cancelled.
- **Action:** control(_:) runs.
- **Expected:** The process and hasClosed checks come first (PR-PROVCLI-019); then controlCounter is advanced and the id is built. If the calling task is already cancelled, control(_:) throws CancellationError before anything is stored or written: no control_request line is sent, and that id number is used up, so the next request's id skips it. Otherwise the id is registered before the line is sent. If the calling task is cancelled while the reply is outstanding, the waiting entry is removed and the caller resumes by throwing CancellationError, and a control_response that arrives later for that id is dropped; a reply delivered before the cancellation takes effect is returned to the caller as usual. No timeout applies: a caller that is neither cancelled nor answered waits until the reply arrives or didClose fails it. This holds for every control() caller, start()'s initialize included.
- **Side effects:** A request cancelled before the send advances controlCounter without writing to stdin

- **Cancellation:** Cancellable before the send and while waiting, as described; the removal on cancellation runs as a separate main-actor task.
