## Requirements

### PR-THEME-089 - Markdown is parsed into exactly seven block kinds; inline styling is not the parser's job
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:3-12 doc "Block-level Markdown for agent output. Inline styling is handled by AttributedString." and `enum MarkdownBlock { case heading(level: Int, text: String); case paragraph(String); case code(language: String?, code: String); case list(ordered: Bool, start: Int, items: [MarkdownListItem]); case quote([MarkdownBlock]); case table(header: [String], rows: [[String]]); case rule }` | DroppyCode/UI/Markdown/MarkdownParser.swift:14-18 `struct MarkdownListItem { var text: String; var checked: Bool?; var children: [MarkdownBlock] }`
- **Preconditions:** A message text is to be rendered.
- **Action:** The text is parsed.
- **Expected:** The result is a flat list of blocks drawn from exactly these seven kinds. Headings carry a level and their text. Code carries an optional info string and its body. Lists carry an ordered flag, a start number and items, each item carrying its own text, an optional checked state and nested child blocks. Quotes carry nested blocks. Tables carry a header row and body rows of cell strings. Rules carry nothing. Emphasis, links and inline code are left inside the block text and resolved later by the inline layer.
- **Persistence:** not persisted
- **Failure cases:** No failure path: any text parses to some block list, possibly empty.
- **Cancellation:** not cancellable
- **Windows path:** A hand-written block parser in shared code. Do not substitute a CommonMark library: the grammar below differs from CommonMark in several load-bearing ways and the differences are user-visible in agent output.
- **Verify by:** contract fixture: a corpus of agent outputs parses to a recorded block tree

### PR-THEME-090 - Lines split on newline with a preceding carriage return dropped, and each line's byte offset is recorded
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:53-64 `private static func parse(_ text: Substring) -> Parse`: splits the UTF-8 on 0x0A without omitting empty subsequences, records each piece's byte distance from the start, and drops a trailing 0x0D from each piece
- **Preconditions:** A text is being parsed.
- **Action:** The text is split into lines.
- **Expected:** Lines are separated by a single line feed; a carriage return immediately before it is dropped, so CRLF and LF text parse identically. Empty lines are kept as empty lines, including a trailing empty line after a final newline. Each line's offset is recorded in UTF-8 bytes from the start of the text, for the incremental restart (PR-THEME-092).
- **Persistence:** not persisted
- **Failure cases:** A lone carriage return that is not followed by a line feed is not a line break; it stays inside the line.
- **Cancellation:** not cancellable
- **Windows path:** Windows agents emit CRLF far more often than macOS ones, so this rule is exercised constantly. A lone CR is deliberately not a break.
- **Verify by:** unit: the same text with LF and with CRLF produces identical blocks

### PR-THEME-091 - A parse reports how many of its leading blocks can no longer change as more text arrives
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:21-31 doc and `struct Parse { var blocks: [MarkdownBlock]; var stable: Int; var restart: Int }` | DroppyCode/UI/Markdown/MarkdownParser.swift:66-72 `guard let stable = parsed.blockLines.lastIndex(where: { $0 <= lines.count - 3 }) else { return Parse(blocks: parsed.blocks, stable: 0, restart: 0) }` then `Parse(blocks:, stable: stable, restart: starts[parsed.blockLines[stable]])`
- **Preconditions:** A streaming text is being parsed.
- **Action:** The parse finishes.
- **Expected:** The parser reports the index of the last top-level block that starts at least two lines above the final line, together with that block's UTF-8 offset. Blocks before that index are final: the parser decides each line from that line and the next, so nothing arriving later can change them. When no block qualifies, stable and restart are both zero and nothing is reusable.
- **Persistence:** not persisted
- **Failure cases:** Fewer than three lines: stable is zero.
- **Cancellation:** not cancellable
- **Windows path:** The stable count is not just an optimization: it is the equality key the block views use (PR-THEME-105), so getting it wrong changes what repaints during a stream.
- **Verify by:** unit: for a growing text, blocks below the reported stable index never change in a later parse

### PR-THEME-092 - A text that merely extends an earlier one reuses that parse's stable blocks and parses only the tail
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:39-51 `parse(_:extending:)`: falls back to a full parse unless the previous parse has a positive stable count, the new text is strictly longer in UTF-8 bytes and starts with the previous text's UTF-8; otherwise parses from the previous restart offset and returns the previous stable blocks followed by the tail's blocks, with the two stable counts and the two restart offsets added
- **Preconditions:** A previous parse of a prefix of this text exists.
- **Action:** The extended text is parsed.
- **Expected:** The first `stable` blocks of the previous parse are reused unchanged and only the text from the previous restart offset is re-parsed. The new stable count is the previous count plus the tail's, and the new restart offset is the previous offset plus the tail's. Any of the three preconditions failing (no stable blocks, not longer, not a prefix) causes a full parse.
- **Persistence:** not persisted
- **Failure cases:** A rewrite rather than an append: full parse.
- **Cancellation:** not cancellable
- **Windows path:** Offsets are UTF-8 bytes here, unlike the veil's character offsets. Mixing the two units is the likeliest porting mistake.
- **Verify by:** unit: incremental parse of a growing text equals a full parse at every step

### PR-THEME-093 - Quotes and lists nest at most eight levels deep; past that their lines are plain paragraph text
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:74-76 `/// Quotes and list items nest by recursion, one level per > or indent step, which model output decides. Past this many levels the inner lines are paragraph text.` `private static let maxDepth = 8` | DroppyCode/UI/Markdown/MarkdownParser.swift:138 `if trimmed.hasPrefix(">"), depth < maxDepth` | DroppyCode/UI/Markdown/MarkdownParser.swift:170 `if depth < maxDepth, let marker = listMarker(line), ...`
- **Preconditions:** Deeply nested output is being parsed.
- **Action:** A quote or list marker is met at depth 8 or deeper.
- **Expected:** The line is not treated as a quote or a list item; it falls through to the paragraph accumulator and its marker characters stay in the text. Blank-line and other rules still apply. The limit counts recursion levels, so a quote inside a list counts toward the same budget.
- **Persistence:** not persisted
- **Failure cases:** No error; the output simply renders as prose.
- **Cancellation:** not cancellable
- **Windows path:** A hard recursion cap protecting against unbounded model output; keep it at 8 so pathological output renders identically.
- **Verify by:** unit: nine levels of '>' render as eight quotes with the ninth marker visible in the text

### PR-THEME-094 - A fenced code block opens on ``` or ~~~ and closes on a line of the same character, with the rest of the opener as the info string
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:299-305 `fenceMarker(_ trimmed:)`: for the markers "```" and "~~~" in that order, when the trimmed line starts with one, returns the run of that character from the start | DroppyCode/UI/Markdown/MarkdownParser.swift:105-119 the fence branch: the language is the trimmed line minus the fence run, trimmed of whitespace, nil when empty; lines are taken verbatim until a trimmed line that starts with the fence and consists only of that character, which is consumed; the body is joined with newlines
- **Preconditions:** A line begins a fence.
- **Action:** The parser reads the code block.
- **Expected:** The fence is the leading run of backticks or tildes on the trimmed line (three or more in practice, but the run is whatever is there once the two-or-more prefix matched). Everything after it on that line, whitespace-trimmed, is the info string; an empty one becomes no language. Body lines are taken untrimmed and verbatim. The block closes on the first trimmed line that starts with the same fence string and contains only that character; that line is consumed. An unclosed fence runs to the end of the text and still produces a code block.
- **Persistence:** not persisted
- **Failure cases:** Unclosed fence at end of text: the code block contains the rest of the text. This is what makes a streaming code block render as code from its first line.
- **Cancellation:** not cancellable
- **Windows path:** Note the closing test requires only that the line start with the fence and be all fence characters, so a longer closing run closes a shorter opener; and a fence of a different character does not close it.
- **Verify by:** unit: mixed-marker fences, a longer closing run, an unclosed fence

### PR-THEME-095 - A heading is one to six leading hashes followed by end of line or a space, and its text is stripped of hashes and spaces at both ends
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:307-312 `headingLevel(_ trimmed:)`: counts leading '#', requires 1...6, and requires the rest to be empty or to start with a space | DroppyCode/UI/Markdown/MarkdownParser.swift:121-128 the heading branch: content is the trimmed line with leading hashes dropped and whitespace trimmed, then trimmed again of the character set "# " at both ends
- **Preconditions:** A non-empty line that is not a fence.
- **Action:** The parser tests it for a heading.
- **Expected:** One to six hashes followed by a space, or a line of hashes alone, is a heading of that level. Seven or more hashes is not a heading. A hash run followed immediately by a non-space character is not a heading. The heading's text has leading hashes and spaces removed and, because of the second trim, also has trailing hashes and spaces removed, so "## Title ##" yields "Title".
- **Persistence:** not persisted
- **Failure cases:** Not a heading: the line falls through to the next test.
- **Cancellation:** not cancellable
- **Windows path:** The closing-hash strip is a side effect of trimming the character set "# " from both ends, so it also removes hashes that were meant as text at the end of a heading. Reproduce it.
- **Verify by:** unit: "#Title", "####### Title", "## Title ##", "###"

### PR-THEME-096 - A horizontal rule is three or more of one of dash, asterisk or underscore, with spaces allowed between them and nothing else
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:314-323 `isRule(_ trimmed:)`: the first byte must be 0x2D, 0x2A or 0x5F; every byte must be either that same byte or 0x20; at least three occurrences are required | DroppyCode/UI/Markdown/MarkdownParser.swift:130-136 the rule branch runs after the heading test and before the quote, table and list tests
- **Preconditions:** A non-empty, non-fence, non-heading line.
- **Action:** The parser tests it for a rule.
- **Expected:** A line made only of three or more copies of a single dash, asterisk or underscore, optionally separated by spaces, is a rule. Mixing two of those characters is not a rule. Any other character disqualifies it. The rule test runs before the list test, so "- - -" is a rule and not a list; "---" is a rule and not a bullet.
- **Persistence:** not persisted
- **Failure cases:** Not a rule: falls through, and a leading dash plus space is then read as a bullet.
- **Cancellation:** not cancellable
- **Windows path:** The byte-level test also means a tab between the characters disqualifies the line, because only 0x20 is allowed.
- **Verify by:** unit: "---", "- - -", "--", "-*-", "- \t -"

### PR-THEME-097 - A quote runs over consecutive lines starting with >, stripping the marker and at most one space, and parses its content one level deeper
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:138-152 the quote branch: while the trimmed line starts with '>', drop that character and, if the next character is a space, that one too; collect; then `blocks.append(.quote(parse(quoted[...], depth: depth + 1).blocks))`
- **Preconditions:** A line begins with a greater-than sign and the depth budget allows.
- **Action:** The parser reads the quote.
- **Expected:** Consecutive lines whose trimmed form starts with '>' are gathered. Each contributes its content after the marker and after at most one following space, so ">  indented" keeps one leading space. The gathered lines are parsed as a fresh document one level deeper, so a quote may contain headings, lists, code and further quotes. The quote ends at the first line that does not start with '>', including a blank line.
- **Persistence:** not persisted
- **Failure cases:** A blank line inside a quote ends it, producing two quote blocks rather than one with a gap.
- **Cancellation:** not cancellable
- **Windows path:** Only one space after the marker is eaten; this matters for code indented inside a quote.
- **Verify by:** unit: nested quotes, a quote containing a list, a quote split by a blank line

### PR-THEME-098 - A table is a line containing a pipe whose next line is a delimiter row, and it runs until a blank or pipe-free line
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:154-168 the table branch: requires a next line, the current trimmed line to contain "|", and `isTableDelimiter(lines[index + 1])`; the header is the current line's cells; the index advances by two; rows are taken while the trimmed line is non-empty and contains "|" | DroppyCode/UI/Markdown/MarkdownParser.swift:325-329 `isTableDelimiter(_ line:)`: the trimmed line must contain "-" and every character must be one of '|', ':', '-' or ' ' | DroppyCode/UI/Markdown/MarkdownParser.swift:331-337 `tableCells(_ line:)`: trims the line, drops one leading '|' and one trailing '|', splits on '|' keeping empty pieces, and trims each cell of whitespace
- **Preconditions:** A line contains a pipe and is followed by another line.
- **Action:** The parser tests for a table.
- **Expected:** The next line must contain at least one dash and consist only of pipes, colons, dashes and spaces. When it does, the current line is the header row and the delimiter line is consumed. Body rows continue while lines are non-empty and contain a pipe. Cells are produced by trimming the line, removing one leading and one trailing pipe, splitting on pipes without dropping empties, and trimming each cell. Alignment colons in the delimiter row are parsed for the purpose of recognising the row but are otherwise discarded: no alignment is carried into the block.
- **Persistence:** not persisted
- **Failure cases:** A delimiter row with no dash is not a delimiter, so the pair renders as paragraphs.; Rows with more or fewer cells than the header are kept as they are; the renderer pads short rows (PR-THEME-119).
- **Cancellation:** not cancellable
- **Windows path:** Column alignment is parsed away and never applied. Every cell renders leading-aligned regardless of the colons; that is the shipped behaviour.
- **Verify by:** unit: a table with alignment colons renders leading-aligned; ragged rows; a pipe line with no delimiter
