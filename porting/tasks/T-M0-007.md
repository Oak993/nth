## The probe, verbatim from the stack decision

P8 - Filesystem watch overflow signal. Point a System.IO.FileSystemWatcher with InternalBufferSize at its 4 KB minimum at a repo-shaped tree and generate a burst (a git checkout across a large branch, or a scripted 10,000-file touch). PASS: the Error event fires carrying InternalBufferOverflowException at least once, and the app's full-rescan path runs to completion. This is the 'we lost events, rescan' semantic that C6's three FSEvents loss flags require. FAIL: move to ReadDirectoryChangesW with overlapped I/O by P/Invoke and re-probe for ERROR_NOTIFY_ENUM_DIR and for the documented zero-lpBytesReturned overflow.

## Rules

- Read `WORKER_BRIEF.md` first. Model the probe on `porting/probes/p1-glass/`, which passed.
- A probe PROVES or DISPROVES one capability. Report the measured result, whichever it is.
  A FAIL reported honestly is a valuable result. A PASS you did not measure is worthless.
- Build a control case that must fail when the thing under test is absent, as P1 did with
  its tint-only render. Without one, a PASS cannot be trusted.
- Never send a prompt to a real AI CLI; `--version` or `--help` only.
- Set `MARROW_PORT_DATA_DIR` to a throwaway folder before running anything.
