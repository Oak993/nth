### PR-MCP-036 - MCPCatalog.entry(matching:) normalizes a server name before matching id then name
- **Source:** DroppyCode/Core/Models/MCPCatalog.swift:462-473 entry(matching:) with the local normalize function
- **Preconditions:** none
- **Action:** A tool call or transcript names a server and the app looks up its catalog entry (for the glyph and the brand tint).
- **Expected:** normalize(value) lowercases, replaces every "_" with "-" and every " " with "-". The function first returns the entry whose normalized id equals the normalized argument; failing that, the entry whose normalized name equals it; otherwise nil. So "Chrome DevTools", "chrome_devtools" and "chrome-devtools" all resolve to the chrome-devtools entry. "Hugging Face" normalizes to "hugging-face" and matches the entry's normalized name through the second pass, returning huggingface; "huggingface" matches through the id pass. Leading/trailing spaces and repeated spaces are not trimmed or collapsed.
- **Side effects:** none
- **Persistence:** none
- **Failure cases:** no match returns nil and the caller falls back to a generic glyph
- **Cancellation:** not cancellable
- **Windows path:** Same two-pass lookup and the same three-rule normalizer. Do not add extra normalization (stripping spaces, removing hyphens): it would change which names resolve.
- **Verify by:** unit with id and normalized-name lookup, the positive "Hugging Face" name fallback, and negative whitespace/punctuation cases; review id-before-name precedence against source
