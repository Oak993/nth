### PR-MCP-085 - MCPCustomServer.makeID slugs the name and always yields a usable custom- id
- **Source:** DroppyCode/Core/Models/MCPCustom.swift:62-76 makeID
- **Preconditions:** A new custom server is being added.
- **Action:** The id is minted from the first name.
- **Expected:** Lowercase the name. Walk its characters: a letter or a number is appended; any other character appends a single "-" but only when the previous appended character was not already a dash (lastWasDash starts true, so leading separators produce nothing). A trailing "-" is removed. The result is "custom-" + the slug, or "custom-server" when the slug came out empty. Examples: "My Server" -> "custom-my-server"; "!!!" -> "custom-server"; "  a  b  " -> "custom-a-b".
- **Side effects:** none
- **Persistence:** the id is persisted in custom-mcp.json and used as the protected-storage account prefix and the provider-config key
- **Failure cases:** a name that slugs to an id already taken is rejected by validate with the takenName message
- **Cancellation:** not cancellable
- **Windows path:** Same algorithm character by character. Unicode letters and digits count as letters and numbers, so a non-ASCII name produces a non-ASCII id, which then becomes a JSON key and part of a proxy route path.
- **Verify by:** unit with the three examples plus a non-ASCII name

### PR-MCP-086 - A custom server's one-line summary names its command or its host
- **Source:** DroppyCode/Core/Models/MCPCustom.swift:79-87 summary
- **Preconditions:** A custom server exists.
- **Action:** Its row or its converted catalog entry is rendered.
- **Expected:** For .stdio: "Runs on this Mac: " + ([command] + args).joined(separator: " ") + "." - so a server with command "npx" and args ["-y","x"] reads "Runs on this Mac: npx -y x." and an empty command with no args reads "Runs on this Mac: .". For .http: "Remote server at " + (URL(string: url)?.host() ?? url) + "." - the host alone when the URL parses, the whole raw string when it does not.
- **Side effects:** none
- **Persistence:** never persisted; recomputed from the definition on every render
- **Failure cases:** an unparseable URL puts the entire raw string into the sentence
- **Cancellation:** not cancellable
- **Windows path:** The string "Runs on this Mac: " is user-visible product text that names a Mac. Changing it is a branding deviation outside the rename allowance and must be escalated, not assumed; the specification records it verbatim as it stands.
- **Verify by:** unit on both branches plus a capture of the row text

### PR-MCP-087 - catalogEntry() turns a custom server into a catalog entry so every other path treats it identically
- **Source:** DroppyCode/Core/Models/MCPCustom.swift:93-118 catalogEntry()
- **Preconditions:** A custom server definition.
- **Action:** Anything needs an MCPCatalogEntry for a custom server.
- **Expected:** fields = one MCPField per variable, with key = label = the variable key, placeholder "", kind .secret when isSecret else .text, help nil, defaultValue nil, isRequired true (the default). placeholders = a map from each variable key to the literal "{key}", built with a uniquing rule that keeps the FIRST of duplicate keys, because a draft reaches the editor's header before duplicates are validated. The entry is id = the server id, name = the server name, vendor "Custom", summary = the server summary, category .developer, asset "" (which makes MCPIcon draw the server.rack symbol), colorValue 0, isMonochrome true, docsURL "" (which makes the info popover omit its docs link), sampleTools empty, keysURL nil. Transport is .stdio(command:args:) for stdio or .http(url:headers: placeholders) for http; for stdio the placeholders go into entry.env instead. Because every field is isRequired true, needsInput is true for any custom server that declares at least one variable, so Connect opens the key panel.
- **Side effects:** none
- **Persistence:** none; derived
- **Failure cases:** a custom server with no variables has needsInput false and connects straight away
- **Cancellation:** not cancellable
- **Windows path:** Same mapping. The isRequired-true-for-every-variable rule is what makes the key panel's save button demand every variable.
- **Verify by:** unit over both kinds plus the duplicate-key uniquing

### PR-MCP-091 - MCPCustomError.validate runs its checks in a fixed order and returns the first failure
- **Source:** DroppyCode/Core/Models/MCPCustom.swift:150-168 validate(_:existingIDs:)
- **Preconditions:** A draft server and the set of taken ids.
- **Action:** saveCustom validates.
- **Expected:** In order: 1) trimmed name empty -> .emptyName. 2) makeID(trimmed name) already in existingIDs -> .takenName(trimmed name). 3) for .stdio, a command that trims to empty -> .emptyCommand; for .http, validRemoteURL(url) false -> .badURL. 4) for each variable in order: an invalid key -> .badVariableKey(key); then a duplicate -> .duplicateVariableKey(key), where the duplicate key used for comparison is lowercased for http (headers are case-insensitive) and used as typed for stdio (environment variables are not). So an http server declaring both "Authorization" and "authorization" is rejected while a stdio server declaring "PATH" and "path" is accepted. Returning nil means valid.
- **Side effects:** none
- **Persistence:** none
- **Failure cases:** each check has its own exact message, listed in PR-MCP-093
- **Cancellation:** not cancellable
- **Windows path:** Same order and the same http-only lowercasing. Note the id is recomputed inside validate from the trimmed name, which for an edit differs from the id saveCustom actually uses.
- **Verify by:** unit over each branch including the http case-collision case

### PR-MCP-094 - A custom remote address must be https anywhere, or http only on loopback
- **Source:** DroppyCode/Core/Models/MCPCustom.swift:172-182 validRemoteURL
- **Preconditions:** kind is http.
- **Action:** validate checks the URL.
- **Expected:** Trim whitespace and newlines. Parse with URLComponents; require a scheme and a non-empty host. Lowercase the scheme; it must be "https" or "http". For "http", the lowercased host must be one of exactly "localhost", "127.0.0.1", "::1", "[::1]"; anything else is rejected. "https" is accepted for any host. An empty string, a string with no scheme, or a scheme such as "ws" is rejected.
- **Side effects:** none
- **Persistence:** none
- **Failure cases:** rejection -> "The URL must start with https:// (or http:// for a local server)."
- **Cancellation:** not cancellable
- **Windows path:** Same four-host allowlist verbatim, including both bracketed and unbracketed IPv6 loopback spellings.
- **Verify by:** unit over the four allowed hosts, a rejected http host, and an https host
