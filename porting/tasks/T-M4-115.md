### PR-PROVCLI-313 - Pi plan limits read only the OAuth logins Pi holds, skipping non-oauth and expired entries
- **Source:** DroppyCode/Services/Providers/PiPlanLimits.swift:10-41 - read(environment:) with the doc comment at :3-5 and the expiry comment at :22 | porting/blocked_requirements.json BLK-0007 owner_ruling (OD-0008, A7)
- **Preconditions:** A config directory.
- **Action:** The usage panel reads Pi's limits.
- **Expected:** <config>/auth.json is read and must parse to an object, else nil. Its keys are walked SORTED. An entry is skipped unless its "type" is exactly "oauth" AND its "access" is a non-empty string. An entry whose "expires" is a double is skipped when that value, read as epoch MILLISECONDS, is already in the past - an expired token buys nothing from the usage endpoint. Then the key decides the reader: exactly "anthropic" reads the Anthropic usage endpoint; exactly "openai-codex" OR exactly "openai" reads the Codex one; EVERY OTHER KEY IS SKIPPED. A nil result from a reader is skipped. Surviving windows are appended in key order and surviving plan names collected. With no windows at all the result is nil; otherwise a PlanLimits whose plan name is the collected names joined by " · " (space, U+00B7, space), or nil when none were collected.
- **Side effects:** READS A THIRD-PARTY CREDENTIAL FILE. Pi's <config>/auth.json holds the OAuth access tokens of the providers Pi is signed into, and those tokens are then sent to Anthropic's and OpenAI's usage endpoints. Up to two network requests carrying a third party's bearer token.
- **Persistence:** The registry persists the plan limits.
- **Failure cases:** No usable logins: nil.
- **Cancellation:** Each request has its own 15 second timeout.
- **Windows path:** PLATFORM BOUNDARY. The key sort must be ordinal. The file is read directly from the CLI's own config directory and the app never writes it. The read, and the requests that carry Pi's tokens to the Anthropic and Codex usage endpoints (PR-PROVCLI-314, PR-PROVCLI-315), are reproduced as upstream: BLK-0007 is RESOLVED by OD-0008 (decision batch A7, "Keep as upstream (it is how the plan-limit feature works)"), ruling: "REPRODUCE UPSTREAM: plan limits read each CLI's own credential file and query that provider's usage endpoint exactly as the source does. Parity, owner-approved." Treated identically to PR-PROVREG-177, PR-PROVREG-121 and PR-PROVCLI-255.
- **Verify by:** unit test over an expired token, a non-oauth entry, an unknown provider key and two live ones

### PR-PROVCLI-314 - Pi reads Anthropic usage with a beta header and prefixes the plan name with Claude
- **Source:** DroppyCode/Services/Providers/PiPlanLimits.swift:7,:43-57 - anthropicUsageURL and readAnthropic | porting/blocked_requirements.json BLK-0007 owner_ruling (OD-0008, A7)
- **Preconditions:** A live anthropic OAuth token.
- **Action:** readAnthropic runs.
- **Expected:** A 15 second request to https://api.anthropic.com/api/oauth/usage carrying Authorization "Bearer <token>", anthropic-beta "oauth-2025-04-20" and Accept "application/json". Anything but HTTP 200, or an unparseable body, yields nil. The body is parsed by PlanLimitsReader.parseClaudeUsage with limits from json.limits (or the empty array), a nil plan name and the titlePrefix "Claude"; a nil result yields nil. The plan name is then OVERWRITTEN with json.subscription_type mapped through PlanLimitsReader.planName and prefixed "Claude ", or, when either step yields nothing, the bare literal "Claude".
- **Side effects:** One network request
- **Persistence:** Part of the persisted plan limits.
- **Failure cases:** A non-200 or unparseable response yields nil for this provider only.
- **Cancellation:** The 15 second timeout.
- **Windows path:** Network only.
- **Verify by:** unit test against a recorded response with and without a subscription_type

### PR-PROVCLI-315 - Pi reads Codex usage with an account id taken from the token's own claim
- **Source:** DroppyCode/Services/Providers/PiPlanLimits.swift:8,:59-79 - codexUsageURL and readCodex with the comment at :64 | DroppyCode/Services/Providers/PiPlanLimits.swift:102-114 - codexAccountID | porting/blocked_requirements.json BLK-0007 owner_ruling (OD-0008, A7)
- **Preconditions:** A live openai-codex or openai OAuth token.
- **Action:** readCodex runs.
- **Expected:** A 15 second request to https://chatgpt.com/backend-api/wham/usage carrying Authorization "Bearer <token>" and Accept "application/json". When an account id can be extracted and is non-empty, the header "ChatGPT-Account-Id" carries it. The account id comes from the token's SECOND dot-separated part decoded as base64url: hyphens become plus, underscores become slash, and the string is padded with equals signs to a multiple of four; the decoded JSON's field at the path "https://api.openai.com/auth" then "chatgpt_account_id" is the id. A token with fewer than two parts, or one that fails to decode or parse, yields no id and the header is omitted. Anything but HTTP 200, or an unparseable body, yields nil. The rate limit object is json.rate_limit, else the whole body. Two windows are built from "primary_window" and "secondary_window"; with none, nil. The plan name is json.plan_type mapped through PlanLimitsReader.codexPlanName and prefixed "Codex ", or the bare literal "Codex".
- **Side effects:** One network request
- **Persistence:** Part of the persisted plan limits.
- **Failure cases:** A malformed token simply omits the header, which may make the endpoint answer for the wrong scope or refuse.
- **Cancellation:** The 15 second timeout.
- **Windows path:** Base64 decoding must be strict about the padding rule described; a decoder that rejects unpadded input would break the header. No credential is ever written anywhere.
- **Verify by:** unit test over a token with and without the claim, plus a recorded usage response

### PR-PROVCLI-316 - Pi's Codex windows require a used percent and a window length, and derive a reset time two ways
- **Source:** DroppyCode/Services/Providers/PiPlanLimits.swift:81-100 - codexWindow(id:raw:)
- **Preconditions:** A rate-limit window object.
- **Action:** codexWindow runs.
- **Expected:** The window is nil unless the raw value exists AND carries a double "used_percent" AND an int "limit_window_seconds". The reset time is Date(timeIntervalSince1970:) of "reset_at" when that is a double; otherwise, when "reset_after_seconds" is an int, it is that many seconds from NOW; otherwise nil. The id is the literal passed in, exactly "codex-primary" or "codex-secondary". The title is the literal "Codex · " (space, U+00B7, space) followed by PlanLimitsReader.windowTitle(minutes: limit_window_seconds / 60) - an INTEGER division, so a window shorter than sixty seconds titles as zero minutes. The percent is used_percent unchanged, with NO clamping.
- **Persistence:** Part of the persisted plan limits.
- **Failure cases:** A missing percent or window length drops that window silently.
- **Cancellation:** not cancellable
- **Windows path:** None.
- **Verify by:** unit test over both reset shapes, a sub-minute window and a missing percent
