### PR-MCP-114 - A 401 or 403 from an OAuth upstream is an unauthorized sign-in, except GitLab's disabled-server 403
- **Source:** DroppyCode/Services/MCP/MCPProbe.swift:155-160 the 401/403 catch inside probeRemote, matching MCPHTTPError
- **Preconditions:** server.oauthUpstream is non-nil.
- **Action:** A POST answers 401 or 403.
- **Expected:** When the status is 403 AND the body contains "MCP server disabled" compared case-insensitively and locale-aware, throw MCPProbeError.needsSetup(gitLabServerDisabled(upstream:)) using server.oauthUpstream, falling back to the request url. In every other 401/403 case throw MCPProbeError.unauthorizedOAuth, which the store catches and turns into one sign-out-and-retry. For a non-OAuth server this catch does not apply and the error stays .http.
- **Side effects:** none here; the retry happens in the store
- **Persistence:** none
- **Failure cases:** unauthorizedOAuth after the retry -> "Sign-in was rejected. Sign in again in your browser."
- **Cancellation:** not cancellable
- **Windows path:** Same substring, same case-insensitive comparison.
- **Verify by:** contract fixture answering 403 with and without that body text

### PR-MCP-115 - A 404 from an OAuth upstream is GitLab's setup case or a plain unavailable host
- **Source:** DroppyCode/Services/MCP/MCPProbe.swift:161-169 the 404 catch | DroppyCode/Services/MCP/MCPProbe.swift:209-212 isGitLabMCP
- **Preconditions:** server.oauthUpstream is non-nil.
- **Action:** A POST answers 404.

If the address is right, try again in a few minutes.".
- **Side effects:** none
- **Persistence:** none
- **Failure cases:** the two messages above
- **Cancellation:** not cancellable
- **Windows path:** Same suffix test on the lowercased path, so a relative URL root such as https://host/gitlab/api/v4/mcp still matches.
- **Verify by:** unit over a GitLab path, a non-GitLab path, and a URL with no host
