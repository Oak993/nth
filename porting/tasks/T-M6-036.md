### PR-PROVREG-239 - A refused Keychain write mirrors the API key into UserDefaults in plain text, and a successful one clears that mirror
> **DO NOT IMPLEMENT. Quarantined by BLK-0006 (owner decision pending).** Leave a clearly marked TODO referencing BLK-0006 and move on. Gate C fails if you implement it.
- **Source:** DroppyCode/App/AppSettings.swift:359-365 - deepseekAPIKeyInput didSet: guard !isReadingKeychain, deepseekAPIKeyInput != oldValue else { return }; let kept = DeepSeekKeychain.setAPIKey(deepseekAPIKeyInput); storeAPIKeyFallback(kept ? "" : deepseekAPIKeyInput, forKey: Key.deepseekAPIKey) | DroppyCode/App/AppSettings.swift:370-376, :381-387 and the Command Code input - the same three-line didSet repeated for metaAPIKeyInput, zaiAPIKeyInput and commandcodeAPIKeyInput | DroppyCode/App/AppSettings.swift:151-154 - static let deepseekAPIKey = "deepseekAPIKey", metaAPIKey = "metaAPIKey", zaiAPIKey = "zaiAPIKey", commandcodeAPIKey = "commandcodeAPIKey" | DroppyCode/App/AppSettings.swift:356 - the comment "Stored in the Keychain when available, with a UserDefaults fallback for migration"
- **Preconditions:** A Keychain write of an API key has just returned.
- **Action:** storeAPIKeyFallback runs for that provider.
- **Expected:** Each of the four API key inputs runs the same three lines on change, guarded so the initial Keychain read does not trigger it and so an unchanged value does nothing. setAPIKey trims the value of whitespace and newlines and returns whether the Keychain KEPT it; note an empty key deletes the item and returns TRUE, so clearing a key also clears the mirror. When the return is FALSE, and only then, storeAPIKeyFallback writes the key to the matching UserDefaults key - deepseekAPIKey, metaAPIKey, zaiAPIKey or commandcodeAPIKey. When it is true the EMPTY STRING is written to that same key, which removes any mirror an earlier refusal left behind. The mirror is written UNTRIMMED, from the input property, while the Keychain stores the trimmed value, so the two stores can hold different strings for the same key. On read, APIKeychain.key(for:fallback:) prefers a non-empty Keychain value and returns the mirror otherwise, making the two a single logical slot.
- **Side effects:** SECURITY-RELEVANT: a provider API key is written to disk in plain text, in the app's user defaults, readable by any process running as the user.
- **Persistence:** UserDefaults keys deepseekAPIKey, metaAPIKey, zaiAPIKey, commandcodeAPIKey.
- **Failure cases:** Nothing tells the user their key is now stored in the clear.; A key with leading or trailing whitespace is mirrored with that whitespace while the Keychain copy is trimmed.
- **Cancellation:** not cancellable
- **Windows path:** PLATFORM BOUNDARY AND POLICY DECISION. This is the one half of the API key store that must NOT be transliterated. The port's own rules require SecretStore (DPAPI through Electron safeStorage) and say that when protected storage is unavailable the app must fail and say so, never fall back to plain text. Reproducing the mirror faithfully would write user API keys to disk unencrypted on every Windows PC where DPAPI is unavailable. The clearing half of the rule - writing the empty string on success - is safe and should be kept whatever is decided about the mirror itself.
- **Verify by:** unit test with a refusing secret store, asserting both the mirror write and the clear-on-success
- **Upstream defect NEW, not in upstream_defects.md: a provider API key is written to UserDefaults in plain text whenever the Keychain refuses the write (AppSettings.swift:363, :374 and the two siblings), and the mirror is written untrimmed while the Keychain copy is trimmed.: reproduce it faithfully, do not fix it.**
