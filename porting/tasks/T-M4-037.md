## Requirements

### PR-PROVAPI-001 - APIKeychain.key returns the stored Keychain value, else the caller's fallback
- **Source:** DroppyCode/Services/Providers/APIKeychain.swift:13-17 key(for:fallback:) - reads the account, returns it when non-empty, otherwise returns fallback
- **Preconditions:** A Keychain item may or may not exist for the account string.
- **Action:** Any caller asks for a provider's stored API key.
- **Expected:** If the Keychain read returns a non-empty string, that string is returned. Otherwise the caller's fallback string is returned unchanged.
- **Side effects:** One Keychain read per call (SecItemCopyMatching)
- **Persistence:** Reads only; nothing is written.
- **Failure cases:** Keychain read fails or returns no item: the fallback is returned, with no error surfaced
- **Cancellation:** not cancellable
- **Windows path:** SecretStore backed by DPAPI through Electron safeStorage. Platform boundary: macOS Keychain generic password item becomes a DPAPI user-scope blob. Same read-then-fallback order.
- **Verify by:** unit

### PR-PROVAPI-002 - APIKeychain.setKey with an empty or whitespace-only value deletes the item and reports success
- **Source:** DroppyCode/Services/Providers/APIKeychain.swift:22-27 setKey - trims whitespace and newlines; an empty trimmed value calls delete(account) and returns true
- **Preconditions:** An item may or may not exist for the account.
- **Action:** The user clears the API key field, or any caller stores an empty or whitespace-only string.
- **Expected:** The stored item for that account is deleted and the function returns true, so the caller stores no plaintext fallback.
- **Side effects:** SecItemDelete on the account
- **Persistence:** Removes the secret for that account from the one Keychain service named by AppInfo.name.
- **Failure cases:** Deleting a non-existent item is not an error; true is still returned
- **Cancellation:** not cancellable
- **Windows path:** SecretStore delete for the same account name; return true so the plaintext fallback is not written.
- **Verify by:** unit

### PR-PROVAPI-003 - APIKeychain.setKey stores the trimmed key as a generic password under one service, delete-then-add
- **Source:** DroppyCode/Services/Providers/APIKeychain.swift:28-39 - Data(trimmed.utf8); query kSecClass kSecClassGenericPassword, kSecAttrService AppInfo.name, kSecAttrAccount account; SecItemDelete(query) then SecItemAdd with kSecValueData and kSecAttrAccessible kSecAttrAccessibleWhenUnlocked; returns whether SecItemAdd was errSecSuccess
- **Preconditions:** A non-empty trimmed key.
- **Action:** A provider API key is saved.
- **Expected:** Any existing item for the account is deleted first, then a new generic-password item is added with the UTF-8 bytes of the trimmed key, service AppInfo.name, the given account, and accessibility kSecAttrAccessibleWhenUnlocked. The function returns true only when the add returned errSecSuccess.
- **Side effects:** SecItemDelete then SecItemAdd against the login Keychain
- **Persistence:** One item per provider account inside a single flat service namespace named by the app display name; MCP secrets share that service under accounts of the form 'MCP <server> <field>'.
- **Failure cases:** The add fails: false is returned and the caller keeps a plaintext copy in the defaults (PR-PROVAPI-008 to PR-PROVAPI-010)
- **Cancellation:** not cancellable
- **Windows path:** DPAPI user scope via safeStorage, one entry per account name in one container named by the app display name, account strings verbatim. kSecAttrAccessibleWhenUnlocked has no Windows analogue; port_impacts.md entry 262 records that substitution. CLAUDE.md forbids a plaintext fallback on Windows, so the false branch is a platform boundary needing a recorded decision rather than a silent copy.
- **Verify by:** unit plus restart test

### PR-PROVAPI-004 - APIKeychain.read rejects a blank stored value and returns the trimmed key
- **Source:** DroppyCode/Services/Providers/APIKeychain.swift:42-56 read - query with kSecReturnData true and kSecMatchLimit kSecMatchLimitOne; requires errSecSuccess, Data, a UTF-8 decode and a non-blank trimmed value, then returns the trimmed value
- **Preconditions:** An item exists or does not.
- **Action:** The app reads a provider key.
- **Expected:** Returns the key trimmed of whitespace and newlines. Returns nil when the item is missing, the data is not valid UTF-8, or the trimmed value is empty.
- **Side effects:** One SecItemCopyMatching
- **Persistence:** none
- **Failure cases:** Non-UTF-8 data: nil; Whitespace-only stored value: nil, so the caller falls back
- **Cancellation:** not cancellable
- **Windows path:** SecretStore read with the same trimming and blank rejection.
- **Verify by:** unit

### PR-PROVREG-088 - API keys live in four Keychain items under one service, distinguished only by their account strings
- **Source:** DroppyCode/Services/Providers/APIKeychain.swift:29-33 setKey - kSecClassGenericPassword with kSecAttrService = AppInfo.name and kSecAttrAccount = the account string | DroppyCode/Services/Providers/DeepSeekKeychain.swift - account "DeepSeek API Key" | DroppyCode/Services/Providers/MetaKeychain.swift - account "Meta API Key" | DroppyCode/Services/Providers/ZaiKeychain.swift - account "Z.ai API Key"
- **Preconditions:** The user edits an API key field.
- **Action:** setAPIKeyInput is called for that provider.
- **Expected:** The key is trimmed of whitespace and newlines and written as a generic password under the service name AppInfo.name with one of exactly these four account strings: "DeepSeek API Key", "Meta API Key", "Z.ai API Key", "Command Code API Key". Accessibility is kSecAttrAccessibleWhenUnlocked. Each write is a delete followed by an add. An empty key deletes the item rather than storing an empty value. The plaintext mirror that runs when this write REFUSES is a separate behaviour and is specified by PR-PROVREG-239.
- **Side effects:** A Keychain delete followed by an add on every write.
- **Persistence:** Keychain service = the app display name, four fixed account strings.
- **Failure cases:** Keychain unavailable: SecItemAdd returns non-success and setKey returns false; what happens next is PR-PROVREG-239.
- **Cancellation:** not cancellable
- **Windows path:** PLATFORM BOUNDARY: the Windows SecretStore must keep the same one-container-many-accounts partitioning and the same four account strings verbatim, because MCP secrets share the container and are distinguished only by account string.
- **Verify by:** restart test on each of the four accounts plus a contract fixture on the account strings
