### PR-RUNTIME-109 - finishTurn cancels the interrupt watchdog and the head budget first, and falls back to idling when the turn is gone
- **Source:** DroppyCode/App/Runtime/ThreadRuntime.swift:2201-2211 - interruptWatchdog?.cancel(); interruptWatchdog = nil; headBudget?.cancel(); headBudget = nil; guard let turnID = explicitTurnID ?? currentTurnID, let turn = turns.first(where: { $0.id == turnID }) else { phase = .idle; turnStartedAt = nil; drainPendingSend(); return }
- **Preconditions:** A turn is being closed, by any of the seven callers.
- **Action:** finishTurn runs.
- **Expected:** Both timers are cancelled and cleared unconditionally. The turn is identified by the explicit id when the caller already took it out of currentTurnID, otherwise by currentTurnID. When no such turn exists in turns the runtime simply goes idle, clears turnStartedAt and drains any Return-captured pending send, then returns: no summary row, no notification, no save.
- **Side effects:** Possibly a new turn started by drainPendingSend.
- **Persistence:** None on this path.
- **Cancellation:** finishTurn itself is an async function; the callers never cancel it.
- **Windows path:** Same order. The fallback path is what makes a doubled finish safe.
- **Verify by:** unit

### PR-RUNTIME-110 - finishTurn claims the turn before its first suspension so a completion and an exit finalize it once
- **Source:** DroppyCode/App/Runtime/ThreadRuntime.swift:2212-2216 - the comment "Claimed before the first suspension below: a completion and an exit can both arrive for one turn, and the second finalizer finds it taken." then guard finishingTurnID != turnID else { return }; finishingTurnID = turnID; defer { finishingTurnID = nil }
- **Preconditions:** finishTurn has identified a turn.
- **Action:** The claim runs.
- **Expected:** A second finishTurn for the same id returns immediately. The claim is taken before any await, so the check is atomic on the main actor. The claim is released by the defer on every exit path, including the early returns below it.
- **Persistence:** None.

- **Windows path:** The claim must be set before the first asynchronous boundary. A port that awaited first would finalize twice.

### PR-RUNTIME-111 - finishTurn settles every outstanding command snapshot, the lead's and the heads', before counting files
- **Source:** DroppyCode/App/Runtime/ThreadRuntime.swift:2217-2221 - the comment then for id in Array(commandTrees.keys) { settleCommand(id) }; for key in Array(hydraCommandTrees.keys) { settleHydraCommand(key) }
- **Preconditions:** Commands started during the turn may still hold un-settled before-trees.
- **Action:** Both maps are drained.
- **Expected:** Every pending command diff is started while the turn is still current, so the snapshots can still be compared, and before the turn's own summary counts them. The heads' commands settle alongside the lead's because their files are part of this turn's work. The keys are copied into an array first because settling removes from the map.
- **Side effects:** Git snapshots and diffs; tool rows gain edits; hydraTouched grows.
- **Persistence:** Tool row edits reach ThreadDocument.items.
- **Cancellation:** The settle tasks are raced against a three-second sleep below for a non-completed turn (PR-RUNTIME-114).
- **Windows path:** Iterate over a snapshot of the keys; mutating during iteration is undefined.
- **Verify by:** integration test against a real repository

### PR-RUNTIME-113 - finishTurn opens a closing window so late rows still belong to the turn
- **Source:** DroppyCode/App/Runtime/ThreadRuntime.swift:2227-2228 - closingTurnID = turnID; defer { closingTurnID = nil } | DroppyCode/App/Runtime/ThreadRuntime.swift:459-468 - the field comment and private var turnIDForNewRows: UUID? { currentTurnID ?? closingTurnID }
- **Preconditions:** The turn is about to wait for its diffs.
- **Action:** closingTurnID is set.
- **Expected:** Rows created during the wait (a late tool result, a notice, a Hydra note) are filed under the closing turn through turnIDForNewRows. - **Windows path:** turnIDForNewRows must be the single source for every row-creation site; the two exceptions must stay exceptions.
- **Verify by:** unit - append a notice during the wait and assert its turnID

### PR-RUNTIME-114 - A completed turn waits out its command diffs; a stopped or failed one gives them three seconds
- **Source:** DroppyCode/App/Runtime/ThreadRuntime.swift:2225-2240 - the comment "a stopped or failed one gives them three seconds and lets the rest land on their own, so Stop never hangs on git"; let settles = Array(commandSettles.values); commandSettles.removeAll(); if status == .completed { for task in settles { await task.value } } else { await withTaskGroup(of: Void.self) { group in group.addTask { for task in settles { await task.value } }; group.addTask { try? await Task.sleep(for: .seconds(3)) }; await group.next(); group.cancelAll() } }
- **Preconditions:** Command settle tasks are outstanding.
- **Action:** The wait runs.
- **Expected:** For a completed turn every settle is awaited to completion, however long git takes. For any other status the settles race a three-second sleep and whichever finishes first ends the wait, after which the group is cancelled; settles that were still running continue on their own and land their edits later. The settles map is emptied before the wait so a later finishTurn does not wait on them again.
- **Side effects:** Git processes.
- **Persistence:** Tool row edits, whenever they land.
- **Cancellation:** group.cancelAll() cancels the sleep, not the detached settle work.
- **Windows path:** Three seconds is exact. Git on Windows is slower over large checkouts, so the timeout will be hit more often; do not lengthen it.
- **Verify by:** integration test with an injected slow settle
