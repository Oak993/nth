### PR-UPDATE-034 - Byte progress maps linearly onto 0.05...0.55 and only from the preparing or downloading phase
- **Source:** DroppyCode/App/AppUpdater.swift:98-112 noteDownloadProgress - if phase == .preparing { phase = .downloading } else if phase != .downloading { return }; guard downloadFraction > 0 else { startCreep(toward: 0.50, rate: 0.012); return }; stopCreep(); apply(start + (end - start) * min(downloadFraction, 1)) with start = preparingCeiling, end = downloadEnd
- **Preconditions:** The downloader is reporting.
- **Action:** A byte-progress report arrives.
- **Expected:** The first report moves preparing to downloading. Reports arriving in any other phase are ignored outright. A fraction of 0 or less starts a creep toward 0.50 at rate 0.012 instead of freezing. A positive fraction stops the creep and applies 0.05 + 0.50 * min(fraction, 1), so 100 percent downloaded is exactly 0.55.
- **Side effects:** Possible creep task start or stop.
- **Persistence:** None.
- **Failure cases:** Unknown content length reports 0 forever, so the head creeps asymptotically toward 0.50 and never reaches the download-end dot on its own.
- **Cancellation:** not cancellable
- **Windows path:** Same mapping and the same unknown-size creep. Node's download stream must report a fraction of 0 when Content-Length is absent, not a NaN or a guess.
- **Verify by:** unit

### PR-UPDATE-040 - A creep ticks every 125 ms, closing a fixed proportion of the gap, and stops within 0.0005 of its ceiling
- **Source:** DroppyCode/App/AppUpdater.swift:203-219 startCreep(toward:rate:) - sets creepCeiling and creepRate, then guard creepTask == nil else { return }; loop: sleep 125 ms; let remaining = creepCeiling - fraction; guard remaining > 0.0005 else { creepTask = nil; return }; apply(fraction + remaining * creepRate) | DroppyCode/App/AppUpdater.swift:221-224 stopCreep() - cancels and nils the task
- **Preconditions:** A phase with no byte progress is active.
- **Action:** The creep runs.
- **Expected:** Every 125 ms the head advances by (ceiling - fraction) * rate, so it approaches the ceiling asymptotically and never reaches it. When the remaining gap is 0.0005 or less the task ends and clears itself. Calling startCreep again while a task exists only UPDATES the ceiling and rate; it does not start a second task. The task escapes only by cancellation or by the small-gap exit.
- **Side effects:** A repeating timer task.
- **Persistence:** None.
- **Failure cases:** Not applicable.
- **Cancellation:** stopCreep() cancels it; every phase transition calls stopCreep first (except begin, which starts one).
- **Windows path:** A 125 ms interval in the main process, with the same single-task-with-mutable-ceiling shape. Getting this wrong (restarting the task per phase) doubles the creep rate visibly.
- **Verify by:** unit
