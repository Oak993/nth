### PR-PROVCLI-009 - Claude probes --help once per executable path for two optional flags and does not cache a failed probe
- **Source:** DroppyCode/Services/Providers/ClaudeSession.swift:56 - private static var knownOptions: [String: Set<String>] = [:] | DroppyCode/Services/Providers/ClaudeSession.swift:69-80 - knownOptions(of:environment:) | DroppyCode/Services/Providers/ClaudeSession.swift:98 - called from start()
- **Preconditions:** A resolved executable.
- **Action:** start() asks for the executable's known options.
- **Expected:** On a cache hit keyed by executable.path the cached Set is returned and no process runs. On a miss, Shell.run(executable, ["--help"], environment: environment, timeout: 20) runs; ANSI is stripped from result.output + result.errorOutput; the Set is the members of the literal two-element array ["--system-prompt-snapshot", "--forward-subagent-text"] whose text appears in the help output; that Set is cached. If Shell.run throws, the EMPTY set is returned and NOTHING is cached, so the next launch probes again.
- **Side effects:** One `claude --help` child process per executable path, bounded at 20 seconds
- **Persistence:** In-memory static cache for the life of the app process only; nothing on disk.
- **Failure cases:** Probe throws or times out: empty set, not cached, both optional flags omitted for that launch. Behaviour can therefore differ between the first and second launch after a probe failure.
- **Cancellation:** Governed only by Shell.run's 20 second timeout.
- **Windows path:** Shell.run maps to the Windows process layer (PA-0007, PA-0008). ANSI stripping is load-bearing on Windows because CLIs emit VT sequences into pipes.
- **Verify by:** unit test with a scripted stand-in emitting help text, then a failing stand-in, asserting the second launch probes again
