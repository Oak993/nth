### PR-PROVAPI-129 - An in-stream error is always mapped with status code 200
- **Source:** DroppyCode/Services/Providers/OpenAICompatibleSession.swift:621 - statusCode is a constant 200 inside performStream | DroppyCode/Services/Providers/OpenAICompatibleSession.swift:711-717 - the round is built with that constant | DroppyCode/Services/Providers/OpenAICompatibleSession.swift:696-698 - a transport error after a stream error also maps with that constant
- **Preconditions:** The HTTP response was 200 and the error arrived inside the SSE body.
- **Action:** The error is mapped by friendlyError.
- **Expected:** The status code handed to friendlyError is 200, so the status-only branches (Meta's 401, 404, 429 and 504, Z.ai's 401, DeepSeek's 429) cannot fire for an in-stream error; only the message-text branches can. This is source behavior and is reproduced.
- **Persistence:** none
- **Failure cases:** A provider that reports a rate limit only through the HTTP status of a streamed error would fall through to the passthrough message
- **Cancellation:** not applicable
- **Windows path:** Reproduce the constant. Candidate upstream defect not currently recorded in upstream_defects.md; see open questions.
- **Verify by:** unit

- **Cancellation:** not applicable

- **Verify by:** unit with recorded usage payloads from all three providers

### PR-PROVAPI-132 - Streaming text is coalesced off the main actor and flushed at most 30 milliseconds after the first piece
- **Source:** DroppyCode/Services/Providers/OpenAICompatibleSession.swift:152-228 StreamCoalescer - consecutive text accumulates and a flush is scheduled 30 milliseconds after the first piece; switching between text and reasoning flushes the other buffer first; a tool call, a usage value, a token usage or a stream error flushes first and is then yielded; finish and fail flush before closing
- **Preconditions:** A response is streaming.
- **Action:** Deltas arrive faster than the UI needs them.
- **Expected:** Consecutive text arrives at the main actor as one larger delta, at most 30 milliseconds after its first piece. Text and reasoning never interleave within one emitted delta. Ordering between text, reasoning, tool calls, usage and errors is preserved exactly.
- **Side effects:** messageDelta and reasoningDelta events
- **Persistence:** none
- **Cancellation:** A cancelled drain finishes the coalescer, flushing whatever it held.
- **Windows path:** Same 30 millisecond window and the same flush-on-switch rule, so streamed text does not arrive out of order.
- **Verify by:** integration
