### PR-PROVAPI-105 - Consecutive approval-free built-in reads run concurrently, at most four at a time, in the model's order
- **Source:** DroppyCode/Services/Providers/OpenAICompatibleSession.swift:365-387 - a run of consecutive calls whose readOnlyKind is non-nil and which need no approval is executed as one batch, then each output is appended as a tool message in the batch's own order | DroppyCode/Services/Providers/OpenAICompatibleSession.swift:855 maxConcurrentReads = 4 | DroppyCode/Services/Providers/OpenAICompatibleSession.swift:871-892 executeReadBatch - a task group seeded with min(4, count) tasks, refilled as each finishes, results placed by index | DroppyCode/Services/Providers/OpenAICompatibleSession.swift:859-865 readOnlyKind - read_file is .read, list_files and search_text are .search, everything else nil
- **Preconditions:** The model asked for several reads in a row and the current mode approves reads automatically.
- **Action:** The tool loop reaches the first of them.
- **Expected:** At most four of those reads are in flight at once; their results are appended in the order the model asked for them, not in completion order. Only read_file, list_files and search_text can join a batch, and only when they need no approval.
- **Side effects:** Up to four concurrent file reads or greps
- **Persistence:** History gains one tool message per read, in order.
- **Failure cases:** A cancelled or interrupted batch cancels the remaining reads and appends nothing further
- **Cancellation:** Cancelling the turn cancels every read still in flight; a cancelled read's output is never appended.
- **Windows path:** Same concurrency limit and the same order-preserving placement.
- **Verify by:** integration
