### PR-TERM-117 - Nothing about a terminal session survives a restart: tabs, scrollback, selection and running shells are all per-run

- **Preconditions:** The app is quit with several terminals open.
- **Action:** The app is relaunched.
- **Expected:** Every thread starts with no sessions and a hidden drawer. Opening the drawer spawns one fresh shell. Scrollback, tab names beyond the regenerated "Terminal 1", and which tab was selected are all gone. The ONLY thing restored is the drawer height, under the key "terminalHeight".
- **Persistence:** terminalHeight only.
- **Cancellation:** not cancellable
- **Windows path:** Same. Do not add session restoration; that would be new behaviour.
- **Verify by:** restart test

### PR-TERM-123 - A script tab launches the shell with exactly four arguments whose fourth is the command interpolated unquoted, followed by an exec back into a login shell; the port runs it in PowerShell
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:37-39 - if let command { arguments = ["-l", "-i", "-c", "\(command); exec \(shell) -l"] } | DroppyCode/App/Views/Terminal/TerminalStore.swift:28 - shell = LoginEnvironment.userShell(), the same value that is interpolated into the fourth argument and used as the executable | DroppyCode/App/Views/Terminal/TerminalStore.swift:40 - args: arguments | porting/owner_decisions_pending.md:141 - the recorded C5 ruling: "terminal tabs and project scripts run in PowerShell 7 (pwsh) when installed, otherwise Windows PowerShell." It fixes only the interpreter. The lead's question Q125 at :143 (question text, not the ruling) is what raised the hyphen argv[0] and the POSIX-script consequences
- **Preconditions:** A session is being created with a startup command.
- **Action:** TerminalSession.init runs.
- **Expected:** Upstream: the arguments are exactly ["-l", "-i", "-c", <fourth>] in that order, four elements, never three and never five. The fourth is built by string interpolation as the command, then "; exec ", then the SHELL'S OWN ABSOLUTE PATH, then " -l": the same path used as the executable, not the bare shell name. Neither the command nor the path is quoted or escaped, so the command runs as written and a shell path containing a space would break the exec. The trailing exec replaces the shell with a fresh login shell instead of letting the tab exit when the script finishes, and it runs whether the command succeeded or failed, because the two are joined by a semicolon rather than by &&. DEVIATION (OD-0008 C5): the port runs the script in PowerShell 7 if installed, otherwise Windows PowerShell. The source intent kept is: run the command as written, then leave an interactive shell in the same tab whether it succeeded or failed. The exact PowerShell argument vector is not fixed by the ruling or the source and remains an engineering decision to record before this is SPECIFIED.
- **Side effects:** The command runs with the user's full login environment and profile, in the project directory
- **Persistence:** None.
- **Failure cases:** A command containing an unbalanced quote, a stray semicolon or a trailing backslash changes what the composed line means; the source does no escaping; A shell path containing a space breaks the exec and the tab exits when the script ends (upstream); The command failing does not stop the hand-back: the tab still becomes an interactive shell; Port: a droppy-code.json command written in POSIX shell syntax is interpreted by PowerShell. This follows from the C5 interpreter; the ruling (owner_decisions_pending.md:141) and the decision sheet's C5 row do not mention it, so it is a consequence the lead's question Q125 (:143) raised, not one the owner ruled on
- **Cancellation:** The user can interrupt the running command with the shell's own keys; the app offers no cancel control.
- **Windows path:** PowerShell 7 if installed, otherwise Windows PowerShell (OD-0008 C5). The -l/-i/-c triple and the trailing exec are POSIX shell syntax and are not carried; the concrete vector that runs the command then stays interactive is an open engineering decision.
- **Verify by:** contract fixture asserting the four-element vector and the exact fourth element for a command containing a space and a quote

### PR-TERM-124 - The embedded terminal's font is chosen by TerminalFont.preferred() once, when each session is created
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:22 - view.font = TerminalFont.preferred(), inside TerminalSession.init | DroppyCode/App/Views/Terminal/TerminalStore.swift:119-121 open(threadID:directory:title:command:) and :140-147 restart(_:) - every new tab, script tab and restart constructs a new TerminalSession | DroppyCode/App/Views/Terminal/TerminalFont.swift:3-8 - the doc comment: the font the embedded terminal draws with is the running terminal's configured font, so a Starship prompt's Nerd Font glyphs render instead of landing as empty boxes; preferred(fallbackSize: CGFloat = 12)
- **Preconditions:** A terminal session is being created: a new tab, a script tab or a restart.
- **Action:** TerminalSession.init runs.
- **Expected:** TerminalFont.preferred() is evaluated with its default fallbackSize of 12 and its result becomes the terminal view's font. It is evaluated once per session: an existing tab keeps the font it was created with even if another terminal's configuration changes later, and a restarted tab re-reads it because restart builds a new session.
- **Side effects:** Reads up to two Ghostty config files and the iTerm2 and Terminal.app defaults domains, and enumerates installed font families (PR-TERM-125 to PR-TERM-134).
- **Persistence:** None. Droppy Code stores no terminal font setting.
- **Failure cases:** Nothing is configured and no Nerd Font is installed: the 12-point regular monospaced system font is used (PR-TERM-125).
- **Cancellation:** not cancellable
- **Windows path:** Evaluate the port of TerminalFont.preferred() once per session creation, as upstream. PLATFORM BOUNDARY: Ghostty, iTerm2 and Terminal.app are macOS applications and their defaults domains and Application Support paths do not exist on Windows; no ruling names a Windows terminal to read instead, so none is added (an engineering decision would be needed to add one).
- **Verify by:** unit test counting preferred() calls across open, run and restart, and asserting an existing session's font is not changed by a later configuration change
