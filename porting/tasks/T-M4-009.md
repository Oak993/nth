### PR-MCP-084 - MCPPaths fixes the on-disk layout of every MCP file
- **Source:** DroppyCode/Services/MCP/MCPPaths.swift:5-22 MCPPaths | DroppyCode/Services/MCP/MCPProviderConfig.swift:230 geminiSettingsURL | DroppyCode/Services/MCP/MCPProxy.swift:17 portFile | DroppyCode/Services/MCP/MCPExternalSync.swift:52 managedURL
- **Preconditions:** none
- **Action:** Any MCP file is read or written.
- **Expected:** MCPPaths.directory is <data root>/mcp/ and is created with intermediate directories on first access. mcp.json and custom-mcp.json sit in <data root>, NOT inside mcp/. Inside mcp/ live exactly: claude.json ({"mcpServers": …}), codex.json ({"mcp_servers": …}), copilot.json ({"mcpServers": …}), gemini-settings.json ({"mcpServers": …}), proxy-port (a decimal UInt16 as UTF-8 text) and managed.json (the legacy migration list).
- **Side effects:** creating mcp/ on first access
- **Persistence:** this is the complete persisted file inventory for the area
- **Failure cases:** a directory that cannot be created leaves every write failing silently
- **Cancellation:** not cancellable
- **Windows path:** <data root> is %LOCALAPPDATA%\<AppName>\ and the mcp subdirectory is %LOCALAPPDATA%\<AppName>\mcp\. Putting mcp.json or custom-mcp.json inside mcp\ silently loses every connection and custom server. The bridge file, which macOS writes to <Application Support>/<AppName>/MCP/, collapses onto the same mcp\ folder on a case-insensitive filesystem and is written there (PR-MCP-193). managed.json is used only by MCPExternalSync, which is not ported (ED-061, PR-MCP-176), so the port neither reads nor writes it.
- **Verify by:** restart test plus a file-inventory assertion
