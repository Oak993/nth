### PR-COMPOSER-030 - Return while a turn runs interrupts and sends; with heads at work it queues or goes to a head instead
- **Source:** DroppyCode/App/Views/Composer/ComposerView.swift:370-382 send() - guard !draft.isEmpty; historyIndex = nil; suggestions = SuggestionState(); if runtime.isRunning { interruptAndSend() } else { runtime.send() } | DroppyCode/App/Runtime/ThreadRuntime.swift:809-830 interruptAndSend - guard !isReverting, !draft.isEmpty, phase != .idle; dispatchSentHead first; then, if hasWorkingHeads, enqueueFollowUp and clear the draft without interrupting; else pendingSend and interrupt()
- **Preconditions:** A non-empty draft.
- **Action:** The user presses Return (or clicks send) while a turn runs.
- **Expected:** The history index and the suggestion list are cleared. With always-heads on, the message is dispatched to a head and the lead's turn is untouched. With heads at work, the message is queued as a follow-up and nothing is interrupted, because native heads run inside the lead's session and a stop would kill them. Otherwise the draft is captured as a pending send, the composer clears at once, and the turn is interrupted; the message goes out as soon as the stop lands.
- **Side effects:** Interrupts the provider session in the third case; Spawns a Droppy-run head in the first case
- **Persistence:** A queued follow-up is saved with the thread (scheduleSave).
- **Failure cases:** isReverting: nothing happens.
- **Cancellation:** not cancellable
- **Windows path:** Same three-way decision, in the same order.
- **Verify by:** integration test per branch with the offline agent
