### PR-TERM-015 - Releasing the strip applies one final delta, commits the height to settings, clears the drag state, and re-reads hover from the real pointer position
- **Source:** DroppyCode/UI/Chrome/DragHandle.swift:222-232 mouseUp - guard isDragging else return; computes the release travel; isDragging = false; pops dragCursor if one is set (Terminal passes none); calls onChange(travel), THEN onEnd(); then refreshHover() and updateGrip(animated: true) | DroppyCode/UI/Chrome/DragHandle.swift:142-151 refreshHover - guard isActive, a window, and not hidden, else isHovering = false; otherwise isHovering = bounds.contains(the real mouseLocationOutsideOfEventStream converted into the view) | DroppyCode/App/Views/Terminal/TerminalPanel.swift:91-96, 126-128 - onEnd assigns model.settings.terminalHeight from dragHeight when it is non-nil, clears dragHeight and dragOrigin, and sets runtime.isTerminalResizing = false; TerminalResizeHandle wires this onEnd straight to DragHandle's onEnd parameter, unchanged from B2's onEnd callback | DroppyCode/App/AppSettings.swift:309-311 - terminalHeight's didSet writes defaults.set(terminalHeight, forKey: Key.terminalHeight)
- **Preconditions:** A drag is in progress.
- **Action:** The user releases the mouse.
- **Expected:** mouseUp does nothing unless isDragging is already true. The release position is applied as one last clamped onChange call, so the final pixel counts; onEnd then runs, which takes settings.terminalHeight from the clamped dragHeight and writes it to the defaults store under the key "terminalHeight", clears dragHeight and dragOrigin, and sets runtime.isTerminalResizing = false. Only after onEnd does the handle re-read the grip's shown state: refreshHover() asks for the pointer's actual current position (not the last tracked enter/exit event) and sets isHovering from whether that position is still inside the strip's bounds, then updateGrip animates the grip to its resting width unless the pointer is truly still over the strip at that instant. A press with no movement still commits, writing back the same value it started from.
- **Side effects:** One write to the persistent settings store.
- **Persistence:** Key "terminalHeight", a Double, written on release only.
- **Failure cases:** dragHeight nil (no onChange ever ran): nothing is written and only the flags clear. mouseUp itself prevents this by calling onChange before onEnd.
- **Cancellation:** not cancellable
- **Windows path:** pointerup; write the same key with the same name and type. Re-read hover from the real pointer position (a hit test against the strip's bounds) after committing, rather than trusting the last enter/exit event.
- **Verify by:** restart test: drag, quit, relaunch, assert the height; plus an interaction test releasing with the pointer off the strip, asserting the grip retracts immediately

### PR-TERM-019 - Hover on the strip is tracked over its visible rectangle, stays live whether or not the app is active, and is also re-read from the real pointer position on release and on attach
- **Source:** DroppyCode/UI/Chrome/DragHandle.swift:234-245 updateTrackingAreas - removes the previous area and adds NSTrackingArea with options mouseEnteredAndExited, activeAlways and inVisibleRect, only while a grip is configured (Terminal always configures one) | DroppyCode/UI/Chrome/DragHandle.swift:247-255 mouseEntered and mouseExited - set isHovering and animate the grip | DroppyCode/UI/Chrome/DragHandle.swift:127-138 viewDidMoveToWindow - when the strip attaches to a window and a grip is configured, refreshHover() then updateGrip(animated: false); also, if taken out of a window mid-drag, clears isDragging and pops dragCursor if one was set | DroppyCode/UI/Chrome/DragHandle.swift:142-151 refreshHover - isHovering = bounds.contains(the real pointer position), guarded by isActive, a window, and not hidden
- **Preconditions:** The panel is visible.
- **Action:** The pointer crosses the strip boundary, or the strip is released from a drag, or the strip is attached to a window.
- **Expected:** Entering sets isHovering true and animates the grip in; exiting sets it false and animates it out, exactly as at B2. Tracking follows the view's visible rectangle, so a clipped strip tracks only its visible part, and is active even when the application is not frontmost. Exactly one tracking area exists at a time. Two cases beyond simple enter/exit now also set isHovering, both from the pointer's real current position rather than from the last enter/exit event: once on mouseUp after a drag ends (PR-TERM-015), and once whenever the strip is attached to a window (first appearance, or moved between windows). - **Cancellation:** not cancellable

- **Verify by:** interaction test covering enter/exit, plus the release-with-pointer-off-strip and attach-while-hovering cases
