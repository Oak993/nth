### PR-SETTINGS-136 - The three heatmap modes scale the same cells differently: per day, per week, and as a running total
- **Source:** DroppyCode/Services/Store/TokenLedger.swift:655-681 - daily: each cell is that day's total; weekly: every cell of a column takes the column's seven-day sum, and a nil cell stays 0; cumulative: a running total accumulated across columns and rows, written to every cell including nil ones | DroppyCode/Services/Store/TokenLedger.swift:682 - `let maxValue = values.flatMap { $0 }.max() ?? 0` | DroppyCode/Services/Store/TokenLedger.swift:604 comment - "Display value per cell, already scaled for the mode."
- **Preconditions:** A grid is being built.
- **Action:** The mode is applied.
- **Expected:** Daily writes each day's own total into its cell and leaves cells outside the year at 0. Weekly sums the seven days of a column and writes that one number into every cell of the column, except cells outside the year which stay 0, so a week reads as one shade. Cumulative walks the columns and then the rows in order, adding each real day's total to a running count and writing the running count into every cell, including the ones outside the year, so the year fills as it goes. - **Persistence:** None.
- **Cancellation:** not cancellable
- **Windows path:** Same three passes with the same treatment of out-of-year cells, which differs between weekly (0) and cumulative (the running total).
- **Verify by:** unit test over a small fixture year in all three modes

- **Action:** The ledger loads at launch.

- **Verify by:** unit test loading a state whose liveCodex is non-empty
