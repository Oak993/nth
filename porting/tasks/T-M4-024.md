### PR-PROVACP-032 - Session state is applied, then the pending selection, before start() returns
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:141-147 - `applySessionState(session)` then `await applySelection(model: configuration.model, effort: configuration.effort, fastMode: configuration.fastMode, interaction: configuration.interactionMode)`
- **Preconditions:** A session reply is in hand.
- **Action:** start() finishes its sequence.
- **Expected:** The order is fixed: state first (which discovers the config option ids and the mode ids), selection second (which uses them). The selection uses the launch configuration's model, effort, fastMode and interactionMode. start() therefore does not return until every needed session/set_config_option, session/set_model or session/set_mode round trip has completed.
- **Side effects:** Up to four extra requests before the session is reported ready.
- **Persistence:** None.
- **Failure cases:** Every selection request is `try?` or a fire-and-forget setConfigOption, so a failure to apply the model, effort, fast or mode does not fail start(); the session opens on the agent's own defaults.
- **Cancellation:** not cancellable
- **Windows path:** Same ordering. Do not parallelize; the calls mutate shared session state on the agent.
- **Verify by:** contract fixture (frame order assertion)

### PR-PROVACP-036 - Build mode is the first id among agent, build, code, default, else the first id that is neither plan nor ask
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:302-303 - `buildMode = ids.first { ["agent", "build", "code", "default"].contains($0) } ?? ids.first { $0 != "plan" && $0 != "ask" }`
- **Preconditions:** A list of mode ids has been discovered.
- **Action:** resolveModes runs.
- **Expected:** The preferred set has exactly four ids: agent, build, code, default. Preference is by the AGENT's own list order, not by the order of that four-element array, because `ids.first` walks the agent's list. When none of the four is present, buildMode is the agent's first id that is neither "plan" nor "ask" - exactly two exclusions. When every id is plan or ask, buildMode is nil and no mode is ever set for build interaction.
- **Persistence:** None.
- **Failure cases:** An agent listing only plan and ask leaves buildMode nil; applySelection's `if let mode` then does nothing for build.
- **Cancellation:** not cancellable
- **Windows path:** Same. Implement as a first-match over the agent's ordered ids, not as a lookup over the literal set.
- **Verify by:** unit (mode-resolution table, including the order-sensitivity case where the agent lists code before agent)
