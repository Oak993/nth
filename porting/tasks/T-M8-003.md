### PR-UPDATE-056 - The external installer waits for the app to exit, swaps the bundles with a restore-on-failure backup, clears quarantine and relaunches
- **Source:** DroppyCode/App/AppUpdater.swift:414-442 installerScript - trap '' HUP; polls kill -0 "$PID" every 0.25 s, giving up when i > 240 with "The app did not quit" and rm -rf of the staging tree, exit 1; BACKUP="$(dirname "$DEST")/.$(basename "$DEST").previous"; rm -rf BACKUP; mv DEST BACKUP or fail with "Could not move the installed app aside"; mv NEW DEST then rm -rf BACKUP, else "Could not move the update into place", restore BACKUP, rm -rf STAGING, exit 1; xattr -dr com.apple.quarantine "$DEST"; open "$DEST"; rm -rf "$STAGING"
- **Preconditions:** The installer was launched with the three arguments.
- **Action:** The installer runs after the app quits.
- **Expected:** It ignores HUP so the parent's exit cannot kill it. It polls for the process at 0.25 s intervals and gives up after more than 240 iterations (about 60 seconds), logging "The app did not quit", removing the staging tree and exiting 1. On success it removes any stale backup, moves the installed bundle to a hidden sibling named ".<name>.previous", moves the staged bundle into place, removes the backup, clears the quarantine attribute, opens the new bundle and removes the staging tree. If the move-in fails it logs "Could not move the update into place", restores the backup, removes the staging tree and exits 1.
- **Side effects:** Replaces the installed application.; Relaunches it.; Writes the three messages to install.log.
- **Persistence:** None of its own; the relaunch marker was written by the app.
- **Failure cases:** Three log messages, verbatim: "The app did not quit", "Could not move the installed app aside", "Could not move the update into place". None of them is ever shown to the user: they go only to install.log, which nothing reads.
- **Cancellation:** not cancellable
- **Windows path:** PLATFORM BOUNDARY. The Windows updater must wait for the parent process id to exit (not kill -0), with the same roughly 60 second ceiling and the same give-up-and-clean-up behavior; move the installed files aside to a hidden sibling, move the new ones in, restore on failure, and relaunch. There is no quarantine attribute on Windows, so xattr has no analogue. PA-0015 applies: clear read-only attributes before deleting, and retry replace and delete with backoff. UNK-0009 is resolved by OD-0008 C6: until the owner has a Windows release feed no release qualifies, so this path is not reached and its live verification waits on that feed.
- **Verify by:** interaction test
