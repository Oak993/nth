### PR-CHAT-193 - Conversation fonts are the plain system text styles, with headline semibold unless a weight is given, and no chat zoom
- **Source:** DroppyCode/UI/Common/ChatFont.swift:3-10 `extension Font { static func chat(_ style: Font.TextStyle, weight: Font.Weight? = nil, design: Font.Design = .default) -> Font { let resolvedWeight = weight ?? (style == .headline ? .semibold : nil); let font = Font.system(style, design: design); return resolvedWeight.map { font.weight($0) } ?? font } }` | DroppyCode/UI/Common/ChatFont.swift:4-5 the doc comment: A text style in the conversation's own weight, so the chat reads as the app's type and not a second scale. The app-wide zoom scales the window, not the type. | Callers at B2, for example DroppyCode/App/Views/Chat/ChatBadge.swift:28 `.font(.chat(.callout, weight: .medium))`, TimelineRows.swift:1370 `.font(.chat(.caption))` and TimelineRows.swift:2151 `.font(.chat(.caption, design: .monospaced))` | DroppyCode/UI/Common/AppZoom.swift:18-26 AppZoomModifier scales the window content with `content.scaleEffect(scale, anchor: .topLeading)`
- **Preconditions:** A chat view asks for a conversation font.
- **Action:** Font.chat(style, weight:, design:) is evaluated.
- **Expected:** The result is the system font for the text style, in the given design, with the given weight; with no weight given, headline is semibold and every other style keeps its own weight. The size is always the text style's own size: no setting or environment value changes it, and the app-wide zoom scales the whole window content rather than the type, so the conversation and the rest of the app share one type scale.
- **Persistence:** None.
- **Cancellation:** not cancellable
- **Windows path:** One text-style table for the whole app; the conversation carries no second scale and no zoom factor. The per-style sizes are the macOS ones recorded in B1 DroppyCode/UI/Common/ChatZoom.swift:44-57 (title2 17, title3 15, headline and body 13, callout 12, subheadline 11, footnote, caption and caption2 10); the face follows OD-0009.
- **Verify by:** unit over the font helper for every text style with and without an explicit weight, plus a capture comparison showing a chat row and a chrome label at the same text style render at the same size

### PR-THEME-179 - Markdown text takes no per-conversation zoom: every markdown font is a plain system text style or a fixed size, and the only scaling is the app-wide window zoom
- **Source:** DroppyCode/UI/Common/ChatFont.swift:3-10 `static func chat(_ style: Font.TextStyle, weight: Font.Weight? = nil, design: Font.Design = .default) -> Font { let resolvedWeight = weight ?? (style == .headline ? .semibold : nil); let font = Font.system(style, design: design); return resolvedWeight.map { font.weight($0) } ?? font }`, documented "The app-wide zoom scales the window, not the type." | DroppyCode/UI/Markdown/MarkdownView.swift:376-383 headingFont: `.chat(.title2, weight: .semibold)`, `.chat(.title3, weight: .semibold)`, `.chat(.headline)`, `.chat(.subheadline, weight: .semibold)` | DroppyCode/UI/Markdown/MarkdownView.swift:1290 `.font(.chat(.caption))`, :1301 `.font(.chat(.callout, design: .monospaced))`, :1313 and :1389 `.font(.chat(.caption))` | DroppyCode/UI/Markdown/MarkdownView.swift:1130 and DroppyCode/UI/Markdown/ProseRunView.swift:17 `let scaled = (pointSize * 2).rounded() / 2`
- **Preconditions:** A reply is rendered as markdown, at any app zoom level.
- **Action:** Any markdown block (heading, paragraph, inline text, list, quote, code block, table, head mention) chooses its font size.
- **Expected:** No markdown font reads a per-conversation zoom; the conversation has no zoom of its own at B2. Named text styles resolve through the font helper to the plain system text style with no size arithmetic (headline defaults to semibold). The native inline and prose-run point sizes are the markdown point size rounded to the nearest half point. The Text-path mention glyph is always 16 points. Markdown, like everything else in the window, is enlarged or reduced only by the app-wide zoom that scales each window root and chat column as a whole (levels and layout specified by the WIN area, the "appZoom" setting and its Settings card by the SETTINGS area). There is no separate text-size control for the chat.
- **Persistence:** Not persisted by this behaviour; the app zoom is stored under "appZoom" (DroppyCode/App/AppSettings.swift:131), specified by the SETTINGS area.
- **Failure cases:** None expressed in source.
- **Cancellation:** not cancellable
- **Windows path:** Do not port the B1 chat zoom or its "chatZoom" stored value: nothing at B2 reads it and there is no migration. Markdown sizes come from the port's text-style table; scaling is applied once at the window root by the app zoom, never per font.
- **Verify by:** unit: the font helper has no zoom input and returns the plain text style (semibold for headline by default) for every style; capture comparison: the same reply at app zoom 100 and 150 differs only by the whole-window scale
