### PR-THEME-057 - Setting softness clamps by writing back only a genuinely out-of-range value, which is what stops the slider recursing to a crash
- **Source:** DroppyCode/UI/Theme/Wallpaper.swift:41-55 the softness didSet: `let clamped = min(1, max(0, softness)); guard clamped == softness else { softness = clamped; return }` then the persist and `scheduleRerender()` | DroppyCode/UI/Theme/Wallpaper.swift:44-47 comment: "Writing the property from its own observer calls the observer again, and an unconditional clamp here recursed until the stack ran out: dragging the softness slider crashed the app."
- **Preconditions:** The store exists.
- **Action:** Softness is assigned, in range or out of range.
- **Expected:** An in-range value is persisted and schedules a re-render. An out-of-range value is written back clamped and returns immediately, and the second pass (with the now in-range value) does the persisting and the re-render. - **Side effects:** Persists the softness; Schedules a render (live or full, per PR-THEME-059)
- **Persistence:** see PR-THEME-055
- **Failure cases:** None expressed in source.
- **Cancellation:** not cancellable
- **Windows path:** If the port's state system re-enters setters, reproduce the guard exactly. If it does not, the observable behaviour is the same and the guard is harmless; it must not be replaced by an unconditional clamp in a re-entrant setter.
- **Verify by:** unit: assigning 1.5 leaves softness at 1 with exactly one persist and one re-render

### PR-THEME-061 - A full render downsamples twice, blurs, and discards its result if a newer render or a removal overtook it
- **Source:** DroppyCode/UI/Theme/Wallpaper.swift:160-178 render(): returns with no file; captures softness; cancels the previous render task; in one detached task computes `(Self.thumbnail(fileURL, maxPixel: 3200), Self.thumbnail(fileURL, maxPixel: 1600))`; returns if the 3200 thumbnail is nil; blurs in a second detached task when softness > 0, otherwise uses the base; then `guard let self, !Task.isCancelled, self.fileURL == fileURL, let rendered else { return }`; stores base and preview bases and sets image with no animation | DroppyCode/UI/Theme/Wallpaper.swift:175 comment: "Deliberately no animation here: an animated bitmap swap makes the picture flash."
- **Preconditions:** A file is installed.
- **Action:** A full render is scheduled.
- **Expected:** Two downsampled copies are produced in one background step: the base at up to 3200 pixels and a preview at up to 1600. If the base cannot be produced the render stops with the current picture untouched. The base is blurred only when softness is above zero. - **Persistence:** not persisted
- **Failure cases:** The file cannot be decoded: nothing changes, no error is shown.; A newer render started, or the wallpaper was removed: the result is discarded.
- **Cancellation:** A new render cancels the previous one; remove() also cancels it.
- **Windows path:** Reproduce the identity check as well as the cancellation check: cancellation alone is not enough, because a removal followed by a new install would otherwise let a stale bitmap land.
- **Verify by:** unit: a render whose file changed mid-flight publishes nothing; interaction test: no flash when softness settles
