### PR-PROVCLI-203 - Command Code's executable name is the bare cmd, with three alternate names and five directories as fallbacks
- **Source:** DroppyCode/Core/Models/Provider.swift:54 - case .commandcode: "cmd" | DroppyCode/Core/Models/Provider.swift:76 - loginCommand "cmd login" | DroppyCode/Core/Models/Provider.swift:35 - displayName "Command Code" | DroppyCode/Services/Providers/ProviderRegistry.swift:246-259 - the fallback list: which("command-code"), which("commandcode"), which("cmd"), then command-code and cmd under <home>/.local/bin, /opt/homebrew/bin, /usr/local/bin, <home>/.npm-global/bin and <home>/.volta/bin
- **Preconditions:** Provider detection is resolving the Command Code CLI.
- **Action:** The registry resolves the executable.
- **Expected:** The primary name is the bare string "cmd". When a custom path is set it is used instead and no fallback is tried. Otherwise PATH is searched for "cmd"; failing that, the fallback list is searched in order and the FIRST executable file wins: which("command-code"), which("commandcode"), which("cmd"), then, for each of <home>/.local/bin, /opt/homebrew/bin, /usr/local/bin, <home>/.npm-global/bin and <home>/.volta/bin, the names "command-code" then "cmd". The comment records why: "cmd" is the documented alias and "command-code" and "commandcode" are the package's own names.
- **Side effects:** Filesystem probes
- **Persistence:** The resolved path is used for every later spawn.
- **Failure cases:** Nothing resolvable leaves configuration.executable nil, which start() reports as not installed.
- **Cancellation:** not cancellable
- **Windows path:** THIS IS THE NAMED WINDOWS HAZARD. Resolving the bare name "cmd" through PATH plus PATHEXT on Windows finds C:\Windows\System32\cmd.exe, the command interpreter, long before any provider CLI; launching it with this provider's argv would open a console that speaks no protocol on stdout and the session would hang at the first read. UNK-0006 is RESOLVED by PA-0016 (ENGINEERING DECISION): resolution honours PATHEXT, and a candidate whose Windows version resource identifies it as the command interpreter (CompanyName Microsoft Corporation with OriginalFilename Cmd.Exe or Cmd.Exe.MUI, or FileDescription Windows Command Processor), or which is %SystemRoot%\System32\cmd.exe or %SystemRoot%\SysWOW64\cmd.exe, is rejected. PA-0016 validates identity before any resolution is accepted, so the fallback which("cmd") is checked too. If nothing else resolves, the provider reports not installed, exactly as the source does when nothing is found, and the user can point the existing binaryPath setting at the executable. The fallback directories are macOS and Unix package-manager paths; where an npm or volta install puts the Command Code CLI on Windows is not in the pinned source and stays a live-verification item under PA-0016, which is unverified against a real Command Code Windows install.
- **Verify by:** PA-0016's Windows contract test: with no Command Code installed, resolution returns not installed rather than System32\cmd.exe, and a stub executable whose version resource does not identify the command interpreter IS accepted; plus a unit test on the fallback order; plus a live Windows probe recording where the CLI actually installs
