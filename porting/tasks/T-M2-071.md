### PR-TERM-121 - swift, swiftc, node, npm, python and python3 read only when the whole argument array is exactly one of three version arrays
- **Source:** DroppyCode/Core/Support/Shell.swift:207-208 - case "swift", "swiftc", "node", "npm", "python", "python3": return arguments == ["--version"] || arguments == ["-version"] || arguments == ["-v"]
- **Preconditions:** A part's tool is one of the six.
- **Action:** The rule runs.
- **Expected:** WHOLE-ARRAY equality, not membership: the argument array must equal exactly ["--version"], exactly ["-version"] or exactly ["-v"]. One extra argument makes the part a writer, so `node --version --foo` writes, and so does a bare `node` with an EMPTY argument array, because the empty array equals none of the three. The six tool names are exact; python2, pip, npx and yarn are not in this case and fall to the default readers set.
- **Persistence:** None.
- **Failure cases:** A bare interpreter invocation with no arguments is classified as a writer, which is the safe answer and is reproduced
- **Cancellation:** not cancellable
- **Windows path:** Same six names and the same whole-array equality. Do not relax it to 'contains a version flag'.
- **Verify by:** unit over each of the three arrays, an array with one extra element, and an empty array

### PR-TERM-122 - env reads only when every argument starts with a dash
- **Source:** DroppyCode/Core/Support/Shell.swift:209-211 - case "env": // Bare env prints the environment; with a command after it, that command runs. return arguments.allSatisfy { $0.hasPrefix("-") }
- **Preconditions:** A part's tool is env.
- **Action:** The rule runs.
- **Expected:** Every argument must begin with a dash. A bare `env` reads, because allSatisfy over an empty array is true. `env FOO=1 ls` writes, because FOO=1 does not begin with a dash, and so does `env ls`. The command env would run is never classified on its own: the whole part is judged a writer and the classifier stops there.
- **Persistence:** None.
- **Failure cases:** Nothing validates that the dash-prefixed arguments are real env flags; an unknown flag still reads.; The rule is sound in practice only because a command name cannot begin with a dash: env -i ls IS classified as a writer, because "ls" fails the prefix test. The hole the comment warns about is closed by that accident, not by an explicit check.
- **Cancellation:** not cancellable
- **Windows path:** Same rule. env does not exist on Windows but the classifier runs on model-produced text, so the case ships.
- **Verify by:** unit over bare env, env with only flags, env with an assignment, and env with a command
