### PR-CHAT-019 - Array members of a thread document decode leniently: an unreadable item is dropped, never the document

- **Preconditions:** A thread file holds an item this build cannot read.

- **Expected:** The unreadable element is silently omitted and every readable element around it survives, in order. usage and continuation default to null. The user sees the conversation minus the broken item, never an empty or failed thread.

- **Cancellation:** not cancellable

### PR-CHAT-169 - A message stored by a build that cleaned text as it arrived is cleaned again on read, which is an upstream lossy rewrite of stored prose
- **Source:** DroppyCode/Core/Models/Timeline.swift:35-38 the doc comment - model-written prose with its long dashes flattened, for threads stored by a build that cleaned text only as it arrived | DroppyCode/Core/Models/Timeline.swift:39-55 the rewrite itself
- **Preconditions:** A thread holds assistant prose, reasoning or a plan containing an em dash.
- **Action:** The item passes through the cleanup on read.
- **Expected:** The stored characters are replaced in memory, and the next save persists the replacement, so the original em dash is not recoverable. This is the shipped behavior and is reproduced.
- **Persistence:** The rewritten text is what the next save writes.
- **Failure cases:** A code block inside a reply that legitimately contains an em dash is rewritten along with the prose; the cleanup is not markdown-aware.
- **Cancellation:** not cancellable
- **Windows path:** Reproduce. Flagged here because it silently edits stored user-visible content; it is an ordinary parity quirk rather than a destructive or security-sensitive behavior, so it needs no escalation.
- **Verify by:** restart test with an em dash inside a fenced code block in a reply

### PR-CHAT-190 - An image more than 2000 pixels on its longest side is sent to providers as an orientation-corrected JPEG at quality 0.8
- **Source:** DroppyCode/Core/Models/Timeline.swift:113-114 `/// The longest side a photo may keep on its way to a provider.` `private static let maxPixelSize = 2000` | DroppyCode/Core/Models/Timeline.swift:116-119 the doc comment: a JPEG of the image at no more than maxPixelSize on its longest side, or nil for an image already that small or one ImageIO cannot read, which keeps its own bytes; the thumbnail is generated with its transform applied, so an orientation flag does not reach the provider as a sideways photo | DroppyCode/Core/Models/Timeline.swift:120-125 `guard let source = CGImageSourceCreateWithData(data as CFData, nil), let properties = CGImageSourceCopyPropertiesAtIndex(source, 0, nil) as? Int, max(width, height) > maxPixelSize else { return nil }` | DroppyCode/Core/Models/Timeline.swift:126-130 `kCGImageSourceCreateThumbnailFromImageAlways: true`, `kCGImageSourceCreateThumbnailWithTransform: true`, `kCGImageSourceThumbnailMaxPixelSize: maxPixelSize`
- **Preconditions:** A message with image attachments is being sent through the ACP, Claude or OpenAI-compatible session.
- **Action:** base64Images prepares each image.
- **Expected:** The pixel width and height are read from the properties of the image at index 0. If either cannot be read, or the longer of the two is 2000 or less, nothing is re-encoded and the original bytes are used; an image exactly 2000 pixels on its longest side is sent as it is. Otherwise a thumbnail of the image at index 0 is created from the full image (always, not from an embedded thumbnail), with its orientation transform applied, no more than 2000 pixels on its longest side, and encoded as a single-image JPEG (public.jpeg) at lossy compression quality 0.8. If the thumbnail or the JPEG cannot be produced, the original bytes are used.
- **Side effects:** The image is decoded and re-encoded in memory; nothing is written to disk
- **Persistence:** None; the attachment file on disk and the stored Attachment are untouched.
- **Failure cases:** An image that cannot be read or decoded falls back to its original bytes and mime type, silently.; A failed JPEG encode falls back to the original bytes and mime type, silently.
- **Cancellation:** not cancellable
- **Windows path:** Windows needs a decoder that reads the pixel dimensions and the orientation flag, an orientation-aware resize to at most 2000 pixels on the longest side that keeps the aspect ratio, and a JPEG encoder at quality 0.8 (for example Windows Imaging Component). The comparison is strictly greater than 2000.
- **Verify by:** unit over fixture images: 2000 by 1000 (original bytes and mime), 2001 by 1000 and 4000 by 3000 (JPEG, longest side at most 2000, mime image/jpeg), a photo with a rotating orientation flag (upright JPEG) and a corrupt file (original bytes)
