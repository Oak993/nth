### PR-SETTINGS-104 - Keyboard shortcut overrides persist as one JSON blob under "keyboardShortcuts", storing only what was changed
- **Source:** DroppyCode/Core/Models/Shortcuts.swift:239 comment - "Only changed chords are stored; a stored empty chord means the shortcut was cleared." | DroppyCode/Core/Models/Shortcuts.swift:245-249 - `private struct Override: Codable, Hashable { var chord: KeyChord? }` and `private static let defaultsKey = "keyboardShortcuts"` | DroppyCode/Core/Models/Shortcuts.swift:259-265 - overrides didSet encodes [String: Override] with JSONEncoder and writes it to UserDefaults.standard | DroppyCode/Core/Models/Shortcuts.swift:267-274 init - decodes [String: Override] from the stored Data, or starts empty
- **Preconditions:** The Shortcuts page is showing.
- **Action:** The user records, clears or resets a shortcut.
- **Expected:** A dictionary keyed by the shortcut's raw value, holding an Override whose chord is either the new chord or nil. Recording a chord equal to the shipped default removes the override entirely rather than storing it, so the store only ever names genuinely customised commands. Clearing a shortcut stores an override whose chord is nil, which is what distinguishes 'cleared' from 'default'. The whole dictionary is re-encoded and written on every change. It is written to the standard defaults suite directly, not through the settings store's suite.
- **Side effects:** One defaults write per change
- **Persistence:** UserDefaults.standard, key "keyboardShortcuts", JSON Data.
- **Failure cases:** Stored data that fails to decode: the store starts empty, so every shortcut falls back to its default, and the next change overwrites the blob.
- **Cancellation:** not cancellable
- **Windows path:** The stored contents cannot be carried over: keyCode values are macOS virtual key codes and modifiers are raw NSEvent.ModifierFlags bits. The port defines its own chord format over Windows virtual-key codes and starts from defaults; this is a recorded, deliberate incompatibility, not a translation. Keep the same key name, the same 'absent means default, present-with-null means cleared' three-state model, and the same 'equal to default removes the override' rule.
- **Verify by:** unit test over the three states; restart test; explicit test that a macOS blob is discarded rather than misread
