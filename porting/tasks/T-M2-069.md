### PR-TERM-089 - The continuation is resumed exactly once however many callbacks race for it
- **Source:** DroppyCode/Core/Support/Shell.swift:218-243 final class OnceContinuation - a Mutex-guarded optional continuation (:223 private let continuation: Mutex<CheckedContinuation<Value, Error>?>); resume(returning:) and resume(throwing:) both go through take(), which returns the stored continuation and nils it inside withLock (defer { continuation = nil }); the doc comment at :220-221 says it is taken out under the lock and resumed outside it, since a resume runs whatever the awaiting task does next and withLock is non-reentrant | DroppyCode/Core/Support/Shell.swift:73-75 and :86-89 - the termination handler and the launch-failure path both resume the same OnceContinuation
- **Preconditions:** A process launch is in flight.
- **Action:** The termination handler fires while the launch path is also resuming, or vice versa.

- **Persistence:** None.
- **Cancellation:** not cancellable

As the B2 doc comment at DroppyCode/Core/Support/Shell.swift:220-221 says, the continuation is taken out under the lock and resumed outside it, since a resume runs whatever the awaiting task does next and the lock is non-reentrant.
- **Verify by:** unit test resuming twice

### PR-TERM-091 - Shell.run(tool:) has no outputLimit parameter, so a tool run by name always keeps its whole output
- **Source:** DroppyCode/Core/Support/Shell.swift:120-133 - the tool overload takes in, environment, input and timeout but no outputLimit, and the forwarded call at :132 passes none, so the URL overload's nil default applies
- **Preconditions:** A caller uses the by-name overload.

- **Persistence:** None.
- **Cancellation:** not cancellable

- **Verify by:** unit test asserting the forwarded arguments

### PR-TERM-093 - Any command containing a greater-than sign, a dollar-parenthesis or a backtick is a writer outright
- **Source:** DroppyCode/Core/Support/Shell.swift:167-169 - the comment: redirection writes whatever the tool in front of it does, and a substitution hides a command this cannot see; then guard !command.contains(">"), !command.contains("$("), !command.contains("`") else { return true }
- **Preconditions:** A command text is being classified.
- **Action:** The three substring tests run.
- **Expected:** The presence of any of the three anywhere in the text, including inside quotes, inside a comparison such as `test 1 > 2`, or as part of `2>&1`, makes the answer true immediately without any further analysis. `>>` matches too because it contains `>`. A `${VAR}` expansion does NOT match, because the test is for `$(` specifically.
- **Persistence:** None.
- **Failure cases:** A read-only command that merely mentions a greater-than sign is classified as a writer, which is the safe direction and is deliberate.
- **Cancellation:** not cancellable
- **Windows path:** Same three literal substring tests, in this order, before anything else.
- **Verify by:** unit test over each trigger and over the non-matching ${VAR} case

- **Action:** The rule runs.
- **Expected:** Only arguments that begin with a dash are skipped, not the values some of them take: `git --no-pager log` classifies on "log", but in `git -C /tmp status` the first non-dash argument is "/tmp", which is not in the table, so that part is a writer.
