### PR-THEME-125 - A streaming text is recognised as an extension of an earlier one by comparing 64 byte head and tail probes, not the whole text
- **Source:** DroppyCode/UI/Markdown/MarkdownView.swift:150-167 extends(_:to:): requires the earlier text to be non-empty and strictly shorter; for texts of 128 bytes or fewer it compares the full prefix; otherwise it compares the first 64 bytes and the 64 bytes of the new text ending where the earlier text ended
- **Preconditions:** A flush arrives for a streaming message.
- **Action:** The renderer looks for the slot holding the previous parse.
- **Expected:** A text of 128 bytes or fewer is tested by a real prefix comparison. A longer one is accepted as an extension when its first 64 bytes match and the 64 bytes ending at the earlier text's length match the earlier text's last 64 bytes. This is a probabilistic test: a text that matches both probes but differs in the middle would be wrongly treated as an extension, reusing stale stable blocks.
- **Persistence:** not persisted
- **Failure cases:** A rewrite that preserves both probes reuses the wrong stable blocks. No guard exists against this; it is the shipped behaviour.
- **Cancellation:** not cancellable
- **Windows path:** Byte probes, not character probes. A port that compares whole texts is slower but strictly safer; because the difference is observable only in a case upstream never hits, reproduce the probe as written.
- **Verify by:** unit: the 128 byte boundary and both probe positions
