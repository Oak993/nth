## Requirements

### PR-THEME-099 - A bullet marker is a dash, asterisk or plus followed by a space or tab; an ordered marker is up to nine digits then a dot or a bracket
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:272-289 `listMarker(_ line:)`: for the first non-indent character in "-*+", the rest must start with a space or tab; the content is the rest with leading spaces and tabs dropped; contentOffset is indent + 2. Otherwise the leading digits must be non-empty and at most 9, the next character must be '.' or ')', and what follows must start with a space or be empty; the content is the remainder with leading spaces dropped; the start number is the digits as an integer or 1; contentOffset is indent + digit count + 2 | DroppyCode/UI/Markdown/MarkdownParser.swift:291-297 `indentation(_ line:)`: a space counts 1, a tab counts 4, anything else stops the count
- **Preconditions:** A line is being tested for a list item.
- **Action:** The parser reads its marker.
- **Expected:** Indentation is measured with tabs worth four spaces. An unordered marker is one of dash, asterisk or plus followed immediately by a space or a tab; a marker followed by any other character is not a marker. An ordered marker is one to nine digits followed by a dot or a closing bracket, then a space or the end of the line, so "1." alone on a line is an item with empty content. Ten or more digits is not a marker. The start number of the list is the first item's digits.
- **Persistence:** not persisted
- **Failure cases:** Not a marker: the line becomes paragraph text.
- **Cancellation:** not cancellable
- **Windows path:** Note the asymmetry: an unordered marker accepts a tab after it, an ordered one accepts only a space or nothing.
- **Verify by:** unit: "-x", "-\tx", "1.x", "1234567890. x", "1."

### PR-THEME-100 - A list starts only at a paragraph boundary, or for an unordered marker, or for an ordered list beginning at 1
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:170 `if depth < maxDepth, let marker = listMarker(line), paragraph.isEmpty || !marker.ordered || marker.start == 1`
- **Preconditions:** A line carries a list marker while a paragraph is being accumulated.
- **Action:** The parser decides whether to start a list.
- **Expected:** A list starts when no paragraph is open, or when the marker is unordered, or when it is an ordered marker whose number is 1. An ordered marker with a number other than 1 that appears in the middle of a paragraph does not start a list and stays as paragraph text, which is what keeps a sentence ending in "...in 2020. Next" from becoming a list.
- **Persistence:** not persisted
- **Failure cases:** None; the line falls through to the paragraph.
- **Cancellation:** not cancellable
- **Windows path:** Reproduce the three-part condition exactly; simplifying it changes how ordinary prose renders.
- **Verify by:** unit: a paragraph line followed by "2. text" stays one paragraph; the same after a blank line becomes a list starting at 2

### PR-THEME-101 - List items absorb following lines as continuation text or as nested child blocks, and a list ends when its kind changes
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:195-262 parseList: a marker at or above the first item's indent starts a new item, but only when its ordered flag matches the first item's, otherwise the list ends; a line indented past the first item's indent is dropped by the smaller of its indentation and the item's content offset and appended to the child lines, unless the child lines are still empty and the line is neither a marker nor a fence, in which case its trimmed form continues the item's own text; an unindented line continues the item's text only while there are no child lines and it is not a heading, a fence or a quote; anything else ends the list | DroppyCode/UI/Markdown/MarkdownParser.swift:222-234 a blank line is skipped when the next line is indented past the item (recorded as an empty child line) or when the next line is a sibling marker of the same indent and kind; otherwise it ends the list | DroppyCode/UI/Markdown/MarkdownParser.swift:214 each item's children are `parse(childLines[...], depth: depth + 1).blocks`
- **Preconditions:** A list has started.
- **Action:** The parser reads the lines after the first marker.
- **Expected:** Sibling items are markers at the same or a smaller indent with the same ordered flag; a marker of the other kind ends the list rather than continuing it. Indented lines become the item's nested blocks, parsed one level deeper, except that indented prose arriving before any nested block simply continues the item's text. Unindented lines continue the item's text only until the item has nested blocks, and never when they are a heading, a fence or a quote. A blank line does not end the list when the next line either is indented content or is a sibling marker; otherwise it does.
- **Persistence:** not persisted
- **Failure cases:** None expressed in source; every line either continues, nests or ends the list.
- **Cancellation:** not cancellable
- **Windows path:** This is the most intricate part of the grammar and the part a CommonMark library will get differently. It must be ported rule by rule and covered by fixtures.
- **Verify by:** contract fixture: a list corpus covering loose lists, nested code, mixed markers and blank lines

### PR-THEME-102 - A list item beginning "[ ] " or "[x] " becomes a checkbox item, case-insensitively for x, and the marker is removed from its text
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:203-217 flushItem: the item's joined text is whitespace-trimmed, then `if text.hasPrefix("[ ] ") { checked = false; text.removeFirst(4) } else if text.lowercased().hasPrefix("[x] ") { checked = true; text.removeFirst(4) }`
- **Preconditions:** A list item's text has been gathered.
- **Action:** The parser finalises the item.
- **Expected:** An item whose text begins with exactly "[ ] " is unchecked; one beginning with "[x] " or "[X] " is checked. In both cases the first four characters are removed from the text. Any other bracket form, including "[]" with no space and "[ ]" with no following space, is left as ordinary text with no checkbox.
- **Persistence:** not persisted
- **Failure cases:** No match: checked stays absent and the item renders with its normal marker.
- **Cancellation:** not cancellable
- **Windows path:** Note the lower-casing is applied to the whole item text just to test the prefix, which is wasteful but harmless; only the prefix test is case-insensitive, the removal is a fixed four characters.
- **Verify by:** unit: "[ ] a", "[x] a", "[X] a", "[] a", "[ ]a"

### PR-THEME-103 - Paragraph lines accumulate until a blank line or another block starts, and a paragraph that trims to nothing is dropped
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:86-93 flushParagraph: `let text = paragraph.joined(separator: "\n").trimmed`; `if !text.isEmpty { blocks.append(.paragraph(text)); blockLines.append(paragraphStart) }`; `paragraph.removeAll()` | DroppyCode/Core/Support/Text.swift:222-224 `var trimmed: String { trimmingCharacters(in: .whitespacesAndNewlines) }` | DroppyCode/UI/Markdown/MarkdownParser.swift:99-103 a blank line flushes the paragraph | DroppyCode/UI/Markdown/MarkdownParser.swift:179-181 otherwise the raw (untrimmed) line is appended and the paragraph's start line is recorded on the first one
- **Preconditions:** A line is not any other block.
- **Action:** The parser accumulates it.
- **Expected:** Lines are kept with their original leading and trailing whitespace and joined with newlines; the joined text is then trimmed at both ends. A paragraph of only whitespace produces no block at all. Interior line breaks are preserved in the paragraph's text and are resolved later by the inline layer.
- **Persistence:** not persisted
- **Failure cases:** Whitespace-only paragraph: no block.
- **Cancellation:** not cancellable
- **Windows path:** Interior newlines survive into the block text; the inline parse is asked to preserve whitespace (PR-THEME-124), so soft line breaks inside a paragraph are real breaks in the rendered text.
- **Verify by:** unit: a two-line paragraph keeps its newline; a whitespace-only line produces nothing

### PR-THEME-104 - Line trimming takes a fast path for lines that begin and end with printable ASCII
- **Source:** DroppyCode/UI/Markdown/MarkdownParser.swift:264-270 `trimmed(_ line:)`: when the first and last UTF-8 bytes are both above 0x20 and below 0x7F the line is returned as it is; otherwise it is whitespace-trimmed
- **Preconditions:** A line is about to be tested.
- **Action:** The parser trims it.
- **Expected:** A line whose first and last bytes are printable ASCII other than space is used unchanged. Any other line is trimmed of the whitespace character set, which includes Unicode spaces. The fast path is observably equivalent because a leading byte above 0x20 and below 0x7F cannot be a space, a tab or the lead byte of a Unicode space.
- **Persistence:** not persisted
- **Failure cases:** An empty line has no first byte and takes the slow path, which returns an empty string.
- **Cancellation:** not cancellable
- **Windows path:** The fast path is an optimization with no behavioural difference; a port may trim unconditionally, but must trim the full Unicode whitespace set, not just ASCII.
- **Verify by:** unit: a line surrounded by U+00A0 is trimmed; an ASCII line is returned identically
