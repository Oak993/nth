### PR-PROVAPI-151 - A vision model receives at most four images as base64 data URLs after the text part, with any image over 2000 px downscaled to a JPEG

- **Preconditions:** Image attachments with a vision model selected.
- **Action:** The user message is built.
- **Expected:** The content is an array whose first element is the text part and whose following elements are up to four image_url parts carrying data URLs of the form data:<mime type>;base64,<base64 payload>. A fifth and later image is dropped before anything is read. An attachment whose bytes cannot be read is skipped silently. An image whose width or height is greater than 2000 pixels is sent as a JPEG re-encoded at lossy quality 0.8, at most 2000 pixels on its longest side, with its orientation transform applied, and its data URL reads data:image/jpeg;base64,<payload>. - **Side effects:** Up to four image files are read and base64 encoded off the main actor; An image over 2000 pixels on its longest side is decoded, downscaled and re-encoded as a JPEG in memory once per message build; the file on disk is not changed

- **Cancellation:** not cancellable
- **Windows path:** Same cap of four, same part ordering and the same data URL grammar. The downscale uses the Windows Imaging Component in place of ImageIO with the same rule: only when max(width, height) > 2000, longest side scaled to at most 2000, EXIF orientation applied, JPEG at quality 0.8, and the MIME type becomes image/jpeg only when the re-encode succeeded; otherwise the original bytes and MIME type are sent. The two encoders are not expected to produce identical JPEG bytes; the fixture checks dimensions, orientation, MIME type and decodability, not bytes.
- **Verify by:** contract fixture on the request body: a 1000x800 PNG is sent unchanged as data:image/png; a 4000x3000 JPEG and a 3000x4000 JPEG carrying EXIF orientation 6 are each sent as data:image/jpeg whose decoded longest side is at most 2000 px and whose pixels are upright; a file with an image MIME type that no decoder can read is sent with its own bytes and MIME type; with five images attached only the first four appear
