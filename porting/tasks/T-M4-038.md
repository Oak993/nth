### PR-PROVCLI-327 - Antigravity interrupt sets the stopping flag before killing, so the chat does not read an unexpected exit
- **Source:** DroppyCode/Services/Providers/AntigravitySession.swift:166-178 - interrupt() with the comments at :169-176 | porting/port_impacts.md entry 24
- **Preconditions:** turnActive is true.
- **Action:** The user stops the turn.
- **Expected:** With no active turn nothing happens. Otherwise interruptRequested is set, THEN isStopping is set, THEN the process is terminated. The ordering matters: without isStopping, didClose would follow the interrupted turn with an .exited event and the chat would read that Antigravity stopped unexpectedly every time the user stopped a turn. There is NO interrupt message, because the stream has none; stopping the process ends the turn and the conversation persists server-side for the next turn's --conversation resume. start() clears isStopping again for the next launch.
- **Side effects:** Process termination
- **Persistence:** The conversation persists server-side.
- **Failure cases:** none
- **Cancellation:** This IS the cancellation path.
- **Windows path:** TerminateProcess behaves like SIGKILL, which is acceptable because the source already relies only on server-side persistence and nothing is flushed on the signal. The FLAG-BEFORE-KILL ORDERING must be preserved so the chat does not read an unexpected exit (port_impacts.md entry 24).
- **Verify by:** interaction test asserting no .exited event follows an interrupt
