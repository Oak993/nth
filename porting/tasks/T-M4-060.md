### PR-PROVCLI-105 - Codex parses a reset date as epoch seconds, epoch milliseconds above 1e10, or ISO 8601
- **Source:** DroppyCode/Services/Providers/CodexSession.swift:461-472 - resetDate: a double or a numeric string, rejecting values that are not greater than zero, dividing by 1000 when above 10000000000; otherwise ISO8601 with fractional seconds, falling back to plain ISO8601
- **Preconditions:** A credit expiry value.
- **Action:** resetDate parses it.
- **Expected:** A nil value yields nil. A double, or a string that parses as a double, is rejected when it is not greater than zero; otherwise it is treated as epoch MILLISECONDS when greater than 10000000000 (divided by 1000) and epoch SECONDS otherwise. A non-numeric string is parsed first with ISO8601DateFormatter using [.withInternetDateTime, .withFractionalSeconds], then, on failure, with a default ISO8601DateFormatter. Anything else yields nil.
- **Persistence:** none
- **Failure cases:** An unparseable value yields nil and the credit simply has no expiry.
- **Cancellation:** not cancellable
- **Windows path:** ISO 8601 parsing must be culture-invariant on Windows; a locale-aware date parser would accept or reject different strings.
- **Verify by:** unit test over seconds, milliseconds, a fractional ISO string, a plain ISO string and junk
