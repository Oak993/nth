## Requirements

### PR-STORE-128 - A single model item is observed through its own box so siblings never re-render it
- **Source:** DroppyCode/Core/Support/ObservedValue.swift:4-13 - doc comment "One value under its own observation. A view that reads a thread or project through its cell depends on that item alone, so a change to any other item never re-renders it." then @MainActor @Observable final class ObservedValue<Value> { var value: Value; init(_ value: Value) } | DroppyCode/App/AppModel.swift:138-140 - the project and thread cells are built once inside the initializer because property observers stay quiet there
- **Preconditions:** A list of projects or threads is on screen.
- **Action:** One item changes.
- **Expected:** Only the row reading that item’s box re-renders. The box holds exactly one property, is main-actor isolated and is created once per item. Cells are built inside AppModel.init because property observers do not fire there.
- **Persistence:** none
- **Cancellation:** not cancellable
- **Windows path:** Per-item observable boxes rather than a whole-list signal. This is the mechanism that keeps a long sidebar cheap; a port that re-renders the whole list on any change will not meet the source’s scroll behaviour.
- **Verify by:** interaction test counting row renders when one thread is renamed
