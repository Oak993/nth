### PR-WIN-121 - Fifty-seven key positions are treated as typing or caret keys that a bare or shifted chord must not steal
- **Source:** DroppyCode/Core/Models/Shortcuts.swift:75-78 the comment 'Keys that type or move the caret, which a chord without Command, Control or Option would steal from text.' and `static func typesText(_ code: Int) -> Bool { characters[code] != nil || [36, 48, 49, 51, 53, 117, 123, 124, 125, 126].contains(code) }` | DroppyCode/Core/Models/Shortcuts.swift:325-327 refusal: `if flags.subtracting(.shift).isEmpty, KeyNames.typesText(chord.keyCode) { return "Add ⌘, ⌃ or ⌥ so typing still works." }`
- **Preconditions:** The user is recording a chord.
- **Action:** They press a character key, Return, Tab, Space, Delete, Escape, forward Delete or an arrow, with no modifier or with Shift alone.
- **Expected:** Every key in the character table, plus those ten named keys, counts as typing text. Such a chord is refused unless it carries at least one of Command, Control or Option; Shift alone is not enough. Function keys, Home, End, Page Up and Page Down are NOT in this set, so F5 on its own is an acceptable chord.
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** Same predicate over the same key positions, with Ctrl, Alt or Win as the qualifying modifiers.
- **Verify by:** unit: bare F5 is accepted, bare Return and Shift-Return are refused

### PR-WIN-123 - Only changed chords are stored, under the key keyboardShortcuts, as JSON keyed by the command's raw value
- **Source:** DroppyCode/Core/Models/Shortcuts.swift:239 the doc comment 'The user's shortcuts. Only changed chords are stored; a stored empty chord means the shortcut was cleared.' | DroppyCode/Core/Models/Shortcuts.swift:245-249 `private struct Override: Codable, Hashable { var chord: KeyChord? }` and `private static let defaultsKey = "keyboardShortcuts"` | DroppyCode/Core/Models/Shortcuts.swift:259-274 the overrides didSet writing `try? JSONEncoder().encode(overrides)` to UserDefaults under that key, and the init decoding `[String: Override]` or falling back to an empty dictionary
- **Preconditions:** The user has recorded or cleared at least one chord.
- **Action:** The store mutates.
- **Expected:** The whole override dictionary is re-encoded and written on every mutation, under the exact key "keyboardShortcuts", as JSON of the shape {"<rawValue>": {"chord": {"keyCode": Int, "modifiers": UInt} | null}}. An absent entry means the default applies; a present entry with a null chord means the command was deliberately cleared and answers to nothing. A write failure is swallowed silently by the try?.
- **Persistence:** Key "keyboardShortcuts", a JSON blob, rewritten in full on every change.
- **Failure cases:** Encoding fails: nothing is written and no error is surfaced; Stored data that does not decode: the whole store falls back to empty, so every customisation is lost silently and the defaults apply
- **Cancellation:** not cancellable
- **Windows path:** The macOS blob holds raw AppKit modifier bits and macOS key codes and is unreadable on Windows, so the port defines its own chord encoding and starts from the defaults (port_impacts.md entry 110, CC1). Keep the same key name, the same per-command raw-value keys, the same rewrite-everything-on-change behavior and the same three-state semantics (absent, present-with-chord, present-with-null).
- **Verify by:** restart test over all three states; unit on the corrupt-blob fallback

### PR-WIN-124 - A command's chord is its override when one exists, otherwise its default
- **Source:** DroppyCode/Core/Models/Shortcuts.swift:276-279 `func chord(for shortcut: AppShortcut) -> KeyChord? { if let override = overrides[shortcut.rawValue] { return override.chord }; return shortcut.defaultChord }` | DroppyCode/Core/Models/Shortcuts.swift:281-283 `func keyboardShortcut(for shortcut: AppShortcut) -> KeyboardShortcut? { chord(for: shortcut)?.keyboardShortcut }`
- **Preconditions:** The store is loaded.
- **Action:** Any caller asks for a command's chord.
- **Expected:** The override wins whenever an entry exists, including when its chord is null, which yields no chord at all. Otherwise the default applies. A command with no chord carries no menu shortcut, shows no chord in the palette's column and contributes an empty string to any help hint.
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** Same two-step resolution, and every consumer must read through it live rather than caching, so a remap corrects every label at once.
- **Verify by:** unit over the three store states

### PR-WIN-125 - Recording a command's own default clears the override rather than storing it
- **Source:** DroppyCode/Core/Models/Shortcuts.swift:300-302 `func set(_ chord: KeyChord?, for shortcut: AppShortcut) { overrides[shortcut.rawValue] = chord == shortcut.defaultChord ? nil : Override(chord: chord) }`
- **Preconditions:** A command may or may not be customised.
- **Action:** The user records a chord for it.
- **Expected:** If the recorded chord equals the command's own default, the override is removed entirely, so the settings file records only real customisations and the command stops reporting itself as customised. Any other chord, including nil, is stored as an override. Note that clearing a command whose default is nil therefore also removes the entry.
- **Persistence:** Rewrites the keyboardShortcuts blob.
- **Cancellation:** not cancellable
- **Windows path:** Same rule, so a round trip back to the default leaves no residue on disk.
- **Verify by:** unit: set to the default and assert the entry is gone and isCustomized is false

### PR-WIN-126 - A command or a whole section can be reset, and customisation can be queried per command and per section
- **Source:** DroppyCode/Core/Models/Shortcuts.swift:304-310 `func reset(_ shortcut: AppShortcut) { overrides[shortcut.rawValue] = nil }` and `func reset(_ section: AppShortcut.Section) { for shortcut in section.shortcuts { overrides[shortcut.rawValue] = nil } }` | DroppyCode/Core/Models/Shortcuts.swift:312-318 `func isCustomized(_ shortcut: AppShortcut) -> Bool { overrides[shortcut.rawValue] != nil }` and `func hasCustomizations(in section: AppShortcut.Section) -> Bool { section.shortcuts.contains(where: isCustomized) }`
- **Preconditions:** Some commands may be customised.
- **Action:** A reset is requested, or the settings page asks whether to offer one.
- **Expected:** Resetting a command removes its entry, so its default applies again. Resetting a section removes every entry in that section, one write per command because each assignment triggers the persisting observer. A command counts as customised whenever an entry exists, including a cleared one. A section counts as having customisations when any of its commands does.
- **Persistence:** Each removal rewrites the whole keyboardShortcuts blob.
- **Cancellation:** not cancellable
- **Windows path:** Same four operations. The per-command write amplification on a section reset is harmless but should be reproduced or coalesced knowingly, not by accident.
- **Verify by:** unit over all four operations including a cleared chord counting as customised
