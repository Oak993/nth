### PR-TERM-117 - Nothing about a terminal session survives a restart: tabs, scrollback, selection and running shells are all per-run
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:106-107 - sessions and selection are plain in-memory dictionaries with no persistence | DroppyCode/App/Views/Terminal/TerminalStore.swift:1-176 - the file writes nothing to disk and reads nothing from disk | DroppyCode/App/Runtime/ThreadRuntime.swift:239 - isTerminalVisible defaults to false on every new runtime | DroppyCode/App/AppSettings.swift:301-303 and :722 - terminalHeight is the only persisted value in this area
- **Preconditions:** The app is quit with several terminals open.
- **Action:** The app is relaunched.
- **Expected:** Every thread starts with no sessions and a hidden drawer. Opening the drawer spawns one fresh shell. Scrollback, tab names beyond the regenerated "Terminal 1", and which tab was selected are all gone. The ONLY thing restored is the drawer height, under the key "terminalHeight".
- **Persistence:** terminalHeight only.
- **Cancellation:** not cancellable
- **Windows path:** Same. Do not add session restoration; that would be new behaviour.
- **Verify by:** restart test

### PR-TERM-123 - A script tab launches the shell with exactly four arguments whose fourth is the command interpolated unquoted, followed by an exec back into a login shell
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:37-39 - if let command { arguments = ["-l", "-i", "-c", "\(command); exec \(shell) -l"] } | DroppyCode/App/Views/Terminal/TerminalStore.swift:28 - shell = LoginEnvironment.userShell(), the same value that is interpolated into the fourth argument and used as the executable | DroppyCode/App/Views/Terminal/TerminalStore.swift:40 - args: arguments
- **Preconditions:** A session is being created with a startup command.
- **Action:** TerminalSession.init runs.
- **Expected:** The arguments are exactly ["-l", "-i", "-c", <fourth>] in that order, four elements, never three and never five. The fourth is built by string interpolation as the command, then "; exec ", then the SHELL'S OWN ABSOLUTE PATH, then " -l": the same path used as the executable, not the bare shell name. Neither the command nor the path is quoted or escaped, so the command runs as written and a shell path containing a space would break the exec. The trailing exec replaces the shell with a fresh login shell instead of letting the tab exit when the script finishes, and it runs whether the command succeeded or failed, because the two are joined by a semicolon rather than by &&.
- **Side effects:** The command runs with the user's full login environment and profile, in the project directory
- **Persistence:** None.
- **Failure cases:** A command containing an unbalanced quote, a stray semicolon or a trailing backslash changes what the composed line means; the source does no escaping and this is reproduced; A shell path containing a space breaks the exec and the tab exits when the script ends; The command failing does not stop the exec: the tab still becomes an interactive shell
- **Cancellation:** The user can interrupt the running command with the shell's own keys; the app offers no cancel control.
- **Windows path:** PLATFORM BOUNDARY. The four-element vector is POSIX shell syntax and the -l/-i/-c triple has no direct equivalent in cmd.exe or PowerShell. The intent to preserve is: run the script, then leave an interactive shell in the same tab, with the command interpolated as written. The concrete vector depends on the interpreter chosen under UNK-0005.
- **Verify by:** contract fixture asserting the four-element vector and the exact fourth element for a command containing a space and a quote
- **Depends on UNK-0005**, which is unresolved. Implement only the part the source settles; flag the rest.
