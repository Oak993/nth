### PR-PROVACP-027 - One auth retry, triggered by the substring auth in the RPC error message
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:134-140 - `do { session = try await openSession(connection) } catch let error as RPCError where error.message.localizedCaseInsensitiveContains("auth") && !authMethods.isEmpty { _ = try await connection.request("authenticate", ["methodId": .string(authMethods[0])]); session = try await openSession(connection) }`
- **Preconditions:** The first openSession threw an RPCError whose message contains "auth" case-insensitively, and authMethods is non-empty.
- **Action:** ACPSession authenticates and retries the session open.
- **Expected:** It sends method "authenticate" with the single parameter methodId set to authMethods[0], the FIRST advertised method, with no user choice and no preference ordering. It then retries openSession exactly once. A non-RPCError, an RPCError without "auth" in its message, or an empty authMethods list all skip the retry and the error propagates out of start(). The substring match is on the message only, not on the error code.
- **Side effects:** One authenticate request; a second session/new or session/load.
- **Persistence:** None.
- **Failure cases:** The authenticate request itself is `try await`, not `try?`: its failure propagates out of start() and the session never opens.; The retried openSession's failure propagates; there is no third attempt.; A provider whose unrelated error text happens to contain the letters "auth" (for example "author") triggers a spurious authenticate.
- **Cancellation:** Cancellation of the awaiting task surfaces as CancellationError from the pending request.
- **Windows path:** Same. Use a case-insensitive indexOf on the message string; do not switch to a code check.
- **Verify by:** contract fixture (scripted agent that rejects the first session/new with an auth message, then accepts)

### PR-PROVACP-030 - Every session/update is dropped while a load is replaying
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:258,260 - `isReplaying = true` before the session/load request and `isReplaying = false` after it returns | DroppyCode/Services/Providers/ACPSession.swift:490 - `guard method == "session/update", !isReplaying, let update = params["update"] else { return }`
- **Preconditions:** A session/load request is in flight.
- **Action:** The agent streams the stored transcript as session/update notifications.
- **Expected:** Every one of those notifications is discarded: no message deltas, no tool rows, no todos, no model or mode events are emitted for the replay. The flag is cleared as soon as the load request returns, so updates arriving after the reply are processed normally.
- **Persistence:** None.
- **Failure cases:** An agent that streams part of the replay after the reply will have those trailing updates rendered; the source has no sequence guard beyond the in-flight window.
- **Cancellation:** If the load throws, isReplaying is still cleared at :260 before the fallthrough.
- **Windows path:** Same flag, same window.
- **Verify by:** contract fixture (scripted replay; assert zero timeline events)
