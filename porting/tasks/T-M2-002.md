### PR-RUNTIME-264 - FileChangeSummary is stored with Swift's synthesized keys: per-file path, additions, deletions and isBinary, plus files and the two totals
- **Source:** DroppyCode/Core/Models/FileChangeSummary.swift:3-15 - the comment "What a turn changed, file by file, as the timeline and the changes tab show it."; struct FileChangeSummary: Codable, Hashable, Sendable { struct File: Codable, Hashable, Sendable { var path: String; var additions: Int; var deletions: Int; var isBinary: Bool }; let files: [File]; let additions: Int; let deletions: Int } | DroppyCode/Core/Support/Coding.swift:19-25 JSONEncoder.storage - .iso8601 dates, .sortedKeys
- **Preconditions:** A turn ends, or a stored turn is shown.
- **Action:** The turn-end row's summary is written or read.
- **Expected:** FileChangeSummary uses Swift's synthesized Codable and Hashable, so it is stored with exactly the keys files, additions and deletions, and each file with exactly path, additions, deletions and isBinary. Every key is required on decode, and the totals are stored as given (the memberwise init; the summing init(files:) is PR-GIT-092). Where it is stored: TurnSummary.changes on the turn-end row, PR-CHAT-012. Who writes it: finishTurn, PR-RUNTIME-121; install's nil marker, PR-RUNTIME-161; the legacy back-fill, PR-RUNTIME-200. A summary that fails to decode fails its TimelineItem, which ThreadDocument drops through Lenient (Timeline.swift:356-365, PR-CHAT-019); the thread still opens.
- **Persistence:** Inside ThreadDocument.items as TurnSummary.changes (PR-CHAT-012); this record fixes only the summary's own keys.
- **Cancellation:** not cancellable
- **Windows path:** Keep these key names; the thread file is the compatibility surface for an existing installation. How the summary is computed from a diff is PR-GIT-092.
- **Verify by:** contract fixture - encode a two-file summary, one of them binary, with JSONEncoder.storage, assert the exact bytes and keys, and decode it back equal
