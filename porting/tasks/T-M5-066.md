## Requirements

### PR-THEME-078 - Chimes are synthesized to a 16-bit mono WAV in memory; no sound file ships with the app
- **Source:** DroppyCode/UI/Sound/ToneSynth.swift:3-5 doc: "Renders a short struck tone to 16-bit mono WAV data, so the app's chimes ship as a few numbers rather than sound files and stay tunable right where they are declared." | DroppyCode/UI/Sound/ToneSynth.swift:21 `private static let sampleRate = 44_100.0` | DroppyCode/UI/Sound/ToneSynth.swift:48-68 the hand-written RIFF header and the sample loop
- **Preconditions:** The app is running.
- **Action:** A chime is needed for the first time.
- **Expected:** The tone is generated as a byte buffer: a canonical 44 byte RIFF/WAVE header followed by signed 16-bit little-endian mono samples at 44100 Hz. No audio asset is read from disk.
- **Side effects:** Allocates the rendered buffer once and keeps it for the app's lifetime
- **Persistence:** not persisted
- **Failure cases:** None expressed in source: the synthesis has no failure branch.
- **Cancellation:** not cancellable
- **Windows path:** Synthesize the same PCM and hand it to the Windows audio stack. Shipping a pre-rendered .wav asset produced by this same algorithm is acceptable only if it is bit-identical; the tuning constants stay in code either way.
- **Verify by:** contract fixture: the generated buffer's bytes for both chimes are checked against a recorded golden buffer

### PR-THEME-079 - The tone generator sums notes of exponentially decaying partials over a raised-cosine attack
- **Source:** DroppyCode/UI/Sound/ToneSynth.swift:7-19 Note (frequency, onset, level) and Partial (multiple, level, decay) | DroppyCode/UI/Sound/ToneSynth.swift:22-23 `private static let attack = 0.006` with the comment "A raised-cosine onset: quick enough to feel struck, with no click." | DroppyCode/UI/Sound/ToneSynth.swift:27-40 the loop: `let count = Int(sampleRate * duration)`; per note `let start = Int(note.onset * sampleRate)`; for each index from start, `time = Double(index - start) / sampleRate`, `onset = time < attack ? 0.5 - 0.5 * cos(.pi * time / attack) : 1`, `tone = sum over partials of partial.level * exp(-time / partial.decay) * sin(2 * .pi * note.frequency * partial.multiple * time)`, `samples[index] += note.level * onset * tone`
- **Preconditions:** A note list, a partial list and a duration are given.
- **Action:** The tone is rendered.
- **Expected:** The buffer holds floor(44100 times duration) samples. Each note starts at floor(onset times 44100) and runs to the end of the buffer. Within a note, the envelope is 0.5 minus 0.5 times cos(pi times t / 0.006) for the first 6 milliseconds and 1 afterwards. The note's timbre at time t is the sum over its partials of level times exp(-t / decay) times sin(2 pi f multiple t), where f is the note's own frequency. Notes are summed into the same buffer, so overlapping notes add.
- **Persistence:** not persisted
- **Failure cases:** None expressed in source.
- **Cancellation:** not cancellable
- **Windows path:** Pure arithmetic; port it directly in double precision. The partial set is shared by every note of a chime, not per note.
- **Verify by:** unit: sample-by-sample comparison against the formula for a known note and partial list

### PR-THEME-080 - Every rendered tone gets an 80 millisecond linear tail fade and is normalized to 0.9 of full scale
- **Source:** DroppyCode/UI/Sound/ToneSynth.swift:24-25 `private static let release = 0.08` with the comment "The tail is inaudible by the end; the fade makes sure it stops without a tick." | DroppyCode/UI/Sound/ToneSynth.swift:41-44 `let fade = Int(release * sampleRate)` then `for index in (count - fade)..<count { samples[index] *= Double(count - index) / Double(fade) }` | DroppyCode/UI/Sound/ToneSynth.swift:45-46 `let peak = samples.reduce(0) { max($0, abs($1)) }` and `let scale = peak > 0 ? 0.9 / peak : 0` | DroppyCode/UI/Sound/ToneSynth.swift:66-67 `append(Int16((sample * scale * Double(Int16.max)).rounded()))`
- **Preconditions:** The sample buffer has been filled.
- **Action:** The tone is finished and written out.
- **Expected:** The last 3528 samples (0.08 seconds at 44100 Hz) are multiplied by a linear ramp falling from 1 to just above 0. The whole buffer is then scaled so its loudest sample is exactly 0.9 of full scale; a silent buffer scales to zero rather than dividing by zero. Samples are converted with round-half-away-from-zero to signed 16-bit using 32767 as full scale, so the peak sample is 29490.
- **Persistence:** not persisted
- **Failure cases:** An all-zero buffer produces silence, not a division by zero.
- **Cancellation:** not cancellable
- **Windows path:** The normalization means the declared per-note levels set the balance between notes, not the absolute loudness; the absolute loudness comes only from the per-chime volume (PR-THEME-081, PR-THEME-082).
- **Verify by:** unit: peak sample equals 29490 for both chimes; the last sample is near zero
