### PR-RUNTIME-192 - A finished command settles by diffing two trees, filtering build output and paths another row already claimed
- **Source:** DroppyCode/App/Runtime/ThreadRuntime.swift:3383-3413 settleCommand - guard let before = commandTrees.removeValue(forKey: id), let git = repositoryGit else { return }; the settle task awaits the before tree, captures an after tree, sets latestTree, and when treeEpoch still matches and both watch maps are empty records settledTree; returns when base equals after or the changed paths cannot be read; filters out empty paths, TouchedPaths.isBuildOutput paths and paths already attributed to another row of the same turn; returns when nothing real is left or the patch is empty; builds one FileEdit per file; guard !edits.isEmpty, the row is still a tool row, and call.edits.allSatisfy({ $0.diff == nil }) before replacing call.edits; then if entry.turnID == currentTurnID { recordCurrentTurnEdits(edits) }; then entry.item.content = .tool(call), saveRevision += 1, noteHydraHeadEvent(edits:) and scheduleSave() | DroppyCode/App/Runtime/ThreadRuntime.swift:3396-3399 - the comment: a head that builds in its copy once put 7,632 edits and 7 MB on two rows
- **Preconditions:** A watched command reached a terminal status, or the turn is finishing.
- **Action:** settleCommand(_:) runs.
- **Expected:** Exactly this sequence. The diffed edits are also recorded into hydraCurrentTurnTouchedPaths (PR-RUNTIME-255) only when the row belongs to the current turn; a row of an earlier turn gets its edits without touching that set. Build-output paths are excluded by name before any diff is taken, so they never reach the row or a merge. Paths another row of the turn already carries stay on that row and still count for the turn. A provider that did report its own edits with patches keeps them: the replacement only happens when every existing edit has a nil diff.
- **Side effects:** Git snapshots and diffs; the tool row gains edits; hydraCurrentTurnTouchedPaths grows when the row is of the current turn; a save is scheduled.
- **Persistence:** ToolCall.edits inside ThreadDocument.items.
- **Failure cases:** Any git failure returns silently and the row simply gets no edits.
- **Cancellation:** The settle task is raced against three seconds by a non-completed finishTurn (PR-RUNTIME-114).
- **Windows path:** Platform boundary: capturing a tree is several git processes over the whole checkout and is markedly slower on Windows; the serialization in PR-RUNTIME-194 matters more there, not less.
- **Verify by:** integration test against a real repository
