## Requirements

### PR-TERM-035 - The frame sync is skipped unless the hosted view is still this container's subview and the bounds are non-zero and different
- **Source:** DroppyCode/App/Views/Terminal/TerminalPanel.swift:437-442 syncFrame - guard let hostedView, hostedView.superview === self; then guard bounds.width > 0, bounds.height > 0, hostedView.frame != bounds; only then hostedView.frame = bounds
- **Preconditions:** A sync beat or finishResize fires.
- **Action:** syncFrame runs.
- **Expected:** Nothing happens if the hosted view has been reparented to another container, if either bound is zero, or if the frame already equals the bounds. Otherwise the frame is set to the container bounds, which is the single action that triggers the terminal's re-wrap.
- **Side effects:** At most one terminal reflow.
- **Persistence:** None.
- **Failure cases:** A zero-height container (collapsed drawer) produces no sync, so the terminal keeps its last non-zero geometry.
- **Cancellation:** not cancellable
- **Windows path:** Same three guards before calling the terminal's fit.
- **Verify by:** unit test over the guard matrix

### PR-TERM-036 - The host container registers its live-resize observers per window and tears them down when it is destroyed
- **Source:** DroppyCode/App/Views/Terminal/TerminalPanel.swift:396-412 viewDidMoveToWindow - removes every existing observer, empties the array, returns if there is no window, then registers the willStartLiveResize and didEndLiveResize observers on that window with the main queue | DroppyCode/App/Views/Terminal/TerminalPanel.swift:390-394 - the isolated deinit cancels pendingSync and removes every observer
- **Preconditions:** The container moves between windows or is destroyed.
- **Action:** viewDidMoveToWindow fires, or the container is deallocated.
- **Expected:** Exactly two observers exist at a time and only for the container's current window; moving to no window leaves none. Destroying the container cancels the pending beat and removes both observers, so no notification reaches a dead object.
- **Side effects:** NotificationCenter registrations added and removed.
- **Persistence:** None.
- **Cancellation:** The pending beat is cancelled here.
- **Windows path:** Add and remove the window resize listeners with the component lifecycle; the pending throttle timer must be cleared on unmount.
- **Verify by:** unit test counting registrations across window moves

### PR-TERM-116 - The embedded terminal is the only terminal: the app never hands terminal work to an external terminal application
- **Source:** DroppyCode/App/Views/Terminal/TerminalPanel.swift:1-443 and DroppyCode/App/Views/Terminal/TerminalStore.swift:1-176 - the whole terminal surface is in-window, built on SwiftTerm's LocalProcessTerminalView; nothing in either file opens an external terminal | DroppyCode/App/AppModel.swift:1094-1098 runScript - scripts are run through terminals.run, never through the workspace | porting/PORT_CONTRACT.md:171 - do not replace the embedded terminal with an external terminal
- **Preconditions:** Any terminal or script action.
- **Action:** The user runs a script or opens a terminal.
- **Expected:** Everything happens in the drawer. No code path in this area opens Terminal.app, iTerm or any other terminal application for a project script or a terminal tab. (Workspace.openTerminal exists in the source for provider sign-in flows, which belong to a different area and are not a terminal-panel behaviour.)
- **Persistence:** None.
- **Cancellation:** not cancellable
- **Windows path:** The Windows build must embed a terminal in the window. Shelling out to Windows Terminal, conhost or PowerShell in a separate window for these paths is forbidden by contract section 10, regardless of how much simpler it would be.
- **Verify by:** code review plus an interaction test asserting no external process window appears
