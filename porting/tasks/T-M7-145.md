### PR-MCP-208 - Saving the custom editor validates, writes the values, re-probes a previously connected server, and closes
- **Source:** DroppyCode/App/Views/Settings/MCPSettingsPage.swift:841-866 save()
- **Preconditions:** The editor has a draft.
- **Action:** The user presses Add server or Save.
- **Expected:** wasConnected is captured before anything changes. saveCustom runs with the edited server's id, or the id saved earlier in this editor session, as the replacement id; on failure its message is shown and the editor stays open. On success the id is remembered so a second press edits rather than duplicates. The variable values are then collected with their keys trimmed and empty-key rows dropped and handed to saveCustomValues with the PRE-EDIT entry as the replaced fields; a false return shows "The Keychain could not save a value. Keep this editor open and try again." and the editor stays open. Finally, when the server had been connected, refresh runs on the freshly looked-up entry, and the popover is dismissed.
- **Side effects:** writes custom-mcp.json, possibly mcp.json, possibly protected-storage items; may start a probe; may rewrite the provider config files through saveCustom
- **Persistence:** the definition and its values
- **Failure cases:** the six validation messages, and the Keychain message above
- **Cancellation:** not cancellable once started
- **Windows path:** Same order, and keep the saved-id memory so a failed then retried save does not create a second server.
- **Verify by:** interaction test editing a connected server and asserting a re-probe follows

### PR-MCP-209 - The custom editor prefills stored values when editing and focuses the name only when adding

- **Preconditions:** The editor popover opens.

- **Expected:** When adding (no server), the name field takes focus. - **Persistence:** none

- **Cancellation:** not cancellable
- **Windows path:** Same focus asymmetry and the same prefill-on-appear.
- **Verify by:** interaction test opening the editor in both modes

### PR-MCP-211 - The info button opens on hover after 220 milliseconds and closes 320 milliseconds after the pointer leaves both it and the popover

- **Side effects:** none
- **Persistence:** none
- **Failure cases:** none
- **Cancellation:** each hover change cancels the pending task
