### PR-THEME-088 - A newly connected MCP server plays the settle chime unconditionally, ignoring the settle sound setting, and is silenced only by Reduce Motion
- **Source:** DroppyCode/App/Views/Settings/MCPSettingsPage.swift:64-73 `.onChange(of: model.mcp.states) { previous, current in guard !reduceMotion else { return }; for (id, state) in current where state.isConnected && !(previous[id]?.isConnected ?? false) { celebrating.insert(id); SettleChime.play(); ... } }`
- **Preconditions:** The MCP settings page is on screen and a server transitions from not connected to connected.
- **Action:** The connection lands.
- **Expected:** The settle chime plays once per newly connected server, and the row celebrates for 900 milliseconds. The settle sound setting is not consulted here, so a user who turned that setting off still hears this. The whole effect, chime included, is skipped when the system's reduce-motion preference is on.
- **Side effects:** Plays audio; Marks the row as celebrating for 900 ms
- **Persistence:** not persisted
- **Failure cases:** None expressed in source.
- **Cancellation:** not cancellable
- **Windows path:** Reproduce both quirks: the sound is gated on a motion preference rather than on the sound setting, and it bypasses the sound setting entirely. Several servers connecting in one update each call play(), and because the settle chime restarts from the top (PR-THEME-082) the result is one tick, not several.
- **Verify by:** interaction test with the settle sound setting off: connecting a server is still audible
