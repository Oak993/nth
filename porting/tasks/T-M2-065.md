### PR-STORE-115 - Provider payloads are parsed into a seven-case JSON tree that allows top-level fragments
- **Source:** DroppyCode/Core/Support/JSONValue.swift:3-12 - doc comment "A Sendable JSON tree. Every provider protocol is decoded into this shape off the main actor." then enum JSONValue with cases null, bool, int, double, string, array, object | DroppyCode/Core/Support/JSONValue.swift:15-24 - static func parse(_ data: Data) -> JSONValue? uses JSONSerialization.jsonObject(with: data, options: [.fragmentsAllowed]) and returns nil on failure; parse(_ string:) is parse(Data(string.utf8))
- **Preconditions:** Bytes from a provider process or a file.
- **Action:** Parsing.
- **Expected:** Fragments are allowed, so a bare number, string, boolean or null at the top level parses successfully. A parse failure returns nil rather than throwing. The result is one of exactly seven cases.
- **Failure cases:** Invalid JSON yields nil with no diagnostic.
- **Cancellation:** not cancellable
- **Windows path:** A parser that accepts top-level fragments and returns an optional. Most Windows JSON libraries reject fragments by default and must be configured to allow them.
- **Verify by:** unit over a bare fragment and over malformed input

### PR-STORE-116 - Foundation numbers are bridged as boolean, double or integer by their runtime type
- **Source:** DroppyCode/Core/Support/JSONValue.swift:26-45 - init(foundation object:) { case let number as NSNumber: if CFGetTypeID(number) == CFBooleanGetTypeID() { .bool } else if CFNumberIsFloatType(number as CFNumber) { .double } else { .int }; case let string as String: .string; case let array as [Any]: .array(mapped); case let dictionary as [String: Any]: .object(mapValues); default: .null }
- **Preconditions:** A parsed Foundation object tree.
- **Action:** Bridging into JSONValue.
- **Expected:** A boxed boolean becomes .bool; a float-typed number becomes .double; every other number becomes .int. Strings, arrays and dictionaries map recursively. Anything unrecognised, including NSNull, collapses to .null.
- **Failure cases:** A JSON literal true is never mistaken for the integer 1, which matters because provider protocols use both.
- **Cancellation:** not cancellable
- **Windows path:** Distinguish boolean from numeric explicitly. A port whose parser reports true as 1 will send the wrong type back to providers. Whether an integral value written as 1.0 arrives as .double or .int depends on the parser and must be tested against the provider fixtures.
- **Verify by:** contract fixture over provider payloads containing booleans, integers and floats

### PR-STORE-118 - The integer accessor coerces doubles and strings; the double accessor does not parse strings

- **Preconditions:** A JSONValue field from a provider payload.
- **Action:** Reading it through a typed accessor.
