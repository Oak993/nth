### PR-PROVCLI-235 - Command Code's close path clears the turn, withdraws every prompt and deletes the leftover gate files
- **Source:** DroppyCode/Services/Providers/CommandCodeSession.swift:434-443 - didClose(status:process:) preamble | DroppyCode/Services/Providers/CommandCodeSession.swift:764-770 - clearApprovalFiles with its doc comment
- **Preconditions:** The turn's process exited.
- **Action:** didClose runs.
- **Expected:** A close for a process that is no longer the current one returns immediately. Otherwise the stored process is cleared, turnActive becomes false, the current message and reasoning ids are cleared, every pending approval emits .requestResolved and the map is cleared, and EVERY file in the approvals directory is deleted - requests and replies alike - so a stale one never answers a later call. Then, when the session was stopped, the method returns without any turn event.
- **Side effects:** Provider events; files deleted
- **Persistence:** none
- **Failure cases:** A failed delete is ignored.
- **Cancellation:** A stop suppresses the turn outcome entirely.
- **Windows path:** Deleting files the CLI may still hold open can fail on Windows; the failures are ignored, but a stale request file that survives could be picked up by the next turn's scan. The port should verify that the reply files are keyed by tool call id so a survivor cannot answer a different call (PA-0015).
- **Verify by:** interaction test asserting the directory is empty after a turn and that a locked file does not throw

### PR-PROVCLI-236 - Command Code reports an interrupted turn on the interrupt flag or exit code 130, before anything else
- **Source:** DroppyCode/Services/Providers/CommandCodeSession.swift:445-448 - if interruptRequested || status == 130 { onEvent?(.turnCompleted(status: .interrupted, error: nil)); return }
- **Preconditions:** The process exited.
- **Action:** didClose evaluates the outcome.
- **Expected:** This test comes FIRST, before the result line is consulted. When interruptRequested is true OR the exit status is exactly 130, the turn is reported .interrupted with a nil error and nothing further is evaluated - even if a result line arrived.
- **Side effects:** One provider event
- **Persistence:** none
- **Failure cases:** none
- **Cancellation:** This IS the cancellation outcome.

The port must choose and record the Windows termination exit code deliberately (port_impacts.md entry 24).
- **Verify by:** interaction test asserting an interrupted turn on Windows reports .interrupted through the flag alone

- **Persistence:** none
- **Failure cases:** Every branch above is a failure path except 0 and 8.

### PR-PROVCLI-240 - Command Code rewrites two families of account errors into actionable sentences
- **Source:** DroppyCode/Services/Providers/CommandCodeSession.swift:502-512 - friendlyError with its doc comment
- **Preconditions:** A failure error text.
- **Action:** friendlyError runs.
- **Expected:** The text is lowercased for the tests. When it contains "not authenticated" OR "unauthorized" OR "session expired", the whole message is REPLACED by "Command Code is not signed in. Run `cmd login` in Terminal, or add a Studio API key in Settings → Providers → Command Code." When it contains "insufficient credits" OR "out of credits", it is replaced by "Command Code is out of credits. Top up at commandcode.ai/billing, or wait for the monthly credits to reset." Both replacements are identical to the exit-code 3 and 10 messages. Otherwise the original text is returned unchanged. The sign-in test is evaluated first, so a message containing both families reports sign-in.
- **Persistence:** none
- **Failure cases:** No match: the CLI's own wording survives.
- **Cancellation:** not cancellable
- **Windows path:** The lowercasing must be invariant. On Windows the sentence still names `cmd login` in Terminal; whether that instruction is accurate for the Windows CLI is part of UNK-0006 and must not be reworded without evidence. Executable identity is validated per PA-0016: PATH resolution honours PATHEXT, and a candidate whose Windows version resource identifies it as the command interpreter (CompanyName Microsoft Corporation with OriginalFilename Cmd.Exe/Cmd.Exe.MUI, or FileDescription Windows Command Processor), or which is %SystemRoot%System32cmd.exe or %SystemRoot%SysWOW64cmd.exe, is rejected and the provider reports not installed.
- **Verify by:** unit test over both families and a plain error
