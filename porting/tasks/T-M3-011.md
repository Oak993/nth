## Requirements

### PR-GIT-099 - RevertPreview parses numstat records strictly and throws a corrupt-file error on anything malformed
- **Source:** DroppyCode/Services/Git/RevertPreview.swift:28-41 init(numstat:) - split on "\0" discarding empties; each record split on "\t" with at most 2 splits keeping empties; throws CocoaError(.fileReadCorruptFile) when there are not exactly 3 fields, when the third is empty, when a non-binary count fails to parse, or when a count is negative; a binary file is both counts equal to "-" and gets zero and zero | porting/port_impacts.md entry 231 (G12) - the outer/inner split asymmetry
- **Preconditions:** numstat output.
- **Action:** It is parsed into a preview.
- **Expected:** The outer split is on the NUL byte discarding empty subsequences; the inner split is on tab with at most two splits and empty fields kept. Exactly three fields are required and the third must be non-empty. A record whose first two fields are both the literal "-" is a binary file with additions and deletions of zero. Otherwise both counts must parse as integers and neither may be negative. Any violation throws a corrupt-file error. Empty input yields an empty file list and no error.
- **Side effects:** None
- **Persistence:** None.
- **Failure cases:** A corrupt record throws, and the message editor then shows the error's description beside a warning triangle
- **Cancellation:** not cancellable
- **Windows path:** Read stdout as bytes and decode UTF-8 with no CRLF translation: -z output carries no newlines and normalising a path containing a carriage return would corrupt it.
- **Verify by:** unit over a text record, a binary record, an empty input and three malformed shapes

### PR-GIT-100 - A revert preview's headline counts sum only the files that will actually be put back
- **Source:** DroppyCode/Services/Git/RevertPreview.swift:23-26 - restorable is the files not marked kept; additions and deletions reduce over restorable only, not over all files
- **Preconditions:** A preview with some kept files.
- **Action:** The editor shows the totals.
- **Expected:** The restorable list excludes every file marked kept. The headline addition and deletion totals sum over the restorable list alone, so a preview whose files are all kept shows totals of zero even though the file rows are listed.
- **Side effects:** None
- **Persistence:** None.
- **Failure cases:** Not applicable
- **Cancellation:** not cancellable
- **Windows path:** Direct port.
- **Verify by:** unit with a mixed kept and restorable preview
