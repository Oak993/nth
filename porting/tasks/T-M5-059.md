### PR-THEME-030 - A nil accent in the palette means the system control accent, never a substituted colour
- **Source:** DroppyCode/UI/Theme/AppTheme.swift:107-108 doc: "accent/success/warning/danger: nil keeps the system hue" | DroppyCode/UI/Theme/AppTheme.swift:193 `accent: palette.accent.map(Color.init(hex:))` | DroppyCode/UI/Chrome/Chrome.swift:78 `private static let systemAccent = Color(nsColor: .controlAccentColor)` | DroppyCode/UI/Chrome/Chrome.swift:83 `static var accent: Color { ThemeManager.spec.accent ?? systemAccent }`
- **Preconditions:** The active theme is system, light or dark (the only three with a nil accent).
- **Action:** Anything reads the app accent colour.
- **Expected:** The accent resolves to the OS's own control accent colour, which the user can change in system settings; the app does not hard-code a blue. ThemeSpec.accent stays nil so that callers can tell "no theme accent" from "a theme accent that happens to look system blue".
- **Persistence:** not persisted
- **Failure cases:** None expressed in source.
- **Cancellation:** not cancellable
- **Windows path:** Platform boundary: read the Windows accent colour (the personalization accent) and follow changes to it. The optional must stay an optional in the shared model, because two consumers (PR-THEME-036, PR-THEME-037) deliberately pass the raw nil through.
- **Verify by:** unit: spec.accent is nil for system/light/dark and non-nil for the other 23; interaction test: changing the OS accent repaints accented controls
