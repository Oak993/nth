- **Action:** Each such text is passed through inline().
- **Expected:** Three passes run in this order over the whole text. First every `![alt](target)` whose target has no whitespace becomes its alt text, which may be empty. Then every `[title](target)`, with a non-empty title free of square brackets, a target without whitespace, and optionally whitespace and a double-quoted title attribute before the closing parenthesis, becomes the target alone when title and target are equal, otherwise `title (target)`. Then every `<http:...>`, `<https:...>` or `<mailto:...>` with no whitespace or angle bracket inside becomes the bare address. The passes use Swift's Regex, whose default matching unit is the Character (an extended grapheme cluster): a combining mark attached to a bracket, parenthesis or angle bracket makes one character with it, so that bracket no longer matches the pattern's literal. - **Failure cases:** No failure path: a text with no match is returned unchanged.
- **Cancellation:** not cancellable
- **Windows path:** Port the three patterns and their order verbatim, and match over user-perceived characters (grapheme clusters), not UTF-16 code units, to reproduce B2 at combining marks. The grapheme-level difference is derived from reading the code and Swift's documented Regex semantics, not from running it on a Mac.
