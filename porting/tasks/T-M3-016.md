### PR-COMPOSER-061 - Storage.attach counts room twice and deletes the copies that no longer fit
- **Source:** DroppyCode/Services/Store/Storage.swift:161-174 attach - batch = sources.prefix(max(0, limit - current count)); a detached task imports them; on the main actor room is recomputed and imported.prefix(room) is appended; every orphan past that has its file removed
- **Preconditions:** Sources were handed to the composer.
- **Action:** The copies and transcodes finish.
- **Expected:** The call returns before any byte is copied. When the copies land the free slots are counted again, since more may have been attached in the meantime, and anything past the limit by then is appended nowhere and its copied file is deleted from app storage.
- **Side effects:** Writes files into the attachments directory; Deletes orphaned copies
- **Persistence:** Attachment files under the storage root, named as a UUID plus the extension.
- **Failure cases:** No room at all: the call returns nil and nothing is copied.; A source that fails to import is dropped silently by compactMap.
- **Cancellation:** The detached task is not cancelled by the composer.
- **Windows path:** Same double count and orphan cleanup. File copies go to the Windows storage root of the app-paths adaptation.
- **Verify by:** integration test attaching from two sources at once

### PR-COMPOSER-062 - HEIC and HEIF files are transcoded to JPEG at quality 0.88 and pasted images are stored as PNG named "Pasted image.png"
- **Source:** DroppyCode/Services/Store/Storage.swift:179-199 importSource - folders are skipped; heic and heif are transcoded to jpeg and stored as the base name plus ".jpg"; image data that is already png is stored as is, otherwise transcoded to png, and named "Pasted image.png" | DroppyCode/Services/Store/Storage.swift:203-219 transcode - full pixel size, orientation applied, jpeg at kCGImageDestinationLossyCompressionQuality 0.88
- **Preconditions:** A file or pasted image is imported.

- **Cancellation:** not cancellable
- **Windows path:** Use a Windows imaging codec for HEIF where available; the JPEG quality and the PNG naming are verbatim. If HEIF decoding is unavailable the import must fail the same way (dropped silently), not fall back to copying the HEIC.
- **Verify by:** contract fixture comparing output bytes' dimensions and the stored names

### PR-STORE-001 - The store root is <Application Support>/<AppInfo.name>, created once at first touch

- **Preconditions:** App process started; no store folder need exist.
- **Action:** Any first read of Storage.root (library load, thread save, MCP store, token ledger).
- **Expected:** In a capture run (launched with --website-captures or --tour-captures, so CaptureRun.storageRoot is not nil) the root is <output folder>/storage, returned as is with no directory created here (Storage.swift:20; the capture run itself is PR-LAUNCH-007). Otherwise: the user-domain Application Support directory is taken at index [0], the app display name is appended as a directory component, the directory is created with intermediates, and the resulting URL is cached in a lazily initialised static for the life of the process. The folder name is exactly the value of CFBundleDisplayName, falling back to the literal "Droppy Code" when the key is absent. - **Persistence:** Directory <Application Support>/<AppInfo.name> upstream; %LOCALAPPDATA%\Marrow Code in the port (OD-0008 C7). Everything else in this area is relative to it.
- **Failure cases:** createDirectory is called with try? so a failure is swallowed and the URL is still returned and cached; every later write against it then fails individually.
- **Cancellation:** not cancellable
- **Windows path:** Local app data root: %LOCALAPPDATA%\Marrow Code, created recursively (OD-0008 C7). The folder name is the data identity fixed by the ruling, not a value read at run time; the layout under it is unchanged. Windows: PA-0015 applies - file replace, delete and rename can fail transiently with a sharing violation, so the operation retries with backoff, clears the read-only attribute before a delete, uses an atomic replace primitive and surfaces a real error after a bounded number of attempts rather than dropping the write.
- **Verify by:** restart test: delete %LOCALAPPDATA%\Marrow Code, launch, assert it exists and holds library.json after the first save, and assert %LOCALAPPDATA%\Marrow is not created or touched
