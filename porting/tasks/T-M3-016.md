### PR-COMPOSER-061 - Storage.attach counts room twice and deletes the copies that no longer fit
- **Source:** DroppyCode/Services/Store/Storage.swift:150-163 attach - batch = sources.prefix(max(0, limit - current count)); a detached task imports them; on the main actor room is recomputed and imported.prefix(room) is appended; every orphan past that has its file removed
- **Preconditions:** Sources were handed to the composer.
- **Action:** The copies and transcodes finish.
- **Expected:** The call returns before any byte is copied. When the copies land the free slots are counted again, since more may have been attached in the meantime, and anything past the limit by then is appended nowhere and its copied file is deleted from app storage.
- **Side effects:** Writes files into the attachments directory; Deletes orphaned copies
- **Persistence:** Attachment files under the storage root, named as a UUID plus the extension.
- **Failure cases:** No room at all: the call returns nil and nothing is copied.; A source that fails to import is dropped silently by compactMap.
- **Cancellation:** The detached task is not cancelled by the composer.
- **Windows path:** Same double count and orphan cleanup. File copies go to the Windows storage root of the app-paths adaptation.
- **Verify by:** integration test attaching from two sources at once

### PR-STORE-013 - An undecodable library.json is surfaced to the user and never overwritten by the next save
- **Source:** DroppyCode/Services/Store/Storage.swift:49-52 - static func loadLibrary() -> Library { guard let data = try? Data(contentsOf: libraryURL) else { return Library() }; return (try? - **Preconditions:** library.json exists but cannot be read or is not decodable as a Library (truncated write, not valid JSON, or a non-object at the top level).
- **Action:** App launch, and every write of library.json that follows in the same run: the debounced save, the immediate saves on settle, reopen and thread delete, and the quit-time save.
- **Expected:** Deviation, OD-0008 A10 (BLK-0010 FIX): the failed load is not swallowed. It is surfaced to the user, and library.json is not overwritten after the failed load: no writer of library.json writes over it in that run. That covers the 400 ms debounced save after a mutation (AppModel.swift:1304-1314), the immediate saveLibrary() calls on settle (AppModel.swift:814-815), reopen (:834) and thread delete (:965), and the synchronous quit-time save (:1335). - **Failure cases:** Per-element leniency (Library.init(from:) decoding [Lenient<Project>] and [Lenient<ChatThread>]) means a single bad record is dropped without reaching this path; only a whole-file failure does.; A library.json that does not exist is not a failed load: PR-STORE-012 applies, the app starts empty and ordinary saves create the file.
- **Cancellation:** not cancellable

Thread file saves are not affected. Named deviation. The report is shown in the main window at launch with the OD-0012 E4 text, byte for byte: "Marrow could not read library.json, so your projects and threads are hidden. The file will not be changed until it can be read."
- **Verify by:** contract fixture: launch against a deliberately corrupted library.json (truncated, not JSON, a top-level array) and assert the main window shows, at launch, exactly "Marrow could not read library.json, so your projects and threads are hidden.
