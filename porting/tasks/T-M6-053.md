### PR-HYDRA-156 - A recipe resolves to a pair only when both sides have a ready provider whose catalogue lists the model
- **Source:** DroppyCode/App/HydraCookbook+Resolve.swift:8-10 isReady is settings.isEnabled(provider) && registry.status(provider).isInstalled | DroppyCode/App/HydraCookbook+Resolve.swift:14-19 provider(for side:) - the first of the side's providers that is ready AND, when the side names models, lists one | DroppyCode/App/HydraCookbook+Resolve.swift:23-28 missingProvider(for recipe:) - for lead then heads, the first side with no ready provider at all yields that side's FIRST provider as the one to set up | DroppyCode/App/HydraCookbook+Resolve.swift:32-45 resolve() - both providers must resolve; the pair takes the lead provider, the lead model's id, the lead effort filtered by effort(), a workerProvider only when the heads provider differs, the heads model's id, the heads effort filtered by effort(), and the recipe's maxHeads
- **Preconditions:** The cookbook panel is listing recipes on this machine.
- **Action:** Each recipe is resolved.
- **Expected:** isReady requires BOTH that the provider is enabled in Settings and that the registry says it is installed; note this is registry.status(...).isInstalled, not countsAsInstalled. A side's provider is the first in its list that is ready and, when the side names model fragments, lists a matching model. Both sides must resolve or the recipe is not offered. The created pair carries the resolved model ids, the efforts filtered through effort() against the resolved model or the provider default, a workerProvider only when the heads provider differs from the lead's, and the recipe's cap. When a side has no ready provider at all, missingProvider names that side's FIRST provider as the one to set up, checking the lead side before the heads side.
- **Persistence:** The resolved pair is only persisted when the user adds it.
- **Failure cases:** Neither side resolves: the recipe is offered with a 'set up this provider' affordance driven by missingProvider
- **Cancellation:** not cancellable
- **Windows path:** Pure resolution over the provider registry.
- **Verify by:** unit with a stubbed registry over a fully ready recipe, one missing a lead provider and one whose provider is ready but lacks the model

### PR-HYDRA-157 - HydraCookbook.model(named:) returns the newest catalogue entry matching the first name fragment that matches anything, tie-breaking toward the LOWEST registry index
- **Source:** DroppyCode/App/HydraCookbook+Resolve.swift:49-62 static func model(named names:for provider:registry:) - for each name in order, the options whose name or id contains it case-insensitively; the first name with any match wins; among those matches the maximum is taken by version parsed from the DISPLAY NAME, with absent treated as -1, and ties broken by comparing registry indices such that the lower index wins | DroppyCode/App/HydraCookbook+Resolve.swift:65-68 private static func version(of name:) - the first match of [0-9]+(\.[0-9]+)? parsed as a Double | porting/port_impacts.md:126 entry 59 - tie-break to the lowest index in registry.models(for:)
- **Preconditions:** A recipe side names model fragments.
- **Action:** The catalogue is searched.
- **Expected:** Fragments are tried in order; the FIRST fragment that matches anything decides, and later fragments are not consulted. Matching is a case-insensitive substring test against either the option's display name or its id. Among the matches, the one with the highest version number parsed from its DISPLAY NAME wins, with a missing version treated as -1. On a version tie the option with the LOWER index in registry.models(for:) wins. The version pattern is one or more digits optionally followed by a dot and more digits, and only the first such run in the name is read: 'Gemini 3.8 Flash' yields 3.8.
- **Persistence:** None.
- **Failure cases:** No fragment matches anything: nil, and the recipe does not resolve
- **Cancellation:** not cancellable
- **Windows path:** Parse the version with a decimal point regardless of locale; a locale-aware number parser would read '3.8' differently in some locales.
- **Verify by:** unit over two same-version models, a versionless model and an id-only match
