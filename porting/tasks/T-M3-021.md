### PR-STORE-068 - HEIC and HEIF photos are transcoded to JPEG on import and renamed to .jpg
- **Source:** DroppyCode/Services/Store/Storage.swift:165-167 - doc comment: "A file the user picked, dropped or pasted, copied into app storage: folders are skipped, HEIC photos become JPEGs, which every provider can read, and pasted images are stored as PNGs." | DroppyCode/Services/Store/Storage.swift:173-177 - let fileExtension = url.pathExtension.lowercased(); guard fileExtension == "heic" || fileExtension == "heif" else { return try? importAttachment(from: url) }; guard let source = CGImageSourceCreateWithURL(url as CFURL, nil), let data = transcode(source, to: .jpeg) else { return nil }; return try? importAttachment(data: data, name: url.deletingPathExtension().lastPathComponent + ".jpg", fileExtension: "jpg")
- **Preconditions:** The dropped file’s extension is heic or heif, case-insensitively.
- **Action:** Attaching that photo.
- **Expected:** The image is decoded and re-encoded as JPEG, stored as <uuid>.jpg, and the Attachment name is the source’s base name with ".jpg" appended, so "IMG_0042.HEIC" becomes name "IMG_0042.jpg" with mimeType "image/jpeg". Every other extension is copied verbatim with no transcode.
- **Side effects:** One image decode and one encode on the import task
- **Persistence:** <root>/attachments/<uuid>.jpg
- **Failure cases:** If the image source cannot be created, or the transcode returns nil, the whole attachment is dropped and nothing is stored: the photo simply does not appear. The original is NOT copied as a fallback.
- **Cancellation:** not cancellable
- **Windows path:** A Windows image codec path that reads HEIC/HEIF and writes JPEG. Windows 11 needs the HEIF Image Extensions to decode HEIC; when the codec is absent the transcode fails and the attachment is dropped, which is the same observable outcome as a failed transcode on macOS. Record the codec dependency.
- **Verify by:** contract fixture over a HEIC sample, on a machine with and without the codec

### PR-STORE-078 - An unreferenced attachment is deleted only once it is more than 24 hours old

- **Preconditions:** An unreferenced, correctly named attachment file.
- **Action:** The sweep evaluates it.
- **Expected:** The cutoff is exactly 86400 seconds before the sweep started. The file’s content modification date must be strictly earlier than the cutoff. - **Cancellation:** not cancellable
