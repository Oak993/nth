### PR-SIDEBAR-047 - One list-wide drag gesture with a 4 pt threshold grabs the open thread row under the pointer at the moment of the grab
- **Source:** DroppyCode/App/Views/Sidebar/SidebarView.swift:122-133 - `DragGesture(minimumDistance: 4, coordinateSpace: .named(Self.listSpace)).onChanged { value in guard let id = drag.id ?? rowFrames.thread(at: value.startLocation) else { return }; dragChanged(id, translation: value.translation.height) }.onEnded { _ in dragEnded() }` attached with `.highPriorityGesture` | DroppyCode/App/Views/Sidebar/SidebarView.swift:339-346 - only non-settled thread rows report their frame: `if !thread.isSettled { rowFrames.note(thread.id, frame) }`, and `.onDisappear { rowFrames.forget(thread.id) }`
- **Preconditions:** Empty query; a thread row under the pointer.
- **Action:** User presses on a row and moves the pointer at least 4 pt.
- **Expected:** The row whose reported frame contains the gesture's start location is grabbed, and it stays grabbed for the rest of the gesture even if the pointer leaves it. A drag started on a settled row, a helper row, a head card, a helper stub, a project row, a header or a gap grabs nothing, because those report no frame. A row scrolled out of the list forgets its frame and cannot be grabbed. Because the gesture is high priority it runs ahead of the row's own button, so a drag never ends in a selection; a press with less than 4 pt of travel still selects.
- **Persistence:** None at the grab.
- **Failure cases:** No frame contains the start point: `onChanged` returns immediately and the gesture is inert for its whole life.
- **Cancellation:** Releasing before 4 pt leaves the click to the row's button.
- **Windows path:** Windows pointer capture with a 4 px threshold measured in the list's own coordinate space, which must be device-independent points, not raw pixels, so the threshold is the same at 125 percent and 200 percent scaling. Platform boundary: DPI scaling.
- **Verify by:** interaction test grabbing each row kind and asserting only open thread rows move.

### PR-SIDEBAR-049 - Grabbing a row pushes the closed-hand cursor and takes a snapshot of its peers and their slot heights
- **Source:** DroppyCode/App/Views/Sidebar/SidebarView.swift:770-777 dragChanged - `if drag.id != id { drag = RowDrag(id: id); dragPeers = DragPeers(peers(of: id), heights: slotHeights); NSCursor.closedHand.push() }` | DroppyCode/App/Views/Sidebar/SidebarView.swift:803-812 dragEnded - `guard drag.id != nil else { return }; NSCursor.pop(); dragPeers = nil; withAnimation(.spring(response: 0.32, dampingFraction: 0.8)) { drag = RowDrag() }`
- **Preconditions:** A drag begins on an open thread row.
- **Action:** The gesture's first change is delivered.
- **Expected:** The cursor becomes the closed hand for the whole drag and is popped exactly once on release. The peers and their slot heights are read once at the grab, and again only after a swap, so a pointer move never rebuilds the list to find them. Release with no grabbed row does nothing at all, so the cursor stack is never popped without a matching push.
- **Side effects:** Pushes and pops a cursor on the system cursor stack.
- **Persistence:** None.
- **Failure cases:** Gesture ends without ever having grabbed: `dragEnded` returns before popping.
- **Cancellation:** A cancelled gesture delivers onEnded, which pops the cursor and springs the offset home.
- **Windows path:** Windows sets a grabbing cursor for the drag's duration via SetCursor/class cursor override and restores it on release; there is no cursor stack, so the implementation must restore exactly once and must not restore when no grab occurred.
- **Verify by:** interaction test asserting cursor set and restored, including the no-grab path.
