### PR-PROVCLI-061 - Claude's close path fails every waiting request, clears prompts and reports an exit only for a started session
- **Source:** DroppyCode/Services/Providers/ClaudeSession.swift:680-698 - didClose
- **Preconditions:** The child's message stream ended.
- **Action:** didClose runs.
- **Expected:** hasClosed is set. The reason is the stored launchError when present, otherwise TextCleanup.lastLines of the stderr tail, and it is written BACK into launchError so a later control() call reports it. Every waiting control continuation is resumed by throwing ProviderError.failed(reason ?? "Claude exited."). Every pending tool emits .requestResolved and the map is cleared. turnActive becomes false. Finally .exited(error: <last lines of the tail>) is emitted ONLY when the session is not stopping AND isStarted is true - a launch that failed is reported by start() throwing instead.
- **Side effects:** Provider events
- **Persistence:** none
- **Failure cases:** A stop suppresses the exit notice; a failed launch reports through start().
- **Cancellation:** Ordering with stop() matters: stop sets isStopping before terminating.
- **Windows path:** The stderr tail is bounded by the process layer (PA-0008); its 3 second post-exit drain window must be preserved so the tail is not empty on Windows.
- **Verify by:** interaction test over a crash, a stop and a failed launch
