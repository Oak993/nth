### PR-CHAT-049 - Jumping to a minimap tick loads history down to it first when it is above the loaded window
- **Source:** DroppyCode/App/Views/Chat/ThreadTimeline.swift:224-252 jump(to:in:animated:) - when the target index is above the window's first block (`let firstVisible = windowStartIndex(in: blocks)`), `windowStartID = blocks[index].id`, needsExpand and historyLoadPending are set; isPinnedToBottom becomes id == blocks.last?.id; anchorsBottomOnGrowth becomes pinned or needsExpand; the scroll targets the id with anchor .top; an animated jump uses .smooth(duration: 0.35) and an unanimated one disables animations; an expanding jump defers the scroll to the next main-queue turn
- **Preconditions:** The reader taps or scrubs the minimap.
- **Action:** A tick is chosen.
- **Expected:** A target inside the window scrolls straight to it, aligned to its top. A target above the window first moves the window's start to that block, so the window runs from the target to the end, then scrolls on the next main-queue turn so layout exists. Jumping away from the latest unpins the follow behavior, so streaming text never yanks the reader back down; jumping to the last block re-pins it. A live scrub is unanimated and a release glides over 0.35 seconds with the smooth curve.
- **Persistence:** None.
- **Failure cases:** A target id not present in the block list leaves the window and the pin untouched and still issues the scroll request, which then resolves to nothing.
- **Cancellation:** not cancellable
- **Windows path:** Windows must defer the scroll one frame after growing the window, exactly as the source defers to the main queue, or the scroll resolves against a layout that does not yet contain the target.
- **Verify by:** interaction test scrubbing to the first tick of a long thread
