### PR-PROVCLI-089 - Codex falls back to forking the thread when the server refuses rollback on a paginated thread
- **Source:** DroppyCode/Services/Providers/CodexSession.swift:208-210 - catch let error as RPCError where error.message.contains("paginated threads do not support thread/rollback") { return try await forkHistory(...) } | DroppyCode/Services/Providers/CodexSession.swift:265-298 - forkHistory
- **Preconditions:** thread/rollback failed with that exact substring.
- **Action:** rollback falls back.
- **Expected:** The fallback fires ONLY on an RPCError whose message contains the substring "paginated threads do not support thread/rollback". With no previousID (the target was the first turn) the original thread is archived with "thread/archive", threadID and turnID are cleared and nil is returned. Otherwise the thread parameters plus "threadId" (the original), "lastTurnId" (previousID) and "excludeTurns" = true are sent as "thread/fork"; the result must carry a string thread.id DIFFERENT from the original, else "Codex did not create a conversation at the revert point." is thrown. The new thread's last turn is then verified with a one-element descending thread/turns/list whose first id must equal previousID and must not equal the target, else "Codex did not confirm the reverted conversation history." is thrown. On success the ORIGINAL thread is archived; on any throw inside that verification block the NEW thread is archived instead with try? and the error is rethrown. Finally threadID becomes the new id, turnID is cleared, activeModel is updated from result.model when present, and the new id is returned.
- **Side effects:** Up to four RPC round trips; one thread archived either way
- **Persistence:** The thread's resume id changes to the forked thread's id, or becomes nil when the whole conversation was archived.
- **Failure cases:** The two exact messages above; a failed verification archives the new thread and rethrows.
- **Cancellation:** not cancellable
- **Windows path:** None.
- **Verify by:** interaction test over the fork path, the no-previous path and the verification failure
