### PR-PROVCLI-246 - Command Code scans request files in lexicographic order and deletes each as it reads it
- **Source:** DroppyCode/Services/Providers/CommandCodeSession.swift:627-640 - scanApprovals with its doc comment
- **Preconditions:** A turn is active and an approvals directory exists.
- **Action:** scanApprovals runs, from the watcher or from tool_queued.
- **Expected:** The scan returns immediately when there is no directory or no active turn. The directory is listed; a failure returns. Files are sorted by their LAST PATH COMPONENT, ascending, and only those whose name ends with the literal suffix ".request.json" are considered. Each is read and parsed; an unreadable or unparseable file is SKIPPED and left in place. A parsed file is DELETED IMMEDIATELY after reading. The id is request.toolCallId when a string, else the file name with ".request.json" removed. A request whose id already has a pending approval is skipped. Otherwise it is decided.
- **Side effects:** Files deleted
- **Persistence:** none
- **Failure cases:** An unparseable request file is left behind and rescanned on every event, forever, until the turn ends and clearApprovalFiles removes it.
- **Cancellation:** A finished turn clears the directory.
- **Windows path:** The sort must be ordinal on the file name, not culture-sensitive. Deleting a file the mod may still have open can fail on Windows; a failed delete leaves the request in place, and the pending-approval check is what stops it being asked twice (PA-0015).
- **Verify by:** interaction test with two request files asserting the order, plus one unparseable file
