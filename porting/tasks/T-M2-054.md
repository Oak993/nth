## Requirements

### PR-CHAT-001 - TimelineItem is the single persisted unit of a conversation, with id, optional turnID, date and a tagged content union
- **Source:** DroppyCode/Core/Models/Timeline.swift:3-14 struct TimelineItem - Codable, Identifiable, Hashable, Sendable; fields id: String, turnID: UUID?, date: Date, content: Content; init defaults id = UUID().uuidString and date = .now | DroppyCode/Core/Models/Timeline.swift:16-25 enum Content - the eight cases the timeline can hold
- **Preconditions:** A thread document is being built in memory or decoded from disk.
- **Action:** The runtime appends or decodes a timeline item.
- **Expected:** Every item carries exactly four stored fields: id (String, defaulting to a fresh UUID string), turnID (UUID or null), date (Date, defaulting to now) and content, which is exactly one of user, assistant, reasoning, tool, plan, todos, notice, turnEnd. No other case exists and no other field is stored.
- **Persistence:** Serialized inside ThreadDocument.items under the JSON keys id, turnID, date, content; the content union is encoded by Swift's synthesized enum coding, i.e. a single-key object whose key is the case name.
- **Failure cases:** An item that fails to decode is dropped rather than failing the whole document (see PR-CHAT-019).
- **Cancellation:** not cancellable
- **Windows path:** A discriminated-union record type in the Windows model layer, serialized with the same key names and the same single-key-object shape for the union, so a thread written by either build round-trips.
- **Verify by:** contract fixture: encode/decode round-trip against a pinned JSON fixture per content case

### PR-CHAT-002 - A reasoning block whose text is only whitespace is flagged empty
- **Source:** DroppyCode/Core/Models/Timeline.swift:27-31 TimelineItem.isEmptyReasoning - guard case .reasoning(let block); returns block.text.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty
- **Preconditions:** A timeline item exists.
- **Action:** Anything asks the item whether it is empty reasoning.
- **Expected:** True only when the content is .reasoning and its text trims to the empty string over the Unicode whitespace-and-newlines set. Every other content case returns false, including an assistant message with empty text.
- **Persistence:** Derived, never persisted.
- **Cancellation:** not cancellable
- **Windows path:** Trim against the same Unicode whitespace and newline set (not ASCII-only), because a redacted reasoning stream can leave non-breaking or line-separator characters behind.
- **Verify by:** unit

### PR-CHAT-003 - Em-dash cleanup rewrites only model-written prose, never the user's words, tool output or notices
- **Source:** DroppyCode/Core/Models/Timeline.swift:34-55 TimelineItem.cleanedOfEmDashes - switches on .assistant, .reasoning and .plan only; default: break leaves user, tool, todos, notice and turnEnd untouched | DroppyCode/Core/Models/Timeline.swift:42 message.text = TextCleanup.withoutEmDashes(message.text) | DroppyCode/Core/Models/Timeline.swift:48 plan.markdown = TextCleanup.withoutEmDashes(plan.markdown)
- **Preconditions:** A stored thread is read back that was written by a build which cleaned text only as it arrived.
- **Action:** The item is passed through cleanedOfEmDashes.
- **Expected:** assistant.text, reasoning.text and plan.markdown are replaced by TextCleanup.withoutEmDashes of themselves. user, tool, todos, notice and turnEnd items are returned byte-identical. The item's id, turnID and date are preserved.
- **Persistence:** Applied to items as read; the cleaned value is what subsequent writes persist.
- **Cancellation:** not cancellable
- **Windows path:** Same three cases only. Do not extend the cleanup to tool output: a command's stdout containing an em dash must survive verbatim.
- **Verify by:** unit: one fixture item per content case, asserting only the three named cases change

### PR-CHAT-004 - UserMessage carries text, attachments and two optional Hydra markers that decide which row draws it
- **Source:** DroppyCode/Core/Models/Timeline.swift:57-69 struct UserMessage - text: String, attachments: [Attachment] = [], hydraHeads: [Int]?, hydraBrief: Bool?; isFromHydra is hydraHeads != nil; isHydraBrief is hydraBrief == true | DroppyCode/App/Views/Chat/TimelineRows.swift:79-83 UserMessageRow - isFromHydra routes to HydraReportRow, isHydraBrief routes to HydraBriefRow, otherwise the plain bubble
- **Preconditions:** A user-kind timeline item is about to be rendered.
- **Action:** The row inspects the message.
- **Expected:** hydraHeads present (even as an empty array) means the message is Hydra's, not the user's, and it draws as HydraReportRow. hydraHeads absent and hydraBrief == true draws as HydraBriefRow. Neither draws the plain user bubble. hydraBrief being absent or false is not a brief. The isFromHydra test precedes the isHydraBrief test.
- **Persistence:** hydraHeads and hydraBrief are optional JSON keys, absent on messages stored before they existed, and their absence decodes as nil without failing.
- **Cancellation:** not cancellable
- **Windows path:** Keep the three-way branch and its order. Windows must distinguish an absent hydraHeads key from an empty array: an empty array is a note from Hydra itself and still takes the report row.
- **Verify by:** unit plus interaction test over the three branches

### PR-CHAT-005 - Attachment identifies a file by path and mime type, and is an image when the mime type starts with image/
- **Source:** DroppyCode/Core/Models/Timeline.swift:88-96 struct Attachment - id = UUID(), name, path, mimeType; url is URL(fileURLWithPath: path); isImage is mimeType.hasPrefix("image/") | DroppyCode/Core/Models/Timeline.swift:99-105 Attachment.base64Images - @concurrent, compactMap over attachments, keeps only isImage entries whose bytes read, returns (image, base64)
- **Preconditions:** A message carries attachments.
- **Action:** The UI or the provider path asks whether an attachment is an image, or asks for the base64 images.
- **Expected:** isImage is a literal prefix test on the mimeType string against "image/", never on the file extension. base64Images reads each image's bytes off the main actor and silently skips any attachment whose bytes cannot be read, returning only the pairs that succeeded, in the original order.
- **Side effects:** base64Images reads each image file from disk
- **Persistence:** id, name, path and mimeType are persisted with the message.
- **Failure cases:** A file that cannot be read is dropped from the result with no error and no notice.
- **Cancellation:** not cancellable
- **Windows path:** URL(fileURLWithPath:) becomes a Windows absolute path; the stored path is the platform path as captured. Base64 encoding must run off the UI thread: the source comment records that a photo is megabytes and its string a third larger again.
- **Verify by:** unit with a fixture directory including one unreadable path

- **Preconditions:** A provider event creates or updates a tool call.
- **Action:** The call is written into the timeline.
- **Expected:** kind is one of the eight literals command, read, edit, search, web, mcp, agent, other. status is one of running, completed, failed, declined and defaults to running. output defaults to the empty string, edits to an empty array, startedAt to now, and detail, exitCode and finishedAt are null until set.
- **Persistence:** Raw strings exactly as listed, lowercase, no other spelling accepted.
- **Failure cases:** An unknown kind or status string fails that item's decode, and the item is dropped by the lenient container (PR-CHAT-019).
- **Cancellation:** not cancellable
- **Windows path:** String-valued enums with the identical raw values, so a thread file is interchangeable.

### PR-CHAT-007 - Tool output is trimmed to a 60000-byte ceiling by replacing the head with a single ellipsis and keeping the last 30000 bytes
- **Source:** DroppyCode/Core/Models/Timeline.swift:137 static let outputLimit = 60_000 | DroppyCode/Core/Models/Timeline.swift:149-157 appendOutput appends then trims; setOutput replaces then trims | DroppyCode/Core/Models/Timeline.swift:164-167 trimOutput - guard output.utf8.count > Self.outputLimit; output = "…" + String(output.suffix(Self.outputLimit / 2))
- **Preconditions:** A tool call is streaming or has just received its whole output.
- **Action:** appendOutput or setOutput is called.
- **Expected:** While the output's UTF-8 byte count is at most 60000 it is kept whole. Above that the output becomes the single character U+2026 HORIZONTAL ELLIPSIS followed by the last 30000 Characters of the current output. Note that the guard counts UTF-8 bytes while suffix counts Characters, so the trimmed result can still exceed 60000 bytes for non-ASCII output; this is the shipped behavior.
- **Persistence:** The trimmed value is what is stored in the item and written to disk.
- **Cancellation:** not cancellable
- **Windows path:** Reproduce the byte-count guard and the Character-count suffix exactly, including the unit mismatch. Windows string indices are UTF-16 code units: suffix must be taken over grapheme clusters, not code units, or a surrogate pair is split.
- **Verify by:** unit with an ASCII case, a CJK case and an emoji case at the boundary

### PR-CHAT-008 - finish() sets the status and stamps finishedAt only the first time
- **Source:** DroppyCode/Core/Models/Timeline.swift:159-162 finish(_ status:) - self.status = status; if finishedAt == nil { finishedAt = .now }
- **Preconditions:** A tool call exists.
- **Action:** finish is called, possibly more than once.
- **Expected:** status is overwritten every time. finishedAt is written only when it is currently null, so a second finish never moves the recorded end time. The elapsed duration a row shows therefore never grows after the first completion.
- **Persistence:** status and finishedAt on the tool item.
- **Cancellation:** not cancellable
- **Windows path:** Same first-write-wins rule on finishedAt.
- **Verify by:** unit
