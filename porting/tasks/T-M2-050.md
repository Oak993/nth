### PR-WIN-131 - Recording a key no menu can express is refused with "Menus cannot use this key."
- **Source:** DroppyCode/Core/Models/Shortcuts.swift:328 `if chord.keyboardShortcut == nil { return "Menus cannot use this key." }`
- **Preconditions:** The user is recording a chord.
- **Action:** They press a key outside all three conversion tables, for example a media key or an unmapped code.
- **Expected:** The recording is refused with exactly "Menus cannot use this key.". This is the third check, so a modifier-only or typing-key chord is refused by its own message first.
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** Verbatim string. The set of refused keys follows the port's own accelerator conversion, which must match the three tiers of the source's table.
- **Verify by:** string fixture; unit on an unmapped key code

### PR-WIN-132 - Eighteen chords are reserved and are refused with "macOS or Droppy Code already uses this chord." upstream and "Windows or Marrow already uses this chord." in the port
- **Source:** DroppyCode/Core/Models/Shortcuts.swift:251-257 the comment 'Chords macOS and the app already answer to, which no command may take.' and `var chords = [12, 4, 46, 8, 9, 7, 0, 6].map { KeyChord(keyCode: $0, modifiers: .command) }; chords.append(KeyChord(keyCode: 6, modifiers: [.shift, .command])); chords += [18, 19, 20, 21, 23, 22, 26, 28, 25].map { KeyChord(keyCode: $0, modifiers: .command) }` | DroppyCode/Core/Models/Shortcuts.swift:329 `if Self.reserved.contains(chord) { return "macOS or Droppy Code already uses this chord." }`
- **Preconditions:** The user is recording a chord.
- **Action:** They press a reserved chord.
- **Expected:** Upstream the recording is refused with exactly "macOS or Droppy Code already uses this chord.". The reserved set is exactly eighteen chords: Command with key codes 12 (Q), 4 (H), 46 (M), 8 (C), 9 (V), 7 (X), 0 (A) and 6 (Z); Shift-Command with key code 6 (Z); and Command with the nine digit positions 18, 19, 20, 21, 23, 22, 26, 28 and 25, which are the digits 1 through 9 in that order. This is the fourth check, so it wins over the conflict message. DEVIATION (OD-0008 B8): the port keeps the same eighteen-chord table and refuses with exactly "Windows or Marrow already uses this chord.".
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** Translate to Ctrl+Q, Ctrl+H, Ctrl+M, Ctrl+C, Ctrl+V, Ctrl+X, Ctrl+A, Ctrl+Z, Ctrl+Shift+Z and Ctrl+1 through Ctrl+9 (ED-050 mapping). OD-0008 B8 keeps the reserved list as is, including Ctrl+H and Ctrl+M whose macOS reasons (Hide, Minimize) do not exist on Windows. The nine digit chords must stay in step with the main window's digit handling (port_impacts.md entry 110, CC1). The message is the ruled "Windows or Marrow already uses this chord.".
- **Verify by:** contract fixture on the eighteen chords; string fixture on "Windows or Marrow already uses this chord."

### PR-WIN-133 - A chord another command already holds is refused with that command's own title
- **Source:** DroppyCode/Core/Models/Shortcuts.swift:330-333 `if let owner = AppShortcut.allCases.first(where: { $0 != shortcut && self.chord(for: $0) == chord }) { return "\(owner.title) already uses this chord." }; return nil`
- **Preconditions:** The user is recording a chord for one command.
- **Action:** They press a chord another command currently holds, whether by default or by override.
- **Expected:** The recording is refused with the owning command's title followed by exactly " already uses this chord.", for example "Toggle terminal already uses this chord.". The owner is the FIRST match in the enum's declaration order, so with two commands somehow holding the same chord the earlier one is named. The comparison is against live chords, so a command whose chord was cleared owns nothing and never blocks. This is the fifth and last check; passing it means the chord is accepted.
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** Same search order and the same message template, using the same nineteen command titles.
- **Verify by:** string fixture; unit on the declaration-order tie-break

### PR-WIN-134 - Shortcut overrides are stored outside the capture-run defaults indirection, unlike every other setting in this family
- **Source:** DroppyCode/Core/Models/Shortcuts.swift:261-262 and :268 the store reads and writes `UserDefaults.standard` directly | DroppyCode/UI/Chrome/WindowChrome.swift:288 and :367 SidebarLayout instead uses `CaptureRun.defaults ?? .standard` | porting/dead_code.md entry 28: CaptureRun.defaults is nil outside a capture run, so all nine redirected sites resolve to the standard store anyway
- **Preconditions:** The process is running.
- **Action:** A shortcut override is read or written.
- **Expected:** It goes to the standard store directly, not through the capture-run indirection the sidebar keys use. Outside a capture run this makes no observable difference, because the indirection resolves to the same store.
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** The port has one settings-store indirection for the whole family (port_impacts.md entry 156, C3). The asymmetry has no user-visible effect outside capture runs, which are not shipped behavior, so the port may route shortcuts through the same store; the divergence is recorded here rather than hidden.
- **Verify by:** unit: reading and writing go to the same store as the sidebar keys outside a capture run

### PR-WIN-135 - Rebindable command newThread: title "New thread", default chord Command-N, stored under "newThread"
- **Source:** DroppyCode/Core/Models/Shortcuts.swift:216 defaultChord: case .newThread: KeyChord(keyCode: 45, modifiers: .command) | DroppyCode/Core/Models/Shortcuts.swift:166-188 title: case .newThread: "New thread" | DroppyCode/Core/Models/Shortcuts.swift:190-212 detail: case .newThread: "Starts a thread in the current project." | DroppyCode/Core/Models/Shortcuts.swift:157-164 section: .newThread is in the threads section
- **Preconditions:** The shortcut store has no override for this command.
- **Action:** The command's chord is looked up, for a menu item, for a help label, or for the palette's shortcut column.
- **Expected:** The chord is Command-N. The command's title in the shortcut settings list is exactly "New thread" and its help line is exactly "Starts a thread in the current project.". It appears in the Threads section. Any override the user records is stored under the exact key "newThread".
- **Persistence:** An override for this command is stored in the "keyboardShortcuts" blob under the key "newThread". No entry means the default above applies; an entry whose chord is null means the command has been deliberately cleared and answers to no chord at all.
- **Cancellation:** not cancellable
- **Windows path:** Virtual-key VK_N with the same modifier set, Command mapping to Ctrl. The macOS key code 45 is a US key POSITION, not a character, so the Windows equivalent is the virtual-key code for the same position. The persisted macOS blob is unreadable on Windows: the port defines its own chord format and starts from these defaults (port_impacts.md entry 110, CC1).
- **Verify by:** contract fixture over all nineteen commands: case, stored key, title, detail, section and default chord
