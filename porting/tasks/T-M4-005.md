## Requirements

### PR-MCP-095 - Secret values are addressed by the account string "MCP <server id> <field key>" in one container named by the app
- **Source:** DroppyCode/Services/MCP/MCPKeychain.swift:7-9 account(server:field:) | DroppyCode/Services/MCP/MCPKeychain.swift:13-19 the query with kSecAttrService = AppInfo.name
- **Preconditions:** none
- **Action:** Any secret is read, written or deleted.
- **Expected:** The item is a generic password whose service is the app display name and whose account is the literal "MCP " + serverID + " " + fieldKey - one space after MCP and one between the two parts, with no escaping, so a server id or field key containing a space produces an ambiguous account string. Two field names are reserved by the OAuth layer and are not entry fields: "oauth" and "oauth-client".
- **Side effects:** none
- **Persistence:** the account string is the persisted key; the same container also holds the four API-provider key accounts
- **Failure cases:** none
- **Cancellation:** not cancellable
- **Windows path:** The Windows SecretStore keeps the same flat account namespace under one container named by the app display name, with the account format "MCP <server> <field>" verbatim, so the partitioning matches. DPAPI user scope through Electron safeStorage replaces kSecAttrAccessibleWhenUnlocked; that substitution is a recorded deviation with no behavioral equivalent.
- **Verify by:** integration test asserting the exact account strings written

### PR-MCP-096 - Reading a secret trims it and treats a whitespace-only value as absent
- **Source:** DroppyCode/Services/MCP/MCPKeychain.swift:11-26 value(server:field:)
- **Preconditions:** none
- **Action:** A secret is read.
- **Expected:** Under a capture run the function returns nil before touching the store at all. Otherwise it fetches exactly one matching item and returns its data decoded as UTF-8, trimmed of whitespace and newlines - but returns nil when the lookup fails, when the data is not valid UTF-8, or when the trimmed value is empty. So a stored value of spaces reads back as nil and the field falls through to its default.
- **Side effects:** one credential-store read
- **Persistence:** none
- **Failure cases:** a locked or unavailable store returns nil, which surfaces as a missing key rather than an error
- **Cancellation:** not cancellable
- **Windows path:** Same trimming and same nil-on-empty. The capture-run short circuit is capture-mode behavior, not user-reachable runtime behavior, and is recorded in dead_code entry 44; it is not a shipped requirement.
- **Verify by:** unit with a whitespace-only stored value

### PR-MCP-098 - Writing a secret updates in place first and only creates the item when none exists
- **Source:** DroppyCode/Services/MCP/MCPKeychain.swift:36-49 the update-then-add path of set
- **Preconditions:** none
- **Action:** set is called with a non-empty value.
- **Expected:** The value is trimmed and encoded as UTF-8. SecItemUpdate is attempted against (class generic password, service = app name, account = the account string) with only the data attribute; success returns true. Any status other than errSecItemNotFound returns false. On errSecItemNotFound, SecItemAdd is called with the same query plus the data and kSecAttrAccessibleWhenUnlocked, and its success is the return value. Because the update path carries no accessibility attribute, an item created by an earlier build keeps its original accessibility forever - accessibility never migrates. This is upstream behavior.
- **Side effects:** one credential-store write
- **Persistence:** the trimmed value under the account string
- **Failure cases:** a store failure returns false, which only saveCustomValues acts on
- **Cancellation:** not cancellable
- **Windows path:** Reproduce the update-then-add shape and the trimming. Windows DPAPI has no accessibility attribute, so defect 21 has no Windows analogue and the attribute has no counterpart; record that rather than inventing one.
- **Verify by:** unit over the three status outcomes
- **Upstream defect 21: reproduce it faithfully, do not fix it.**

### PR-MCP-099 - deleteAll removes only the fields the passed entry declares
- **Source:** DroppyCode/Services/MCP/MCPKeychain.swift:61-67 deleteAll(server entry:)
- **Preconditions:** A disconnect is running.
- **Action:** deleteAll(server: entry) is called.
- **Expected:** For each field of the entry, in field order, delete (entry.id, field.key). The function takes the ENTRY, not an id, precisely so a custom server - which is not in the catalog - has its variables deleted rather than silently nothing. The two OAuth field names are not entry fields and are deleted separately by MCPOAuth.signOut.
- **Side effects:** one deletion per declared field
- **Persistence:** those items are removed
- **Failure cases:** a field the entry no longer declares is left orphaned in the store
- **Cancellation:** not cancellable
- **Windows path:** Same signature: pass the entry, never look the id up in the catalog.
- **Verify by:** unit with a custom server asserting its variables are actually deleted

### PR-MCP-228 - MCPKeychain.deleteAll destroys one protected-storage item per field the ENTRY declares, under the account "MCP <id> <field key>"
> **DO NOT IMPLEMENT. Quarantined by BLK-0012 (owner decision pending).** Leave a clearly marked TODO referencing BLK-0012 and move on. Gate C fails if you implement it.
- **Source:** DroppyCode/Services/MCP/MCPKeychain.swift:61-67 - /// Forgets every secret the entry declares. The entry, not its id: a custom server /// is not in the catalog, so looking it up there would silently delete nothing. static func deleteAll(server entry: MCPCatalogEntry) { for field in entry.fields { delete(server: entry.id, field: field.key) } } | DroppyCode/Services/MCP/MCPKeychain.swift:52-59 delete(server:field:) - a kSecClassGenericPassword query with kSecAttrService = AppInfo.name and kSecAttrAccount = account(server:field:), passed to SecItemDelete with the result DISCARDED | DroppyCode/Services/MCP/MCPKeychain.swift:7-9 - private static func account(server: String, field: String) -> String { "MCP " + server + " " + field } | DroppyCode/Services/MCP/MCPStore.swift:124 - the one call site inside disconnect
- **Preconditions:** A catalog entry or custom-server entry with zero or more declared fields.
- **Action:** Its stored secrets are destroyed.
- **Expected:** One delete per field the ENTRY object declares, iterated in the entry's own field order. The account string is the literal "MCP ", the server id, a single space, and the field's key - three parts joined by single spaces, with no separator characters of any other kind. The service is AppInfo.name, one service for the whole app. The delete result is discarded, so a missing item, a locked store and a refusal are all indistinguishable and none is reported. Crucially the fields come from the ENTRY, not from a catalog lookup by id: a custom server is not in the catalog, so looking it up there would iterate an empty field list and silently delete nothing. An entry with no declared fields deletes nothing and is not an error. A field the entry NO LONGER declares keeps an orphaned item forever, because nothing enumerates the store.
- **Side effects:** One protected-storage item destroyed per declared field, unrecoverably
- **Persistence:** The secrets leave protected storage permanently; they must be re-obtained from the provider.
- **Failure cases:** A locked or unavailable store silently deletes nothing and disconnect still reports success; An entry whose declared fields changed since the values were written leaves orphans
- **Cancellation:** not cancellable once started
- **Windows path:** SECURITY-RELEVANT, DECIDE SEPARATELY. The Windows analogue is a DPAPI-protected store or Credential Manager, and the teardown must destroy exactly the items the entry declares under the same three-part account string, with the same discarded result. Reached from disconnect (PR-MCP-061) this path is implementable. Reached from the custom-server Delete affordance it is quarantined by BLK-0001, so the implementation must not be wired to any delete path while that entry is OPEN. Never fall back to a plaintext store if protected storage is unavailable: fail and leave the item alone, which matches the source's own silence.
- **Verify by:** integration test asserting one delete per declared field with the exact account string, a no-op for an entry with no fields, and that a custom server's fields are taken from the entry rather than the catalog
