## Requirements

### PR-COMPOSER-206 - A previewed image gets one cached attachment value per path, whose MIME type falls back to the literal "image/*"
- **Source:** DroppyCode/UI/Common/AttachmentPreview.swift:80-82 `/// One attachment value per file, so the preview panel's toggle recognises the same image on a second tap and closes instead of reopening.` with `@MainActor private static var attachments: [String: Attachment] = [:]` | DroppyCode/UI/Common/AttachmentPreview.swift:84-93 `/// The file as an attachment, for the same large preview a sent photo opens in.` with `static func attachment(for path: String) -> Attachment { if let known = attachments[path] { return known }; let name = (path as NSString).lastPathComponent; let mimeType = UTType(filenameExtension: (path as NSString).pathExtension.lowercased())?.preferredMIMEType ?? "image/*"; let attachment = Attachment(name: name, path: path, mimeType: mimeType.hasPrefix("image/") ? mimeType : "image/*"); attachments[path] = attachment; return attachment }`
- **Preconditions:** An image on disk is about to be shown in the large preview.
- **Action:** An attachment value is requested for its path.
- **Expected:** Exactly one attachment value exists per path for the process lifetime, returned unchanged on every later request. This identity is load-bearing, not an optimisation: the preview panel's toggle compares the value it is showing against the value it is handed, so a second tap on the same image must produce the same value or the panel reopens instead of closing. The name is the path's last component. The MIME type is resolved from the lowercased extension's preferred MIME type, but only accepted when it starts with "image/"; in every other case, including an unrecognised extension and a recognised non-image type, the MIME type is the literal string "image/*". The cache is unbounded.
- **Persistence:** A process-lifetime cache.
- **Cancellation:** not cancellable
- **Windows path:** The literal "image/*" is the fallback in two separate places in one expression and must be reproduced in both. Returning a fresh equal-valued record per call is not equivalent if the panel's toggle compares by identity; the Windows build must either keep the cache or make the toggle compare by path.
- **Verify by:** unit test over a .png, a .txt and an extensionless path asserting the MIME type, plus an interaction test that a second tap on the same image closes the panel
