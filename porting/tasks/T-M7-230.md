### PR-USAGE-010 - UsagePanel refreshes plan limits and credits once per appearance, for the lead and the heads provider

- **Action:** The view appears.
- **Expected:** refreshPlanLimits and refreshCredits are called for the chat's provider, and additionally for the heads provider when one applies. Neither PlanLimitsView nor CreditsView refreshes anything; they render only. Each call is subject to the registry gates, so reopening within 60 seconds of a successful read does no work.
- **Side effects:** May launch a provider CLI process, read a stored login or call a provider HTTP endpoint; the readers themselves belong to the provider area.
- **Persistence:** None here; the registry caches in memory only.
- **Failure cases:** A reader returning nil leaves the previous values in place; the registry assigns only on success.
- **Cancellation:** The read runs on its own task, so closing the popover that asked for it does not cancel it (ProviderRegistry.swift:604-606).
- **Windows path:** Mount effect calling the two registry methods; the reads must be detached from component lifetime so unmounting cannot abort them.
- **Verify by:** interaction test with a fake registry counting calls, including the heads case

### PR-USAGE-014 - Token counts are compacted to B, M and k with one decimal and a stripped .0
- **Source:** DroppyCode/App/Views/Usage/UsagePanel.swift:110-119 static func tokens(_ count: Int) -> String { func compact(_ value: Double, _ suffix: String) -> String { let text = String(format: "%.1f", value); return (text.hasSuffix(".0") ? String(text.dropLast(2)) : text) + suffix }; if count >= 1_000_000_000 { return compact(Double(count) / 1_000_000_000, "B") }; if count >= 1_000_000 { return compact(Double(count) / 1_000_000, "M") }; if count >= 1_000 { return compact(Double(count) / 1_000, "k") }; return "\(count)" }
- **Preconditions:** A token count is being displayed.
- **Action:** tokens(count) is called.
- **Expected:** count >= 1000000000 gives a value in billions with suffix "B"; >= 1000000 gives millions with "M"; >= 1000 gives thousands with lowercase "k"; anything below 1000 is the plain integer with no suffix. The compact form is formatted with one decimal place and a trailing ".0" is removed, so 1000 gives "1k", 1500 gives "1.5k", 1200000 gives "1.2M". There is no space between number and suffix. Negative counts fall through to the plain branch.
- **Persistence:** None.
- **Failure cases:** String(format: "%.1f") rounds half to even in the C library; reproduce with a one-decimal fixed formatter and accept the same boundary results.
- **Cancellation:** not cancellable
- **Windows path:** Pure function; toFixed(1) with a trailing ".0" strip. Must not use a locale-aware compact number formatter, which would produce "1.2K" or a different separator.
- **Verify by:** unit test at 0, 999, 1000, 1500, 999999, 1000000, 1200000, 1000000000
