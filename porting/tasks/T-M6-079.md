## Requirements

### PR-USAGE-082 - A reported usage event invalidates the cached credits and, for API-key providers, the cached plan limits
- **Source:** DroppyCode/App/Runtime/ThreadRuntime.swift:2132-2139 case .usage(let usage): self.usage = usage; saveRevision += 1; if let provider = thread?.provider { app?.providers.invalidateCredits(provider); app?.providers.invalidatePlanLimits(provider) } | DroppyCode/Services/Providers/ProviderRegistry.swift:642-647 invalidateCredits - guard exposesCredits; creditsFetchedAt[provider] = nil | DroppyCode/Services/Providers/ProviderRegistry.swift:649-655 invalidatePlanLimits - guard provider.isAPIKeyBased && exposesLimits; limitsFetchedAt[provider] = nil
- **Preconditions:** A provider session reports context usage for a thread.
- **Action:** The runtime handles the usage event.
- **Expected:** The thread's usage is replaced, the save revision is bumped so the thread document is written, and the provider's cached fetch timestamps are cleared so the next panel open reads fresh numbers rather than pre-turn ones. Credits are invalidated for any provider that exposes them; plan limits are invalidated only for API-key providers that expose limits, which in the pinned source is Z.ai alone. The cached values themselves are not cleared, only their freshness.
- **Side effects:** Schedules a thread document save.
- **Persistence:** The usage value is persisted in the thread document (PR-USAGE-084).
- **Failure cases:** A CLI-based provider's plan limits are NOT invalidated by a turn, so its windows can still be up to 60 seconds stale after a turn.
- **Cancellation:** not cancellable
- **Windows path:** Same event handling and the same two guards.
- **Verify by:** unit test on both invalidation guards plus an interaction test that a turn makes the next popover open re-read
