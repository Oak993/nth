- **Cancellation:** not cancellable
- **Windows path:** No menu item (OD-0008 C3). Hard-coded character key equivalent (-), outside the shortcut store (PR-WIN-226).

### PR-WIN-226 - The zoom chords are hard-coded: not rebindable, not listed in the shortcut settings, not reserved, and not checked for conflicts
- **Source:** DroppyCode/App/AppCommands.swift:54, :56, :58, :61 `.keyboardShortcut("+", modifiers: .command)`, `.keyboardShortcut("-", modifiers: .command)`, `.keyboardShortcut("0", modifiers: .command)`, `.keyboardShortcut("=", modifiers: .command)`, literal key equivalents rather than `shortcuts.keyboardShortcut(for:)` | DroppyCode/Core/Models/Shortcuts.swift:251-257 the reserved list holds Command with Q, H, M, C, V, X, A, Z, Shift-Command-Z and Command-1 to Command-9 only | DroppyCode/Core/Models/Shortcuts.swift:329-331 the conflict check searches only `AppShortcut.allCases`
- **Preconditions:** The user records a chord for a rebindable command.
- **Action:** The chord is Command-minus or Command-=, or Command-0.
- **Expected:** The four zoom items have no AppShortcut case, so they have no row in the shortcut settings, no override and no default in the store. Recording Command-minus or Command-= for a rebindable command is accepted with no refusal, because neither the reserved list nor the conflict check knows the zoom chords. Recording Command-0 is refused with "Show Droppy Code already uses this chord." only while showMainWindow holds it, because that check sees the showMainWindow command, not "Actual Size". DEVIATION (OD-0002, OD-0012 F1): the owner's title carries the product name, so in the port the refusal reads exactly "Show Marrow already uses this chord." (PR-WIN-152) under the same condition. DEVIATION (OD-0012 G6): showMainWindow has no default chord in the port, so recording Ctrl+0 is refused that way only after the user has recorded Ctrl+0 for showMainWindow; otherwise, like Ctrl+- and Ctrl+=, it is accepted with no refusal.
- **Persistence:** nothing persisted by the zoom items
- **Failure cases:** A rebindable command recorded on Command-minus or Command-= then shares its chord with a zoom item; which one fires is not expressed in source (UNRESOLVED). In the port, where showMainWindow has no default chord (OD-0012 G6), a command recorded on Ctrl+0 shares it with Actual Size in the same way.
- **Cancellation:** not cancellable
- **Windows path:** Same: the port's four zoom chords (Ctrl with +, -, 0 and =) are fixed, outside the shortcut store. Reproduce the absence of a guard rather than adding the zoom chords to the reserved list. The conflict refusal names the owner by its port title, so the showMainWindow case reads "Show Marrow already uses this chord." (OD-0002, OD-0012 F1); under OD-0012 G6 that case arises only once the user has given showMainWindow Ctrl+0, because it has no default chord. Which command fires when a recorded chord shares Ctrl+-, Ctrl+= or Ctrl+0 with a zoom chord depends on macOS menu dispatch upstream and is tracked under UNK-0003.
- **Verify by:** unit: the refusal check accepts Ctrl+- for a rebindable command; contract fixture: the shortcut settings list has no zoom rows; unit: with no overrides, recording Ctrl+0 for a rebindable command is accepted (OD-0012 G6)
- **Depends on UNK-0003**, which is unresolved. Implement only the part the source settles; flag the rest.
