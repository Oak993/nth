### PR-MCP-039 - MCPCatalogEntry.fill substitutes every {key} with the user's value or the field's default
- **Source:** DroppyCode/Core/Models/MCP.swift:132-147 fill(_:values:) - :135 var value = values[field.key].flatMap { $0.isEmpty ? nil : $0 } ?? field.defaultValue ?? "" | :136 let token = "{\(field.key)}" | :138 value = value.trimmed | :144 out = out.replacingOccurrences(of: token, with: value)
- **Preconditions:** An entry with fields and a values map.
- **Action:** An arg, env value, header value or OAuth URL containing {key} is resolved.
- **Expected:** For each field of the entry in field order, the token is the string "{" + field.key + "}". The replacement value is values[field.key] when present and non-empty, else field.defaultValue, else the empty string. Every occurrence of the token in the text is replaced by Foundation's replacingOccurrences(of:with:) with no options (not .literal), so matching is by Unicode canonical equivalence, as is the Swift String dictionary lookup values[field.key]; for ASCII keys and text this is the same as an exact ordinal match. Fields not referenced in the text have no effect. Tokens naming keys that are not fields of the entry are left untouched.
- **Side effects:** none
- **Persistence:** none
- **Failure cases:** an empty draft value falls through to defaultValue, not to "" - a user who clears an optional field gets the default back
- **Cancellation:** not cancellable
- **Windows path:** Replacement in field order that matches by Unicode canonical equivalence, as Foundation's non-literal replacingOccurrences does (for ASCII-only keys and text, ordinal replacement gives the same result). Do not use a regular expression that would also match tokens for non-fields.
- **Verify by:** unit with an empty value, a missing value, a repeated token and an unknown token

### PR-MCP-040 - A placeholder standing as a URL host is stripped of its scheme and trailing slashes
- **Source:** DroppyCode/Core/Models/MCP.swift:137-143 the "://" + token branch of fill - :137 if out.contains("://" + token) { | :138 value = value.trimmed | :139 for scheme in ["https://", "http://"] where value.lowercased().hasPrefix(scheme) { | :140 value = String(value.dropFirst(scheme.count)) | :142 while value.hasSuffix("/") { value.removeLast() }
- **Preconditions:** The text being filled contains the literal "://{key}" (only gitlab's "https://{instance}/api/v4/mcp" does so in the shipped catalog).
- **Action:** The user types an instance address such as "  https://gitlab.example.com/  " and connects.
- **Expected:** Only when the text contains "://" immediately before the token: the value is trimmed of leading and trailing whitespace and newlines; then, for each of "https://" and "http://" in that order, if the value lowercased starts with that scheme the scheme's characters are dropped from the front; then trailing "/" characters are removed one at a time until none remain. The result for the example is "gitlab.example.com", producing "https://gitlab.example.com/api/v4/mcp". The scheme loop runs over both schemes, so a value beginning "https://http://x" loses both prefixes.
- **Side effects:** none
- **Persistence:** the raw typed value is stored in mcp.json; normalization is applied at resolve time, every time
- **Failure cases:** a value that is only "/" characters normalizes to the empty string and produces "https:///api/v4/mcp"
- **Cancellation:** not cancellable
- **Windows path:** Same conditional normalization, and only for tokens directly after "://".
- **Verify by:** unit with whitespace, both schemes, multiple trailing slashes, and a token not preceded by "://" (which must be left alone)
