### PR-LAUNCH-053 - saveBeforeQuit latches persistence off permanently and cancels the debounced save before writing
- **Source:** DroppyCode/App/AppModel.swift:1326-1331 - comment 'Writes everything synchronously, for use while the app terminates.' then 'guard persistenceEnabled else { return }', 'persistenceEnabled = false', 'saveTask?.cancel()', 'saveTask = nil' | DroppyCode/App/AppModel.swift:118 - @ObservationIgnored private var persistenceEnabled = true | DroppyCode/App/AppModel.swift:1304-1314 scheduleSave() - 'guard persistenceEnabled else { return }' then cancel-and-restart a task that sleeps 400 ms and calls saveLibrary() | DroppyCode/App/AppModel.swift:1316-1317 saveLibrary() - 'guard persistenceEnabled else { return }'
- **Preconditions:** Termination step 1.
- **Action:** saveBeforeQuit() runs.
- **Expected:** A second call to saveBeforeQuit does nothing, because of the latch. The pending debounced save is cancelled so it cannot race the synchronous write. After the latch, every later scheduleSave() and saveLibrary() is a no-op for the rest of the process, so nothing that changes during shutdown is written to library.json.
- **Side effects:** Cancels the debounced save task
- **Persistence:** Suppresses all later library writes.
- **Cancellation:** not cancellable
- **Windows path:** Direct port including the 400 ms debounce and the one-way latch. port_impacts.md entry 100 requires the persistenceEnabled latch to be ported together with the teardown ordering, because the ordering only has meaning through it.
- **Verify by:** unit test: a thread mutation after saveBeforeQuit writes nothing
