### PR-USAGE-109 - Grid cell values are per-day, per-week or running-cumulative depending on the mode, and maxValue is their maximum
- **Source:** DroppyCode/Services/Store/TokenLedger.swift:673-700 switch mode { case .daily: each in-range cell takes its own day total; case .weekly: each column sums its seven days and every non-nil cell of that column takes the week total, nil cells take 0; case .cumulative: a running total accumulates across columns and rows in order and every cell, including nil cells, takes the running value }; let maxValue = values.flatMap { $0 }.max() ?? 0
- **Preconditions:** The grid is being built for a mode.
- **Action:** Values are filled.
- **Expected:** Daily: each cell holds its own day's total, zero when absent. Weekly: each column's seven day totals are summed and every non-nil cell in that column holds the week total while nil cells hold zero. Cumulative: a single running sum walks columns then rows in order, adding each in-range day, and every cell holds the running value at that point, including cells outside the year. maxValue is the maximum across all cells, or zero for an empty grid.
- **Persistence:** None.
- **Failure cases:** In cumulative mode the leading out-of-range cells hold the running value zero, and the trailing ones hold the year's final total.
- **Cancellation:** not cancellable
- **Windows path:** Same three fill strategies and the same iteration order for the cumulative running sum.
- **Verify by:** unit test comparing all three modes over the same small day map
