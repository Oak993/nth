## Requirements

### PR-PROVCLI-311 - Pi's catalog probe reads until both replies arrive or thirty seconds pass, then terminates
- **Source:** DroppyCode/Services/Providers/PiCLI.swift:65-83 - the two response slots, the 30 second timeout task, the read loop breaking when both are present, then timeout.cancel() and process.terminate()
- **Preconditions:** The probe started.
- **Action:** The probe reads.
- **Expected:** Each inbound message is filed by its "id": the literal "state" or the literal "models"; anything else is ignored. The loop breaks as soon as BOTH have arrived. A detached Task sleeps exactly 30 seconds and then terminates the process unconditionally - note it does NOT check for cancellation first, unlike Claude's and Codex's watchdogs, so a late cancel races the terminate harmlessly. After the loop the timer is cancelled and the process terminated again.
- **Side effects:** Process termination
- **Persistence:** none
- **Failure cases:** A timeout ends the stream with one or both replies missing, which produces the no-models error.
- **Cancellation:** The 30 second timer.
- **Windows path:** terminate() is TerminateProcess; the probe persists nothing so that is acceptable.
- **Verify by:** interaction test with a stand-in that answers only one request

### PR-PROVCLI-312 - Pi's catalog maps models to provider-slash-id options sorted by provider then name
- **Source:** DroppyCode/Services/Providers/PiCLI.swift:85-112 - the mapping, the current-model test, the empty-list throw and the sort
- **Preconditions:** Both probe replies arrived.
- **Action:** listModels builds the catalog.
- **Expected:** The state payload is stateResponse.data, else the response itself, else JSON null; the current provider and id come from its model.provider and model.id. The items come from modelsResponse.data.models, else modelsResponse.models, else the empty array. Each item needs a string "provider" and a string "id"; reasoning is item.reasoning being exactly true. The option id is "<provider>/<id>", the name is item.name or the id, the detail is the PROVIDER string, the efforts are the seven thinking levels when reasoning and the empty array otherwise, and the default effort is the literal "medium" when reasoning and nil otherwise. isDefault is true when a current provider and id are both known AND either the current id contains a slash and equals the full id, or it does not and the provider and id match separately. An EMPTY result throws ProviderError.failed("Pi listed no models.") verbatim. The list is finally sorted by the pair (detail or the empty string, name) - that is, by provider then name.
- **Persistence:** The registry persists the catalog.
- **Failure cases:** The exact message above.
- **Cancellation:** not cancellable
- **Windows path:** The sort compares strings; it must be ordinal so the catalog order is stable across locales.
- **Verify by:** unit test over a reasoning model, a non-reasoning model, both current-id shapes and an empty list
