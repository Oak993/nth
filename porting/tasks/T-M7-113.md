  - type: .callout
  - colour: .secondary

  - interactions: none
- **UI-COMPOSER-065** Composer area, approval card / Approval option buttons (button)
  - text, verbatim: `<option.title, supplied by the request>`
  - geometry: Trailing HStack(spacing: 8) over the options reversed, after a leading spacer
  - type: Per the glass button styles
  - colour: Approve: .glassProminent; every other role: .glass
  - states: only the top card's approve option claims Command-Return
  - interactions: click resolves the request with that option; Command-Return activates the top card's approve option
- **UI-RUNTIME-006** Composer, approval card / Approval option buttons (button)
  - text, verbatim: `The label of each button is ApprovalRequest.Option.title, supplied by the provider, never by the app. The app contributes no button text here.`
  - geometry: HStack spacing 8 with a leading Spacer, so the buttons are right-aligned. Rendered in reverse of the options array, so the provider's first option ends up rightmost.
  - type: Inherited from the button styles; no explicit font.
  - colour: An option whose role is .approve uses .glassProminent; every other role uses .glass.
  - states: Only the card whose request is first in runtime.approvals owns the keyboard chord; a second card's approve button carries no shortcut, because two cards both claiming it left neither reliably approving.
  - interactions: Click calls runtime.resolve(request, option:). The approve-role button of the frontmost card also answers Command+Return.
