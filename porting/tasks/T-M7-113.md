### PR-GIT-142 - The changes tab is shown only when the thread has change statistics, and its counts come from one summary
- **Source:** DroppyCode/App/Views/Composer/ThreadChangesTab.swift:9-44 - `let stats: FileChangeSummary`; the file count `Text(verbatim: stats.files.count == 1 ? "1 file" : "\(stats.files.count) files")`, the additions `Text(verbatim: "+\(stats.additions)")`, the deletions `Text(verbatim: "\u{2212}\(stats.deletions)")` and the accessibility label all read the one summary | DroppyCode/App/Runtime/ThreadRuntime.swift:1945-1953 refreshChangeStats() - runs once per diff revision, parses the whole thread's diff and sets changeStats to nil when there are no files | DroppyCode/App/Runtime/ThreadRuntime.swift:1938-1939 - changeStats is nil when the thread changed no files
- **Preconditions:** A thread is shown.
- **Action:** The composer lays out its tab row.
- **Expected:** The statistics are computed once per diff revision; showing the thread again, switching threads or reopening the window reuses what the last run found rather than running git and the parser again. When the parsed diff has no files the statistics are nil and the tab is absent. The tab's file count, addition total and deletion total all come from the one summary, so the count in the label and the rows behind it can never disagree.
- **Side effects:** Git and parsing work on the first run per revision
- **Persistence:** None; recomputed per runtime.
- **Failure cases:** A diff that cannot be produced yields no files and therefore no tab
- **Cancellation:** The refresh checks the revision again after the parse and abandons a stale result.
- **Windows path:** Direct port.
- **Verify by:** interaction test asserting the tab appears after the first file-changing turn and not before
