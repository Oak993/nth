### PR-PROVACP-041 - Config option values are flattened one level, so grouped values are read
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:334 - `let values = Self.flatten(option["options"]?.array ?? [])`; :400-405 - `values.flatMap { value in if let nested = value["options"]?.array { return nested }; return [value] }`
- **Preconditions:** A config option carries an options array whose entries may themselves be groups.
- **Action:** flatten runs.
- **Expected:** Exactly ONE level of nesting is unwrapped: an entry with an `options` array is replaced by that array's contents, and an entry without one is kept as is. A group entry is never itself treated as a value, and a doubly nested group is not unwrapped further.
- **Persistence:** None.
- **Failure cases:** Two levels of nesting leave group objects in the value list; those have no `value` string and are dropped by the later compactMaps.
- **Cancellation:** not cancellable
- **Windows path:** Same single-level flatMap.
- **Verify by:** unit

### PR-PROVACP-043 - The rebuilt model list is matched against the previous one by base id, through a prebuilt dictionary
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:343 - `let knownByID = Dictionary(models.map { (Self.baseModelID($0.id), $0) }, uniquingKeysWith: { first, _ in first })` | DroppyCode/Services/Providers/ACPSession.swift:340-342 - comment: one lookup per value, because the walk over OpenCode's four hundred models replies four hundred times and a linear search per value stalled the main actor | DroppyCode/Services/Providers/ACPSession.swift:350,355-359 - `let known = knownByID[Self.baseModelID(valueID)]`; efforts, defaultEffort and fastTier are carried over from `known` | DroppyCode/Services/Providers/ACPSession.swift:347-349 - comment: a rebuilt list keeps what earlier passes learned about each model, because Cursor reports them for the current model only
- **Preconditions:** A model config option is rebuilding the list while a previous catalog exists.
- **Action:** applyConfigOptions rebuilds.
- **Expected:** The lookup dictionary is keyed on baseModelID of the existing entries, and on a duplicate base id the FIRST entry wins. Each rebuilt option inherits efforts, defaultEffort and fastTier from the matching previous entry, so knowledge accumulated across the catalog probe's per-model passes is not thrown away. The dictionary is built once per call, not per value; this is a stated performance requirement, not an implementation detail: O(n*m) here stalls the UI thread on a 400-model catalog.
- **Persistence:** None.
- **Failure cases:** Two models whose base ids collide share the first one's learned scale.
- **Cancellation:** not cancellable
- **Windows path:** Same. Build a Map once per call. The renderer must not do this work per value; the 400-model OpenCode walk is the stated stress case.
- **Verify by:** unit plus a performance guard (400 models x 400 replies completes without blocking)
