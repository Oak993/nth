## Requirements

### PR-STORE-053 - The recent cache is generational, not least-recently-used
- **Source:** DroppyCode/Core/Support/RecentCache.swift:9-20 - private var current / previous dictionaries, currentCost / previousCost, limit and costLimit set in init | DroppyCode/Core/Support/RecentCache.swift:30-32 - contains(_:) is true when the key is in either generation | porting/port_impacts.md entry 117 - "Implement the generational cache exactly; an LRU substitute changes hit rate and memory ceiling."
- **Preconditions:** None.
- **Action:** Any cache use (prefetch ready cache, thumbnail cache, thumbnail memory).
- **Expected:** Two dictionaries are kept. Lookups consult both. Effective capacity is up to twice the limit for reads, because entries demoted to the previous generation remain findable.
- **Persistence:** none
- **Cancellation:** not cancellable
- **Windows path:** Port the generational structure verbatim. An LRU substitute has a different hit rate and a different memory ceiling and would change how often threads and thumbnails are re-decoded.
- **Verify by:** unit reproducing a known hit and eviction sequence

### PR-STORE-054 - A hit in the previous generation is promoted back into the current one
- **Source:** DroppyCode/Core/Support/RecentCache.swift:22-28 - mutating func value(for key:) returns current[key] directly, otherwise removes the entry from previous, subtracts its cost from previousCost and re-inserts it into current at the same cost
- **Preconditions:** The key is in the previous generation.
- **Action:** A read for that key.
- **Expected:** The entry is moved into the current generation at its original cost and returned. Because it re-inserts, the read can itself trigger a rollover. The read is therefore a mutating operation.
- **Persistence:** none
- **Cancellation:** not cancellable
- **Windows path:** The reader must have write access to the cache. A port that exposes a const read will silently lose the promotion and halve the effective capacity.
- **Verify by:** unit

### PR-STORE-055 - The current generation rolls over when it is full by count or by cost
- **Source:** DroppyCode/Core/Support/RecentCache.swift:47-55 - if current.count >= limit || currentCost > costLimit - cost { previous = current; previousCost = currentCost; current = [:]; current.reserveCapacity(limit); currentCost = 0 }; current[key] = Entry(value:cost:); currentCost += cost
- **Preconditions:** The current generation holds limit entries, or adding this cost would exceed the budget.
- **Action:** An insert.
- **Expected:** The whole current map becomes previous, the old previous map is discarded in that same assignment, current is emptied and re-reserved to the limit, and the new entry is written into the fresh current. The condition is exactly current.count >= limit || currentCost > costLimit - cost, evaluated before the write.
- **Persistence:** none
- **Cancellation:** not cancellable
- **Windows path:** Same condition, same wholesale discard, same ordering (rollover, then write).
- **Verify by:** unit on both arms of the condition
- **Upstream defect 44: reproduce it faithfully, do not fix it.**

### PR-STORE-056 - Inserting an over-budget value evicts the existing entry for that key and stores nothing
- **Source:** DroppyCode/Core/Support/RecentCache.swift:43-46 - mutating func insert(_ value:for:cost:) { removeValue(for: key); let cost = max(0, cost); guard cost <= costLimit else { return } ... } | DroppyCode/Core/Support/ThumbnailCache.swift:16 - RecentCache<String, Thumbnail>(limit: 120, costLimit: 32 * 1_024 * 1_024); :25 key "\(path)#\(pixels)#\(fillingSquare)"; :26 and :39 lookup, then insert after the decode | DroppyCode/Core/Support/ThumbnailCache.swift:70 - RecentCache<String, CGImage>(limit: 120, costLimit: 16 * 1_024 * 1_024); :72-74 key "\(path)#\(pixels)" | DroppyCode/Services/Store/Storage.swift:264-270 - DocumentPrefetch init(limit: 12, costLimit: 16 * 1_024 * 1_024, ...) builds the ready RecentCache
- **Preconditions:** The key is already cached with a good value, and the new value’s cost exceeds costLimit.
- **Action:** insert of the over-budget value.
- **Expected:** The existing entry is removed first, then the guard rejects the new value and returns. The cache is left worse than before the call: the key is now absent altogether. This is upstream defect 43 and is reproduced.
- **Persistence:** none
- **Failure cases:** A thread document whose cost exceeds 16 MiB (DocumentPrefetch's ready cache, Storage.swift:264-270) is never cached, and inserting it also removes the earlier version cached under the same thread id.; Image bitmaps go through two caches with different limits: ThumbnailCache.thumbnails at 32 MiB (ThumbnailCache.swift:16) and ThumbnailMemory.images at 16 MiB (ThumbnailCache.swift:70). A bitmap over 16 MiB is never kept in ThumbnailMemory, and one over 32 MiB is kept in neither. Both keys include the pixel size (:25, :73), so an over-budget bitmap never displaces a smaller version of the same image: ThumbnailCache inserts a key only after a miss for it (:26, :39), and ThumbnailMemory.store (:80-82) can only replace an entry with the same path and pixel size.
- **Cancellation:** not cancellable
- **Windows path:** Reproduce the ordering exactly: remove, clamp, then reject. It is an ordinary quirk under AM-0001 (a cache miss, no lasting harm), so it is the product.
- **Verify by:** unit
- **Upstream defect 43: reproduce it faithfully, do not fix it.**

### PR-STORE-057 - Cache limits and costs are clamped on the way in
- **Source:** DroppyCode/Core/Support/RecentCache.swift:16-20 - self.limit = max(1, limit); self.costLimit = max(0, costLimit); current.reserveCapacity(self.limit) | DroppyCode/Core/Support/RecentCache.swift:44 - let cost = max(0, cost) | DroppyCode/Core/Support/RecentCache.swift:43 - cost defaults to 1
- **Preconditions:** None.
- **Action:** Cache construction and insert.
- **Expected:** A limit below 1 becomes 1, a negative cost limit becomes 0, a negative insert cost becomes 0, and an insert with no explicit cost charges 1. The current dictionary reserves capacity for the clamped limit at construction and again at each rollover.
- **Persistence:** none
- **Failure cases:** A costLimit of 0 rejects every entry with a non-zero cost, since guard cost <= costLimit fails.
- **Cancellation:** not cancellable
- **Windows path:** Same three clamps and the same default cost of 1.
- **Verify by:** unit

### PR-STORE-058 - Removing a key clears it from both generations and refunds both cost counters
- **Source:** DroppyCode/Core/Support/RecentCache.swift:34-41 - removeValue(for:) removes from current and from previous, subtracts each entry’s cost from the matching counter, and returns the current entry’s value if there was one, otherwise the previous entry’s | DroppyCode/Core/Support/RecentCache.swift:12, :25, :39, :49 - the only previousCost references at B2 (grep over the pinned tree); none reads it | DroppyCode/Core/Support/RecentCache.swift:43-56 - insert: removeValue(for: key) first; rollover when current.count >= limit || currentCost > costLimit - cost, then previous = current, current = [:]
- **Preconditions:** The key may be in the current or the previous generation. It is never in both: insert removes the key from both before storing it (RecentCache.swift:44), a promotion removes it from previous before re-inserting it (:24-26), and a rollover replaces previous with the current map and starts current empty (:47-52).
- **Action:** removeValue(for:), directly or through insert.
- **Expected:** Both dictionaries are cleaned and both running cost sums are reduced by the removed entry's cost. The removed value is returned: the current generation's entry if there was one, otherwise the previous generation's (:40); the result is discardable. Only currentCost is observable, because it alone decides a rollover (:47). previousCost is written at :25, :39 and :49 and read nowhere in the tree, so its refund has no observable effect.
- **Persistence:** none
- **Cancellation:** not cancellable
- **Windows path:** Same dual removal. The currentCost refund is load-bearing: without it the budget leaks and rollovers come early. previousCost is write-only in the source; keeping it is harmless, and no test can observe it.
- **Verify by:** unit
