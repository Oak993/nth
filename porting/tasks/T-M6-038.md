## Requirements

### PR-TERM-065 - Running a script opens a new terminal tab named after the script, in the thread's working directory, and shows the drawer
- **Source:** DroppyCode/App/AppModel.swift:1103-1107 runScript(_:threadID:) - returns unless the thread and its project resolve; calls terminals.run(script, threadID: threadID, directory: thread.worktreePath ?? project.path); then sets runtime(for: threadID).isTerminalVisible = true | DroppyCode/App/Views/Terminal/TerminalStore.swift:127-129 run(_:threadID:directory:) - open(threadID:directory:title: script.name, command: script.command)
- **Preconditions:** A thread with a project is selected.
- **Action:** The user picks a script from the menu, or presses the Run top script chord.
- **Expected:** A NEW tab is always opened, never reused: it is titled exactly the script's name, runs in the thread's worktree path if it has one and otherwise the project path, and starts the shell with the script's command followed by a hand-back to an interactive shell (PR-TERM-123). In the port that shell is PowerShell 7 if installed, otherwise Windows PowerShell (OD-0008 C5). The new tab is selected and the terminal drawer is shown; because the drawer was previously hidden in the usual case, opening it also moves keyboard focus into the terminal (PR-TERM-030). Running the same script five times leaves five tabs with the same name.
- **Side effects:** A shell process is launched; the drawer becomes visible.
- **Persistence:** None.
- **Failure cases:** The thread or project does not resolve: nothing happens at all, with no message.
- **Cancellation:** The user can interrupt the command from inside the terminal; there is no app-level cancel.
- **Windows path:** Same, with the interpreter of OD-0008 C5 (PowerShell 7 if installed, otherwise Windows PowerShell) and the script vector of PR-TERM-123.
- **Verify by:** interaction test asserting the tab title, directory and drawer visibility

### PR-TERM-066 - Creating a worktree runs every script flagged runOnWorktreeCreate in the new worktree and shows the drawer
- **Source:** DroppyCode/App/AppModel.swift:1142-1146 - after the worktree is added and the thread updated: for script in project.scripts where script.runOnWorktreeCreate { terminals.run(script, threadID: threadID, directory: path); runtime(for: threadID).isTerminalVisible = true } | DroppyCode/App/AppModel.swift:1125-1141 createWorktree(for:) - the surrounding flow, including the git preconditions and the generated path and branch
- **Preconditions:** A thread is being given its own git worktree and the project has flagged scripts.
- **Action:** The worktree is created successfully.
- **Expected:** Each flagged script runs in its own new tab, in project order, with the NEW WORKTREE path as the directory rather than the project path, and the drawer is shown. Unflagged scripts do not run. Nothing runs if the worktree creation fails or is refused.
- **Side effects:** One shell process per flagged script; the drawer becomes visible.
- **Persistence:** None from this step; the thread's worktreePath and branch were written just before.
- **Failure cases:** Worktree creation throws: an alert titled "Could not create a worktree" is shown and no script runs.; Not a git repository or no commits: the alert is titled "Worktree unavailable" with the message "New worktrees need a git repository with at least one commit." and no script runs.
- **Cancellation:** not cancellable
- **Windows path:** Same ordering and the same directory choice.
- **Verify by:** integration test creating a worktree in a project with one flagged and one unflagged script

### PR-TERM-067 - The top script is the selected thread's project's first script; its menu item does not exist in the port and the command stays on its chord
- **Source:** DroppyCode/App/AppModel.swift:1098-1101 topScript - nil unless a thread is selected and resolves; otherwise project.scripts.first | DroppyCode/App/AppCommands.swift:89-94 - Button titled model.topScript.map { "Run \($0.name)" } ?? - **Preconditions:** A thread may or may not be selected.
- **Action:** The user presses the Run top script chord.
- **Expected:** topScript is nil unless a thread is selected and resolves, otherwise the project's first script. Upstream shows a menu item reading "Run " followed by that script's name, or exactly "Run top script" and disabled when there is none, with the default chord Command-R. DEVIATION (OD-0008 C3): the port has no menu bar, so there is no such item and no item title. The command stays on its chord (Ctrl+R by default, OD-0008 B7): with a top script and a selected thread it runs the first script exactly as the popover row does; otherwise it does nothing. The source's command palette has no Run top script row (DroppyCode/App/Views/Palette/CommandPalette.swift:153-178 lists New thread, New thread in worktree, Add project, the three thread actions Toggle terminal, Toggle changes and finish, and Settings), so none is added.
- **Side effects:** A shell process is launched and the drawer is shown.
- **Persistence:** None.
- **Failure cases:** No selected thread or no scripts: the chord does nothing.
- **Cancellation:** not cancellable
- **Windows path:** No menu item. The chord handler keeps the item's guard (model.topScript and model.selectedThreadID) and calls runScript.
- **Verify by:** interaction test pressing the chord with and without scripts, plus an assertion that no menu bar exists
