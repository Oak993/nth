## The probe, verbatim from the stack decision

P6 - Graceful-then-forceful termination with the one-second gap, per transport. Three cases against scripted fixture stand-ins (never a signed-in agent): 0x03 written into ConPTY input for a pty child; stdin close then CTRL_BREAK via an AttachConsole / GenerateConsoleCtrlEvent(CTRL_BREAK_EVENT) / FreeConsole helper for a CREATE_NEW_PROCESS_GROUP console child; and TerminateJobObject at the deadline. PASS: a cooperating fixture exits before t+1000 ms and a deliberately non-cooperating one is terminated at t+1000 ms, both timestamps logged within +/- 50 ms, and a write to a closed pipe surfaces as IOException with ERROR_BROKEN_PIPE or ERROR_NO_DATA and is handled as recoverable. This reproduces C4 / Shell.swift:110-118 / StdioProcess.swift:114-120 rather than collapsing the pair into one kill.

## Rules

- Read `WORKER_BRIEF.md` first. Model the probe on `porting/probes/p1-glass/`, which passed.
- A probe PROVES or DISPROVES one capability. Report the measured result, whichever it is.
  A FAIL reported honestly is a valuable result. A PASS you did not measure is worthless.
- Build a control case that must fail when the thing under test is absent, as P1 did with
  its tint-only render. Without one, a PASS cannot be trusted.
- Never send a prompt to a real AI CLI; `--version` or `--help` only.
- Set `MARROW_PORT_DATA_DIR` to a throwaway folder before running anything.
