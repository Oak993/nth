| Field | Value |

## The probe, verbatim from the stack decision

P3 - Acrylic edge over the desktop, and the layered-window trap. Set Window.TransparencyLevelHint = WindowTransparencyLevel.AcrylicBlur on an Avalonia 12 window with ExtendClientAreaToDecorationsHint true, over a high-contrast desktop wallpaper, and capture with Alt+PrtScn so the window KEEPS FOCUS (background acrylic is documented to flatten to a solid colour on deactivation; pin SystemBackdropConfiguration-equivalent behaviour rather than tracking activation). PASS: desktop content is visibly blurred and tinted through the window, AND the capture's sha256 differs from a bare desktop grab. This is the exact abort condition the repository's own E:/Droppy/port/porting/probes/acrylic_window.ps1 already hit - control_solid.png, desktop_plain.png, acrylic_real.png and acrylic_excluded_from_capture.png are all sha256 98d72e76..., four byte-identical desktop grabs, because Form.TransparencyKey set WS_EX_LAYERED and DWM system backdrops do not apply to layered windows. Assert in the probe that the Avalonia window is never WS_EX_LAYERED. FAIL: fall back to a DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE, DWMSBT_TRANSIENTWINDOW) P/Invoke on TopLevel.TryGetPlatformHandle().Handle, and if that shows nothing, force Win32CompositionMode.RedirectionSurface for that window and re-probe.

## Rules

- Read `WORKER_BRIEF.md` first. Model the probe on `porting/probes/p1-glass/`, which passed.
- A probe PROVES or DISPROVES one capability. Report the measured result, whichever it is.
  A FAIL reported honestly is a valuable result. A PASS you did not measure is worthless.
- Build a control case that must fail when the thing under test is absent, as P1 did with
  its tint-only render. Without one, a PASS cannot be trusted.
- Never send a prompt to a real AI CLI; `--version` or `--help` only.
- Set `MARROW_PORT_DATA_DIR` to a throwaway folder before running anything.
