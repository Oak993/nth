## Requirements

### PR-PROVACP-132 - The exit code is read from rawOutput.exitCode or rawOutput.metadata.exit
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:766 - `result.exitCode = raw["exitCode"]?.int ?? raw["metadata"]?["exit"]?.int`
- **Preconditions:** A tool update carries a non-null rawOutput.
- **Action:** makeToolUpdate reads the exit code.
- **Expected:** rawOutput.exitCode wins; failing that, rawOutput.metadata.exit is used; failing both, the exit code is nil. This assignment runs whenever rawOutput is non-null, even when the content-block branch supplied the output.
- **Persistence:** The exit code is persisted with the tool call.
- **Cancellation:** not cancellable
- **Windows path:** Same two sources in the same order. Windows exit codes can exceed the signed range Unix uses; store the integer the agent reports without clamping.
- **Verify by:** unit

### PR-PROVACP-133 - The literal string (no output) is suppressed as tool output
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:768 - `if !output.isEmpty, output != "(no output)" { result.output = output }`
- **Preconditions:** An output string was collected.
- **Action:** makeToolUpdate finalizes the output.
- **Expected:** An empty output leaves ToolUpdate.output nil. An output equal to exactly "(no output)" - parentheses, lowercase, one space - also leaves it nil, so the row shows no output pane instead of that placeholder. The comparison is exact and unaffected by surrounding whitespace, so " (no output)" is shown.
- **Persistence:** None.
- **Cancellation:** not cancellable
- **Windows path:** Same literal.
- **Verify by:** unit

### PR-PROVACP-134 - A non-zero exit code downgrades a completed tool update to failed
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:769 - `if let exitCode = result.exitCode, exitCode != 0, result.status == .completed { result.status = .failed }`
- **Preconditions:** A tool update has both an exit code and a status.
- **Action:** makeToolUpdate finalizes the status.
- **Expected:** Only a status that is exactly .completed is downgraded, and only when the exit code is present and not zero. A .running or .failed status is untouched, and an update with no status keeps a nil status even with a non-zero exit code.
- **Persistence:** The status is persisted with the tool call.
- **Cancellation:** not cancellable
- **Windows path:** Same. Note that a Windows command failing with a large unsigned exit code is still non-zero and so is downgraded.
- **Verify by:** unit (status and exit-code matrix)

### PR-PROVACP-135 - A tool update carries edits only when at least one diff block was found
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:754-755 - `let edits = diffs(update["content"]); if !edits.isEmpty { result.edits = edits }`
- **Preconditions:** A tool update carries content blocks.
- **Action:** makeToolUpdate maps the edits.

Contrast makeToolCall, which assigns call.edits unconditionally (:734), so a tool call with no diff blocks starts with an empty edit list.
- **Persistence:** Persisted with the tool call.
- **Cancellation:** not cancellable
- **Windows path:** Same nil-versus-empty distinction.
- **Verify by:** unit

### PR-PROVACP-136 - The catalog probe runs a throwaway session in a named temporary directory
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:229-230 - `let directory = FileManager.default.temporaryDirectory.appendingPathComponent("droppy-code-catalog", isDirectory: true); try? FileManager.default.createDirectory(at: directory, withIntermediateDirectories: true)` | DroppyCode/Services/Providers/ACPSession.swift:231-238 - `ACPSession(configuration: SessionConfiguration(provider:executable:workingDirectory: directory, environment:, runtimeMode: .supervised, interactionMode: .build))` | DroppyCode/Services/Providers/ACPSession.swift:898-920 - the convenience init fills resumeID, resumeAt, model and effort with nil | DroppyCode/Services/Providers/ProviderRegistry.swift:570 - `case .cursor, .grok, .devin: try? await ACPSession.probeModels(provider: provider, executable: executable, environment: environment)`
- **Preconditions:** The registry asks for a model catalog for an ACP provider.
- **Action:** probeModels runs.
- **Expected:** The working directory is the system temporary directory plus the folder name "marrow-catalog" (deviation OD-0008, OD-PENDING-17: upstream uses the literal "droppy-code-catalog"), created with intermediate directories; a creation failure is swallowed and the probe proceeds. The throwaway session always uses runtimeMode .supervised and interactionMode .build, and has no resume id, no model and no effort, so the probe never launches with a permissive flag and never opens a session in the user's project. For .cursor, .grok and .devin each catalog load runs its own probe with that provider. For .opencode and .opencodeGo the probe always runs with provider .opencode, and at most once per launch: the running or finished task is shared by both kinds and reused by later loads, unless a load is forced (the stored task is dropped first) or the probe returned nil (the task is dropped so the next load probes again). Every delivered list first passes through openCodeModels for the requested kind. Only when the requested kind's own half is non-empty is anything stored: that half updates the requested kind and closes its attempt, and then, for OpenCode, the sibling kind's half of the same raw list updates the sibling and closes its attempt when that half is not empty. If the requested kind's half is empty (for example a Zen load whose list holds only "opencode-go/" ids), neither kind is updated and neither attempt is closed, even when the sibling's half is not empty.
- **Side effects:** Creates a directory under the system temp path.; Launches one agent CLI process, which passes through the same 1.5 s launch gate as a real session; for OpenCode Zen and OpenCode Go together that is one process per launch unless a load is forced or a probe failed.
- **Persistence:** The directory persists on disk; nothing cleans it up.
- **Failure cases:** Any throw from start() propagates out of probeModels; the registry wraps it in `try?` (ProviderRegistry.swift:570 for Cursor, Grok and Devin; :612 inside the shared OpenCode task), so a failed probe leaves the catalog untouched and is retried on the next ask; for OpenCode the failed task is also cleared (:616).
- **Cancellation:** not cancellable
- **Windows path:** Boundary: the directory is Path.Combine(Path.GetTempPath(), "marrow-catalog"), that is %TEMP%\marrow-catalog, created with Directory.CreateDirectory and a creation failure swallowed. Deviation OD-0008 (OD-PENDING-17): the folder is named "marrow-catalog", not upstream's "droppy-code-catalog"; it is only the probe session's working directory and nothing reads it across runs.
- **Verify by:** contract fixture plus a filesystem assertion on the folder name "marrow-catalog", plus a spawn counter asserting one opencode probe for a Zen load followed by a Go load, and a second probe after a forced load

### PR-PROVACP-137 - The catalog probe captures the models event and always stops its session
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:239-246 - `var models: [ModelOption] = []; session.onEvent = { event in if case .models(let list, _) = event { models = list } }; defer { session.stop() }; _ = try await session.start(); await session.probeModelEfforts(); return models`
- **Preconditions:** A probe session was constructed.
- **Action:** probeModels runs it.
- **Expected:** Only .models events are observed; every other event is discarded. Each .models event REPLACES the captured list, so the value returned is the one from the LAST such event, which is the one emitted after the effort walk finished. `defer` guarantees the session is stopped on every exit path, including a thrown start().
- **Side effects:** The probe process is terminated when the function returns.
- **Persistence:** The registry merges and caches the returned list; probeModels itself persists nothing.
- **Failure cases:** A start() that throws still stops the session, and the error propagates.
- **Cancellation:** not cancellable
- **Windows path:** Same: a try/finally around the probe so the child is always terminated.
- **Verify by:** contract fixture (assert the child exits even when start throws)

### PR-PROVACP-138 - probeModelEfforts walks every model with an unknown effort scale and restores the original
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:287-298 - `guard let modelConfigID else { return }; let original = currentModel; for model in models where model.efforts.isEmpty { await setConfigOption(modelConfigID, value: model.id); currentModel = model.id }; if let original, !Self.sameModel(original, currentModel) { await setConfigOption(modelConfigID, value: original); currentModel = original }` | DroppyCode/Services/Providers/ACPSession.swift:281-286 - rationale: Cursor and OpenCode report the effort scale of the current model only, so each model without a scale is made current in turn and its scale read off the reply; models that arrived with a scale (Grok lists them in _meta.reasoningEfforts) are skipped
- **Preconditions:** A probe session is open.
- **Action:** probeModelEfforts runs.
- **Expected:** Without a model config id it returns immediately, leaving every scale as the catalog delivered it. Otherwise it iterates the CURRENT snapshot of `models`, filtered to entries whose efforts list is empty, sending one session/set_config_option per model. Each reply re-enters applyConfigOptions, which writes that model's scale onto it and rebuilds the list while preserving earlier findings. Afterwards the model the session started on is restored, but only when it differs by base id from where the walk ended.
- **Side effects:** One request and one .models event per walked model. For OpenCode this is on the order of four hundred round trips.
- **Persistence:** None here.
- **Failure cases:** Each setConfigOption swallows its own failure, so a rejected model simply keeps an empty scale.; When `original` is nil no restore is attempted and the probe session is left on the last model walked, which is harmless because the session is discarded.
- **Cancellation:** not cancellable
- **Windows path:** Same walk. The performance requirement of PR-PROVACP-043 is what keeps this from blocking the app for a 400-model catalog.
