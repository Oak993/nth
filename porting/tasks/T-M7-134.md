## Requirements

### PR-MCP-216 - Escape closes whichever MCP panel is visible, through an application-wide key monitor installed at present and removed at close
- **Source:** DroppyCode/App/Views/Settings/FloatingGuidePanel.swift:58-70 startEscapeMonitor and stopEscapeMonitor, one implementation per panel instance | DroppyCode/App/Views/Settings/FloatingGuidePanel.swift:24 startEscapeMonitor() in present(_:) and :28-31 close(), which removes the monitor and orders the panel out | DroppyCode/App/Views/Settings/MCPSetupPanel.swift:35-38 the setup panel's close() override, which clears its presented entry and then calls super
- **Preconditions:** A panel is visible.
- **Action:** The user presses Escape.
- **Expected:** A local key-down monitor is installed on present, only when one is not already installed. It swallows the event and closes the panel when the panel is visible and the key is Escape (key code 53); otherwise it passes the event through. close() removes the monitor and orders the panel out. Because neither panel installs a window-close or resign-key observer and all three window buttons are hidden, the only dismissal is through close(), so the monitor is always removed.
- **Side effects:** installs and removes an application-wide key-down monitor
- **Persistence:** none
- **Failure cases:** un-hiding the window controls in a port would let a panel be dismissed without close(), leaving the monitor installed
- **Cancellation:** not cancellable
- **Windows path:** Same Escape-to-close on both panels. If the port gives the panels a native close affordance, it must route through the same close path or the key handler leaks.
- **Verify by:** interaction test pressing Escape with each panel open
