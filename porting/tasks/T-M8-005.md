### PR-SETTINGS-105 - The update checker's three values persist under their own keys, outside the settings store
- **Source:** DroppyCode/App/UpdateChecker.swift:77-81 - private enum Keys { static let update = "updateChecker_release"; static let lastChecked = "updateChecker_lastChecked"; static let notifiedVersion = "updateChecker_notifiedVersion" } | DroppyCode/App/UpdateChecker.swift:112-117 init - reads UserDefaults.standard: the release as JSON Data decoded into AvailableUpdate, and lastCheckedAt as a Date | DroppyCode/App/UpdateChecker.swift:92-95 updateAvailable - recomputed from the running version, so an installed update stops being one | porting/port_impacts.md:418 entry 205 - persist the same three values under the same logical names, keep them out of the app-settings store
- **Preconditions:** The About page is showing or the background checker has run.
- **Action:** A check completes, or the app launches.
- **Expected:** The newest release found is stored as JSON under "updateChecker_release", the time of the last check as a Date under "updateChecker_lastChecked", and the version a notification has already been posted for under "updateChecker_notifiedVersion". All three live in the standard defaults suite, deliberately not in the settings store that a capture profile redirects, so the About page can show a known update the instant it opens. Whether an update is available is never stored: it is recomputed by comparing the stored release's version with the running version, so installing an update makes it stop being one without any write.
- **Side effects:** Network requests to the releases API, covered by the update subsystem
- **Persistence:** UserDefaults.standard keys "updateChecker_release", "updateChecker_lastChecked", "updateChecker_notifiedVersion".
- **Failure cases:** Stored release fails to decode: treated as no known release, and the About pill reads "Not checked yet" until a check runs.
- **Cancellation:** not cancellable from settings
- **Windows path:** Same three key names in the port's own store slice, kept out of any profile-redirected settings file. The release payload shape follows whatever release feed the Windows build uses; the three key names and the recompute-never-store rule for availability are what carry over.
- **Verify by:** restart test: stub a newer release, restart, assert the About page shows it before any network call

### PR-UPDATE-001 - AppVersion parses a release tag into exactly three integer components, or refuses it
- **Source:** DroppyCode/App/UpdateChecker.swift:7-22 struct AppVersion init?(_ raw:) - 'var text = raw.trimmed' (String.trimmed at DroppyCode/Core/Support/Text.swift:224 is 'trimmingCharacters(in: .whitespacesAndNewlines)'), drops one leading "v" or "V", splits on "." with omittingEmptySubsequences: false, requires 1...3 parts, each non-empty and allSatisfy(\.isNumber) and Int-convertible, then pads with 0 until count == 3
- **Preconditions:** A tag string from the GitLab releases feed, or the running app's CFBundleShortVersionString.
- **Action:** The checker constructs an AppVersion from the string.
- **Expected:** "v1.2.3" -> [1,2,3]; "1.2" -> [1,2,0]; "7" -> [7,0,0]; leading "v" or "V" removed (only one character); surrounding whitespace and newlines trimmed first. Construction returns nil for: 0 parts or more than 3 parts, any empty part (so "1..2" and "1." fail because omittingEmptySubsequences is false), any part containing a non-digit (so "1.2.3-beta.1", "1.2.3-nightly.4" and "1.2.3rc" fail).
- **Persistence:** None directly. AppVersion is never persisted; only the AvailableUpdate.version string is.
- **Failure cases:** Unparseable string yields nil, which makes updateAvailable false (UpdateChecker.swift:93-96) and makes newestRelease skip that release (UpdateChecker.swift:202).
- **Cancellation:** not cancellable
- **Windows path:** Pure logic, no platform boundary. Implement as a TypeScript parse function with the same accept/reject set, including the exact 'reject on any non-digit' rule that excludes prerelease tags.
- **Verify by:** unit

### PR-UPDATE-004 - AvailableUpdate is the persisted record of a found release and carries exactly seven fields
- **Source:** DroppyCode/App/UpdateChecker.swift:41-51 struct AvailableUpdate: Codable, Equatable, Sendable { var version: String; var tag: String; var downloadURL: URL; var size: Int64?; var notes: String; var releasedAt: Date?; var pageURL: URL }
- **Preconditions:** A release has been selected by newestRelease.
- **Action:** The checker stores it in `update` and encodes it to UserDefaults.
- **Expected:** The record holds version (display string), tag (raw tag_name), downloadURL, size (optional bytes), notes (the GitLab release description Markdown, verbatim, empty string when absent), releasedAt (optional Date), pageURL (the release page). Nothing else is retained from the API response: `name` is decoded from JSON but never stored or shown.
- **Persistence:** JSONEncoder-encoded into UserDefaults key "updateChecker_release" (Data).
- **Failure cases:** If JSON encoding fails the key is removed instead of written (UpdateChecker.swift:233-237).
- **Cancellation:** not cancellable
- **Windows path:** Persist the same seven field names in the same JSON object so a stored record survives round-tripping. Swift's JSONEncoder writes Date as a Double seconds-since-2001 by default and URL as a string; a Windows port may choose ISO-8601 for releasedAt but must then own its own store and never claim to read a macOS-written blob.
- **Verify by:** contract fixture

- **Preconditions:** The app finished launching and the guards of PR-UPDATE-008 passed.
- **Action:** startBackgroundChecks() runs once from applicationDidFinishLaunching.
- **Expected:** After 8 seconds the first background check runs; thereafter one background check every 21600 seconds. The loop has no exit other than task cancellation, and nothing in the source cancels it, so it runs until the process ends.
