## The probe, verbatim from the stack decision

P2 - Snapshot budget at production scale. Instrument P1's scene scaled to the real count: 22 glass sites grouped into 3 shared-snapshot groups (GlassEffectContainer spacings 2, 2, 8), window 1320x860, over a transcript streaming at the source's 45 ms flush cadence with .interactive() pointer tracking live. PASS: median frame time <= 16.7 ms and 99th percentile <= 33 ms on this AMD integrated GPU, measured by an in-app frame timer with GPU time for the snapshot pass reported separately and staying under about 3 ms. FAIL: glass over the live transcript must be cached and invalidated on content change - record the fidelity cost before committing.

## Rules

- Read `WORKER_BRIEF.md` first. Model the probe on `porting/probes/p1-glass/`, which passed.
- A probe PROVES or DISPROVES one capability. Report the measured result, whichever it is.
  A FAIL reported honestly is a valuable result. A PASS you did not measure is worthless.
- Build a control case that must fail when the thing under test is absent, as P1 did with
  its tint-only render. Without one, a PASS cannot be trusted.
- Never send a prompt to a real AI CLI; `--version` or `--help` only.
- Set `MARROW_PORT_DATA_DIR` to a throwaway folder before running anything.
