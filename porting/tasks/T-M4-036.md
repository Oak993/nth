### PR-PROVAPI-001 - APIKeychain.key returns the stored Keychain value, else the caller's fallback; a capture run returns the empty string
- **Source:** DroppyCode/Services/Providers/APIKeychain.swift:13-17 key(for:fallback:) - `static func key(for account: String, fallback: String) -> String {` / `guard !CaptureRun.isEnabled else { return "" }` / `if let keychain = read(account), !keychain.isEmpty { return keychain }` / `return fallback` | DroppyCode/Services/Providers/APIKeychain.swift:8-9 the doc comment: `/// A capture run reads nothing, so recorded sessions keep working without` / `/// touching the user's real credentials.`
- **Preconditions:** A Keychain item may or may not exist for the account string.
- **Action:** Any caller asks for a provider's stored API key.
- **Expected:** In a capture run (CaptureRun.isEnabled true; upstream only, porting/dead_code.md entry 44, not ported per ED-061) the empty string is returned without reading the Keychain, whatever fallback was passed. Otherwise, if the Keychain read returns a non-empty string, that string is returned; if not, the caller's fallback string is returned unchanged.
- **Side effects:** One Keychain read per call (SecItemCopyMatching); none in a capture run
- **Persistence:** Reads only; nothing is written.
- **Failure cases:** Keychain read fails or returns no item: the fallback is returned, with no error surfaced; Capture run (upstream only; porting/dead_code.md entry 44, not ported per ED-061): the empty string is returned even when a key is stored and a non-empty fallback was passed
- **Cancellation:** not cancellable
- **Windows path:** Windows Credential Manager (OD-0008 B3): one generic credential per account string under the one service name the port uses in place of AppInfo.name. Same order for the live path: the stored value, then the caller's fallback. The capture-run guard is not ported: it is reachable only from a capture launch argument and is dead-code register entry 44 (porting/dead_code.md), which ED-061 excludes from implementation.
- **Verify by:** unit

### PR-PROVAPI-003 - APIKeychain.setKey stores the trimmed key as a generic password under one service, delete-then-add
- **Source:** DroppyCode/Services/Providers/APIKeychain.swift:44-57 - Data(trimmed.utf8); query kSecClass kSecClassGenericPassword, kSecAttrService AppInfo.name, kSecAttrAccount account; SecItemDelete(query) then SecItemAdd with kSecValueData and kSecAttrAccessible kSecAttrAccessibleWhenUnlocked; returns whether SecItemAdd was errSecSuccess
- **Preconditions:** A non-empty trimmed key.
- **Action:** A provider API key is saved.
- **Expected:** Any existing item for the account is deleted first, then a new generic-password item is added with the UTF-8 bytes of the trimmed key, service AppInfo.name, the given account, and accessibility kSecAttrAccessibleWhenUnlocked. The function returns true only when the add returned errSecSuccess.
- **Side effects:** SecItemDelete then SecItemAdd against the login Keychain
- **Persistence:** One item per provider account inside a single flat service namespace named by the app display name; MCP secrets share that service under accounts of the form 'MCP <server> <field>'.
- **Failure cases:** The add fails: false is returned. The port's caller reports the failure and stores nothing (PR-PROVAPI-008 to PR-PROVAPI-010, deviation OD-0008 A6); upstream's caller instead keeps a plaintext copy in the defaults
- **Cancellation:** not cancellable
- **Windows path:** Windows Credential Manager (OD-0008 B3): delete any existing generic credential for the account, then write one holding the UTF-8 bytes of the trimmed key, one credential per account string under the one service name the port uses in place of AppInfo.name, account strings verbatim. kSecAttrAccessibleWhenUnlocked has no Windows analogue; port_impacts.md entry 262 records that substitution. A false return is never followed by a plaintext copy (OD-0008 A6).
- **Verify by:** unit plus restart test

### PR-PROVREG-088 - API keys live in four Keychain items under one service, distinguished only by their account strings
- **Source:** DroppyCode/Services/Providers/APIKeychain.swift:45-49 setKey - kSecClassGenericPassword with kSecAttrService = AppInfo.name and kSecAttrAccount = the account string | DroppyCode/Services/Providers/DeepSeekKeychain.swift - account "DeepSeek API Key" | DroppyCode/Services/Providers/MetaKeychain.swift - account "Meta API Key" | DroppyCode/Services/Providers/ZaiKeychain.swift - account "Z.ai API Key"
- **Preconditions:** The user edits an API key field.
- **Action:** setAPIKeyInput is called for that provider.
- **Expected:** The key is trimmed of whitespace and newlines and written as a generic password under the service name AppInfo.name with one of exactly these four account strings: "DeepSeek API Key", "Meta API Key", "Z.ai API Key", "Command Code API Key". Accessibility is kSecAttrAccessibleWhenUnlocked. Each write is a delete followed by an add. An empty key deletes the item rather than storing an empty value. The plaintext mirror that runs when this write REFUSES is a separate behaviour and is specified by PR-PROVREG-239.
- **Side effects:** A Keychain delete followed by an add on every write.
- **Persistence:** Keychain service = the app display name, four fixed account strings.
- **Failure cases:** Keychain unavailable: SecItemAdd returns non-success and setKey returns false; what happens next is PR-PROVREG-239.
- **Cancellation:** not cancellable
- **Windows path:** Windows Credential Manager (OD-0008 B3): one credential per account under the one service name the port uses in place of AppInfo.name, keeping the one-container-many-accounts partitioning and the four account strings verbatim, because MCP secrets share the container and are distinguished only by account string. A refused write stores nothing else (PR-PROVREG-239, OD-0008 A6).
- **Verify by:** restart test on each of the four accounts plus a contract fixture on the account strings
