### PR-THEME-032 - Hex colours parse as sRGB with a tolerant scanner: an unparseable string yields black rather than failing
- **Source:** DroppyCode/UI/Theme/AppTheme.swift:236-247 `extension Color { init(hex: String) }` - `var text = hex.trimmed` (:239), `if text.hasPrefix("#") { text = String(text.dropFirst()) }`, `Scanner(string: text).scanHexInt64(&value)`, red=(value >> 16) & 0xFF / 255, green=(value >> 8) & 0xFF / 255, blue=value & 0xFF / 255, `self.init(.sRGB, red: red, green: green, blue: blue, opacity: 1)` | DroppyCode/Core/Support/Text.swift:222-224 `var trimmed: String { trimmingCharacters(in: .whitespacesAndNewlines) }`
- **Preconditions:** A hex string is turned into a colour.
- **Action:** Color(hex:) is called with a six-digit string, with or without a leading "#", possibly with surrounding whitespace.
- **Expected:** The string is trimmed of whitespace and newlines, one leading "#" is dropped, and the remainder is scanned as a hexadecimal integer. Channels are taken as bytes 16..23, 8..15 and 0..7, each divided by 255, in the sRGB space at opacity 1. A string the scanner cannot read leaves the value at 0, producing opaque black: there is no error path and no throw.
- **Persistence:** not persisted
- **Failure cases:** Unparseable text: value stays 0 and the colour is #000000 at full opacity. No message, no log.; A string longer than six hex digits: the scanner reads what it can and the high bits above bit 23 are discarded by the masks.
- **Cancellation:** not cancellable
- **Windows path:** Implement the same tolerant parse, including the black-on-garbage behaviour, so a future palette typo degrades identically. Colours must be treated as sRGB, not as the display's colour space.
- **Verify by:** unit: parse table including "#CBA6F7", "CBA6F7", " CBA6F7 " and a deliberately invalid string
