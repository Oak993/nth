### PR-PROVCLI-277 - Pi rewrites the gate file before every turn, so mode changes take effect per turn while the launch flag does not
- **Source:** DroppyCode/Services/Providers/PiSession.swift:272-282 - writeGate with its doc comment | DroppyCode/Services/Providers/PiSession.swift:163-165 - send(_:) updates runtimeMode and interactionMode then calls writeGate(finalReport: input.isFinalReport) | porting/extracts/provider-argv-and-handshakes.md section 9 item 16 | porting/port_impacts.md entry 21
- **Preconditions:** A gate file path.
- **Action:** A turn is sent, or the session starts.
- **Expected:** The gate object is written atomically with exactly four keys: "runtimeMode" as the RuntimeMode raw value, "interactionMode" as the InteractionMode raw value, "finalReport" as a boolean, and "systemPrompt" as the EMPTY STRING always. It is rewritten before EVERY turn, so finalReport and both modes are per-turn, while the --approve / --no-approve flag is fixed at launch. A runtime mode change mid-session therefore changes the gate's behaviour but NOT the CLI flag. The raw values are camelCase: supervised, autoAcceptEdits, auto, fullAccess, and build, plan.
- **Side effects:** One file written per turn
- **Persistence:** The gate file is the only channel between the app and its own extension.
- **Failure cases:** A failed write is ignored with try?, leaving the previous turn's gate in place.
- **Cancellation:** not cancellable
- **Windows path:** The camelCase raw values are an ON-DISK CONTRACT with the shipped TypeScript, which compares them as literal strings. A serializer that lowercases or snake_cases enum names would silently turn Full access into Supervised. The object must be hand-written rather than produced by a generic enum serializer, and the write must keep write-temp-then-replace semantics because the extension polls while the app rewrites (port_impacts.md entry 21).
- **Verify by:** contract fixture comparing the gate file byte for byte in every runtime mode

### PR-PROVCLI-279 - Pi refuses a second turn while one is running and re-reads the context window after a model switch
- **Source:** DroppyCode/Services/Providers/PiSession.swift:160-179 - send(_:) guards, set_model with the comment at :169-170, set_thinking_level
- **Preconditions:** A live session.
- **Action:** send(_:) begins.
- **Expected:** A session that is not running throws ProviderError.notRunning; one already on a turn throws ProviderError.failed("Pi is still on the last turn.") verbatim. The stored runtime and interaction modes are replaced and the gate rewritten. When the turn's model is non-empty, differs from the stored one AND contains a slash, a line {"type":"set_model","provider":<before the first slash>,"modelId":<after it>} is sent, the stored model updated, and a FRESH get_state request is made whose data.model.contextWindow, when present, replaces the stored context window - because the window was read with the model Pi started on and the usage meter wants the one it runs on now. When the turn's effort is non-empty, differs from the stored one AND is a known thinking level, a line {"type":"set_thinking_level","level":<effort>} is sent and the stored effort updated.
- **Side effects:** Up to three stdin lines and one round trip
- **Persistence:** none
- **Failure cases:** The exact message above for a concurrent turn.; A slashless model is never switched.
- **Cancellation:** not cancellable
- **Windows path:** None.
- **Verify by:** interaction test over a model switch, an effort switch and a double send
