### PR-CHAT-013 - TurnRecord decodes field by field with per-field defaults so a turn written by an older build is never dropped
- **Source:** DroppyCode/Core/Models/Timeline.swift:249-273 struct TurnRecord - id, index, providerTurnID, startedAt, completedAt, status, baseCheckpoint, endCheckpoint, userItemID, providerDiff, providerAnchor, touchedPaths, tokenSpends, hydraMerged = false | DroppyCode/Core/Models/Timeline.swift:275-295 init(from decoder:) - every field read with container.value(key, default:)
- **Preconditions:** A thread file written by an earlier build is being read.
- **Action:** The turns array is decoded.
- **Expected:** Each field falls back to its default when absent or unreadable: id to a fresh UUID, index to 0, status to running, hydraMerged to false, and every optional to null. A turn missing the newest fields still decodes as the turn it was.
- **Persistence:** Same key names on write.
- **Failure cases:** A field present but of the wrong type takes the default rather than failing the record.
- **Cancellation:** not cancellable
- **Windows path:** Implement the same tolerant per-key read. A strict schema validator here would silently lose a user's turn history.
- **Verify by:** restart test: write with the new shape, read a fixture missing touchedPaths, tokenSpends and hydraMerged

### PR-CHAT-019 - Array members of a thread document decode leniently: an unreadable item is dropped, never the document
- **Source:** DroppyCode/Core/Models/Timeline.swift:322-331 ThreadDocument.init(from:) - items, turns, followUps and hydraMerges each decode as [Lenient<T>] with an empty-array default, then .compactMap(\.value)
- **Preconditions:** A thread file holds an item this build cannot read.
- **Action:** The document is decoded.
- **Expected:** The unreadable element is silently omitted and every readable element around it survives, in order. usage and continuation default to null. The user sees the conversation minus the broken item, never an empty or failed thread.
- **Persistence:** The next write persists the surviving items only, so the broken item is lost permanently once the thread is saved again.
- **Failure cases:** There is no notice, log line or badge telling the user an item was dropped.
- **Cancellation:** not cancellable
- **Windows path:** Implement the same per-element tolerant decode. Note the data-loss consequence on the next save; it is upstream behavior and is reproduced.
- **Verify by:** restart test with a corrupted element in a fixture thread

### PR-CHAT-169 - A message stored by a build that cleaned text as it arrived is cleaned again on read, which is an upstream lossy rewrite of stored prose
- **Source:** DroppyCode/Core/Models/Timeline.swift:34-37 the doc comment - model-written prose with its long dashes flattened, for threads stored by a build that cleaned text only as it arrived | DroppyCode/Core/Models/Timeline.swift:38-54 the rewrite itself
- **Preconditions:** A thread holds assistant prose, reasoning or a plan containing an em dash.
- **Action:** The item passes through the cleanup on read.
- **Expected:** The stored characters are replaced in memory, and the next save persists the replacement, so the original em dash is not recoverable. This is the shipped behavior and is reproduced.
- **Persistence:** The rewritten text is what the next save writes.
- **Failure cases:** A code block inside a reply that legitimately contains an em dash is rewritten along with the prose; the cleanup is not markdown-aware.
- **Cancellation:** not cancellable
- **Windows path:** Reproduce. Flagged here because it silently edits stored user-visible content; it is an ordinary parity quirk rather than a destructive or security-sensitive behavior, so it needs no escalation.
- **Verify by:** restart test with an em dash inside a fenced code block in a reply

### PR-GIT-148 - The turn record's git fields are decoded field by field with defaults so an older thread still reads
- **Source:** DroppyCode/Core/Models/Timeline.swift:249-273 TurnRecord - baseCheckpoint, endCheckpoint, providerDiff, providerAnchor, touchedPaths and hydraMerged | DroppyCode/Core/Models/Timeline.swift:275-295 - every field is read with an explicit default, 'so a turn stored by an earlier build, which knew nothing of the newest of them, still reads as the turn it was rather than being dropped'
- **Preconditions:** A thread document is being read.
- **Action:** Turn records are decoded.
- **Expected:** Each field is read individually with a default rather than requiring the key: baseCheckpoint, endCheckpoint, providerDiff, providerAnchor and touchedPaths all default to nil, and hydraMerged defaults to false. A document written by an older build therefore decodes rather than being dropped. The persisted key names are exactly baseCheckpoint, endCheckpoint, providerDiff, providerAnchor, touchedPaths and hydraMerged.
- **Side effects:** None
- **Persistence:** These are the git-area persisted fields of the thread document.
- **Failure cases:** A malformed value for a field falls back to its default rather than failing the whole turn
- **Cancellation:** not applicable
- **Windows path:** Keep the exact key names and the per-field defaulting; a strict decoder would drop the user's history.
- **Verify by:** restart test over documents missing each field in turn
