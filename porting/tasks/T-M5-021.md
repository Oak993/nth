## Requirements

### PR-SIDEBAR-051 - RowDrag.settle walks the grabbed row past every neighbour whose crossing threshold it has passed, folding each slot shift into the compensation
- **Source:** DroppyCode/UI/Chrome/RowDrag.swift:29-61 settle - guards on `let id, let index = order.firstIndex(of: id)`; `let own = heights[id] ?? fallbackHeight`; loop: downward when `offset > 0, current + 1 < order.count` with `let slot = heights[next] ?? fallbackHeight` and `guard offset > (own + slot) / 2 + slot * pastCentre, move(next, true) else { break }` then `settled += slot; current += 1; moved = true`; upward mirrored with `-offset` and `settled -= slot`; returns `moved` | DroppyCode/UI/Chrome/RowDrag.swift:33 - `pastCentre: CGFloat = 0` default | DroppyCode/App/Views/Sidebar/SidebarView.swift:782-801 dragChanged - calls `drag.settle(order:heights:fallbackHeight: Chrome.rowHeight + 1)` with no pastCentre | E:/Droppy/port/porting/port_impacts.md:316 entry 154 - the move callback returns Bool; break on false WITHOUT advancing index or compensation; strict `>`; fallbackHeight = rowHeight + 1 = 29
- **Preconditions:** A row is grabbed and a pointer move has been delivered.
- **Action:** The visual offset exceeds half the sum of the grabbed row's slot and the next neighbour's slot, in either direction.
- **Expected:** The neighbour and the grabbed row swap. The test is a strict greater-than against `(own + slot) / 2 + slot * pastCentre`, with pastCentre zero in the sidebar, so the swap fires the moment the centre is crossed. The loop repeats, so one fast flick can cross several rows in a single delivery. If the move closure returns false the loop breaks without advancing the index and without adding the compensation. Each accepted swap adds or subtracts the neighbour's slot height from `settled`, which keeps the row pinned under the pointer while the list flows around it. The compensation must be applied inside `settle`, not inside the move closure, because `settle` mutates a copy of the caller's state.
- **Side effects:** Each accepted swap writes the model through the move closure.
- **Persistence:** Through the move closure only.
- **Failure cases:** Grabbed id not in `order`: returns false immediately and nothing moves.; Move refused: loop stops there, leaving earlier swaps in place.
- **Cancellation:** not cancellable
- **Windows path:** Direct translation of the arithmetic. A void-returning move callback would reorder forever past a refused move (port_impacts 154), so the Bool return is mandatory. The fallback height is the literal 29 (Chrome.rowHeight 28 plus the list's 1 pt spacing).
- **Verify by:** unit test on RowDrag.settle covering multi-row flicks, a refused move, a missing id and both directions.
