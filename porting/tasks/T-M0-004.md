## The probe, verbatim from the stack decision

P5 - ConPTY and Job Object in ONE attribute list, from C# P/Invoke. InitializeProcThreadAttributeList with dwAttributeCount 2; UpdateProcThreadAttribute with PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE and PROC_THREAD_ATTRIBUTE_JOB_LIST; CreateProcessW with EXTENDED_STARTUPINFO_PRESENT and a blittable STARTUPINFOEXW; one servicing thread per channel per Microsoft's deadlock warning. Launch claude.exe with a harmless non-model argument only (--version or --help): no prompt, no sign-in, no credential file read, per the repository's safety rules. PASS: pty output arrives on both channels; ResizePseudoConsole changes the child's reported column count; and TerminateJobObject kills both the child AND a grandchild it spawned, with no CREATE_SUSPENDED / ResumeThread race anywhere in the path. FAIL: the whole process-supervision design changes and must be redesigned before the supervisor is written.

## Rules

- Read `WORKER_BRIEF.md` first. Model the probe on `porting/probes/p1-glass/`, which passed.
- A probe PROVES or DISPROVES one capability. Report the measured result, whichever it is.
  A FAIL reported honestly is a valuable result. A PASS you did not measure is worthless.
- Build a control case that must fail when the thing under test is absent, as P1 did with
  its tint-only render. Without one, a PASS cannot be trusted.
- Never send a prompt to a real AI CLI; `--version` or `--help` only.
- Set `MARROW_PORT_DATA_DIR` to a throwaway folder before running anything.
