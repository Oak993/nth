## Requirements

### PR-SETTINGS-272 - Command Code's optional Studio API key is kept under the account "Command Code API Key" through the shared key store
- **Source:** DroppyCode/Services/Providers/CommandCodeKeychain.swift:3-6 doc - "Stores an optional Command Code Studio API key in the macOS Keychain, so it never sits in plaintext. The CLI's own `cmd login` keeps its key in `~/.commandcode/auth.json`; this one is for a Mac where the user would rather paste a key than sign in through the browser. UserDefaults keeps a copy only where the Keychain refuses it." | DroppyCode/Services/Providers/CommandCodeKeychain.swift:7-8 - `enum CommandCodeKeychain {` `private static let account = "Command Code API Key"` | DroppyCode/Services/Providers/CommandCodeKeychain.swift:10-12 - `static func apiKey(fallback: String) -> String { APIKeychain.key(for: account, fallback: fallback) }` | DroppyCode/Services/Providers/CommandCodeKeychain.swift:14-17 - `@discardableResult static func setAPIKey(_ key: String) -> Bool { APIKeychain.setKey(key, account: account) }`
- **Preconditions:** The Providers page's Command Code "API key (optional)" field is edited, or the stored keys are read for the first time.
- **Action:** The key is written through setAPIKey or read through apiKey(fallback:).
- **Expected:** Marrow: the Command Code key lives in Windows Credential Manager (OD-0008 B3) as one credential in the app's single container under the account string, verbatim, "Command Code API Key", beside the three other API-key accounts. A write trims the key of whitespace and newlines; an empty key deletes the credential and counts as stored; otherwise the credential is replaced. A read returns the stored trimmed key, or the given fallback (the empty string from the settings read) when nothing is stored. Upstream's capture-run short circuit, which returns the empty string without reading (APIKeychain.swift:14), is user-unreachable (porting/dead_code.md entry 44) and is not ported (ED-061). When the store refuses a key, nothing is stored anywhere and the verbatim "Credential Manager did not accept this key, so it was not saved." is shown under the key field (OD-0008 A6; OD-0012 E5), where upstream keeps a plaintext copy under the defaults key "commandcodeAPIKey". The key is handed to the CLI as COMMAND_CODE_API_KEY (PR-SETTINGS-090).
- **Side effects:** A Credential Manager delete and write per changed key, or a delete for an emptied key
- **Persistence:** Windows Credential Manager, account "Command Code API Key". The legacy settings key "commandcodeAPIKey" is only ever removed.
- **Failure cases:** Credential Manager refuses the write: nothing is stored and the verbatim "Credential Manager did not accept this key, so it was not saved." is shown under the key field (OD-0012 E5; PR-SETTINGS-088).; Nothing stored: the read returns the fallback, and the provider falls back to the COMMAND_CODE_API_KEY environment variable (PR-SETTINGS-090).
- **Cancellation:** not cancellable
- **Windows path:** A thin wrapper over the port's one Credential Manager store with the account string "Command Code API Key" carried verbatim (OD-0008 B3); no plaintext fallback (OD-0008 A6). The capture-run guard (APIKeychain.swift:14) is a capture-mode short circuit listed in porting/dead_code.md entry 44 and is not ported (ED-061).
- **Verify by:** unit test with a stubbed store: a write stores the trimmed key under "Command Code API Key", an empty write deletes it, a read returns it, a refused write stores nothing and shows the verbatim "Credential Manager did not accept this key, so it was not saved." under the key field; restart test for a stored key
