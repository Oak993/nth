## Requirements

### PR-GIT-052 - MergeRequestLink parses GitLab merge_requests, GitHub pull and Gitea pulls URLs with asymmetric index rules
- **Source:** DroppyCode/Core/Models/MergeRequestLink.swift:23-39 init?(url:) - path components filtered of "/"; firstIndex(of: "merge_requests") with index >= 1 and index + 1 < count; else parts.count >= 4 and parts[2] == "pull"; else parts.count >= 4 and parts[2] == "pulls"; every branch requires number > 0
- **Preconditions:** A link appeared in the chat.
- **Action:** The app decides whether the link is a merge request.
- **Expected:** The URL's path components are taken with "/" filtered out. GitLab: the first component equal to "merge_requests" at index 1 or later with a following component that parses as an integer greater than zero, so any GitLab host and any trailing page such as diffs still match. GitHub: at least four components with the component at index 2 exactly "pull" and index 3 an integer greater than zero. Gitea, Forgejo and Codeberg: the same shape with "pulls". Anything else, including a number of zero or below, yields nil and the link stays an ordinary link.
- **Side effects:** None
- **Persistence:** None.
- **Failure cases:** A non-numeric or non-positive number yields nil
- **Cancellation:** not cancellable
- **Windows path:** Direct port, including the asymmetry between the searched GitLab index and the fixed index 2 for the other two.
- **Verify by:** unit table over a GitLab subgroup URL, a /diffs suffix, github.com, a GitHub Enterprise host, Codeberg and a non-matching URL

### PR-GIT-055 - The merge helper's prompt is a fixed three-part text with a per-forge landing paragraph
- **Source:** DroppyCode/Core/Models/MergeRequestLink.swift:47-61 prompt - `var prompt: String` (:47), the three land variants (:48-55) and the shared body whose first line is `Merge \(label) now: \(url.absoluteString)` (:57)
- **Preconditions:** A MergeRequestLink was parsed and the user asked to merge it.
- **Action:** The helper thread is given its prompt.
- **Expected:** The prompt is, verbatim: "Merge <label> now: <url>" (<url> is url.absoluteString, the parsed URL's own text exactly as MergeRequestLink stored it at MergeRequestLink.swift:38, interpolated at :57; not a canonicalized absolute URI), a blank line, then the per-forge paragraph, then, in the same paragraph, " Once it is merged, sync the checkout: if this directory is on main with a clean working tree, run `git pull --ff-only`; otherwise leave the working tree alone and say so. Do not rebuild, install or relaunch anything. Reply in a few lines with the merged commit and the request's link." The per-forge paragraphs are: GitLab "Use glab from this directory: `glab mr merge <number> --yes`. If GitLab answers that the request is still being checked (a 405), wait a few seconds and try again; if it reports conflicts, stop and say so instead of resolving them."; GitHub "Use gh from this directory: `gh pr merge <number> --merge`. If GitHub reports the pull request is not mergeable, stop and say so instead of resolving it."; Gitea "Use tea from this directory: `tea pulls merge <number>`. If tea is not installed or signed in to this host, or the pull request is not mergeable, stop and say so instead of working around it."
- **Side effects:** The prompt is sent to a provider session
- **Persistence:** The prompt is stored as the helper thread's first message.
- **Failure cases:** Not applicable
- **Cancellation:** The helper thread can be stopped like any other.
- **Windows path:** Reproduce every character including the backticks and the parenthetical "(a 405)". The prompt is deliberately self-contained because a native provider reads no AGENTS.md before it starts.
- **Verify by:** unit asserting the three assembled strings byte for byte
