## Requirements

### PR-PROVACP-149 - Line framing splits on the line feed byte only
- **Source:** DroppyCode/Core/Support/StdioFramer.swift:26-34 - `case .lines: guard let newline = buffer[search...].firstIndex(of: 0x0A) else { search = buffer.endIndex; break }; messages.append(Data(buffer[start..<newline])); start = newline + 1; search = start; continue`
- **Preconditions:** Bytes arrived from the child's stdout, framing is .lines.
- **Action:** The framer appends them.
- **Expected:** Messages are split on the byte 0x0A only. The carriage return 0x0D is NOT a separator and stays at the end of the preceding message; it is removed later by the delivery step. A message is the bytes between separators, exclusive. Incomplete trailing bytes stay buffered.
- **Persistence:** None.
- **Cancellation:** not cancellable
- **Windows path:** Same: split on 0x0A only, per port_impacts #18. A CRLF-writing Windows CLI therefore yields messages ending in 0x0D, which the delivery step strips (PR-PROVACP-155) - note that port_impacts #18 says the source does not strip CR, which is true of the framer but NOT of StdioProcess.deliver.
- **Verify by:** unit (CRLF and LF fixtures, plus a message split across two chunks)

### PR-PROVACP-150 - The framer rescans only new bytes and compacts its buffer after each append
- **Source:** DroppyCode/Core/Support/StdioFramer.swift:19-23,58-60 - `buffer.append(data); var start = buffer.startIndex; var search = start + scanned`; and at the end `scanned = search - start; if start != buffer.startIndex { buffer = Data(buffer[start...]) }`
- **Preconditions:** A partial message is buffered and more bytes arrive.
- **Action:** append() runs.
- **Expected:** The scan resumes at the offset already searched rather than from the start, so a large partial message is not rescanned on every chunk. After extracting whatever it can, the framer keeps only the unconsumed remainder and records how much of it has been searched. Correctness requirement: a message split across any number of chunks is delivered exactly once and intact.
- **Persistence:** None.
- **Cancellation:** not cancellable
- **Windows path:** Same incremental behavior is required, not just the same result: an agent streaming a multi-megabyte tool output in small chunks must not cost quadratic time.
- **Verify by:** unit (byte-at-a-time feed of a 1 MB message) plus a performance guard

### PR-PROVACP-151 - Content-Length framing reads a header block terminated by a blank line, then exactly that many bytes
- **Source:** DroppyCode/Core/Support/StdioFramer.swift:13,35-54 - separator is the four bytes of "\r\n\r\n"; when bodyLength is nil the framer looks for that separator, parses the header, and on a nil length continues without consuming a body; when a length is known and enough bytes are buffered it emits exactly `length` bytes and clears bodyLength
- **Preconditions:** framing is .contentLength.
- **Action:** append() runs.
- **Expected:** The header block ends at the literal four-byte sequence CR LF CR LF. A header whose Content-Length cannot be parsed is skipped and scanning continues after it, without consuming any body. Once a length is known, the body is exactly that many bytes and any surplus stays buffered for the next message. When the separator is not yet present the search pointer is rewound to endIndex minus three so a separator straddling two chunks is still found.
- **Persistence:** None.
- **Failure cases:** A malformed header silently discards that header and resumes scanning.
- **Cancellation:** not cancellable
- **Windows path:** Same. ACP never uses this mode - ACPSession takes the .lines default - but the framer is shared with the Copilot connection, so the mode must exist and behave identically.
- **Verify by:** unit

### PR-PROVACP-152 - Content-Length header parsing is case-insensitive and rejects negative lengths
- **Source:** DroppyCode/Core/Support/StdioFramer.swift:71-80 - splits the header on newlines, splits each line on the first colon, requires two parts and `parts[0].trimmingCharacters(in: .whitespaces).lowercased() == "content-length"`, then requires an Int that is `>= 0`, returning nil when it is not
- **Preconditions:** A header block was found.
- **Action:** contentLength(in:) runs.
- **Expected:** Header names are compared case-insensitively after trimming spaces, so "content-length", "Content-Length" and "CONTENT-LENGTH" all match. The value is trimmed of spaces and must parse as an integer of zero or more; a negative or non-numeric value returns nil for the WHOLE header block, not just that line. When no Content-Length line is present the result is nil. A zero length is valid and produces an empty message.
- **Persistence:** None.
- **Cancellation:** not cancellable
- **Windows path:** Same.
- **Verify by:** unit (header table)

### PR-PROVACP-153 - finish() releases a trailing unterminated line, but only in line framing
- **Source:** DroppyCode/Core/Support/StdioFramer.swift:63-69 - `let remainder = framing == .lines && !buffer.isEmpty ? buffer : nil; buffer = Data(); scanned = 0; bodyLength = nil; return remainder`
- **Preconditions:** The child's stdout closed with bytes still buffered.
- **Action:** finish() runs.
- **Expected:** In line framing a non-empty remainder is returned and delivered, so a final JSON line written without a trailing newline is still processed. In Content-Length framing the remainder is DISCARDED, because a partial body is not a message. All framer state is reset either way, so the framer is reusable.
- **Persistence:** None.
- **Cancellation:** not cancellable
- **Windows path:** Same asymmetry.
- **Verify by:** unit
