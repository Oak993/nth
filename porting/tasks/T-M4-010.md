### PR-MCP-100 - MCPProbe.probe dispatches on command then url and rejects a server with neither
- **Source:** DroppyCode/Services/MCP/MCPProbe.swift:52-61 probe(_:)
- **Preconditions:** A resolved server.
- **Action:** The store probes it.
- **Expected:** If command is non-nil, run the stdio probe (even when url is also set). Otherwise, if url is non-nil, run the remote probe. Otherwise throw MCPProbeError.malformed("missing command or URL"), which renders as "The server sent something unexpected: missing command or URL".
- **Side effects:** none before dispatch
- **Persistence:** none
- **Failure cases:** neither set -> the malformed message above
- **Cancellation:** the whole probe runs inside a cancellable task
- **Windows path:** Same precedence: command wins over url.
- **Verify by:** unit

### PR-MCP-106 - A stdio probe gives the server 90 seconds, or 240 when its arguments contain mcp-remote
- **Source:** DroppyCode/Services/MCP/MCPProbe.swift:88-89 isOAuth and the deadline
- **Preconditions:** A resolved stdio server.
- **Action:** probeStdio computes its deadline.
- **Expected:** isOAuth = server.args.contains("mcp-remote") as an exact element match. deadline = now + 240 seconds when true, now + 90 seconds otherwise. No built-in catalog server can reach the 240-second branch: mcp-remote is produced only by acpServers(allowsHTTP: false), whose output never becomes an MCPResolvedServer. Only a user-authored custom stdio server whose arguments literally contain "mcp-remote" reaches it.
- **Side effects:** none
- **Persistence:** none
- **Failure cases:** passing the deadline throws .timedOut -> "The server didn't answer in time."
- **Cancellation:** the time left before the deadline is checked before each request and handed to it as its timeout (MCPProbe.swift:97-103); a cancelled probe task abandons its pending request and CancellationError propagates (PR-MCP-235)
- **Windows path:** Implement the branch exactly, but design no 240-second wait into the built-in server experience; the real OAuth retry comes from the HTTP path.
- **Verify by:** unit on the two deadlines

### PR-MCP-108 - The stdio probe performs initialize, notifications/initialized, then up to ten tools/list pages

- **Preconditions:** The child is running.
- **Action:** probeStdio runs its conversation.
- **Expected:** Send request id 1 initialize with the standard params; await the reply with id 1; require result to be an object or throw malformed("missing result"); read serverInfo.name and serverInfo.version from it. Send the notifications/initialized notification. Then loop at most 10 times: build params as an empty object, adding "cursor" only when a cursor is held; send tools/list with the next id; await that id's reply; append its result's tool summaries; stop when result.nextCursor is absent or empty, otherwise carry the cursor into the next page. Return MCPProbeResult(serverName, serverVersion, tools). A server that keeps returning a cursor is cut off after the tenth page with the tools gathered so far.
- **Side effects:** writes each JSON message followed by a single 0x0A byte to the child's stdin
- **Persistence:** serverVersion and the tool list are persisted by the store on success; serverName is read and then discarded, never persisted or displayed

### PR-MCP-109 - The stdio probe waits for each reply on its stdio connection, with the time left before its deadline as that request's timeout
- **Source:** DroppyCode/Services/MCP/MCPProbe.swift:97-114 nextReply - :98 let remaining = deadline.timeIntervalSinceNow | :99 guard remaining > 0 else { | :100 throw exitError(code: nil, isOAuth: isOAuth, stderr: connection.errorTail) | :103 let reply = try await connection.request(method, params, timeout: remaining) | :104 try checkReply(reply) | :109 throw exitError(code: code, isOAuth: isOAuth, stderr: connection.errorTail) | :111 throw exitError(code: nil, isOAuth: isOAuth, stderr: connection.errorTail) | DroppyCode/Services/MCP/MCPWire.swift:162-187 MCPStdioConnection.request
- **Preconditions:** A request was sent.
- **Action:** The probe waits for the matching reply.
- **Expected:** Before each request (initialize, then each tools/list page) the time left before the probe's deadline is computed; when it is zero or less, exitError(code: nil, ...) is thrown without sending anything. Otherwise the request is sent through MCPStdioConnection.request with that remaining time as its timeout (PR-MCP-235), and the reply carrying the request's id is awaited (PR-MCP-232, PR-MCP-233). When the reply arrives, checkReply runs and the reply is returned. When the connection reports the child's exit (PR-MCP-234), exitError(code: <the exit status>, ...) is thrown. When the timer wins, exitError(code: nil, ...) is thrown. exitError always receives connection.errorTail, the last 4000 bytes of stderr (PR-MCP-236). There is no polling interval: the wait ends as soon as the reply, the exit report or the timer arrives. Replies for ids the probe is not waiting on are kept by the connection, not discarded.
- **Side effects:** none
- **Persistence:** none
- **Failure cases:** exit -> "The server quit (exit <code>). <last non-empty stderr line>" or "The server quit (exit <code>)."; deadline passed before or during a request -> "The server didn't answer in time."; either of the above becomes "Sign-in was rejected. Sign in again in your browser." for an mcp-remote server whose stderr tail contains Unauthorized or invalid_grant (PR-MCP-110)
- **Cancellation:** a cancelled probe task abandons its pending request and CancellationError propagates out of the wait (PR-MCP-235); the deferred connection.stop() then ends the child
- **Windows path:** Event-driven: end the wait the moment the matching reply, the exit report or the timer arrives, with no polling interval. Use the time left before the deadline as each request's timeout, and keep replies for other ids.
- **Verify by:** unit with a scripted server: a reply for another id before the awaited one, an exit mid-request, and a deadline reached between pages

### PR-MCP-110 - A stdio failure is classified as unauthorized OAuth, an exit code, or a timeout

- **Action:** exitError classifies.

- **Persistence:** none
- **Failure cases:** see the three messages in PR-MCP-120
- **Cancellation:** not cancellable
- **Windows path:** Same two substring checks and the same precedence, applied to the same 4000-byte tail. This branch is unreachable for the built-in catalog (see PR-MCP-106).
- **Verify by:** unit over the three outcomes, plus an Unauthorized marker written more than 4000 bytes before the end of stderr, which must not be seen
