### PR-TERM-014 - Dragging the strip sets a live height of origin plus upward travel, clamped to 140...760, without writing settings
- **Source:** DroppyCode/App/Views/Terminal/TerminalPanel.swift:87-90 - onChange computes origin as dragOrigin ?? model.settings.terminalHeight and sets dragHeight = min(760, max(140, origin + delta)) | DroppyCode/App/Views/Terminal/TerminalPanel.swift:228-230 mouseDragged - passes event.locationInWindow.y - pressOriginY | DroppyCode/App/Views/Terminal/TerminalPanel.swift:11-13 - the comment: settings take the height on release, so a drag never writes user defaults on every frame
- **Preconditions:** A drag is in progress.
- **Action:** The pointer moves.
- **Expected:** delta is the pointer's travel since the press in window coordinates with y increasing upward, so dragging UP gives a positive delta and grows the drawer. dragHeight becomes min(760, max(140, origin + delta)), clamped on every frame. The persisted setting is untouched for the whole drag. If dragOrigin is nil the current settings height is used instead.
- **Persistence:** None during the drag.
- **Failure cases:** Dragging past either bound pins the height at 140 or 760 and further travel in that direction has no effect until the pointer comes back inside the range.
- **Cancellation:** There is no cancel gesture; releasing commits (see PR-TERM-015).
- **Windows path:** pointermove with the sign inverted relative to CSS coordinates, because Windows and the DOM measure y downward while AppKit measures it upward. Platform boundary: coordinate-system sign.
- **Verify by:** unit test on the clamp plus an interaction test on the direction

### PR-TERM-015 - Releasing the strip applies one final delta, commits the height to settings and clears the drag state
- **Source:** DroppyCode/App/Views/Terminal/TerminalPanel.swift:232-237 mouseUp - calls onChange with the release delta FIRST, then clears isDragging, animates the grip and calls onEnd | DroppyCode/App/Views/Terminal/TerminalPanel.swift:91-96 - onEnd assigns model.settings.terminalHeight from dragHeight when it is non-nil, clears dragHeight and dragOrigin, and sets runtime.isTerminalResizing = false | DroppyCode/App/AppSettings.swift:309-311 - terminalHeight's didSet writes defaults.set(terminalHeight, forKey: Key.terminalHeight)
- **Preconditions:** A drag is in progress.
- **Action:** The user releases the mouse.
- **Expected:** The release position is applied as one last clamped onChange, so the final pixel counts. Then settings.terminalHeight takes the clamped dragHeight and is written to the defaults store under the key "terminalHeight"; dragHeight and dragOrigin are cleared; runtime.isTerminalResizing becomes false; the grip animates back to its resting width unless the pointer is still hovering. A press with no movement still commits, writing back the same value it started from.
- **Side effects:** One write to the persistent settings store.
- **Persistence:** Key "terminalHeight", a Double, written on release only.
- **Failure cases:** dragHeight nil (no onChange ever ran): nothing is written and only the flags clear. mouseUp itself prevents this by calling onChange before onEnd.
- **Cancellation:** not cancellable
- **Windows path:** pointerup; write the same key with the same name and type.
- **Verify by:** restart test: drag, quit, relaunch, assert the height
