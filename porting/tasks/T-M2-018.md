### PR-STORE-091 - A thread with no stored model decodes with model nil
- **Source:** DroppyCode/Core/Models/Library.swift:231 - model = container.value(.model, default: nil) | DroppyCode/Core/Models/Library.swift:130 - var model: String? | DroppyCode/Core/Support/Coding.swift:5-7 - func value<T: Decodable>(_ key: Key, default fallback: @autoclosure () -> T) -> T { ((try? decodeIfPresent(T.self, forKey: key)) ?? nil) ?? fallback() }, so a missing key, an explicit null and a type mismatch all collapse onto the fallback
- **Preconditions:** A stored thread record in library.json whose "model" key is absent, null, or of the wrong JSON type.
- **Action:** The library is decoded at app launch.
- **Expected:** model decodes to nil. nil means the thread has pinned no model of its own, so the composer and the runtime fall back to the provider's current default rather than to any literal model id. A blank string is NOT the empty state: only nil is.
- **Persistence:** library.json, threads[].model. That key name is the wire format and must not be renamed or re-cased.
- **Failure cases:** A missing key, an explicit null and a value of the wrong type are indistinguishable here: all three land on nil and none of them fails the surrounding thread or the surrounding library.
- **Cancellation:** not cancellable
- **Windows path:** Keep this nullable and keep nil distinct from the empty string; a port that substitutes "" or a hard-coded model id pins every legacy thread to that model.
- **Verify by:** unit test decoding a thread record that carries only id and projectID, plus one carrying the key as null and one carrying it as the wrong JSON type, asserting the same result in all three

- **Source:** DroppyCode/Core/Models/Library.swift:172-179 - doc comments for hydraEnabled and hydraEnabledIsExplicit: "Saves from before it carried an ignored false under the same key, so a thread without this flag decodes as on whatever its stored value says; every save from here on writes the flag, and its stored value is then the user’s own choice." | DroppyCode/Core/Models/Library.swift:256-260 - comment "Threads saved while Hydra was app-wide only carry an ignored false and no explicit flag: they come back on. - **Preconditions:** A thread record written by a build older than the per-chat Hydra switch: it carries hydraEnabled false and no hydraEnabledIsExplicit.

- **Persistence:** library.json, threads[].hydraEnabled (Bool) and threads[].hydraEnabledIsExplicit (Bool).
- **Failure cases:** A hand-edited record with hydraEnabledIsExplicit true and hydraEnabled absent reads as on.
- **Cancellation:** not cancellable
- **Windows path:** Reproduce the whole three-line migration including the unconditional write of the explicit flag. Dropping it makes the migration re-run forever and silently re-enables Hydra for a user who turned it off.
