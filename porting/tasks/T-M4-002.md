## Requirements

### PR-MCP-176 - MCPExternalSync removes only the ids an older build recorded, from three third-party files, once ever
- **Source:** DroppyCode/Services/MCP/MCPExternalSync.swift:7-28 sync | DroppyCode/Services/MCP/MCPExternalSync.swift:33-50 remove | DroppyCode/Services/MCP/MCPExternalSync.swift:52-63 managedURL and readManaged
- **Preconditions:** exportAll is running.
- **Action:** sync(servers) is called.
- **Expected:** Return immediately unless <data root>/mcp/managed.json exists - nothing in this source ever writes that file, so on a fresh install this is a complete no-op. When it exists, read it as {"cursor": [ids], "opencode": [ids], "gemini": [ids]}, defaulting each to an empty list, and remove those ids from: ~/.cursor/mcp.json under root key "mcpServers"; ~/.config/opencode/opencode.json under root key "mcp"; ~/.gemini/settings.json under root key "mcpServers". Then DELETE managed.json, so it can fire at most once ever. remove skips an empty id list, a missing file, unparseable JSON or a missing root object; it removes exactly the listed ids, leaves every other key alone, and rewrites the file atomically with pretty-printed sorted-keys JSON only when something was actually removed. The servers parameter is never referenced in the body.
- **Side effects:** may rewrite up to three third-party configuration files in the user's home directory; deletes mcp/managed.json
- **Persistence:** the three third-party files, once
- **Failure cases:** every failure mode is a silent skip that leaves the file untouched
- **Cancellation:** not cancellable
- **Windows path:** Keep the migration, unused parameter and all, so an upgrading user's %USERPROFILE%\.cursor\mcp.json, %USERPROFILE%\.config\opencode\opencode.json and %USERPROFILE%\.gemini\settings.json are cleaned once. Note this writes into files the app does not own, which is why the id list and the only-when-changed rule are strict.
- **Verify by:** integration test with a seeded managed.json asserting only the listed ids are removed and the file is then gone
