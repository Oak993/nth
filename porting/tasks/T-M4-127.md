### PR-PROVREG-094 - A custom binary path is resolved through the same lookup as the bare name, and a custom path that does not resolve disables the fallback candidates
- **Source:** DroppyCode/Services/Providers/ProviderRegistry.swift:227-234 executable(for:) - the custom path is passed to LoginEnvironment.which; on failure, a non-empty custom path returns nil instead of trying the fallbacks | DroppyCode/Core/Support/Shell.swift:415-427 which - a name containing a slash is expanded for a leading tilde and tested for executability; otherwise PATH is split on colon and each directory joined with the name
- **Preconditions:** A custom binary path is stored for a non API-key provider.
- **Action:** executable(for:) is called.
- **Expected:** The custom string is resolved with the same which() rule: containing a separator it is treated as a path with tilde expansion, otherwise it is searched on PATH. If it does not resolve, the function returns nil WITHOUT consulting fallbackExecutables. Only an empty custom path reaches the fallback list.
- **Side effects:** Filesystem existence tests.
- **Persistence:** None.
- **Failure cases:** Custom path set but unresolvable: nil, so the section shows Not installed and the Install row, even though a bare-name copy exists on PATH.
- **Cancellation:** not cancellable
- **Windows path:** PLATFORM BOUNDARY: the is-a-path test must also accept backslash and a drive prefix, PATH must split on semicolon, and the execute-bit test must become a PATHEXT-aware existence test. Executable identity is validated per PA-0016: PATH resolution honours PATHEXT, and a candidate whose Windows version resource identifies it as the command interpreter (CompanyName Microsoft Corporation with OriginalFilename Cmd.Exe/Cmd.Exe.MUI, or FileDescription Windows Command Processor), or which is %SystemRoot%\System32\cmd.exe or %SystemRoot%\SysWOW64\cmd.exe, is rejected and the provider reports not installed.
- **Verify by:** contract fixture over a synthetic filesystem and PATH
