### PR-WIN-154 - Command-1 to Command-9 are taken in the main window before menu dispatch, and the event is swallowed
- **Source:** DroppyCode/App/Window/ThreadWindow.swift:5-19 the comment 'Command-1 to Command-9, taken before the event is dispatched. AppKit hands a chord that a menu item carries to the item without asking the window, and firing the item flashes its menu title, which holds the main thread for a tenth of a second on every switch.' and the monitor body `guard let self, event.window === self, attachedSheet == nil, event.modifierFlags.intersection(KeyChord.allowedModifiers) == .command, let number = Self.digitKeyCodes[event.keyCode], let selectThreadNumber else { return event }; selectThreadNumber(number); return nil` | DroppyCode/App/Window/ThreadWindow.swift:22-23 `private static let digitKeyCodes: [UInt16: Int] = [18: 1, 19: 2, 20: 3, 21: 4, 23: 5, 22: 6, 26: 7, 28: 8, 25: 9]` | DroppyCode/App/Window/WindowManager.swift:64-65 the main window's selectThread and selectThreadNumber closures are wired to model.selectThread(offset:) and model.selectThread(number:)
- **Preconditions:** The main window is key, no sheet is attached to it, and the digit closure has been installed.
- **Action:** The user presses Command and a number-row digit from 1 to 9.
- **Expected:** The nth thread in the sidebar's order is selected and the event is consumed, so the matching menu item never fires and its title never flashes. Every one of the five conditions is required: the event must belong to this window, no sheet may be attached, the masked modifier set must be exactly Command and nothing else, the key code must be one of the nine, and the closure must be installed. Failing any of them the event is returned unchanged and follows its normal route. Note the key code map's crossover: 23 is digit 5 and 22 is digit 6.
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** A pre-translate keyboard hook on the main window that runs before accelerator dispatch, testing VK_1..VK_9 (not the numpad) with the masked modifier set exactly equal to Ctrl. It must consume the message so the menu command does not also fire. The macOS reason for the interception (a flashing menu title costing a tenth of a second) may not apply, but the double-fire it prevents does.
- **Verify by:** interaction test: Command-3 selects the third thread once, not twice; unit over the nine key codes including the 22/23 crossover

### PR-WIN-155 - The digit monitor is installed at most once and is never removed
- **Source:** DroppyCode/App/Window/ThreadWindow.swift:8-20 the didSet installs the monitor only `guard digitMonitor == nil else { return }`, storing the token in `private var digitMonitor: Any?` | DroppyCode/App/Window/ThreadWindow.swift:1-39 the file has no deinit and no removeMonitor call
- **Preconditions:** The main window exists.
- **Action:** The selectThreadNumber closure is assigned, possibly more than once.
- **Expected:** A single monitor is installed on the first non-nil assignment and is kept for the process lifetime. A second assignment does not install a second monitor, so the digit chord never fires twice. Nothing removes it, which is intentional because the main window is created once.
- **Side effects:** Installs a process-level key-down monitor that is never torn down
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** Install the hook once per main window and hold it for the window's lifetime. Guard against a second installation, and unhook when the window is finally destroyed even though the source does not, since a leaked Windows hook is a process-wide cost rather than a per-app one; record that as a deliberate, safe divergence.
- **Verify by:** unit: assign the closure twice and assert one hook

### PR-WIN-156 - The main window answers the next and previous thread chords itself, but only for the Tab key
- **Source:** DroppyCode/App/Window/ThreadWindow.swift:25-38 `override func performKeyEquivalent(with event: NSEvent) -> Bool { if event.keyCode == 48, attachedSheet == nil { let chord = KeyChord(keyCode: Int(event.keyCode), modifiers: event.modifierFlags); if chord == ShortcutStore.shared.chord(for: .nextThread) { selectThread?(1); return true }; if chord == ShortcutStore.shared.chord(for: .previousThread) { selectThread?(-1); return true } }; return super.performKeyEquivalent(with: event) }`
- **Preconditions:** The main window is key and no sheet is attached.
- **Action:** The user presses a Tab chord, by default Control-Tab or Control-Shift-Tab.
- **Expected:** If the chord matches the live next-thread chord the selection moves down one; if it matches the previous-thread chord it moves up one; either way the event is consumed. The window handles this ONLY for key code 48 (Tab): a user who rebinds next thread to a non-Tab chord falls through to the ordinary menu route instead. The chords are read live from the shortcut store, so a remap of a Tab chord is honored here too. Next is tested before previous, so if both are bound to the same chord next wins.
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** Handle VK_TAB chords on the main window before the frameworks consume Tab for focus navigation, which they otherwise do. Keep the key-code gate: a rebound non-Tab chord must reach the ordinary command route. Keep the next-before-previous order.
- **Verify by:** interaction test with the defaults and after rebinding next thread to a non-Tab chord

### PR-WIN-157 - A secondary window closes on Escape, unless a text field has focus
- **Source:** DroppyCode/App/Window/ThreadWindow.swift:41-56 the class comment and `override func sendEvent(_ event: NSEvent) { if event.type == .keyDown, event.keyCode == 53, event.modifierFlags.intersection(KeyChord.allowedModifiers).isEmpty, !(firstResponder is NSText) { performClose(nil); return }; super.sendEvent(event) }` with the comment 'Escape closes it as well, like a sheet. Taken here rather than in keyDown, which the SwiftUI hosting view never passes on. A field being typed in keeps its Escape, and a shortcut being recorded takes it before any window sees it.'
- **Preconditions:** A secondary window, in practice the Settings window, is key.
- **Action:** The user presses Escape with no modifiers.
- **Expected:** The window closes, exactly as a sheet would. Escape is NOT taken when any modifier is held, nor while the focused responder is a text field, which keeps Escape for the field itself. A shortcut recorder claims Escape before the window sees it, so recording Escape as a chord still works.
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** Handle VK_ESCAPE at the window's message loop, before the content tree, with the same two exclusions: any masked modifier, or a focused text input. Note that the source takes it in the raw event path specifically because the SwiftUI host swallows it; the Windows port must pick an equivalently early point.
- **Verify by:** interaction test: Escape in Settings closes it; Escape inside a settings text field does not

- **Verify by:** interaction test: rebind Archive thread, assert Command-W still closes Settings
