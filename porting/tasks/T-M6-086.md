### PR-WIN-020 - The theme sets both the SwiftUI color scheme and the process-wide appearance, applied at first build
- **Source:** DroppyCode/App/Window/WindowManager.swift:148-159 HostedRoot.body: `.preferredColorScheme(model.settings.theme.spec.scheme)` and `.onChange(of: model.settings.theme, initial: true) { _, theme in NSApp.appearance = switch theme.spec.scheme { case nil: nil; case .light: NSAppearance(named: .aqua); case .dark: NSAppearance(named: .darkAqua); @unknown default: nil } }`
- **Preconditions:** A window root is built or the theme changes.
- **Action:** The theme is read, or the user picks a different theme.
- **Expected:** The hosted tree's color scheme follows the theme's spec. The process appearance is set at the same time: a nil scheme leaves the appearance nil, so the system decides; .light sets the light appearance; .dark sets the dark appearance. Because the change handler runs with initial: true, this applies at first build and not only on a later change.
- **Side effects:** Sets the process-wide appearance, which affects framework-drawn controls including the window's own buttons
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** Set both the content tree's scheme and the window's immersive dark-mode attribute (DwmSetWindowAttribute DWMWA_USE_IMMERSIVE_DARK_MODE) together, including at first build. A nil scheme follows the system's app light/dark preference.
- **Verify by:** interaction test: switch themes and assert the framework-drawn window controls follow, including on a freshly opened window

### PR-WIN-021 - The theme tint is applied through one unconditional branch, never an if/else
- **Source:** DroppyCode/App/Window/WindowManager.swift:180-190 ThemeTint.body with the comment 'One branch, never two: an `if` here made the whole window's content a different view once a theme with an accent replaced one without, so every page was built afresh and Settings jumped back to its top on a theme change. A nil tint keeps the system accent.' and the body `content.tint(theme.spec.accent)`
- **Preconditions:** A hosted tree exists.
- **Action:** The user changes from a theme without an accent to one with an accent, or the reverse.
- **Expected:** The tint changes and nothing else. The content is NOT rebuilt, so scroll positions are kept and the Settings window does not jump back to its top. A nil accent means the system control accent, applied by passing nil rather than by taking a different branch.
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** Apply the accent as a value on one code path, including when it is absent. A conditional wrapper that changes the tree's identity reproduces the bug this comment records.
- **Verify by:** interaction test: scroll Settings, switch to a theme with an accent, assert the scroll position is kept
