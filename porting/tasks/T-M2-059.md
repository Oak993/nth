## Requirements

### PR-LAUNCH-005 - Capture-run launch arguments are parsed exactly once per process, by exact token match, in the order --website-captures then --tour-captures
- **Source:** DroppyCode/Core/Support/CaptureRun.swift:10-19 outputDirectory - a nonisolated static let whose initializer scans CommandLine.arguments for the flags in the literal array ["--website-captures", "--tour-captures"], requiring arguments.indices.contains(index + 1), and returns URL(fileURLWithPath: arguments[index + 1], isDirectory: true) | DroppyCode/Core/Support/CaptureRun.swift:27 isEnabled - outputDirectory != nil
- **Preconditions:** Process launched with or without the flags.
- **Action:** Any code reads CaptureRun.outputDirectory or CaptureRun.isEnabled for the first time.
- **Expected:** The arguments are scanned once and the result cached for the process lifetime. --website-captures is checked first; if it is present with a following argument, that argument is the output folder and --tour-captures is not consulted. A flag with no following argument is ignored. With neither flag present, outputDirectory is nil and isEnabled is false, which is the normal launch.
- **Side effects:** Reads process launch arguments
- **Persistence:** Nothing is persisted.
- **Failure cases:** A flag as the last argument is ignored (the indices.contains(index + 1) guard fails) and the scan continues to the next flag.
- **Cancellation:** not cancellable
- **Windows path:** OPEN ENGINEERING DECISION: whether capture mode is ported at all. port_impacts.md:344 entry 168 records 'Capture mode is tooling, not shipped behaviour' while requiring exact argv token matching, next-argv-element-is-the-folder, a single parse per process and the derived <folder>/storage redirection if it IS ported; dead_code.md entries 33, 38 and 42 state the subsystem is shipped but unreachable in a user launch and that the port does not need it.
- **Verify by:** unit test over an argv vector table

### PR-LAUNCH-006 - A --tour-captures launch is a distinguishable sub-mode of the same capture machinery
- **Source:** DroppyCode/Core/Support/CaptureRun.swift:21-25 isTourRun - true only when "--tour-captures" is present AND a following argument exists | DroppyCode/App/Captures/WebsiteCaptures.swift:303-304 run(model:) - 'if isTourRun { await TourCaptures.run(model: model); return }'
- **Preconditions:** Capture run is enabled.
- **Action:** The capture run starts.
- **Expected:** isTourRun is true only for --tour-captures with a following argument. The tour run takes the TourCaptures path; every other capture run takes the website path. isTourRun re-scans CommandLine.arguments on each read (it is a computed var, unlike outputDirectory which is a cached let).
- **Persistence:** Nothing is persisted.
- **Failure cases:** --tour-captures without a following argument yields isTourRun false, and outputDirectory is also nil, so no capture run starts.
- **Cancellation:** not cancellable
- **Windows path:** Same open decision as PR-LAUNCH-005.
- **Verify by:** unit test over an argv vector table
