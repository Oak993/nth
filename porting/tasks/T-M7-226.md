### PR-UPDATE-097 - The tour window is centred on the main window when one is visible, otherwise on screen
- **Source:** DroppyCode/App/Views/Tour/TourWindowController.swift:92-101 if let main = NSApp.windows.first(where: { $0.title == "Droppy Code" && $0.isVisible }) { origin = (mainFrame.midX - contentSize.width / 2, mainFrame.midY - contentSize.height / 2); window.setFrameOrigin(origin) } else { window.center() }
- **Preconditions:** A new tour window is being placed.
- **Action:** The origin is chosen.
- **Expected:** The main window is located by an exact title match on the literal string "Droppy Code" plus visibility. When found, the card is centred on that window's frame with no screen clamping. When not found, the window centres itself on screen.
- **Persistence:** None.
- **Failure cases:** If the main window's title ever differs from the literal, the card silently falls back to screen-centring. Note the source performs no screen clamping here, unlike the settings window (WindowManager.swift:50-52), so a main window partly off-screen can place the card partly off-screen.
- **Cancellation:** not cancellable
- **Windows path:** Centre on the main BrowserWindow's bounds directly rather than matching a title string; matching on a title is fragile and the port owns its own window handles. Record that as an ENGINEERING DECISION: it preserves the intent and removes a silent-fallback failure mode, and nothing user-visible changes when the title is what the source expects.
- **Verify by:** interaction test
