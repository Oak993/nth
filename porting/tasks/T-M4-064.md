### PR-PROVCLI-130 - Codex decision options default to four names, add an amendment option, and sort by role
- **Source:** DroppyCode/Services/Providers/CodexSession.swift:998-1023 - decisionOptions(_:command:)
- **Preconditions:** An approval request being described.
- **Action:** decisionOptions runs.
- **Expected:** With nil available decisions the literal four-element list ["accept", "acceptForSession", "decline", "cancel"] is used. Each string decision maps to: "accept" -> title "Approve" role .approve; "acceptForSession" -> "Approve for session" role .approveAlways; "decline" -> "Decline" role .decline; "cancel" -> "Stop turn" role .cancel. Any other string is DROPPED and no payload is stored for it. A non-string decision is considered only when command is true and it carries the key "acceptWithExecpolicyAmendment", which adds the option id "amend" with title "Always allow" and role .approveAlways. The option id doubles as the payload key. Finally the options are SORTED by the role order [.approve, .approveAlways, .decline, .cancel], with an unknown role sorting as index 0.
- **Persistence:** none
- **Failure cases:** An unrecognized decision name simply does not appear as a button.
- **Cancellation:** The "cancel" option stops the turn.
- **Windows path:** The sort must be a stable ordering by that role list, so two approveAlways options keep their relative order.
- **Verify by:** unit test over the default list, an amendment decision and an unknown name
