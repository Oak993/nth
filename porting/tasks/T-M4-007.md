### PR-MCP-159 - The three OAuth HTTP helpers each use a 30-second timeout and collapse unexpected failures to a bare network error
- **Source:** DroppyCode/Services/MCP/MCPOAuth.swift:717-742 fetchJSON | DroppyCode/Services/MCP/MCPOAuth.swift:744-766 post | DroppyCode/Services/MCP/MCPOAuth.swift:768-790 postForm | DroppyCode/Services/MCP/MCPOAuth.swift:792-798 oauthErrorMessage
- **Preconditions:** none
- **Action:** Any OAuth HTTP call is made.
- **Expected:** All three use timeoutInterval 30. fetchJSON is a GET with Accept: application/json; a non-HTTP response throws network("The server didn't answer properly."); any other thrown error becomes network("") which renders as "The network didn't answer."; a non-2xx status or an unparseable body throws metadataFailed("The server answered <status>."). post sends JSON with Content-Type and Accept application/json and returns the data and response without checking the status. postForm builds the body by percent-encoding the fields as a query string, sends it with Content-Type application/x-www-form-urlencoded and Accept application/json, and likewise returns without checking the status. An unparseable URL in any of them throws network("That address isn't valid."). oauthErrorMessage returns the body's non-empty error_description, else its error, else nil. origin builds "<scheme>://<host>" plus ":<port>" when a port is present, and throws discoveryFailed("That address doesn't look like a URL.") when the scheme or host is missing or empty.
- **Side effects:** one HTTP request per call
- **Persistence:** none
- **Failure cases:** the five literal messages above
- **Cancellation:** each request is a cancellation point
- **Windows path:** Same timeouts, same content types, same message collapsing. Note network and callbackFailed render their detail with no prefix, while the other cases prefix a base sentence.
- **Verify by:** unit over each helper's failure branches

### PR-MCP-161 - PKCE uses a 32-byte verifier and a 24-byte state, base64url encoded without padding, from the default random generator
- **Source:** DroppyCode/Services/MCP/MCPOAuth.swift:816-834 randomToken, pkceChallenge and base64url
- **Preconditions:** A sign-in is starting.
- **Action:** The secrets are minted.
- **Expected:** randomToken fills a byte array of the requested length with values drawn one at a time from the language's DEFAULT random generator - not a cryptographic-random API - and base64url encodes it. The verifier is 32 bytes and the state is 24 bytes. base64url is standard base64 with "+" replaced by "-", "/" replaced by "_", and every "=" removed. The challenge is the SHA-256 digest of the verifier's UTF-8 bytes, base64url encoded, and the method sent is always "S256". The byte counts, the encoding and S256 are parity-relevant; the generator choice is a defect the register notes.
- **Side effects:** none
- **Persistence:** none; both values live only for the duration of the sign-in
- **Failure cases:** none
- **Cancellation:** not cancellable
- **Windows path:** Keep the 32 and 24 byte lengths, the base64url encoding without padding and S256. Use the platform's cryptographic random source rather than a general-purpose generator: that is a deliberate, recorded strengthening of an upstream weakness, not a behavioral change, because the wire format and lengths are unchanged.
- **Verify by:** unit asserting the encoded lengths and the S256 challenge against a known verifier
- **Upstream defect 22: reproduce it faithfully, do not fix it.**

### PR-MCP-164 - Text interpolated into a callback page is HTML-escaped for five characters
- **Source:** DroppyCode/Services/MCP/MCPOAuth.swift:915-929 escapeHTML
- **Preconditions:** A server name or a provider message is being rendered.
- **Action:** escapeHTML runs.
- **Expected:** Character by character: "&" becomes "&amp;", "<" becomes "&lt;", ">" becomes "&gt;", a double quote becomes "&quot;", a single quote becomes "&#39;"; everything else is copied unchanged. This is applied to the server name in both pages and to the provider's error message in the failure page, so a hostile error_description cannot inject markup.
- **Side effects:** none
- **Persistence:** none
- **Failure cases:** none
- **Cancellation:** not cancellable
- **Windows path:** Same five replacements, in a page served to the user's browser from a loopback listener, so the escaping is load-bearing.
- **Verify by:** unit feeding a message containing markup and quotes
