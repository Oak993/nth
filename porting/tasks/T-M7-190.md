- **Preconditions:** The panel is shown.
- **Action:** User drags the 16x16 grip at the panel's bottom-right corner.
- **Expected:** The panel resizes live and the new size is written to settings on every drag tick, not on release. The clamp applies the outer maximum last, so in a narrow chat area the written size can be smaller than the stated 240x320 minimum, and that sub-minimum value reaches the settings store; the read path floors it again, hiding the bad value until the window grows. The clamp is also anchored on `origin`, which is the dragged origin while the title strip is held, so resizing during a move clamps against the dragged origin rather than the resting one. - **Persistence:** settings.sidebarPanelSize, under the exact key `sidebarPanelSize` as a two-element array of doubles [width, height]; nil removes the key; a stored array not of length two is ignored on read.
- **Failure cases:** Sub-minimum value persisted: floored again on read.
- **Cancellation:** A cancelled drag leaves the last written size in place.
- **Windows path:** Same key name and array form. Reproduce both clamp arithmetics separately and accept that a sub-240 or sub-320 size can reach the store (port_impacts entry 155). The frame-resize cursor is the Windows diagonal resize cursor.
- **Verify by:** unit test on the clamp proving a sub-minimum value is written in a narrow area, plus a restart test.
- **Upstream defect 56: reproduce it faithfully, do not fix it.**
