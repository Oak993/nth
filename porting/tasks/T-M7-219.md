### PR-TERM-046 - Terminating a session is idempotent and flips it to not running
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:59-63 terminate() - guard isRunning else { return }; view.terminate(); isRunning = false
- **Preconditions:** A session exists.
- **Action:** terminate() is called from close, restart, closeAll or terminateAll.
- **Expected:** The first call kills the shell through the terminal view and sets isRunning false. Every later call returns immediately and does nothing, so a session already reported as exited by its own process callback is never killed twice.
- **Side effects:** The shell process and its children receive SwiftTerm's termination.
- **Persistence:** None.
- **Failure cases:** A shell that ignores the signal is not escalated by this code; the source has no kill ladder here, unlike Shell.terminate (PR-TERM-081) and StdioProcess.terminate (PR-TERM-124).
- **Cancellation:** not cancellable
- **Windows path:** Close the ConPTY and terminate the process tree. Platform boundary: Windows has no signals; killing only the shell can orphan its children, which the source does not have to handle because the pty session dies with it. Record whatever escalation the port needs as an engineering decision, and note that the source has none here.
- **Verify by:** unit test on idempotence plus a process-tree assertion

### PR-TERM-047 - A shell that exits on its own marks the session not running via a hop to the main actor
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:97-100 processTerminated - captures the session and runs Task { @MainActor in session?.processEnded() } | DroppyCode/App/Views/Terminal/TerminalStore.swift:78-80 processEnded - sets isRunning = false | DroppyCode/App/Views/Terminal/TerminalStore.swift:84-89 TerminalBridge - a weak reference to the session, held as the terminal view's process delegate
- **Preconditions:** A session's shell is running.
- **Action:** The user types exit, or the shell dies for any reason.
- **Expected:** The delegate callback schedules a main-actor task that sets isRunning false. The tab immediately dims to 0.55, gains its restart button, and changes its tooltip and accessibility label (PR-TERM-022, PR-TERM-026, PR-TERM-027). The tab is NOT removed and the terminal view keeps showing its final scrollback. The exit code is received by the callback and deliberately discarded: it is never shown anywhere.
- **Side effects:** The thread becomes eligible for idle runtime release only after every session is closed, not merely exited (PR-TERM-062).
- **Persistence:** None.
- **Failure cases:** The session has already been deallocated: the weak reference is nil and nothing happens.
- **Cancellation:** not cancellable
- **Windows path:** Same: the exit callback marks the session dead on the UI thread and the exit code is discarded.
- **Verify by:** interaction test typing exit and asserting the tab state

- **Expected:** Nothing happens. The tab title stays exactly what the store gave it, the session's directory stays what it was constructed with, and no size event is acted on. A shell prompt that sets the window title has no visible effect anywhere in the app.

### PR-TERM-049 - Whether the shell owns the terminal foreground is read from the kernel process table, not from the pty
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:65-68 - the doc comment: true at the prompt, false while a job it started (vim, claude, less) has the terminal; read from the kernel's view of the shell, since the pty's master side answers no tcgetpgrp to a process it is not the controlling terminal of | DroppyCode/App/Views/Terminal/TerminalStore.swift:69-76 foregroundJobIsTheShell - returns false for shell <= 0; builds the MIB [CTL_KERN, KERN_PROC, KERN_PROC_PID, shell]; returns false unless sysctl returns 0 and size > 0; otherwise returns info.kp_eproc.e_tpgid == info.kp_eproc.e_pgid | porting/port_impacts.md:436 entry 214 - the Terminal subsystem's hardest macOS dependency is foregroundJobIsTheShell, not SwiftTerm
- **Preconditions:** A session has a shell pid.
- **Action:** The Escape monitor asks whether the shell is in the foreground.
- **Expected:** False when the pid is not positive, false when the sysctl call fails or reports zero bytes, otherwise true exactly when the terminal's foreground process group id equals the shell's own process group id. It is nonisolated and safe to call from the event monitor.
- **Side effects:** One sysctl read per Escape keypress while the terminal has focus.
- **Persistence:** None.
- **Failure cases:** Any failure answers false, which means Escape is passed through to the terminal rather than closing the drawer. Failing closed is the source's behaviour and must be preserved.
- **Cancellation:** not cancellable
- **Windows path:** PLATFORM BOUNDARY, unresolved. ConPTY has no process groups and no tpgid, so this predicate has no translation. An explicit engineering decision is required; the fail-closed direction (answer false when unknown, so Escape reaches the terminal) is the source-defined safe answer and must be kept whatever mechanism is chosen.
- **Verify by:** contract fixture with a foreground child running and with the shell idle
- **Depends on UNK-0005**, which is unresolved. Implement only the part the source settles; flag the rest.

### PR-TERM-051 - open() names an untitled tab Terminal followed by the thread's session count plus one, appends it and selects it
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:118-125 open(threadID:directory:title:command:) - let number = sessions(for: threadID).count + 1; title defaults to "Terminal \(number)"; the session is appended to sessions[threadID] and selection[threadID] is set to its id; the session is returned and the result is discardable
- **Preconditions:** None.
- **Action:** open is called with no explicit title.
- **Expected:** The first tab in a thread is "Terminal 1", the second "Terminal 2", and so on. The number is derived from the CURRENT count, so closing tab 2 of three and then opening a new one produces a second tab also called "Terminal 3": names are not unique and are never renumbered. - **Persistence:** None.
- **Cancellation:** not cancellable
- **Windows path:** Same numbering, including the duplicate-name consequence. Do not make the names unique.
- **Verify by:** unit test: open three, close the second, open a fourth, assert two tabs named "Terminal 3"

### PR-TERM-052 - restart() kills the old shell and substitutes a fresh session at the same position, keeping the title and directory and dropping the startup command
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:137-138 - the doc comment: replaces an exited shell with a fresh one in the same place in the row, keeping the tab's name and its directory, so a shell that quit is one click from working again | DroppyCode/App/Views/Terminal/TerminalStore.swift:139-155 restart(_:) - session.terminate(); a fresh TerminalSession with the same threadID, directory and title and command: nil; replaced at the old session's index when it is still in the array, otherwise appended; selection[threadID] set to the fresh id; the fresh session is returned
- **Preconditions:** A session exists, typically one whose shell has exited.
- **Action:** The user clicks the restart button on a tab.
- **Expected:** The old session is terminated (a no-op when it already exited), a new session is created with the same thread, directory and title but NO startup command, it takes the old one's index in the row so the tab does not jump, and it becomes the selection. A script tab restarted this way becomes a plain interactive shell that keeps the script's name: the script is not re-run. If the old session is no longer in the array the fresh one is appended at the end instead.
- **Side effects:** A new shell process is launched; the old session object, its view and its scrollback are discarded.
- **Persistence:** None.
- **Cancellation:** not cancellable
- **Windows path:** Same, including that the restarted script tab does not re-run its command and keeps the script's name.
- **Verify by:** unit test on index preservation plus an interaction test on a script tab

### PR-TERM-053 - close() terminates and removes the session, and moves the selection to the last remaining tab
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:157-163 close(_:) - session.terminate(); removeAll matching the id from sessions[threadID]; if selection[threadID] was that id, it becomes sessions[threadID]?.last?.id
- **Preconditions:** A session exists.
- **Action:** The user clicks the tab's close cross.
- **Expected:** The shell is killed, the tab disappears, and if the closed tab was the selected one the selection moves to the LAST remaining tab (not the neighbour, not the first). Closing an unselected tab leaves the selection alone. Closing the last tab sets the selection to nil and shows the empty state (PR-TERM-010).
- **Side effects:** The shell process is terminated; scrollback is lost.
- **Persistence:** None.
- **Cancellation:** not cancellable; there is no confirmation, and settings.confirmBeforeDeleting is not consulted anywhere in this file
- **Windows path:** Same, including the last-tab (not neighbour) selection rule and the absence of any confirmation.
- **Verify by:** unit test over selection transitions

### PR-TERM-056 - terminateAll() kills every shell across every thread at shutdown but leaves the dictionaries intact

- **Preconditions:** The app is quitting.
- **Action:** Shutdown runs.
