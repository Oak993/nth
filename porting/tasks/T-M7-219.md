## Requirements

### PR-TERM-011 - The selected session is the one whose id matches the thread's selection, falling back to the last session in the row
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:113-116 selected(for:) - list.first matching selection[threadID], otherwise list.last
- **Preconditions:** The thread has one or more sessions.
- **Action:** The panel asks for the selected session.
- **Expected:** If selection[threadID] names a session still in the list, that one is selected. Otherwise the LAST session in the list is selected, so a stale or missing selection still shows a live tab. With no sessions at all, nil is returned and the empty state renders.
- **Persistence:** None; selection is in-memory per run.
- **Failure cases:** Selection names a removed session: the last session is shown instead, and the stale key is left in the dictionary.
- **Cancellation:** not cancellable
- **Windows path:** Same fallback, including leaving the stale key in place.
- **Verify by:** unit test on the store

### PR-TERM-037 - A session is identified by a fresh UUID and carries its thread, directory and title for its whole life
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:7-12 - class TerminalSession: Identifiable with let id = UUID(), let threadID: UUID, let directory: String, var title: String, private(set) var isRunning = true
- **Preconditions:** None.
- **Action:** A session is created.
- **Expected:** id is a new UUID and never changes; threadID and directory are immutable; title is mutable but is only ever set at construction by the store; isRunning starts true and is only ever set to false, never back to true (a restart makes a new session instead).
- **Persistence:** Nothing about a session is persisted; every session is gone on quit.
- **Cancellation:** not cancellable
- **Windows path:** Same immutable identity and one-way isRunning.
- **Verify by:** unit test on the session model

### PR-TERM-038 - Each session creates its terminal view at a fixed 640 by 240 frame with the font TerminalFont.preferred() picks and Option treated as Meta
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:21-23 - view = LocalProcessTerminalView(frame: NSRect(x: 0, y: 0, width: 640, height: 240)); view.font = TerminalFont.preferred(); view.optionAsMetaKey = true | DroppyCode/App/Views/Terminal/TerminalFont.swift:8-16 preferred(fallbackSize: CGFloat = 12) - the configured terminal font with Nerd glyphs, else its Nerd sibling, an installed Nerd Font or the configured font itself, else an installed Nerd Font at 12, else NSFont.monospacedSystemFont(ofSize: fallbackSize, weight: .regular)
- **Preconditions:** A session is being created.
- **Action:** TerminalSession.init runs.
- **Expected:** The terminal view starts at 640 by 240 points (its real size comes from the host container immediately afterwards), renders in the font TerminalFont.preferred() returns at the moment the session is created (PR-TERM-124 and PR-TERM-125: a font read from the Ghostty, iTerm2 or Terminal.app configuration, preferring one with Nerd Font glyphs; only with no configured font and no installed Nerd Font is it the 12-point regular monospaced system font), and sends Option-modified keys as Meta escape sequences.
- **Persistence:** None. Droppy Code itself has no setting for the terminal font or size; the face and size can come from another terminal application's configuration, read afresh for every new session.
- **Cancellation:** not cancellable
- **Windows path:** An xterm-class terminal with Alt treated as Meta (xterm.js macOptionIsMeta equivalent), whose font comes from the port of TerminalFont.preferred() (PR-TERM-125). Platform boundary: the three configuration sources are macOS terminals (PR-TERM-126); the final monospaced-system fallback is Cascadia Mono under OD-0009 (monospace as recommended in D3), a named deviation.
- **Verify by:** contract fixture over TerminalFont.preferred() with each source present and absent, plus capture comparison of cell metrics and a key test for Alt as Meta

### PR-TERM-039 - The session runs the user's login shell as resolved by LoginEnvironment.userShell(); the port runs PowerShell 7 if installed, otherwise Windows PowerShell
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:28 - let shell = LoginEnvironment.userShell() | DroppyCode/Core/Support/Shell.swift:429-439 userShell() - SHELL from the process environment if it is an executable file, else getpwuid(getuid()).pw_shell if it is an executable file, else the literal "/bin/zsh"
- **Preconditions:** None.
- **Action:** A session is created.
- **Expected:** Upstream: the executable launched is the first of the SHELL environment variable when it names an executable file, the login shell from the password database when it names an executable file, or the literal /bin/zsh. - **Cancellation:** not cancellable

### PR-TERM-040 - The shell inherits the captured login environment with exactly four variables overridden
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:29-33 - var environment = LoginEnvironment.current; environment["TERM"] = "xterm-256color"; environment["COLORTERM"] = "truecolor"; environment["TERM_PROGRAM"] = "Droppy Code"; environment["DROPPY_CODE_PROJECT_ROOT"] = directory | DroppyCode/Core/Support/Shell.swift:335-339 - TERM, TERM_PROGRAM and COLORTERM are among the keys stripped from the captured login environment, so these three are always set by this code and never inherited
- **Preconditions:** None.
- **Action:** A session is created.
- **Expected:** The child receives the captured login environment plus exactly these four entries: TERM=xterm-256color, COLORTERM=truecolor, TERM_PROGRAM=Marrow, DROPPY_CODE_PROJECT_ROOT set to the session's directory. No other variable is added or removed here. Because the capture strips TERM, TERM_PROGRAM and COLORTERM, these assignments are always writes rather than overwrites. DEVIATION (OD-0008 B12): upstream sets TERM_PROGRAM to "Droppy Code"; the variable names, the other three values and DROPPY_CODE_PROJECT_ROOT's name are unchanged.
- **Side effects:** User shell profiles and any tool the user runs can read DROPPY_CODE_PROJECT_ROOT and TERM_PROGRAM.
- **Persistence:** None, but the variable names are an external contract with whatever the user's shell configuration and scripts read.
- **Cancellation:** not cancellable
- **Windows path:** Same four names. TERM_PROGRAM's value is "Marrow" (OD-0008 B12); DROPPY_CODE_PROJECT_ROOT keeps its name (resolution of Q131, recorded with OD-0008 in porting/owner_decisions_pending.md; precedent porting/port_impacts.md:114 entry 53).
- **Verify by:** contract fixture asserting the child environment

### PR-TERM-041 - The environment dictionary is flattened to KEY=VALUE strings with no quoting or escaping
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:34 - let pairs = environment.map { "\($0.key)=\($0.value)" } | DroppyCode/App/Views/Terminal/TerminalStore.swift:40 - the pairs array is passed as the environment argument to startProcess
- **Preconditions:** None.
- **Action:** A session is created.
- **Expected:** Each entry becomes one string of the key, an equals sign and the value, with no quoting, escaping or sorting. Dictionary iteration order is unspecified, so the order of the resulting array is not stable between runs; nothing in the source depends on it.
- **Persistence:** None.
- **Failure cases:** A value containing a newline or NUL is passed through as-is; the source performs no validation.
- **Cancellation:** not cancellable
- **Windows path:** Windows takes an environment block rather than an argv-style array; build it from the same map with no quoting. Platform boundary: Windows environment variable names are case-insensitive, so two keys differing only in case would collide where macOS keeps both.
- **Verify by:** unit test on the flattener

### PR-TERM-042 - The shell is launched as a login shell by setting argv[0] to a hyphen followed by the shell's file name; the port drops that convention
- **Source:** DroppyCode/App/Views/Terminal/TerminalStore.swift:35 - let shellName = "-" + (shell as NSString).lastPathComponent | DroppyCode/App/Views/Terminal/TerminalStore.swift:40 - execName: shellName is passed to startProcess | porting/port_impacts.md:438 entry 215 - Windows cannot use hyphen-argv[0] login semantics; replace it explicitly with the user's shell, the project directory as cwd, the same four environment variables, and a script tab that runs the command then hands back to an interactive shell | porting/owner_decisions_pending.md:141 - the recorded C5 ruling: "terminal tabs and project scripts run in PowerShell 7 (pwsh) when installed, otherwise Windows PowerShell." It fixes only the interpreter. The lead's question Q125 at :143 (question text, not the ruling) is what raised the hyphen argv[0] and the POSIX-script consequences
- **Preconditions:** None.
- **Action:** A session is created.
- **Expected:** Upstream: argv[0] is a hyphen followed by the last path component of the shell executable (for example "-zsh" for /bin/zsh), which is the Unix convention that makes the shell read its login profile files. DEVIATION (OD-0008 C5): the port launches PowerShell, and Windows cannot use hyphen argv[0] login semantics (porting/port_impacts.md:438 entry 215), so no hyphen execName is set; the C5 ruling itself fixes only the interpreter; PowerShell runs the user's profile for an interactive session on its own.
- **Side effects:** The user's profile scripts are executed inside the terminal.
- **Persistence:** None.
- **Cancellation:** not cancellable
- **Windows path:** No hyphen argv[0]. The interpreter is PowerShell 7 if installed, otherwise Windows PowerShell (OD-0008 C5); the tab is a full interactive shell with the user's profile applied.
- **Verify by:** contract fixture asserting the launch vector carries no hyphen-prefixed argv[0]
