### PR-COMPOSER-205 - Finder icons for non-media attachments are cached by a four-way key and bounded at 64 entries evicted oldest first
- **Source:** DroppyCode/UI/Common/AttachmentPreview.swift:102-106 `/// Finder icons by extension, cached: one lookup per row per render stalled scrolling.` with `@MainActor enum FileIcons { private static var cache: [String: NSImage] = [:]; private static var order: [String] = [] }` | DroppyCode/UI/Common/AttachmentPreview.swift:108-120 `static func icon(for path: String) -> NSImage { let key = iconKey(for: path); if let hit = cache[key] { return hit }; let image = NSWorkspace.shared.icon(forFile: path); cache[key] = image; order.append(key); /* Bounded: icons are small but unbounded kinds are not. */ while order.count > 64, let oldest = order.first { order.removeFirst(); cache.removeValue(forKey: oldest) }; return image }` | DroppyCode/UI/Common/AttachmentPreview.swift:122-133 `private static func iconKey(for path: String) -> String { let ext = (path as NSString).pathExtension.lowercased(); if !ext.isEmpty { return ext }; var isDirectory: ObjCBool = false; if FileManager.default.fileExists(atPath: path, isDirectory: &isDirectory), isDirectory.boolValue { return "folder" }; if let type = try? - **Preconditions:** An attachment row needs a file icon.
- **Action:** The icon is requested for a path.
- **Expected:** The cache key is derived in four steps, in this order: the path's extension lowercased when it is non-empty; otherwise the literal "folder" when the path exists and is a directory; otherwise the literal "type:" followed by the resolved content type's identifier; otherwise the literal "file". The cache is bounded at 64 entries and evicts in insertion order, oldest first, in a loop, so several entries over the bound are all evicted in one call.
