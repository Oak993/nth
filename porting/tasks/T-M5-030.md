### PR-COMPOSER-206 - A previewed image gets one cached attachment value per path, whose MIME type falls back to the literal "image/*"
- **Source:** DroppyCode/UI/Common/AttachmentPreview.swift:80-82 `/// One attachment value per file, so the preview panel's toggle recognises the same image on a second tap and closes instead of reopening.` with `@MainActor private static var attachments: [String: Attachment] = [:]` | DroppyCode/UI/Common/AttachmentPreview.swift:84-93 `/// The file as an attachment, for the same large preview a sent photo opens in.` with `static func attachment(for path: String) -> Attachment { if let known = attachments[path] { return known }; let name = (path as NSString).lastPathComponent; let mimeType = UTType(filenameExtension: (path as NSString).pathExtension.lowercased())?.preferredMIMEType ?? "image/*"; let attachment = Attachment(name: name, path: path, mimeType: mimeType.hasPrefix("image/") ? mimeType : "image/*"); attachments[path] = attachment; return attachment }`
- **Preconditions:** An image on disk is about to be shown in the large preview.
- **Action:** An attachment value is requested for its path.
- **Expected:** Exactly one attachment value exists per path for the process lifetime, returned unchanged on every later request. This identity is load-bearing, not an optimisation: the preview panel's toggle compares the value it is showing against the value it is handed, so a second tap on the same image must produce the same value or the panel reopens instead of closing. The name is the path's last component. The MIME type is resolved from the lowercased extension's preferred MIME type, but only accepted when it starts with "image/"; in every other case, including an unrecognised extension and a recognised non-image type, the MIME type is the literal string "image/*". The cache is unbounded.
- **Persistence:** A process-lifetime cache.
- **Cancellation:** not cancellable
- **Windows path:** The literal "image/*" is the fallback in two separate places in one expression and must be reproduced in both. Returning a fresh equal-valued record per call is not equivalent if the panel's toggle compares by identity; the Windows build must either keep the cache or make the toggle compare by path.
- **Verify by:** unit test over a .png, a .txt and an extensionless path asserting the MIME type, plus an interaction test that a second tap on the same image closes the panel

- **Preconditions:** A video attachment's thumbnail (AttachmentVideoThumbnail, drawn by AttachmentThumbnail for a video) appears in an attachment strip: the composer draft, a queued follow-up, a prompt editor or a sent message.
- **Action:** The thumbnail's task runs prefetchVideoSize for the attachment.
- **Expected:** When the attachment is a video and its path has no cached size, the first video track and its natural size and preferred transform are loaded asynchronously; the transform is applied, both sides are made positive, and the size is aspect-fitted into 480 by 360 with each side floored, then stored under the attachment's path. A path already cached, or a non-video attachment, returns at once with no load. The check comes before the two awaited loads and the store after them, so two runs for one path that overlap both load and each stores its result. No track, a failed load, or a zero width or height stores nothing, so the next run of the thumbnail's task tries again. The cache is keyed by path only, has no bound and no eviction, and lives for the life of the process, so a different file later placed at the same path keeps the first size.
- **Side effects:** Reads the video file's track metadata whenever its path has no cached size when a run starts: runs that do not overlap read it once per path while it succeeds, but two runs for the same path whose loads overlap (for example the same file in the draft strip and in a sent message's strip) both read it, because the cache is checked before the awaited loads (:269) and written only after them (:278); Grows an unbounded, process-lifetime path-to-size map
- **Persistence:** Nothing on disk; an in-memory map for the life of the process.
- **Failure cases:** No readable video track, a failed load or a zero size: nothing is cached and a later run retries.; The thumbnail never appears: nothing is cached and the preview opens at 480 by 360 (PR-COMPOSER-210).
- **Cancellation:** Runs inside the thumbnail's .task(id: attachment.path), which SwiftUI cancels when the thumbnail goes away or its path changes; the source adds no cancellation handling of its own.
- **Windows path:** An asynchronous media-metadata read of the first video stream's frame size and rotation, the rotation applied, sides made positive, fitted into 480 by 360 with floor, and stored in a process-lifetime dictionary keyed by path with no eviction. Start it from the video thumbnail's appearance, before the thumbnail's frame grab, as the source does; not from the preview's open.
- **Verify by:** unit test of the fit over a landscape track, a portrait track rotated by its transform and a zero-size track, plus an integration test asserting one metadata read per path across two appearances that do not overlap, two reads for two appearances whose loads overlap, and a retry after a failed read
