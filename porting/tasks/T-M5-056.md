### PR-THEME-105 - A finished message renders its blocks as prose runs and standalone blocks; a streaming one renders every block separately
- **Source:** DroppyCode/UI/Markdown/MarkdownView.swift:25-45 `segments(_:)`: headings, paragraphs, lists and quotes accumulate into a prose run; code, tables and rules close the run and stand alone | DroppyCode/UI/Markdown/MarkdownView.swift:63-102 the body: when not streaming, the segments are rendered as ProseRunView for a run and MarkdownBlockView for a standalone block; while streaming, every block is a MarkdownBlockView carrying `settled: index < stable` and the streaming environment set only on the last block; both arms use a VStack of alignment leading and spacing 12 and set the veiled environment for the whole message | DroppyCode/UI/Markdown/MarkdownView.swift:9-23 the view is Equatable on text and the streaming flag, so finished replies are skipped entirely while a new reply streams
- **Preconditions:** A message is being rendered.
- **Action:** Its blocks are laid out.
- **Expected:** Blocks are stacked leading-aligned with 12 points between them. A finished message groups consecutive headings, paragraphs, lists and quotes into one prose run rendered as a single text object, breaking the run at each code block, table or rule, which render as their own views. A streaming message renders every block on its own, marks blocks below the stable count as settled, and marks only the last block as streaming. The whole message is marked veiled while it streams, so every block dissolves its arriving text, not only the last.
- **Persistence:** not persisted
- **Failure cases:** None expressed in source.
- **Cancellation:** not cancellable
- **Windows path:** The two paths produce visibly different typography (the run path is one native text object, the block path is a stack of views), and a message swaps from one to the other when its stream ends. That swap is the shipped behaviour and must be reproduced, including the spacing being 12 in both.
- **Verify by:** interaction test: a reply's layout when streaming and after it finishes; unit: the segment grouping

### PR-THEME-106 - Blocks compare by content, except that two blocks both marked settled compare equal without looking at their content
- **Source:** DroppyCode/UI/Markdown/MarkdownView.swift:278-298 MarkdownBlockView is Equatable: `nonisolated static func == (lhs: MarkdownBlockView, rhs: MarkdownBlockView) -> Bool { if lhs.settled, rhs.settled { return true }; return lhs.block == rhs.block }` (:295-298), with the comment (:280-283) that comparing every byte of every earlier block of the reply on every flush is work the flush does not need
- **Preconditions:** A streaming reply flushes.
- **Action:** The view tree is diffed.
- **Expected:** Two block views in the same position that are both settled are treated as identical without comparing their content; every other pair is compared by value. Because the parser guarantees a settled block cannot change (PR-THEME-091), the result is the same as a deep comparison.
- **Persistence:** not persisted
- **Failure cases:** If the stable count were wrong, stale content would be shown; the correctness of PR-THEME-091 is what makes this safe.
- **Cancellation:** not cancellable
- **Windows path:** An equality short-circuit keyed on the parser's stability claim. A port that diffs by value everywhere is behaviourally identical but slower on long replies.
- **Verify by:** unit: two settled views compare equal even with different content, which is the documented contract
