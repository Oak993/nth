### PR-GIT-063 - Deleting one thread deletes its checkpoints, and its worktree only when the user chose that or the thread owned its copy

- **Preconditions:** A thread belongs to a project.
- **Action:** The user deletes the thread.
- **Expected:** In one background task, in this order: the thread's checkpoints are deleted, then, only when the user chose "Delete thread and worktree" or the thread is a Hydra head that owned its own copy, the worktree is removed. - **Cancellation:** not cancellable
- **Windows path:** Direct port. Worktree removal on Windows must contend with open file handles; the try? swallow is reproduced.
- **Verify by:** interaction test on both menu choices

### PR-LAUNCH-030 - A reused launch thread is refreshed to what a fresh chat would open on today, clearing the provider session if the provider changed
