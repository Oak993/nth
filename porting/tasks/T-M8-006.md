### PR-UPDATE-014 - A feed with no qualifying release is an error, not an empty success
- **Source:** DroppyCode/App/UpdateChecker.swift:164-166 guard let newest = Self.newestRelease(in: releases) else { throw UpdateError.noRelease } | DroppyCode/App/UpdateChecker.swift:271 case .noRelease: "No release with a disk image was found."
- **Preconditions:** The API answered 2xx and decoded, but every release was filtered out.
- **Action:** check() evaluates newestRelease.
- **Expected:** UpdateError.noRelease is thrown and handled by the catch branch, so lastError becomes exactly "No release with a disk image was found." and any previously stored update is LEFT IN PLACE (the catch branch never clears `update`). The pill therefore shows "Check failed" while a stale waiting update may still be offered by the About page.
- **Side effects:** Only "updateChecker_lastChecked" is written; "updateChecker_release" is untouched.
- **Persistence:** "updateChecker_lastChecked" only.
- **Failure cases:** This IS the failure case.
- **Cancellation:** not cancellable
- **Windows path:** OD-0008 C6 (resolving UNK-0009) rules the state only: the update check shows its "Check failed" state until the owner has a Windows release feed. OD-0012 I1 rules the message while the feed value is empty (its default): no request is made and lastError is exactly "No update feed is set." (PR-UPDATE-005). Once the owner supplies a feed, the message is whatever lastError the failing branch of check() sets, as upstream: a feed that answers 2xx with releases none of which qualifies reaches this branch and gives "No release with a disk image was found." (UpdateChecker.swift:271); a non-2xx answer gives "GitLab answered with HTTP <status>." (UpdateChecker.swift:191-193, :272); any other failure of the fetch or decode gives "Couldn't reach GitLab." (UpdateChecker.swift:182). Whichever branch runs, its message must not be papered over with a friendlier one.
- **Verify by:** contract fixture

### PR-UPDATE-015 - newestRelease keeps the highest version among releases that are published, dated in the past, parse, and ship an installable asset
- **Source:** DroppyCode/App/UpdateChecker.swift:199-219 for release in releases { guard !release.upcomingRelease, let version = AppVersion(release.tagName) else { continue }; if let releasedAt = release.releasedAt, releasedAt > .now { continue }; guard let link = release.assets.links.first(where: { $0.isDiskImage }) else { continue }; guard let downloadURL = URL(string: link.directAssetURL ?? link.url) else { continue }; ...; if let current = best, current.0 >= version { continue }; best = (version, candidate) }
- **Preconditions:** A decoded array of releases.
- **Action:** The selection runs over the array in feed order.
- **Expected:** A release is skipped when upcoming_release is true, when its tag does not parse (PR-UPDATE-001), when released_at is strictly in the future, when no asset link qualifies as the installable artifact, or when the chosen link's URL string will not parse. Among the survivors the highest AppVersion wins; on an exact tie the FIRST one in feed order is kept, because the replace test is `current.0 >= version` (a later equal candidate is skipped).
- **Persistence:** None.
- **Failure cases:** Empty survivor set returns nil, which check() turns into UpdateError.noRelease.
- **Cancellation:** not cancellable
- **Windows path:** Same five filters and the same tie rule. The asset predicate is the one thing that changes: on Windows the qualifying asset is the Windows release artifact rather than a .dmg. Under OD-0008 C6 (resolving UNK-0009) no release qualifies until the owner has a Windows release feed, and the check shows "Check failed"; the artifact's suffix is not fixed by the ruling. None of this is licence to loosen any of the other four filters.
- **Verify by:** contract fixture

### PR-UPDATE-016 - An asset link counts as the installable artifact when either its URL path or its name ends in .dmg, case-insensitively
- **Source:** DroppyCode/App/UpdateChecker.swift:288-291 var isDiskImage: Bool { let path = (directAssetURL ?? url).lowercased(); return path.hasSuffix(".dmg") || name.lowercased().hasSuffix(".dmg") }

- **Action:** The selection tests the link.
- **Expected:** True when the lowercased direct_asset_url (or url when direct_asset_url is absent) ends in ".dmg", OR when the lowercased name ends in ".dmg". - **Cancellation:** not cancellable

Do not add a platform field to the feed; the feed has none. OD-0008 C6 resolves UNK-0009: until the owner has a Windows release feed no link qualifies and the check shows "Check failed"; the Windows suffix itself is not fixed by the ruling.
- **Verify by:** unit

### PR-UPDATE-018 - The artifact size is learned from a HEAD request only when the release JSON did not supply one, and nothing depends on it
- **Source:** DroppyCode/App/UpdateChecker.swift:171-173 if found.size == nil { found.size = await downloadSize(of: found.downloadURL) } | DroppyCode/App/UpdateChecker.swift:221-229 downloadSize(of:) - httpMethod "HEAD"; requires 2xx and expectedContentLength > 0, else nil
- **Preconditions:** A release was selected and its size field is nil (newestRelease always builds the candidate with size: nil at UpdateChecker.swift:210, so the HEAD always runs on the success path).
- **Action:** check() fills in the size.
- **Expected:** One HEAD request to the download URL on the same session. The size is taken from expectedContentLength only when the response is 2xx and the length is strictly greater than 0; any other outcome leaves size nil. A failed HEAD does NOT fail the check: it is swallowed by try?.
- **Side effects:** Network: one HEAD per successful check.
- **Persistence:** Stored as "size" in the persisted record; nil is persisted as absent.
- **Failure cases:** Non-2xx, thrown error, or length <= 0 -> size stays nil, and the About page's release detail line simply omits the size segment (PR-UPDATE-067).
- **Cancellation:** not cancellable
- **Windows path:** Same HEAD, same swallow-on-failure. Use Content-Length; treat a missing or zero length as nil. This is display-only and must never gate the install.
- **Verify by:** contract fixture
