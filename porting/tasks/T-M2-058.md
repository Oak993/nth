### PR-USAGE-087 - TokenSpend semantics: the amount is what one event consumed, cached input is a subset, and an agentID belongs to that head alone
- **Source:** DroppyCode/Core/Models/TokenSpend.swift:3-14 doc comment - The amount is what this event is responsible for, the usage one request or one turn just consumed, never the occupancy of a context window, which ContextUsage carries separately. cachedInputTokens is a subset of totalTokens, so it is never added on top of input tokens; only totalTokens is authoritative. agentID names the head a provider ran inside the session; a consumer must not attribute an event carrying an agentID to the session's lead as well.
- **Preconditions:** A consumer is aggregating spend.
- **Action:** Spend events are summed or attributed.
- **Expected:** totalTokens is the only authoritative amount; input, output and cached values are informational breakdowns and cachedInputTokens must never be added on top of inputTokens. A spend is never treated as a context-window occupancy. An event carrying an agentID is attributed to that head only and must not also be counted against the session's lead.
- **Persistence:** None of its own.
- **Failure cases:** Double counting a head's spend against its lead inflates every aggregate that reads these records.
- **Cancellation:** not cancellable
- **Windows path:** Enforce in the aggregation code and in any test fixture; the contract is stated only in the doc comment, so it must be carried into the port's own documentation.
- **Verify by:** unit test summing a mixed lead-and-head spend list

### PR-USAGE-088 - Merging two spends adds the totals but erases a breakdown the other side lacks, and never changes identity
- **Source:** DroppyCode/Core/Models/TokenSpend.swift:42-52 mutating func merge(_ other: TokenSpend) { totalTokens += other.totalTokens; inputTokens = Self.sum(inputTokens, other.inputTokens); outputTokens = ...; cachedInputTokens = ... } and private static func sum(_ lhs: Int?, _ rhs: Int?) -> Int? { guard let lhs, let rhs else { return nil }; return lhs + rhs }
- **Preconditions:** Two spend observations are being combined.
- **Action:** merge is called.
- **Expected:** totalTokens is always added. Each of the three optional breakdowns becomes the sum only when both sides have a value; if either side is nil the merged field is nil, so merging a detailed spend with one lacking a breakdown erases that breakdown rather than reporting a partial total. provider, model and agentID are not touched, so the receiver's identity always wins.
- **Persistence:** None.
- **Failure cases:** Treating nil as zero would report a partial breakdown as if it were complete; that is not the source behaviour.
- **Cancellation:** not cancellable
- **Windows path:** Same nil-propagating sum; do not use a zero default.
- **Verify by:** unit test over (both present), (left nil), (right nil), (both nil)
