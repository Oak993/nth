### PR-THEME-064 - The live softness render runs one at a time and always renders the newest value asked for
- **Source:** DroppyCode/UI/Theme/Wallpaper.swift:192-210 renderLive(): falls back to render() when either base is missing; records liveRequested = softness; returns when a live task is already running; computes `let scale = CGFloat(previewBase.width) / CGFloat(baseImage.width)`; loops taking the newest request, blurring the preview base at that value and that radius scale, publishing it while the drag continues, and clears the task when the loop ends | DroppyCode/UI/Theme/Wallpaper.swift:212-217 takeLiveRequest(): returns nil once the drag is over, otherwise the stored value, clearing it
- **Preconditions:** A drag is in progress and both the base and the preview base exist.
- **Action:** Softness changes repeatedly during the drag.
- **Expected:** At most one live render runs at a time. A value arriving while one is in flight replaces any earlier pending value, so intermediate values are skipped rather than queued and the slider never lags behind. Each live render blurs the half-size copy at a radius scaled by the ratio of the preview width to the base width, so it looks like the full-size result. When the drag ends the loop stops without publishing further frames. If either cached base is missing the store falls back to a full render.
- **Side effects:** Background blur work; Publishes preview-resolution bitmaps while the drag lasts
- **Persistence:** not persisted
- **Failure cases:** A blur that returns nothing ends the loop.
- **Cancellation:** Ending the drag ends the loop at the next iteration.
- **Windows path:** Coalesce, do not queue. The radius scale must be derived from the actual widths, not assumed to be 0.5: the two thumbnail limits are 3200 and 1600 but the real ratio depends on the source picture's aspect and size.
- **Verify by:** unit: a burst of ten softness values produces fewer than ten renders and the last one rendered is the last value asked for

### PR-THEME-065 - Downsampling asks the image system for a thumbnail with a fixed option set, always creating one and honouring orientation
- **Source:** DroppyCode/UI/Theme/Wallpaper.swift:236-245 thumbnail(_:maxPixel:): CGImageSourceCreateWithURL, options kCGImageSourceCreateThumbnailFromImageAlways: true, kCGImageSourceCreateThumbnailWithTransform: true, kCGImageSourceThumbnailMaxPixelSize: maxPixel, kCGImageSourceShouldCacheImmediately: true, then CGImageSourceCreateThumbnailAtIndex(source, 0, ...)
- **Preconditions:** A wallpaper file exists on disk.
- **Action:** The store downsamples it.
- **Expected:** A thumbnail is always generated from the full image (never taken from an embedded thumbnail), the file's orientation transform is applied, the long side is capped at the requested pixel count, and the pixels are decoded immediately rather than lazily. Only the first image in the file is used, so the first frame of an animated file is the wallpaper. A file the decoder cannot open yields nothing.
- **Side effects:** Reads and decodes the file
- **Persistence:** not persisted
- **Failure cases:** Unopenable or undecodable file: returns nothing, which the caller turns into an install failure or a dropped render.
- **Cancellation:** not cancellable once started
- **Windows path:** Platform boundary: use a Windows imaging decoder with the same four behaviours - always re-scale from the full image, apply the EXIF orientation, cap the long side, decode eagerly. An embedded-thumbnail shortcut would produce a visibly softer wallpaper.
- **Verify by:** unit: a rotated JPEG comes out upright; a 6000 pixel picture comes out at 3200 on its long side

### PR-THEME-066 - Softness blurs with a radius of softness times 28, clamped at the edges so the frame stays solid
- **Source:** DroppyCode/UI/Theme/Wallpaper.swift:247-248 the doc comment: 'Softens the base picture per `softness`, scaled by `radiusScale` so a smaller copy gets a proportionally smaller radius. Runs anywhere: Core Image does the work.' | DroppyCode/UI/Theme/Wallpaper.swift:250-251 `let radius = softness * 28 * radiusScale` and `guard radius > 0.01 else { return base }` | DroppyCode/UI/Theme/Wallpaper.swift:252 `guard let blur = CIFilter(name: "CIGaussianBlur") else { return base }` - the filter identity is the literal string "CIGaussianBlur" | DroppyCode/UI/Theme/Wallpaper.swift:253-254 comment: "The blur shrinks opaque edges toward transparent, so the image is clamped first and cropped back to its own extent: the middle softens while the frame stays solid."
- **Preconditions:** A downsampled base picture exists.
- **Action:** The picture is softened for a softness value.
- **Expected:** The Gaussian radius is softness multiplied by 28 and by the radius scale (1 for the full-size render, the preview-to-base width ratio for a live preview). A radius of 0.01 or less returns the base unchanged, so softness 0 costs nothing. The filter is created by name, and the name is exactly "CIGaussianBlur"; the input image is set under kCIInputImageKey and the radius under kCIInputRadiusKey. The source is clamped to its own extent before blurring and the result cropped back to that extent, taken as the origin plus the base image's pixel width and height, so the picture's outer pixels stay opaque instead of fading to transparent at the window edges. One shared GPU-backed render context is used for every blur, never one per picture.
- **Side effects:** GPU image work
- **Persistence:** not persisted
- **Failure cases:** The blur filter cannot be created: the base is returned unblurred.; The filter produces no output: nothing is returned, and the caller drops the render.
- **Cancellation:** not cancellable once started
- **Windows path:** Platform boundary: "CIGaussianBlur" is a Core Image filter identifier with no Windows counterpart, so the Windows build substitutes its own Gaussian blur (Direct2D's Gaussian blur effect or equivalent). The filter's IDENTITY is recorded here so the substitution is a named one rather than a guess, and so the radius semantics can be matched: Core Image's radius parameter is the Gaussian's standard-deviation-derived radius, and a Windows blur whose parameter means something else must be converted rather than passed through. The 28 multiplier, the 0.01 short-circuit, and the clamp-then-crop edge handling are all observable and must match; a blur without edge clamping puts a soft translucent band around the whole window.
- **Verify by:** unit: radius formula and the short-circuit; capture comparison: the picture's corner pixels stay opaque at softness 1

### PR-THEME-067 - The install-time decode uses the same 3200 pixel cap and the same blur as a full render
- **Source:** DroppyCode/UI/Theme/Wallpaper.swift:262-269 decode(_:softness:): thumbnail at maxPixel 3200, then blurred when softness > 0, then wrapped as an image at the rendered pixel size; returns nothing if either step fails
- **Preconditions:** A file has just been copied into the library.
- **Action:** The install decodes it.
- **Expected:** The copy is downsampled to at most 3200 pixels on its long side and blurred at the softness captured when the install began, exactly as a full render would. Failure at either step returns nothing, which fails the install (PR-THEME-062). The install path deliberately does not produce the 1600 pixel preview copy; that is produced by the next full render.
- **Side effects:** Reads and decodes the copied file
- **Persistence:** not persisted
- **Failure cases:** Either step fails: the install fails and the copy is deleted.
- **Cancellation:** not cancellable
- **Windows path:** Same pipeline as the render, reused.
- **Verify by:** unit: an install with softness 1 shows a blurred picture without waiting for a second render
