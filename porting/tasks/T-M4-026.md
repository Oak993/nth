### PR-PROVACP-072 - resolveApproval answers the agent with the chosen option and resolves the card, once
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:213-217 - `guard let id = pendingPermissions.removeValue(forKey: requestID) else { return }; connection?.respond(to: id, result: ["outcome": ["outcome": "selected", "optionId": .string(optionID)]]); onEvent?(.requestResolved(id: requestID))`
- **Preconditions:** An approval card for requestID is open.
- **Action:** The user picks an option.
- **Expected:** The entry is removed from pendingPermissions first, so a second click on the same card is a no-op: it returns without responding and without emitting. The response payload is exactly {"outcome": {"outcome": "selected", "optionId": <the chosen id>}}. A .requestResolved event with the same request id follows, dismissing the card.
- **Side effects:** One response frame; one event.
- **Persistence:** None.
- **Failure cases:** An unknown requestID returns silently.; A nil connection skips the response but the entry is already removed, so the agent is never answered and the card is never dismissed - `onEvent` is only reached after the optional-chained respond, which does not throw, so the event IS still emitted.
- **Cancellation:** Superseded by interrupt() and finishPrompt, which answer cancelled.
- **Windows path:** Same payload shape and same remove-then-respond order.
- **Verify by:** contract fixture (double click on one card yields one response)

### PR-PROVACP-075 - isRunning is true only while a connection exists and is not closed

### PR-PROVACP-077 - agent_message_chunk streams assistant text and keys the bubble by messageId when the agent supplies one
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:492-497 - `guard let text = update["content"]?["text"]?.string else { return }; thoughtID = nil; let id = update["messageId"]?.string.map { "message-\($0)" } ?? messageID ?? nextID("message"); messageID = id; onEvent?(.messageDelta(id: id, text: text))`
- **Preconditions:** A session/update of type agent_message_chunk arrived outside a replay.
- **Action:** handleNotification handles it.
- **Expected:** A chunk without content.text is dropped entirely. thoughtID is cleared, so the next thought chunk opens a new reasoning block. The bubble id is "message-" + the agent's messageId when present (note the literal prefix, so the same agent id maps to the same bubble across chunks), otherwise the current messageID, otherwise a freshly generated id. The event is .messageDelta(id:text:), an append, not a replace.
- **Side effects:** Emits ProviderEvent.messageDelta.
- **Persistence:** The thread document is written by the runtime, not here.
- **Failure cases:** A chunk whose content is a non-text block is dropped silently.
- **Cancellation:** not cancellable
- **Windows path:** Same, including the "message-" prefix literal.
- **Verify by:** interaction test (two chunks with the same messageId land in one bubble)

### PR-PROVACP-078 - agent_thought_chunk streams reasoning text into one block per run of thoughts

- **Cancellation:** not cancellable
- **Windows path:** Same asymmetry: thoughts clear nothing, messages clear the thought id.

### PR-PROVACP-079 - Generated stream ids are prefix, counter and eight UUID characters
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:701-704 - `counter += 1; return "\(prefix)-\(counter)-\(UUID().uuidString.prefix(8))"`
- **Preconditions:** A message or thought chunk arrived with no id to reuse.
- **Action:** nextID runs.
- **Expected:** The format is exactly <prefix>-<counter>-<8 chars>, where prefix is "message" or "thought", counter is a per-session integer starting at 1 and shared by both prefixes, and the suffix is the first eight characters of an uppercase hyphenated UUID string, so it is eight hexadecimal digits from the UUID's first group. Example shape: message-1-3F2A9C1B.
- **Persistence:** The ids end up in the persisted thread document via the runtime.
- **Cancellation:** not cancellable
- **Windows path:** Same format. Use a UUID v4 rendered uppercase with hyphens and take its first eight characters, so the shape matches; the value is opaque but the format is observable in stored threads.
- **Verify by:** unit (regex on the produced id)

### PR-PROVACP-081 - A tool_call that already carries output or a status also emits an immediate update
- **Source:** DroppyCode/Services/Providers/ACPSession.swift:514-515 - `let initial = makeToolUpdate(update); if initial.output != nil || initial.status != nil { onEvent?(.toolUpdated(id: id, update: initial)) }`

- **Action:** The same payload is run through makeToolUpdate.

- **Side effects:** A second event on the same row id.
- **Persistence:** None here.
- **Cancellation:** not cancellable
- **Windows path:** Same two-event sequence and the same non-nil test on exactly those two fields.
- **Verify by:** interaction test (single-notification completed tool call)
