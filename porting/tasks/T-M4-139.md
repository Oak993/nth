### PR-RUNTIME-007 - The ProviderSession protocol has two properties and eight methods
- **Source:** DroppyCode/Services/Providers/ProviderSession.swift:136-151 protocol ProviderSession: AnyObject, @MainActor - var onEvent: ((ProviderEvent) -> Void)? { get set }, var isRunning: Bool { get }, func start() async throws -> String, func send(_ input: TurnInput) async throws, func interrupt() async, func resolveApproval(_ requestID: String, optionID: String), func answerQuestion(_ requestID: String, answers: [String: [String]]), func compact() async throws, func stop(), func stopAgent(_ id: String) async -> Bool
- **Preconditions:** A provider adapter is being written.
- **Action:** The adapter conforms to the protocol.
- **Expected:** start() returns the session id as a String. resolveApproval and answerQuestion are synchronous and return nothing. answers is a dictionary of question id to an array of answer strings. The whole protocol is main-actor isolated.
- **Persistence:** None.
- **Failure cases:** start() and send() and compact() may throw; interrupt() and stop() cannot.
- **Cancellation:** start(), send(), interrupt() and compact() are async and therefore cancellable by the caller's task; stop() is synchronous.
- **Windows path:** Interface on the main/UI thread equivalent. The main-actor isolation is what makes the epoch guard in observe() safe without locking (PR-RUNTIME-043).
- **Verify by:** contract fixture - a scripted stand-in session implementing the full surface
