## Requirements

### PR-WIN-216 - The app zoom has exactly eight levels: 75, 90, 100, 110, 125, 150, 175 and 200 percent
- **Source:** DroppyCode/UI/Common/AppZoom.swift:3-6 the doc comment 'The app-wide zoom: the window's content is laid out in the space the window has divided by the scale, then drawn back up, so a bigger zoom shows less at once instead of clipping.' and `static let levels = [75, 90, 100, 110, 125, 150, 175, 200]` | DroppyCode/App/AppSettings.swift:251-255 the comment 'The app-wide zoom in percent: the whole window scales, the way a browser's zoom does, rather than the conversation's type alone.' and `var appZoom: Int { didSet { defaults.set(appZoom, forKey: Key.appZoom) } }`
- **Preconditions:** None.
- **Action:** A zoom step, a normalization or a scale is computed.
- **Expected:** The only zoom values the app ever applies are the eight integer percentages 75, 90, 100, 110, 125, 150, 175 and 200, in that ascending order; 100 is the stock size. The setting is an integer percent, AppSettings.appZoom; its storage, its default and the Settings card that edits it belong to the settings area.
- **Persistence:** Nothing persisted by the table itself; the setting is stored by the settings area under the key "appZoom" (AppSettings.swift:131, :253-254).
- **Cancellation:** not cancellable
- **Windows path:** One ordered constant table of the same eight integers, shared by the zoom chords, the Settings card and the scaling wrapper.
- **Verify by:** unit: the table equals [75, 90, 100, 110, 125, 150, 175, 200] exactly

### PR-WIN-217 - A zoom value that is not one of the eight levels counts as 100, never as the nearest level
- **Source:** DroppyCode/UI/Common/AppZoom.swift:8-10 `static func normalized(_ percent: Int) -> Int { levels.contains(percent) ? percent : 100 }` | DroppyCode/App/AppSettings.swift:722 `appZoom = AppZoom.normalized(defaults.object(forKey: Key.appZoom) as? Int ?? 100)` | DroppyCode/UI/Common/AppZoom.swift:22 `let scale = CGFloat(AppZoom.normalized(percent)) / 100`
- **Preconditions:** None.
- **Action:** A zoom value is normalized: at settings load, when the scale is computed, or before a step.
- **Expected:** normalized returns the value unchanged when it is exactly one of the eight levels and 100 for every other integer, including a value between two levels (95, 130) and a value outside the range (60, 250). It does not clamp or round to the nearest level. The settings load, the scale and the step function all go through it, so an off-table value draws at the stock size.
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** The same membership test with the same fallback of 100; no nearest-level rounding.
- **Verify by:** unit: normalized(95) == 100, normalized(130) == 100, normalized(60) == 100, normalized(250) == 100, normalized(125) == 125

### PR-WIN-218 - A zoom step moves to the neighbouring level and stays put at either end
- **Source:** DroppyCode/UI/Common/AppZoom.swift:12-15 `static func next(_ percent: Int, increasing: Bool) -> Int { let current = normalized(percent); return increasing ? (levels.first { $0 > current } ?? current) : (levels.last { $0 < current } ?? current) }`
- **Preconditions:** None.
- **Action:** A zoom in or zoom out step is computed from the current value.
- **Expected:** The current value is normalized first, so an off-table value counts as 100. Increasing returns the first level above it and decreasing the last level below it. At 200 increasing returns 200 and at 75 decreasing returns 75: no wrap and no error. Examples: next(100, up) = 110, next(110, down) = 100, next(95, up) = 110.
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** The same function over the same table, used by the zoom chords (PR-WIN-222 to PR-WIN-225) and the Settings card.
- **Verify by:** unit over every level in both directions, both ends, and an off-table input

### PR-WIN-219 - The app zoom draws the content at scale percent / 100 about its top-leading corner, inside a layout that reflows it
- **Source:** DroppyCode/UI/Common/AppZoom.swift:18-27 `struct AppZoomModifier: ViewModifier { let percent: Int; func body(content: Content) -> some View { let scale = CGFloat(AppZoom.normalized(percent)) / 100; ZoomLayout(scale: scale) { content.scaleEffect(scale, anchor: .topLeading) } } }`
- **Preconditions:** A hosted view tree carries the modifier (PR-WIN-221).
- **Action:** The tree draws with a given appZoom.
- **Expected:** The scale is normalized(appZoom) / 100: 0.75, 0.9, 1, 1.1, 1.25, 1.5, 1.75 or 2. The content is drawn scaled by that factor about its top-leading corner, and the scaled drawing is laid out by the zoom layout (PR-WIN-220), so nothing is clipped. At 100 the scale is exactly 1.
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** A render transform of the same factor with its origin at the top-left corner, applied inside a layout that measures the content at the unscaled size (PR-WIN-220).
- **Verify by:** unit: the scale for each level; capture comparison of the main window at 75, 100 and 200

### PR-WIN-220 - The zoom layout proposes the unscaled viewport, reports the scaled size and places the content at its origin, so a bigger zoom shows less instead of clipping
- **Source:** DroppyCode/UI/Common/AppZoom.swift:29-51 the comment 'Proposes the unscaled viewport so forms reflow and keep their scrollbars inside the window; a bare `scaleEffect` would clip the enlarged content.' and ZoomLayout: sizeThatFits `guard let content = subviews.first else { return .zero }; let size = content.sizeThatFits(unscaled(proposal)); return CGSize(width: size.width * scale, height: size.height * scale)`; placeSubviews `subviews.first?.place(at: bounds.origin, anchor: .topLeading, proposal: unscaled(ProposedViewSize(bounds.size)))`; `private func unscaled(_ proposal: ProposedViewSize) -> ProposedViewSize { ProposedViewSize(width: proposal.width.map { $0 / scale }, height: proposal.height.map { $0 / scale }) }`
- **Preconditions:** A hosted view tree carries the app zoom.
- **Action:** The tree is measured and placed.
- **Expected:** Measuring: the child is asked for its size given the proposal divided by the scale in each dimension, an unspecified dimension staying unspecified, and the layout reports that size multiplied by the scale. Placing: the child is placed at the layout's origin, anchored top-leading, with a proposal of the layout's bounds divided by the scale. So at 200% a window 1000 points wide lays its content out 500 points wide and draws it twice as large: forms reflow and their scroll bars stay inside the window. With no child the layout is zero by zero.
- **Persistence:** nothing persisted
- **Cancellation:** not cancellable
- **Windows path:** A layout panel whose measure and arrange pass the available size divided by the scale to the child, report the child's desired size times the scale, and arrange the child at the origin. Avalonia clamps every DesiredSize to its constraint (ED-150), so when the content wants more than the host divided by the scale, the layout reports the host size rather than the content's wish times the scale; placement from the arranged bounds is unchanged, and hosts arrange the zoom at their own frame as FrameHostingView (sizingOptions = []) does.
- **Verify by:** unit on the proposal arithmetic at each level; interaction test at 200% that a Settings page scrolls inside the window and nothing is cut off at the right edge
