### PR-HYDRA-029 - The 14 Hydra AppSettings keys have these exact names and these exact defaults, with Hydra on by default
- **Source:** DroppyCode/App/AppSettings.swift:155-176 Key names - hydraEnabled, hydraDefaultEnabled (= ChatThread.hydraDefaultKey = "hydraDefaultEnabled"), hydraQueueHeads, hydraAlwaysHeads, hydraIsolateHeads, hydraAutoMerge, hydraReviewHeads, hydraAutoClearFinished, hydraAutoHidesIdleHeads, hydraShowsHeadDetails, hydraAutoPopsHeads, hydraTempersHeadEffort, hydraMaxHeads, hydraPairs | DroppyCode/App/AppSettings.swift:743-776 defaults - hydraEnabled true, hydraDefaultEnabled true, hydraQueueHeads true, hydraAlwaysHeads false, hydraIsolateHeads true, hydraMaxHeads = HydraPair.clampedCap(stored Int) so nil when absent, hydraAutoMerge false, hydraReviewHeads false, hydraAutoClearFinished false, hydraAutoHidesIdleHeads false, hydraShowsHeadDetails false, hydraAutoPopsHeads false, hydraTempersHeadEffort true, hydraPairs = Self.load([Lenient<HydraPair>].self)?.compactMap(\.value) ?? [] | DroppyCode/App/AppSettings.swift:563-573 hydraMaxHeads didSet removes the key entirely when set to nil
- **Preconditions:** The app starts with no stored settings, or with settings from an earlier build.
- **Action:** Settings are read.
- **Expected:** hydraEnabled true, hydraDefaultEnabled true, hydraQueueHeads true, hydraIsolateHeads true and hydraTempersHeadEffort true; hydraAlwaysHeads, hydraAutoMerge, hydraReviewHeads, hydraAutoClearFinished, hydraAutoHidesIdleHeads, hydraShowsHeadDetails and hydraAutoPopsHeads all false; hydraMaxHeads genuinely absent (nil, not 0 and not 8) and clamped into 1...8 on read as well as on write; hydraPairs an empty list. - **Verify by:** unit over each default, a restart test, and a corruption test that injects one bad pair

### PR-HYDRA-151 - AppSettings.hydraPair(for:model:) picks the exact-model pair, else an any-model pair, else the provider's first
- **Source:** DroppyCode/App/AppSettings.swift:805-814 func hydraPair(for provider: ProviderKind, model: String?) -> HydraPair? - candidates are the pairs on that provider; an exact orchestratorModel match wins; else the first with a nil orchestratorModel; else the first candidate
- **Preconditions:** The per-chat Hydra switch is being turned on, or a new chat needs a pair.
- **Action:** The best-fit pair is chosen.
- **Expected:** Three-step preference over the pairs on the chat's provider, in setup order: a pair whose lead model equals the chat's model, then a pair that names no lead model, then simply the first. nil when the provider has no pairs at all.
- **Persistence:** Reads the persisted pairs list.
- **Cancellation:** not cancellable
- **Windows path:** Pure lookup; the order of the stored list decides ties.
- **Verify by:** unit over all three steps

### PR-PROVAPI-012 - Key fields start empty at launch and are filled from the Keychain once, off the main thread
- **Source:** DroppyCode/App/AppSettings.swift:731-735 - deepseekAPIKeyInput, metaAPIKeyInput and zaiAPIKeyInput are set to the empty string during init, with the comment that the Keychain is read later | DroppyCode/App/AppSettings.swift:446-449 readKeychainIfNeeded | DroppyCode/App/AppSettings.swift:453-458 loadKeychainInBackground - detached at userInitiated priority, guarded by didReadKeychain | DroppyCode/App/AppSettings.swift:434-441 readKeys - one Keychain round trip per key
- **Preconditions:** App launch.
- **Action:** The app starts and later something asks for a key, or the background load runs.
- **Expected:** No Keychain query happens before the first frame. The fields hold the empty string until either loadKeychainInBackground completes or a first ask triggers readKeychainIfNeeded; the read then happens exactly once per process, one query per account.
- **Side effects:** Four Keychain reads (DeepSeek, Meta, Z.ai, Command Code) in one batch
- **Persistence:** none
- **Failure cases:** A read that returns nothing leaves the field at the UserDefaults fallback value
- **Cancellation:** not cancellable
- **Windows path:** Deferred, single, off-the-UI-thread DPAPI read in the main process; the renderer never touches the secret store directly.
- **Verify by:** integration
