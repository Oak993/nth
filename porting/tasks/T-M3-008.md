### PR-GIT-059 - A checkpoint of an unchanged tree reuses the commit the watch remembers and costs only the update-ref
- **Source:** DroppyCode/Services/Git/Git.swift:419-427 - if let known = watch?.commit(of: tree) { commit = known } else { … watch?.remember(commit: commit, of: tree) } | DroppyCode/Services/Git/WorkingTreeWatch.swift:339-352 commit(of:) and remember(commit:of:) - both require the last snapshot to be exactly that tree
- **Preconditions:** A checkpoint was already taken of the current tree and nothing was written since.
- **Action:** A new checkpoint is requested.
- **Expected:** The watch returns the remembered commit only when its last snapshot's tree equals the requested tree; the commit-tree process is skipped entirely and only the update-ref runs. remember stores the commit only when the snapshot still holds that same tree, so a snapshot replaced meanwhile drops the record silently.
- **Side effects:** One git process instead of two
- **Persistence:** In-memory only.
- **Failure cases:** No watch (a non-local volume or an unresolvable index) means no reuse, and every checkpoint pays for its own commit-tree
- **Cancellation:** not cancellable
- **Windows path:** Same one-entry memo keyed on the snapshot's tree.
- **Verify by:** unit asserting a second checkpoint of an untouched tree spawns exactly one process
