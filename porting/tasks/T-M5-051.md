## Requirements

### PR-THEME-134 - A video link's id is recognised from five YouTube URL shapes and must be at least eight id-safe characters
- **Source:** DroppyCode/UI/Markdown/LinkTitles.swift:11-31 videoID(for:): the host is lower-cased and a leading "www." removed; for "youtu.be" the first path segment is the id; for "youtube.com", "m.youtube.com", "music.youtube.com" and "youtube-nocookie.com" a first segment of "shorts", "embed", "live" or "v" makes the second segment the id, otherwise the "v" query item's value is the id; any other host yields nothing | DroppyCode/UI/Markdown/LinkTitles.swift:71-77 checked(_:): the value must be at least 8 characters and contain only letters, digits, hyphens and underscores
- **Preconditions:** A link is being examined for a video title.
- **Action:** Its id is extracted.
- **Expected:** Ids are taken from youtu.be/<id>, and from youtube.com, m.youtube.com, music.youtube.com and youtube-nocookie.com in the forms /shorts/<id>, /embed/<id>, /live/<id>, /v/<id> and ?v=<id>. A candidate shorter than 8 characters, or containing anything other than letters, digits, hyphens and underscores, is rejected, so a bare /watch path or a playlist link is not a video.
- **Persistence:** not persisted
- **Failure cases:** Not a video link: no title fetch is attempted and the host-and-path title stands.
- **Cancellation:** not cancellable
- **Windows path:** The four host names and the four path prefixes are exact. "www." is stripped but no other subdomain is.
- **Verify by:** unit: the five shapes, the four hosts, and the two id rejections

### PR-THEME-135 - A video title is fetched once per id from the public oEmbed endpoint, and a failure is remembered as an answer
- **Source:** DroppyCode/UI/Markdown/LinkTitles.swift:4-9 doc: titles come from YouTube's public oEmbed endpoint, which needs no key; the store is locked rather than main-actor because the pretty string is built off the main actor | DroppyCode/UI/Markdown/LinkTitles.swift:40-56 title(forVideo:): `if let known = Store.shared.title(id) { return known }`; `guard Store.shared.claim(id) else { return nil }`; the request must return status 200 and decode to `OEmbed` with a `title`, else `Store.shared.finish(id, title: nil)`; `let title = payload.title.trimmed`; `Store.shared.finish(id, title: title.isEmpty ? nil : title)` | DroppyCode/UI/Markdown/LinkTitles.swift:62-69 the endpoint: "https://www.youtube.com/oembed" with the query items url="https://www.youtube.com/watch?v=<id>" and format="json" | DroppyCode/UI/Markdown/LinkTitles.swift:79-110 the store: `private final class Store: Sendable` with `private let state = Mutex(State())` (Synchronization, :2); claim() (:96-99) is `state.withLock { $0.claimed.insert(id).inserted }`; finish() (:101-110) stores a title when there is one and always inserts the id into claimed
- **Preconditions:** A paragraph carries a video link.
- **Action:** The title is fetched.
- **Expected:** A GET is made to the oEmbed endpoint with the canonical watch URL and format json. Only a 200 with a decodable title counts; the title is trimmed and an empty one is treated as no title. Exactly one fetch happens per id across the whole app, because a claim is taken before the request and a caller that loses the claim returns nothing rather than waiting. A private, deleted or unavailable video is remembered as having no title and is never asked about again, so the host-and-path form stands permanently.
- **Side effects:** One outbound HTTPS request per video id, to www.youtube.com, carrying the video id
- **Persistence:** In memory only, for the process lifetime.
- **Failure cases:** Non-200, a network error or an undecodable body: recorded as no title, no retry.; An empty title after trimming: recorded as no title.; A losing claimant: returns nothing immediately, which shows the fallback title until some later render picks up the fetched one.
- **Cancellation:** The request is not cancellable from the caller; a cancelled row's task simply stops awaiting it.
- **Windows path:** Outbound network from the renderer for chat content. The claim-before-fetch pattern is what stops a streaming row, which restarts its task on every token, from firing a request per token.
- **Verify by:** contract fixture against a mock endpoint: one request per id, a 404 is never retried
