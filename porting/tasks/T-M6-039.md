### PR-PROVAPI-012 - Key fields start empty at launch and are filled from the Keychain once, off the main thread
- **Source:** DroppyCode/App/AppSettings.swift:744-748 - deepseekAPIKeyInput, metaAPIKeyInput and zaiAPIKeyInput are set to the empty string during init, with the comment that the Keychain is read later | DroppyCode/App/AppSettings.swift:450-453 readKeychainIfNeeded | DroppyCode/App/AppSettings.swift:457-462 loadKeychainInBackground - detached at userInitiated priority, guarded by didReadKeychain | DroppyCode/App/AppSettings.swift:434-441 readKeys - one Keychain round trip per key
- **Preconditions:** App launch.
- **Action:** The app starts and later something asks for a key, or the background load runs.
- **Expected:** No Keychain query happens before the first frame. The fields hold the empty string until either loadKeychainInBackground completes or a first ask triggers readKeychainIfNeeded; the read then happens exactly once per process, one query per account.
- **Side effects:** Four Keychain reads (DeepSeek, Meta, Z.ai, Command Code) in one batch
- **Persistence:** none
- **Failure cases:** Upstream: a Keychain read that returns nothing fills the field from the UserDefaults plaintext copy (DroppyCode/App/AppSettings.swift:412-413 `inKeychain = !keychain.isEmpty` / `value = inKeychain ? keychain : fallback`, with the fallbacks read at :434-437). - **Cancellation:** not cancellable
- **Windows path:** Deferred, single, off-the-UI-thread Credential Manager read (OD-0008 B3), one query per account, never before the first frame. No plaintext fallback is read (OD-0008 A6): a field whose account holds nothing stays empty.
- **Verify by:** integration
