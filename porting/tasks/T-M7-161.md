### PR-PROVREG-091 - Editing an API key field saves it and schedules a 600 millisecond debounced re-check, cancelling any pending one
- **Source:** DroppyCode/App/Views/Settings/SettingsView.swift:768-779 onChange(of: apiKey) - an edit only counts when the value differs from the stored input; then setAPIKeyInput, keyCheck?.cancel(), and a task that sleeps 600 milliseconds, checks Task.isCancelled, then calls refresh(provider) and loadCatalog(provider, force: true)
- **Preconditions:** The provider has acceptsAPIKey true and the field value differs from the stored input.
- **Action:** The user types or pastes into the API key field.
- **Expected:** The value is stored immediately. Any in-flight debounce task is cancelled. After exactly 600 milliseconds of no further edits, refresh(provider) runs, then loadCatalog(provider, force: true). Loading the stored key into the field on appear does not trigger this, because the guard compares against the stored input.
- **Side effects:** Network validation call for the API-key providers; a CLI launch for Command Code.
- **Persistence:** The key is persisted immediately, before the debounce elapses.
- **Failure cases:** The task is cancelled by a further edit or by the section disappearing: the check does not run and no status changes.
- **Cancellation:** The debounce task is explicitly cancelled on the next edit and the cancellation is checked after the sleep before any work.
- **Windows path:** Same 600 millisecond debounce and the same cancel-then-replace pattern.
- **Verify by:** interaction test with a fake clock asserting exactly one check after a burst of keystrokes
