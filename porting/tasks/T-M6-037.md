### PR-TERM-066 - Creating a worktree runs every script flagged runOnWorktreeCreate in the new worktree and shows the drawer
- **Source:** DroppyCode/App/AppModel.swift:1133-1137 - after the worktree is added and the thread updated: for script in project.scripts where script.runOnWorktreeCreate { terminals.run(script, threadID: threadID, directory: path); runtime(for: threadID).isTerminalVisible = true } | DroppyCode/App/AppModel.swift:1116-1132 createWorktree(for:) - the surrounding flow, including the git preconditions and the generated path and branch
- **Preconditions:** A thread is being given its own git worktree and the project has flagged scripts.
- **Action:** The worktree is created successfully.
- **Expected:** Each flagged script runs in its own new tab, in project order, with the NEW WORKTREE path as the directory rather than the project path, and the drawer is shown. Unflagged scripts do not run. Nothing runs if the worktree creation fails or is refused.
- **Side effects:** One shell process per flagged script; the drawer becomes visible.
- **Persistence:** None from this step; the thread's worktreePath and branch were written just before.
- **Failure cases:** Worktree creation throws: an alert titled "Could not create a worktree" is shown and no script runs.; Not a git repository or no commits: the alert is titled "Worktree unavailable" with the message "New worktrees need a git repository with at least one commit." and no script runs.
- **Cancellation:** not cancellable
- **Windows path:** Same ordering and the same directory choice.
- **Verify by:** integration test creating a worktree in a project with one flagged and one unflagged script
