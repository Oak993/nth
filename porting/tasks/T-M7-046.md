- **Preconditions:** The timeline's scroll content is being laid out.
- **Action:** Layout runs.
- **Expected:** The content is capped at 820 points wide and lead-aligned, padded 20 points on each side, 72 points from the top (so it clears the sticky chrome row) and 18 points at the bottom. This is the same column the composer uses, so messages line up with its edges.

### PR-CHAT-023 - While the window is being reshaped the rows wrap to a width quantized to 12 points and capped at 860

- **Preconditions:** The window is being dragged, the sidebar is sliding or dragging, or the terminal divider is held.
- **Action:** The pane's width changes.
- **Expected:** The content lays out at a stepped width so rows re-measure a few times over a drag rather than every frame. - **Verify by:** interaction test measuring re-layout count during a simulated drag

### PR-CHAT-024 - The measured viewport height is quantized to 12 points and written only when it moves
- **Source:** DroppyCode/App/Views/Chat/ThreadTimeline.swift:442-445 onGeometryChange of visibleHeight - let stepped = (height / resizeStep).rounded(.down) * resizeStep; if stepped != viewportHeight { viewportHeight = stepped } | DroppyCode/App/Views/Chat/ThreadTimeline.swift:882-884 visibleHeight - max(0, proxy.size.height - safeAreaInsets.top - safeAreaInsets.bottom)
- **Preconditions:** The timeline is on screen.

### PR-CHAT-028 - Entries are partitioned into contiguous runs sharing one turn id, and each run with a turn id becomes exactly one block
- **Source:** DroppyCode/App/Views/Chat/ThreadTimeline.swift:1557-1565 the run loop - a new run starts whenever the turnID differs from the last run's, nil grouping with nil | DroppyCode/App/Views/Chat/ThreadTimeline.swift:1575-1584 the turn branch - rows filtered to exclude .turnEnd and .reasoning, block id "turn-<turnID.uuidString>-<first row id>"
- **Preconditions:** A thread's entries are being turned into display blocks.
- **Action:** build runs.
- **Expected:** Entries are walked once; adjacent entries with the same turn id form one run. Each run with a turn id becomes one .turn block whose rows are the run's entries minus every turnEnd and reasoning entry, whose summary is the turn's summary from the meta table, and whose id is the literal "turn-" plus the turn UUID string plus "-" plus the id of the run's first row. The composite id is required because a note filed under no turn landing mid-turn splits the turn into two runs, and two blocks under one id left the second, running tail undrawn.
- **Persistence:** None; blocks are transient.
- **Cancellation:** not cancellable
- **Windows path:** Reproduce the composite id exactly, including both hyphens and the uppercase-hyphenated UUID spelling, because the minimap, the scroll outline and the lazy list all key on it.
- **Verify by:** unit over a fixture entry list containing a mid-turn note
