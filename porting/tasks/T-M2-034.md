### PR-PROVREG-026 - Command Code executable name is cmd, which collides with the Windows command interpreter
- **Source:** DroppyCode/Core/Models/Provider.swift:51 executableName - case .commandcode returns "cmd" | DroppyCode/Services/Providers/ProviderRegistry.swift:239-247 fallbackExecutables for commandcode - the comment names "cmd" as the documented alias and "command-code" and "commandcode" as the package's own names
- **Preconditions:** Provider is not API-key based.
- **Action:** executable(for:) looks the CLI up on PATH under the bare name cmd, then walks the commandcode fallback list.
- **Expected:** The bare name searched first is exactly "cmd". The same string is the Binary path placeholder for the Command Code section.
- **Side effects:** A PATH walk plus the fallback candidate walk.
- **Persistence:** None.
- **Failure cases:** Nothing found: returns nil.
- **Cancellation:** not cancellable
- **Windows path:** PLATFORM BOUNDARY AND COLLISION. On Windows the bare name cmd resolves to the system command interpreter cmd.exe on the machine PATH, so a direct PATHEXT lookup finds the wrong program and would make Command Code read as installed on every Windows PC. The source contains no identity check, so the rule for distinguishing them is an open decision and must not be guessed. Executable identity is validated per PA-0016: PATH resolution honours PATHEXT, and a candidate whose Windows version resource identifies it as the command interpreter (CompanyName Microsoft Corporation with OriginalFilename Cmd.Exe/Cmd.Exe.MUI, or FileDescription Windows Command Processor), or which is %SystemRoot%System32cmd.exe or %SystemRoot%SysWOW64cmd.exe, is rejected and the provider reports not installed.
- **Verify by:** contract fixture plus an interaction test proving a system cmd.exe is never accepted as Command Code
